    SAP ABAP 수업 정리 노트

    배운 순서대로, 키워드와 한 줄 설명으로 정리했어요.

    SAP S/4HANA 2023ABAP 7.58클라이언트 100

    "주의"는 꼭 지킬 점, "비유"는 낯선 개념을 익숙한 것에 빗댄 설명이에요. 점선 밑줄 용어는 눌러서 뜻을 봐요. "더 알아보기"는 처음엔 안 봐도 되는 내용이에요.

    0장SAP와 ABAP

    ABAP은 회사 업무 시스템 SAP 안에서 프로그램을 만드는 언어예요.

    ERP

    구매·판매·회계·인사 업무를 한 시스템에서 처리하는 프로그램이에요.

    회사에는 물건을 사는 부서, 파는 부서, 돈을 관리하는 부서, 사람을 관리하는 부서가 있어요. 부서마다 따로 프로그램을 쓰면 같은 정보를 여러 번 입력해야 하고, 서로 숫자가 안 맞는 일이 생겨요. ERP는 이 업무들을 하나의 시스템과 하나의 데이터베이스로 묶어서, 한 번 입력한 데이터를 모든 부서가 같이 쓰게 해요.

    한 부서가 입력하면 다른 부서도 같은 데이터를 바로 봐요.

    SAP

    ERP를 만드는 독일 회사, 그리고 그 제품 이름이에요.

    "SAP"는 회사 이름이기도 하고, 그 회사가 파는 ERP 제품을 부를 때도 써요. 우리가 수업에서 접속하는 시스템이 바로 SAP의 ERP 제품이에요.

    S/4HANA

    SAP ERP의 최신 세대예요. 수업 서버는 S/4HANA 2023이에요.

    SAP ERP는 오래전부터 여러 세대가 나왔어요. S/4HANA는 그중 가장 최근 세대이고, 뒤에 붙은 2023은 출시 연도예요. 수업 서버도 이 버전이라서, 책이나 인터넷 자료를 볼 때 S/4HANA 기준인지 확인하면 좋아요.

    SAP가 만든 데이터베이스 HANA 위에서 동작해요.

    표준 기능

    SAP가 미리 만들어 둔 기능이에요.

    SAP를 설치하면 주문, 회계, 재고 같은 일반적인 업무 화면과 보고서가 이미 들어 있어요. 이것을 표준 기능이라고 해요. 대부분의 업무는 표준 기능으로 처리하고, 회사만의 특별한 요구가 있을 때만 새로 만들어요.

    회사마다 필요한데 표준에 없는 보고서나 화면은 직접 만들어요.

    ABAP

    표준에 없는 기능을 SAP 안에 만드는 언어예요. 수업 버전은 7.58이에요.

    표준 기능만으로 부족할 때 개발자가 직접 프로그램을 만들어요. 이때 쓰는 언어가 ABAP이에요. ABAP으로 만든 프로그램은 내 PC가 아니라 SAP 서버 안에서 실행되고, SAP 데이터베이스의 데이터를 바로 읽고 쓸 수 있어요.

    SAP 시스템의 세 층

    SAP GUI내 PC. 화면을 보여 주고 입력을 받아요
    ↓ 입력을 보내고 화면을 받아요
    애플리케이션 서버우리가 만든 ABAP 코드가 실행돼요
    ↓ 데이터를 읽고 써요
    데이터베이스모든 데이터가 테이블에 저장돼요

    6장(테이블 만들기)과 8장(데이터 읽기)에서 이 그림을 다시 써요.

    1장SAP GUI 접속과 기본 조작

    SAP GUI로 서버에 접속하고, T-code로 화면을 열어요.

    접속 항목값
    시스템 IDEFX
    인스턴스 번호00
    클라이언트100
    로그인 언어EN (오류 메시지를 영어로 검색하기 쉬워요)

    서버 주소와 비밀번호는 노트에 적지 않고 따로 보관해요.

    SAP GUI

    내 PC에서 SAP 서버에 접속하는 프로그램이에요. 개발 작업은 여기서 해요.

    SAP 서버는 회사 서버실이나 클라우드에 있어요. 우리는 PC에 설치한 SAP GUI로 그 서버에 접속해서 화면을 보고 입력해요. 실제 계산과 저장은 서버가 하고, SAP GUI는 화면을 보여 주고 입력을 전달하는 창구 역할을 해요.

    더 알아보기: 접속이 안 될 때
    • 접속 항목을 더블클릭해도 창이 안 뜨면 서버와 연결되지 않은 거예요. 서버 주소, 인스턴스 번호, 네트워크를 확인해요.
    • SAP GUI의 패치 레벨이 0이면 최신 패치로 올려요.
    클라이언트

    한 SAP 시스템 안에서 데이터를 나눠 쓰는 단위예요. 수업은 100번이에요.

    같은 SAP 시스템을 쓰더라도 로그인할 때 고른 클라이언트 번호에 따라 보이는 데이터가 달라져요. 그래서 로그인할 때 클라이언트 번호를 잘못 넣으면 내가 만든 데이터가 안 보일 수 있어요.

    한 건물에 층마다 다른 회사가 있는 것처럼, 들어간 층의 데이터만 보여요.

    나뉘는 건 데이터뿐이고, 프로그램 코드는 모든 클라이언트가 같이 써요.

    T-code

    화면이나 프로그램을 여는 단축 코드예요. 왼쪽 위 명령창에 입력해요.

    SAP에는 화면이 아주 많아서 메뉴를 하나하나 눌러 찾기 어려워요. 그래서 화면마다 짧은 코드가 붙어 있고, 이 코드를 입력하면 바로 그 화면이 열려요. 예를 들어 SE38은 프로그램을 만드는 화면, SE11은 테이블을 만드는 화면이에요.

    T-code여는 화면장
    SE38ABAP 에디터 (프로그램 만들기·실행)2
    SE11ABAP Dictionary (테이블, Data Element, Domain)6
    SE91메시지 클래스10
    SE93T-code 만들기2
    SE80프로그램과 관련 객체를 트리로 보기
    SU3내 사용자 설정 (날짜 형식, 언어)3
    /n · /o · /nex

    T-code 앞에 붙이는 접두어예요.

    T-code만 입력하면 SAP 초기 화면에서만 바로 열려요. 다른 작업 중일 때는 /n을 앞에 붙여 지금 화면을 그 T-code로 바꾸거나, /o를 붙여 새 창으로 열어요. /nex는 모든 창을 닫고 로그오프해요.

    입력동작
    /nSE38지금 창에서 SE38로 이동
    /oSE38새 창을 열어 SE38 실행
    /n하던 화면을 끝내고 첫 화면으로
    /nex창을 모두 닫고 로그오프

    접두어 없이 SE38만 넣으면 첫 화면에서만 열려요.

    도움말(F1)

    커서가 있는 필드나 키워드의 설명을 보여 줘요.

    코드 편집기에서 키워드에 커서를 두고 도움말(F1)을 누르면 그 키워드의 공식 설명서가 열려요. 문법이 헷갈릴 때 바로 확인할 수 있어요.

    값 목록(F4)

    그 칸에 넣을 수 있는 값 목록을 보여 줘요.

    입력 칸에 무엇을 넣어야 할지 모를 때 써요. 목록에서 골라 넣으니까 철자를 틀릴 걱정이 없어요.

    2장첫 프로그램 만들기 (SE38)

    SE38에서 프로그램을 만들고 저장 → 검사 → 활성화 → 실행해요.

    Z · Y

    고객이 만든 객체는 이름이 Z나 Y로 시작해요. 나머지는 SAP 표준 객체예요.

    SAP에는 SAP가 만든 표준 프로그램과 테이블이 수만 개 있어요. 우리가 만든 것과 이름이 겹치면 안 되니까, 고객이 만드는 객체는 Z나 Y로 시작하도록 정해져 있어요. 이름만 보고도 "회사에서 직접 만든 것"인지 바로 알 수 있어요.

    수업 프로그램 이름: ZRC05W0101 (05 수강생 번호, W0101 주차·순번). 수업에서는 Z는 실제 사용, Y는 연습용으로 구분해요.

    $TMP

    Local Object를 누르면 들어가는 연습용 패키지예요. 다른 서버로 전송하지 않아요.

    프로그램을 만들 때 패키지를 고르라는 창이 떠요. 패키지는 관련 객체를 묶는 폴더 같은 것인데, 연습할 때는 Local Object를 눌러 $TMP에 넣어요. $TMP에 넣은 객체는 내 서버에만 있고 다른 서버로 옮겨지지 않아요.

    REPORT

    프로그램의 첫 문장이에요.

    REPORT 뒤에는 프로그램 이름을 적어요. 프로그램을 새로 만들면 SAP가 이 줄을 자동으로 넣어 주니까 지우지 않으면 돼요.

    WRITE

    화면에 글자를 출력해요.

    WRITE로 출력한 내용은 프로그램을 실행했을 때 뜨는 결과 화면에 나와요. 값이 제대로 들어갔는지 확인할 때도 WRITE로 찍어 보면 편해요.

    실행(F8)하면
    Hello

    키워드와 값 사이에 공백이 필요해요. WRITE'Hello'.는 오류예요.

    .

    문장의 끝이에요. 모든 문장은 마침표로 끝나요.

    ABAP은 줄바꿈이 아니라 마침표로 문장이 끝났다고 판단해요. 그래서 한 문장을 여러 줄에 나눠 써도 되고, 마침표를 빠뜨리면 다음 줄까지 한 문장으로 읽혀서 오류가 나요.

    빠뜨리면 오류가 다음 줄에 표시돼요. 윗줄 끝을 확인해요.

    : ,

    같은 키워드로 시작하는 문장을 한 번에 써요(체인 문장).

    WRITE를 여러 번 쓸 때 매번 WRITE를 적는 대신, WRITE: 뒤에 쉼표로 이어서 쓸 수 있어요. 키워드 뒤의 콜론(:)은 "여기부터 이어서", 쉼표(,)는 "같은 키워드로 한 번 더"라는 뜻이에요.

    " · *

    주석(실행되지 않는 메모)이에요. "는 그 뒤부터, 줄 맨 앞 *는 줄 전체예요.

    주석은 실행되지 않고, 코드를 읽는 사람을 위한 메모예요. 왜 이렇게 짰는지 적어 두면 나중에 나 자신이나 다른 사람이 코드를 이해하기 쉬워요. 잠시 실행하지 않을 코드를 주석으로 막아 두는 데도 써요.

    여러 줄을 한 번에: 주석 처리(Ctrl + <), 주석 해제(Ctrl + >)

    대소문자

    구분하지 않아요. 키워드를 대문자로 쓰는 건 관례예요.

    write라고 써도 WRITE라고 써도 똑같이 동작해요. 그래도 키워드를 대문자로 맞춰 두면 키워드와 변수 이름이 구분돼서 읽기 쉬워요.

    Pretty Printer 버튼을 누르면 자동으로 맞춰 줘요.

    저장 → 활성화

    저장한 뒤 활성화해야 실행할 수 있는 버전이 돼요.

    저장(Ctrl+S)은 지금까지 쓴 내용을 보관만 해요. 활성화(Ctrl+F3)를 해야 문법 검사를 거쳐 실제로 실행되는 버전이 바뀌어요. 고쳤는데 결과가 그대로라면 활성화를 했는지 먼저 확인해요.

    기능 (단축키)하는 일
    저장(Ctrl+S)Save 버튼. 중간 저장이고 아직 비활성 버전이에요
    문법 검사(Ctrl+F2)Check 버튼. 오류 위치와 이유를 알려 줘요
    활성화(Ctrl+F3)Activate 버튼. 실행할 수 있는 버전으로 확정해요
    실행(F8)Execute 버튼. 프로그램을 실행해요

    저장만 하면 고친 내용이 비활성 버전으로만 남아요.

    더블클릭

    코드의 변수나 테이블 이름을 더블클릭하면 정의로 이동해요(포워드 내비게이션).

    코드에 나온 변수나 테이블이 어떻게 만들어졌는지 궁금할 때, 이름을 더블클릭하면 정의된 곳으로 바로 이동해요. 테이블 이름이면 SE11 화면이 열려요. 돌아올 때는 뒤로(F3)를 눌러요.

    SE93

    만든 프로그램에 T-code를 붙여요. 수업에서는 꼭 만들어 둬요.

    SE38에서 실행(F8)하지 않아도, 프로그램에 T-code를 만들어 두면 명령창에 그 코드만 입력해서 프로그램을 바로 열 수 있어요. 실제 사용자는 SE38을 쓰지 않으니까, 프로그램을 만들면 T-code까지 만들어 두는 게 완성이에요.

    입력 화면(5장)이 있는 리포트는 Start object를 Program and selection screen(report transaction)으로 골라요.

    3장변수와 타입

    변수는 값을 담아 두는 이름 붙은 공간이에요. 타입은 그 공간에 들어갈 값의 모양이에요.

    DATA

    변수를 만들어요.

    변수는 값을 잠시 담아 두는 그릇이에요. DATA로 이름과 타입을 정해 만들고, 그 뒤로 값을 넣거나 꺼내 써요. 프로그램이 끝나면 변수와 그 값은 사라져요.

    같은 이름은 두 번 만들 수 없어요.

    더 알아보기: TYPE 대신 LIKE

    DATA gv_b LIKE gv_a.처럼 이미 있는 변수와 같은 타입으로 만들어요. 실무에서는 거의 TYPE을 써요.

    TYPE 테이블-필드

    DB 필드와 같은 모양으로 만들어요. 실무에서 가장 많이 써요.

    나중에 DB 필드 길이가 바뀌어도 변수가 같이 따라가서 안전해요.

    DB에서 읽은 값을 담을 때 길이가 어긋나지 않아요.

    기본 타입

    ABAP이 기본으로 주는 타입이에요. 초기값은 처음 만들었을 때 들어 있는 값이에요.

    타입은 그릇의 모양이에요. 글자를 담을지(c), 정수를 담을지(i), 날짜를 담을지(d)에 따라 고르는 타입이 달라요. 타입마다 처음 만들었을 때 들어 있는 초기값도 정해져 있어요.

    타입뜻초기값
    c문자 (길이 지정)공백
    n숫자만 들어가는 문자. 번호·코드용0으로 채움
    d날짜 YYYYMMDD00000000
    i정수0
    p소수점 숫자 (DECIMALS로 자릿수)0
    더 알아보기: p 타입의 크기

    길이를 안 주면 8바이트로 숫자 15자리와 부호를 가져요. 소수점 아래 자리도 15자리에 포함돼요. 예: DATA gv_amt TYPE p DECIMALS 2.

    d (날짜)

    점 없이 8자리로 넣어요. gv_date = '20261111'.

    날짜는 내부적으로 연월일 8자리 글자(숫자만)로 저장돼요. 화면에 보이는 점이나 하이픈은 사용자 설정에 따라 붙는 모양일 뿐이에요. 그래서 넣을 때는 항상 점 없이 8자리로 넣어요.

    WRITE로 출력하면 내 설정(SU3) 형식대로 2026.11.11처럼 보여요.

    '2026.11.11'을 넣으면 앞 8글자 2026.11.만 들어가요.

    '20261132'처럼 없는 날짜도 오류 없이 들어가요.

    더 알아보기: 9999.12.31

    "끝나는 날짜 없음"은 관례적으로 9999.12.31로 넣어요. 시작일(BEGDA)이 오늘이고 종료일(ENDDA)이 9999.12.31이면 "오늘부터 계속 유효"라는 뜻이에요.

    gv_ gs_ gc_ pa_

    이름 앞 접두어로 종류를 알려요.

    변수 이름 앞에 정해진 글자를 붙이면, 이름만 보고도 "글로벌 변수인지, 구조체인지, 상수인지" 알 수 있어요. 코드가 길어질수록 이런 약속이 읽기를 편하게 해 줘요. 이름 규칙은 부록 E에 모아 뒀어요.

    gv_ 글로벌 변수 · gs_ 글로벌 구조체 · gc_ 글로벌 상수 · pa_ 입력 필드(5장)

    이름에 -는 못 써요. -는 구조체의 필드를 가리키는 기호예요.

    BEGIN OF

    여러 필드를 묶은 구조체(Structure)를 만들어요.

    관련된 값 여러 개를 따로따로 변수로 만들면 관리가 어려워요. 구조체는 여러 필드를 하나로 묶은 변수라서, 한 덩어리로 옮기거나 비울 수 있어요. 엑셀로 치면 한 줄(행)을 통째로 담는 그릇이에요.

    같은 종류의 데이터(예: 항공사·가격·통화)는 따로따로 변수로 두지 말고 구조체 하나에 묶어 정리해요.

    구조체-필드

    구조체 안의 필드 하나를 가리켜요. 예: gs_edu-price

    구조체 안의 필드 하나를 쓰고 싶으면 구조체 이름 뒤에 하이픈(-)을 붙이고 필드 이름을 적어요. 그래서 변수 이름 자체에는 하이픈을 쓸 수 없어요.

    TYPE 테이블

    테이블의 모든 필드를 통째로 가진 구조체를 만들어요. 예: DATA gs_row TYPE ztc0503.

    TYPE 뒤에 테이블 이름을 적으면 그 테이블의 한 줄과 똑같은 모양의 구조체가 돼요. 편하지만 필요 없는 필드까지 다 들어오니까, 몇 개 필드만 쓸 때는 BEGIN OF로 필요한 필드만 묶는 게 깔끔해요.

    MANDT까지 다 들어오고, 다른 테이블 필드는 못 담아요. 보통은 필요한 필드만 BEGIN OF로 만들어요.

    TYPES

    변수가 아니라 타입(모양)을 만들어요. 이 타입으로 변수를 여러 개 만들 수 있어요.

    DATA는 바로 그릇을 만들고, TYPES는 그릇을 찍어 낼 틀만 만들어요. 같은 모양의 변수를 여러 개 만들어야 할 때 틀을 한 번 정해 두면, 모양을 고칠 때도 TYPES 한 곳만 고치면 돼요.

    타입 이름은 t_ 또는 tv_로 시작해요. 이 프로그램 안에서만 쓰는 로컬 타입이에요.

    CONSTANTS

    바꿀 수 없는 값(상수)을 만들어요.

    세율이나 고정 코드처럼 프로그램 안에서 바뀌면 안 되는 값은 CONSTANTS로 만들어요. 실수로 값을 바꾸는 코드를 쓰면 활성화할 때 바로 오류가 나서 막아 줘요.

    값을 바꾸는 코드를 쓰면 문법 오류예요. 구조체로 만들어도 필드 하나도 못 바꿔요.

    더 알아보기: 구조체 상수

    모든 필드에 VALUE가 있어야 해요. 빈 값은 VALUE IS INITIAL로 써요. 수업에서는 접두어 co_도 언급했어요.

    4장값 다루기와 조건문

    변수에 값을 넣고, 조건에 따라 다른 코드를 실행해요.

    =

    오른쪽 값을 왼쪽 변수에 넣어요.

    수학의 "같다"가 아니라 "오른쪽 값을 왼쪽에 넣어라"라는 뜻이에요. 그래서 gv_a = gv_b는 gv_b의 값을 gv_a에 복사하는 거예요.

    더 알아보기: MOVE와 ADD (옛 문법)

    MOVE pa_num TO gv_result.는 =와 같고, ADD 1 TO gv_result.는 1을 더해요. 예전 코드에서 읽을 수만 있으면 돼요.

    CLEAR

    변수를 초기값으로 되돌려요. 구조체는 모든 필드가 초기화돼요. 새로 담기 전과 다 쓴 뒤에 비워요.

    기준은 하나예요. 새로 담기 전에 비우고, 다 쓰고 나면 비워요. 이전 값이 남으면 오류 없이 틀린 결과가 나와요.

    언제왜
    APPEND 다음다음 줄에 앞 줄 값이 따라 들어가지 않게 (11장)
    LOOP 앞·안·뒤이전 줄이나 마지막 줄 값이 다음 처리에 섞이지 않게 (11장)
    MODIFY 다음순서는 값 바꾸기 → MODIFY → CLEAR. 먼저 비우면 빈 값이 반영돼요
    SELECT SINGLE 전못 찾으면 담을 변수에 이전 값이 그대로 남아요 (8장)
    SELECT ... INTO TABLE 전INTO TABLE은 원래 내용을 지우지만, 의도가 보이게 습관처럼 비워요

    안 써도 되는 때: DATA로 막 만든 변수(이미 초기값), FORM 안에서 만든 로컬 변수(부를 때마다 새로 만들어져요).

    기존 줄 뒤에 더 붙이는 APPENDING TABLE을 쓸 때는 SELECT 전에 비우면 안 돼요.

    더 알아보기: CLEAR와 FREE

    인터널 테이블에 CLEAR gt_info.를 쓰면 모든 줄이 지워져요. 메모리까지 돌려주려면 FREE gt_info.를 써요. 수업 수준에서는 CLEAR면 충분해요.

    MOVE-CORRESPONDING

    구조가 다른 구조체끼리 이름이 같은 필드만 골라 옮겨요.

    두 구조체의 필드 구성이 다르면 =로 옮길 때 자리 순서대로 옮겨져서 엉뚱한 칸에 값이 들어갈 수 있어요. MOVE-CORRESPONDING은 필드 이름을 보고 같은 이름끼리만 옮기니까 안전해요.

    구조가 다를 때 =를 쓰면 필드 이름이 아니라 자리 순서대로 옮겨지거나 오류가 나요.

    DB에서 읽을 때 같은 일을 하는 건 INTO CORRESPONDING FIELDS OF(8장)예요.

    자동 형변환

    타입이 다른 값을 넣으면 받는 쪽 타입으로 바뀌어요. i에 '1'을 넣어도 돼요.

    타입이 다른 값을 넣으면 ABAP이 받는 쪽 타입으로 알아서 바꿔 줘요. 편하지만, 바꿀 수 없는 값이면 프로그램이 멈춰요(덤프). 그래서 가능하면 같은 타입끼리 주고받는 게 좋아요.

    i에 'A'처럼 숫자가 아닌 글자를 넣으면 덤프가 나요.

    IF

    조건이 맞을 때만 실행해요. ELSEIF, ELSE로 "아니면"을 이어요.

    조건에 따라 다른 코드를 실행하고 싶을 때 써요. 위에서부터 조건을 차례로 확인해서 처음 맞는 곳 하나만 실행하고, 하나도 안 맞으면 ELSE를 실행해요.

    ENDIF로 꼭 닫아요.

    CASE

    변수 하나의 값마다 갈 길을 나눠요. 어디에도 안 맞으면 WHEN OTHERS로 가요.

    변수 하나의 값에 따라 갈 길이 여러 개일 때, IF와 ELSEIF를 길게 이어 쓰는 대신 CASE로 쓰면 읽기 쉬워요. WHEN마다 값 하나를 적고, 맞는 WHEN 아래 코드만 실행돼요.

    IS INITIAL

    값이 초기값(빈 값)인지 검사해요. 반대는 IS NOT INITIAL이에요.

    "값이 비어 있는지"를 확인할 때 써요. 글자는 공백, 숫자는 0이 초기값이라서, 타입마다 "빈 값"을 따로 적지 않아도 IS INITIAL 하나로 검사할 수 있어요.

    비교 연산자

    기호와 글자 중 아무거나 써도 돼요.

    =와 EQ, <>와 NE처럼 기호와 글자가 같은 뜻이에요. 팀에서 하나로 정해 쓰면 코드가 일관돼요.

    기호글자뜻
    =EQ같다
    <>NE다르다
    > <GT LT크다, 작다
    >= <=GE LE크거나 같다, 작거나 같다
    AND · OR · NOT

    AND는 둘 다, OR는 하나라도, NOT은 조건을 뒤집어요.

    조건 여러 개를 합칠 때 써요. 괄호로 묶으면 어떤 조건끼리 먼저 판단할지 분명해져서 실수가 줄어요.

    5장입력 화면과 이벤트

    PARAMETERS로 실행 전 입력 화면을 만들어요. 리포트는 코드 순서가 아니라 이벤트 순서대로 실행돼요.

    입력 화면

    PARAMETERS

    입력 칸을 만들어요. 실행 전에 입력 화면(셀렉션 스크린)이 자동으로 생겨요.

    PARAMETERS를 한 줄 쓰면 SAP가 실행 전에 입력 화면을 자동으로 만들어 줘요. 사용자가 입력한 값은 그 이름의 변수에 들어가서, 프로그램 안에서 조건 등에 쓸 수 있어요.

    입력한 값은 실행(F8)하는 순간 변수에 들어가요.

    scarr-carrid가 아니라 spfli-carrid로 만들어요. 그래야 VALUE CHECK와 값 목록(F4)이 동작해요(7장).

    SCARR의 키 필드보다, Check Table이 걸린 SPFLI의 외래 키 필드를 참조해야 실제로 있는 데이터에 맞는 값만 들어와요.

    OBLIGATORY

    필수 입력으로 만들어요.

    반드시 입력해야 하는 칸이에요. 비워 두고 실행하면 SAP가 막고 입력하라는 메시지를 띄워요. 직접 검사 코드를 쓰지 않아도 돼요.

    DEFAULT

    처음에 채워지는 기본값이에요. 사용자가 바꿀 수 있어요. 예: DEFAULT 'AA'

    입력 화면이 열릴 때 칸에 미리 채워 둘 값이에요. 자주 쓰는 값을 넣어 두면 사용자가 입력하는 수고를 덜 수 있어요.

    VALUE CHECK

    허용된 값인지 검사해요. 필드에 Check Table이나 Fixed Values가 있어야 해요.

    AS LISTBOX

    목록에서 골라 넣게 해요. VISIBLE LENGTH 20으로 폭을 정해요.

    직접 입력하는 대신 드롭다운 목록에서 고르게 만들어요. 고를 수 있는 값은 필드에 연결된 Fixed Values나 Check Table에서 가져와요.

    이벤트

    식당이 문 열기 전 준비 → 주문 → 주문 확인 → 조리 순서로 일하듯, 정해진 순서로 실행돼요.

    INITIALIZATION

    입력 화면이 뜨기 전에 실행돼요. 오늘 날짜처럼 매번 바뀌는 기본값을 넣어요.

    DEFAULT는 고정된 값만 넣을 수 있어요. 오늘 날짜처럼 실행할 때마다 달라지는 값은 INITIALIZATION에서 코드로 넣어요.

    AT SELECTION-SCREEN

    실행(F8)한 뒤, 본 처리 전에 실행돼요. 입력값을 검사해요(10장).

    사용자가 실행(F8)을 누른 직후, 본 처리로 넘어가기 전에 실행돼요. 여기서 입력값을 검사하고 틀리면 E 메시지를 띄워요. 그러면 입력 화면에 머물러서 바로 고칠 수 있어요.

    START-OF-SELECTION

    본 처리예요. 데이터를 읽고(8장) 출력해요.

    입력 검사를 통과하면 이 구역의 코드가 실행돼요. 데이터를 읽고 출력하는 실제 일은 여기서 해요. 이벤트 키워드를 하나도 안 쓰면 선언을 뺀 코드는 모두 여기에 들어가요.

    SELECT는 입력 검사가 끝난 뒤인 여기서 해요. 데이터가 없으면 보통 I나 S 메시지를 띄우고 RETURN으로 빠져나와요(10장).

    RETURN

    지금 실행 중인 구역(이벤트, FORM)을 바로 빠져나가요.

    EXIT

    반복문 안에서는 반복만, 밖에서는 구역을 빠져나가요.

    반복문 밖에서는 뜻이 분명한 RETURN을 써요.

    더 알아보기: PBO와 PAI

    직접 만드는 화면에서는 PBO(화면을 보여 주기 전)와 PAI(입력하고 Enter나 버튼을 누른 뒤) 두 단계로 처리해요. SE80에서 프로그램을 열면 Fields, Events, Screens로 나눠 볼 수 있어요.

    6장ABAP Dictionary (SE11)

    계속 남겨야 하는 데이터는 테이블에 저장해요. SE11에서 테이블과 필드의 모양을 정해요.

    테이블

    데이터를 행과 열로 저장하는 곳이에요. 엑셀 시트와 모양이 비슷해요.

    DB 테이블은 데이터를 오래 보관하는 곳이에요. 프로그램이 끝나도 데이터가 남아 있고, 여러 프로그램과 사람이 같이 써요. 키 필드 값의 조합은 행마다 달라서, 키 값을 모두 알면 원하는 행 하나를 정확히 찾을 수 있어요.

    열 하나는 필드(Field), 행 하나는 레코드(Record), 행을 하나로 집어 주는 필드는 키(Key)예요.

    활성화(Ctrl+F3)

    정의대로 데이터베이스에 실제 테이블이 만들어져요(Transparent Table).

    SE11에서 테이블을 설계하고 저장만 하면 아직 설계도일 뿐이에요. 활성화를 해야 데이터베이스에 실제 테이블이 만들어지고, 프로그램에서 읽고 쓸 수 있어요.

    저장(Ctrl+S)만 하면 테이블이 아직 없어요.

    남이 만든 객체는 조회 모드로 열어요. 수정 모드로 열면 기록이 남아요.

    현업에서 이미 데이터가 들어 있는 테이블은 필드를 추가·삭제한 뒤 Activate하면 안의 데이터가 날아갈 수 있어요. 함부로 Activate하지 말고 최대한 신중하게 해요.

    MANDT

    거의 모든 테이블의 첫 필드예요. 클라이언트 번호를 담는 키 필드예요(CLNT 3).

    클라이언트마다 데이터를 나누려면, 각 행이 어느 클라이언트의 데이터인지 표시해야 해요. 그 표시가 MANDT 필드예요. 그래서 거의 모든 테이블이 MANDT를 첫 키 필드로 가져요.

    더 알아보기: 테이블 설계 규칙
    • 테이블 이름은 보통 코드로 지어요. 예: ZTC0503
    • 키 필드(PK)를 맨 앞에, 일반 필드를 그 뒤에 둬요. 일반 필드나 외래 키는 꼭 위로 올릴 필요는 없지만, 테이블에 맞게 순서를 신경 써서 배치해요.
    • 필드 이름은 5글자 정도로 지어요. 예: SCODE, STEXT, BEGDA
    • 텍스트 길이는 보통 CHAR 20(짧은 이름), 40(일반 이름), 60(긴 설명) 중에서 골라요.
    Data Element

    필드의 뜻이에요. 필드 라벨과 도움말(F1) 설명을 적어요.

    같은 국가 코드라도 어떤 테이블에서는 "출발 국가", 다른 테이블에서는 "도착 국가"일 수 있어요. Data Element는 이런 필드의 의미와 화면에 보일 이름(라벨)을 정해요.

    프로그램에서 TYPE으로 쓸 수 있어요.

    Domain

    필드의 모양이에요. 타입, 길이, 허용 값을 정해요.

    Domain은 "글자 3칸"처럼 값의 기술적인 모양만 정해요. 같은 모양을 쓰는 Data Element 여러 개가 Domain 하나를 같이 쓸 수 있어서, 길이를 바꿀 때 Domain 한 곳만 고치면 돼요.

    Domain은 칸의 규격(글자 3칸), Data Element는 그 칸에 붙는 이름표("국가 코드")예요.

    프로그램에서 TYPE으로 쓸 수 없어요. TYPE에는 Data Element를 써요.

    더 알아보기: Domain 없이 만들기

    Data Element에 타입과 길이를 직접 적을 수도 있어요(Predefined Type). Fixed Values, Value Table, Lowercase는 Domain에만 있어요. 그래서 이런 설정이 필요하면 Domain을 연결한 Data Element로 만들어요.

    필드 하나가 참조하는 두 층 (예: 국가 필드)

    테이블 필드ZTC0503-LAND1 저장되는 자리
    ↓ 참조
    Data ElementLAND1 뜻. 라벨 "Country key", 도움말(F1) 설명
    ↓ 참조
    DomainLAND1 모양. CHAR 3, Value Table T005
    Fixed Values

    Domain의 Value Range 탭에 허용 값을 미리 정해 둬요. 예: 성별 M 남, F 여

    성별처럼 들어갈 값이 몇 개로 정해져 있고 잘 안 바뀌면, Domain에 그 값들을 적어 두면 돼요. 별도 테이블을 만들지 않아도 값 목록과 검사가 동작해요.

    값 목록(F4), LISTBOX, VALUE CHECK의 기준이 돼요. 값이 많거나 자주 바뀌면 Check Table(7장)을 써요.

    Lowercase

    Domain에서 체크하면 영문 소문자를 그대로 저장해요.

    SAP는 화면에서 입력한 글자를 기본적으로 대문자로 바꿔 저장해요. 메일 주소처럼 대소문자가 중요한 값은 Domain에서 Lowercase를 체크해야 입력한 그대로 저장돼요.

    체크하지 않으면 모두 대문자로 저장돼요.

    이 체크는 Domain에만 있어요. 대소문자 구분이 필요한 필드는 Domain을 연결한 Data Element로 만들어요.

    Structure

    여러 프로그램에서 같이 쓰는 구조체 틀이에요. 데이터는 저장되지 않아요.

    프로그램 안에서 BEGIN OF로 만든 구조체는 그 프로그램에서만 쓸 수 있어요. 여러 프로그램이 같은 모양을 써야 하면 SE11에서 Structure로 만들어 두고, 어느 프로그램에서든 TYPE으로 가져다 써요.

    SE11 Data type → Structure로 만들어요. 필요한 필드만, 여러 테이블에서 섞어 담을 수 있어요. 이름 예: ZSC05...

    Structure 안의 필드로 다른 Structure나 Table Type(11장)을 넣을 수도 있어요.

    CURR · CUKY

    금액 필드(CURR)는 반드시 통화 필드(CUKY, 보통 WAERS)를 참조해요.

    금액은 숫자만으로는 의미가 없어요. 100이 원인지 달러인지 알아야 하니까, 금액 필드는 반드시 통화 필드와 짝을 지어요. SAP는 이 통화를 보고 소수점 자리를 맞춰 보여 줘요.

    CURR는 소수점 2자리로 저장돼요. 원화 10,010원은 DB에 100.10으로 들어가고, 화면에는 10,010으로 보여요.

    테이블 고칠 때

    이미 여러 프로그램이 쓰는 테이블은 기존 필드를 바꾸지 말고, 필요한 필드를 따로 추가해요.

    기존 필드를 바꾸면 그 테이블을 쓰는 프로그램에서 오류가 나요.

    필드를 언어별로 나눠야 하면 테이블을 고치지 말고 Text Table을 따로 만들어요(10장 텍스트 테이블).

    마스터 데이터

    자주 바뀌지 않고, 여러 업무가 기준으로 계속 참조하는 데이터예요. 예: 항공사(SCARR), 고객, 자재

    이런 데이터를 담은 테이블을 마스터 테이블(Master Table)이라고 해요.

    트랜잭션 데이터

    업무가 일어날 때마다 쌓이는 기록이에요. 자주 바뀌고 계속 늘어나요. 예: 예약, 주문, 운항편(SFLIGHT)

    이런 데이터를 담은 테이블을 트랜잭션 테이블(Transaction Table)이라고 해요.

    7장테이블 관계

    Check Table을 걸면 다른 테이블에 실제로 있는 값만 들어오게 막을 수 있어요.

    항공사 → 노선 → 운항편 (키 필드만)

    SCARR 항공사CARRID
    ↓ 1 : CN 항공사 하나에 노선 0개 이상
    SPFLI 노선CARRID CONNID
    ↓ 1 : CN 노선 하나에 운항편 0개 이상
    SFLIGHT 운항편CARRID CONNID FLDATE

    SPFLI의 CARRID에는 SCARR에 있는 항공사 코드만 들어갈 수 있어요. 같은 노선의 운항편은 날짜(FLDATE)마다 1건이에요.

    외래 키

    다른 테이블의 키 값을 가져다 쓰는 필드예요. 예: SPFLI-CARRID

    테이블끼리 연결하려면 같은 값을 양쪽에 둬야 해요. 예를 들어 SPFLI(노선)에는 항공사 이름 대신 항공사 코드(CARRID)만 적어 두고, 이름은 SCARR(항공사)에서 찾아요. 이렇게 다른 테이블의 키를 가져다 둔 필드가 외래 키예요. 이름을 여러 테이블에 반복해서 적지 않아도 되고, 항공사 이름이 바뀌어도 SCARR 한 곳만 고치면 돼요.

    외래 키는 "여러 개" 쪽 테이블에 둬요. 항공사 하나에 직원이 여러 명(1:CN)이면, 사원 테이블에 담당 항공사 필드를 외래 키로 넣어요.

    Check Table

    외래 키에 들어갈 값을 검사하는 기준 테이블이에요. 예: SCARR

    외래 키에 아무 값이나 들어가면 연결이 끊겨요. SPFLI에 항공사 코드 ZZ가 들어갔는데 SCARR에 ZZ가 없으면, 그 노선이 어느 항공사 것인지 알 수 없어요. 그래서 "이 필드에는 SCARR에 있는 값만 들어갈 수 있다"고 정해 두는데, 이때 기준이 되는 SCARR가 Check Table이에요. 입력 화면에서 값 목록(F4)을 누르면 Check Table의 값이 보이고, 없는 값을 넣으면 오류가 나요.

    연결하는 두 필드는 같은 Domain이어야 해요.

    Check Field

    Check Table로 검사받는 외래 키 필드예요.

    Check Table이 "기준이 되는 표"라면 Check Field는 "검사받는 칸"이에요. SPFLI-CARRID가 Check Field, SCARR가 Check Table이에요. 둘은 항상 짝으로 다녀요.

    Value Table

    Domain에 적어 두는 추천 Check Table이에요. Check Table을 걸 때 자동으로 제안돼요.

    Domain은 여러 테이블이 같이 쓰는 값의 규칙이에요(6장). Domain에 "이 값은 보통 SCARR에서 와요"라고 적어 두면, 그 Domain을 쓰는 필드에 Check Table을 걸 때 SAP가 SCARR를 먼저 제안해 줘요. 추천일 뿐이라 Value Table만 적어서는 검사가 일어나지 않아요.

    설정은 Value Table → Check Table → Check Field 순서, 해제는 반대 순서예요.

    T000

    클라이언트 목록 테이블이에요. MANDT도 T000을 Check Table로 걸어요.

    카디널리티

    한쪽 데이터 하나에 다른 쪽이 몇 개 연결되는지예요.

    외래 키로 연결할 때 "한쪽 하나에 다른 쪽이 몇 개 붙는지"도 적어요. 항공사 하나에 노선은 여러 개 있을 수 있고, 아직 노선이 없는 항공사도 있어요. 이런 관계가 1:CN이에요. C는 "0개일 수도 있다", N은 "여러 개"라는 뜻이에요. 1:1은 하나에 딱 하나, 1:N은 하나에 1개 이상이에요.

    SAP에서는 1:CN(하나에 0개 이상)을 가장 많이 써요. "사원 한 명에 사원증 하나만"이면 1:1이에요.

    더 알아보기: 제약 조건 세 가지
    • 키 제약: 키 값은 중복될 수 없어요.
    • 참조 제약: 외래 키 값은 상대 테이블에 있어야 해요.
    • 관계 제약: 카디널리티를 지켜야 해요.

    ERD(테이블 관계 그림)에서는 다른 경로로 찾아갈 수 있는 테이블까지 직접 연결하지 않아요.

    8장DB 읽기: SELECT SINGLE과 sy-subrc

    SELECT SINGLE로 조건에 맞는 한 건을 읽고, 찾았는지는 sy-subrc로 확인해요.

    pa_carrgv_namesy-subrc

    위 한 줄을 실행하면 이렇게 돼요. 그래서 SELECT 다음에는 sy-subrc로 찾았는지 확인해요.

    Open SQL

    ABAP 안에서 데이터베이스를 읽고 쓰는 문법이에요. 지금 이름은 ABAP SQL이에요.

    DB마다 쓰는 SQL 문법이 조금씩 달라요. Open SQL(ABAP SQL)은 ABAP 안에서 쓰는 공통 문법이라서, SAP가 실제 DB에 맞게 바꿔서 실행해 줘요. 그래서 DB 종류를 신경 쓰지 않고 같은 문법으로 쓰면 돼요.

    더 알아보기: ADBC

    데이터베이스 전용 SQL을 직접 쓰는 ADBC(ABAP Database Connectivity)도 있어요. 데이터베이스마다 문법이 달라질 수 있어서 보통은 Open SQL을 써요.

    SELECT SINGLE

    조건에 맞는 한 건을 읽어요.

    키 필드를 모두 조건으로 주면 정확히 한 건이 나와요.

    필요한 필드와 행만 가져와요. 서버와 데이터베이스가 주고받을 때마다 시간이 들어요.

    못 찾으면(sy-subrc 4) 담을 변수가 비워지지 않고 이전 값이 남아요. 읽기 전에 CLEAR해 둬요(4장 CLEAR).

    INTO ( , )

    필드 여러 개는 괄호 안에 같은 순서로 받아요.

    SELECT로 필드 여러 개를 읽어 변수 여러 개에 나눠 담을 때 써요. 이름이 아니라 순서로 짝지어지니까, 필드 순서와 변수 순서를 똑같이 맞춰야 해요.

    SELECT 필드 순서와 괄호 안 변수 순서가 같아야 해요.

    INTO CORRESPONDING FIELDS OF

    이름이 같은 구조체 필드에 알아서 짝지어 담아요. 예: INTO CORRESPONDING FIELDS OF gs_edu

    구조체에 담을 때 필드 이름이 같은 칸끼리 알아서 짝지어 줘요. SELECT 필드 순서와 구조체 필드 순서가 달라도 이름만 같으면 제자리에 들어가요.

    구조체끼리 옮길 때 같은 일을 하는 건 MOVE-CORRESPONDING(4장)이에요.

    WHERE

    읽을 행의 조건이에요. = 대신 EQ를 써도 돼요.

    WHERE 뒤에 조건을 적으면 그 조건에 맞는 행만 읽어요. 조건이 없으면 엉뚱한 행을 읽거나, 여러 건을 읽을 때는 필요 없는 행까지 모두 가져오게 돼요. 그래서 필요한 행만 읽도록 조건을 꼭 적어요.

    MANDT는 안 써도 돼요. 로그인한 클라이언트가 자동으로 들어가요.

    sy-subrc

    방금 실행한 문장의 결과 코드예요. SELECT 뒤에는 0이면 찾음, 4면 없음이에요.

    SELECT 같은 문장을 실행하면 SAP가 결과를 sy-subrc에 숫자로 남겨요. 0이면 성공, 그 밖의 값은 실패나 "없음"이에요. 이 값을 확인하지 않으면 데이터가 없는데도 있는 것처럼 처리할 수 있어요.

    서류 창고 직원이 "있어요(0)", "없어요(4)"라고 하는 대답이에요.

    문장마다 값이 바뀌어요. SELECT 바로 다음 줄에서 확인해요.

    IS INITIAL은 0과 같아요. 수업 코드에서는 IF sy-subrc IS INITIAL.(찾음), IS NOT INITIAL(못 찾음)로 확인해요.

    sy-

    시스템이 자동으로 채우는 시스템 필드예요(구조체 SYST).

    9장서브루틴 (FORM)

    자주 쓰는 코드를 FORM으로 묶고 PERFORM으로 불러 써요. 고칠 때 한 곳만 고치면 돼요.

    FORM

    코드를 이름 붙여 묶어요. ENDFORM으로 닫아요.

    같은 코드를 여러 곳에서 쓰거나, 긴 코드를 기능별로 나누고 싶을 때 FORM으로 묶어 이름을 붙여요. 이렇게 하면 메인 흐름이 짧아지고, 고칠 때도 FORM 한 곳만 고치면 돼요.

    PERFORM

    FORM을 불러요. 넘기는 값을 파라미터라고 해요.

    PERFORM은 "이 이름의 FORM을 실행해"라는 명령이에요. FORM이 끝나면 PERFORM 다음 줄로 돌아와서 이어서 실행해요.

    파라미터는 이름이 아니라 순서로 짝지어져요. 빠짐없이 순서대로 넘겨요.

    PERFORM의 FORM 이름을 더블클릭하면 FORM을 바로 만들 수 있어요. 이때 위의 주석 블록(파라미터 목록)도 같이 생겨요.

    USING

    FORM이 쓸 값으로 받아요. 이름은 값 하나면 pv_, 구조체면 ps_로 시작해요.

    FORM에 값을 넘겨서 FORM 안에서 읽기만 할 때 써요. VALUE( )를 붙이면 복사본을 받아서, FORM 안에서 바꿔도 밖의 원래 변수는 그대로예요.

    변수 대신 값(10)을 바로 넘기는 건 USING에만 할 수 있어요.

    CHANGING

    FORM이 바꿔서 돌려줄 값으로 받아요. 이름은 값 하나면 cv_, 구조체면 cs_로 시작해요.

    FORM이 일한 결과를 밖으로 돌려줘야 할 때 써요. FORM 안에서 바꾼 값이 FORM이 끝난 뒤 밖의 변수에 반영돼요.

    인터널 테이블 넘기기

    인터널 테이블은 보통 VALUE( ) 없이 원본 그대로(Call by Reference) 넘겨요.

    줄이 많으면 복사하는 데만 시간과 메모리가 들어요. 원본을 넘기면 복사가 없어요.

    파라미터 타입은 11장의 Table Type으로 적으면 깔끔해요.

    받는 방식에 따라 달라지는 것

    쓰는 법받는 것FORM 안에서 바꾸면 밖은
    USING VALUE(p)복사본그대로예요
    USING p원본바로 바뀌어요
    CHANGING VALUE(c)복사본ENDFORM에서 바뀌어요

    예: 밖의 값이 10이고 FORM 안에서 2배로 바꾸면, 위에서부터 10, 20, 20이 돼요.

    로컬 변수

    FORM 안에서 만든 변수예요. ENDFORM에서 사라져요.

    FORM 안에서만 쓰는 변수는 FORM 안에서 DATA로 만들어요. FORM이 끝나면 사라지니까 다른 곳의 값과 섞일 걱정이 없어요.

    FORM 안에서는 글로벌 변수를 직접 쓰지 말고 파라미터로 받아요.

    팀 프로젝트에서는 서브루틴을 여러 사람이 같이 써요. 글로벌 변수에 기대면 다른 프로그램에서 그대로 쓸 수 없고, 어디서 값이 바뀌는지 찾기 어려워요.

    gv_subrc

    FORM 안 SELECT의 결과를 밖에서 확인하려고 CHANGING으로 돌려받는 변수예요.

    sy-subrc는 문장을 실행할 때마다 바뀌어요. 그래서 FORM 안에서 SELECT한 직후의 sy-subrc를 CHANGING 변수에 옮겨 담아 밖으로 돌려줘요.

    FORM이 끝난 뒤의 sy-subrc는 다른 문장 때문에 바뀌어 있을 수 있어요.

    TOP include

    DATA, PARAMETERS 같은 글로벌 선언을 모아 두는 인클루드예요.

    프로그램이 커지면 선언, 이벤트, FORM을 한 파일에 다 쓰기 어려워요. 그래서 글로벌 선언은 TOP include에, FORM은 F01 같은 다른 include에 나눠 담아 정리해요.

    프로그램을 만들 때 With TOP INCL.을 고르면 ZRC05W0241_TOP처럼 생겨요. 출력만 맡는 FORM은 보통 display_...로 이름 붙여요.

    SE38에서 프로그램을 복사할 때는 인클루드도 같이 골라서 복사해요.

    그냥 복사하면 새 프로그램이 원래 프로그램의 TOP, F01 인클루드를 같이 써요. 새 프로그램에서 고치면 원래 프로그램도 바뀌어요.

    SE91

    메시지 클래스를 만들고, 번호(000~999)별로 문구를 등록해요. 수업 클래스는 ZMC05C예요.

    메시지 문구를 코드에 직접 쓰지 않고 SE91에 번호로 등록해 두면, 같은 문구를 여러 프로그램에서 번호로 불러 쓸 수 있어요.

    번호 붙은 안내 방송 문구집이에요. 코드는 번호만 부르고, 문구는 사용자 언어로 나가요.

    MESSAGE '데이터가 없습니다.' TYPE 'E'.처럼 직접 쓰면 번역할 수 없어요.

    WITH

    메시지 문구의 & 자리에 값을 넣어요. 최대 4개예요.

    "항공사 & 이(가) 없습니다"처럼 문구 안에 바뀌는 부분을 &로 비워 두고, WITH 뒤의 값으로 채워요. 같은 문구로 여러 상황을 알릴 수 있어요.

    TEXT-xxx

    텍스트 심볼이에요. WRITE 같은 출력 문구를 3자리 이름으로 등록해 써요.

    WRITE로 출력하는 글자도 언어별로 바꾸고 싶으면 코드에 직접 쓰지 말고 텍스트 심볼로 등록해요. 그러면 번역만 추가해서 다른 언어로 로그인한 사용자에게 그 언어로 보여 줄 수 있어요.

    그 프로그램 안에서만 쓰는 로컬 텍스트예요. 다른 프로그램에서는 쓸 수 없어요.

    '문구'(t02)를 더블클릭하면 텍스트 심볼이 만들어져요. 처음 만든 언어(EN으로 로그인했다면 영어)가 원본이에요.

    sy-langu

    현재 로그인 언어예요.

    사용자가 로그인할 때 고른 언어가 들어 있어요. 텍스트 테이블에서 사용자 언어에 맞는 문구를 읽을 때 조건으로 써요.

    텍스트 테이블

    테이블 필드(국가 이름 등)를 언어별로 나눠 저장하는 테이블이에요(Text Table). 원래 테이블의 키에 언어 키 SPRAS를 추가해요.

    이름처럼 언어마다 달라지는 데이터는 원래 테이블에 언어별로 칸을 늘리지 않고, 텍스트 테이블에 언어 키(SPRAS)와 함께 따로 저장해요. 읽을 때는 sy-langu로 사용자 언어의 행만 골라요.

    테이블 이름과 필드는 예시예요. 실제 수업 테이블에 맞게 바꿔 써요.

    번역이 필요한 필드는 원래 테이블에서 빼서 텍스트 테이블의 필드로 옮겨요. 텍스트 테이블을 JOIN으로 같이 읽을 때는 12장을 봐요.

    11장인터널 테이블 (Internal Table)

    인터널 테이블은 프로그램 안에서 여러 건의 데이터를 표처럼 담아 두는 변수예요. DB에서 여러 건을 읽어 한 줄씩 처리할 때 써요.

    인터널 테이블

    같은 모양의 구조체(3장)를 여러 줄 쌓아 놓은 변수예요. 줄 번호는 1번부터 시작해요.

    SELECT SINGLE은 한 건만 읽어요. 여러 건을 한꺼번에 읽어 두고 한 줄씩 처리하려면 여러 줄을 담을 그릇이 필요한데, 그게 인터널 테이블이에요. 프로그램 안 메모리에만 있어서 DB를 바꾸지 않아요.

    구조체가 신청서 한 장이라면, 인터널 테이블은 같은 양식의 신청서 묶음이에요.

    DB 테이블과 달리 프로그램이 끝나면 사라져요. 메모리에 담기 때문에 담을 수 있는 양에 한계가 있어요. 처음 만들면 한 줄도 없는 빈 상태예요.

    구조체 변수 (Work Area)

    인터널 테이블에 넣거나 꺼낼 때 한 줄을 잠시 담는 구조체 변수예요. 예: gs_info 이렇게 쓰는 구조체 변수를 Work Area라고도 불러요.

    인터널 테이블은 줄 단위로 넣고 꺼내요. 그때 줄 하나를 잠시 올려 두는 그릇이 구조체 변수예요. 넣을 때는 구조체 변수에 값을 채운 뒤 넣고, 꺼낼 때는 구조체 변수로 받아서 써요.

    WRITE로 출력하려면 한 줄씩 구조체 변수에 받아서 처리해요.

    gt_

    글로벌 인터널 테이블(Table) 이름 앞에 붙여요. 예: gt_info

    TYPE TABLE OF

    인터널 테이블을 만들어요. 한 줄의 모양을 뒤에 적어요.

    뒤에 적은 모양의 줄을 여러 개 담는 그릇이 만들어져요.

    수업에서 가장 깔끔하다고 한 방식이에요. 아래 두 방식도 써요. 어떤 걸 쓸지는 취향이에요.

    LIKE TABLE OF

    이미 있는 구조체 변수와 같은 모양의 줄로 인터널 테이블을 만들어요.

    TYPE이 "타입을 보고" 만든다면 LIKE는 "이미 있는 변수를 보고" 만들어요. 구조체 변수를 먼저 만들어 두었다면 그 모양 그대로 테이블을 만들 수 있어요.

    인터널 테이블은 구조체 변수와 같이 쓰는 경우가 많아서 LIKE를 자주 써요.

    LIKE LINE OF

    인터널 테이블의 한 줄 모양으로 구조체 변수를 만들어요.

    인터널 테이블을 먼저 만들었다면, LIKE LINE OF로 그 테이블의 한 줄 모양을 그대로 본뜬 구조체 변수를 만들 수 있어요. 테이블 모양이 바뀌어도 구조체 변수가 같이 따라가요.

    Table Type

    SE11에서 만드는 "인터널 테이블 모양" 타입이에요. 한 줄 모양(Line Type)으로 구조체나 테이블을 지정해요.

    인터널 테이블 모양을 SE11에 이름 붙여 저장해 둔 거예요. 여러 프로그램이 같은 모양의 인터널 테이블을 써야 할 때, 이 이름 하나로 선언할 수 있어요.

    Table Type은 이미 테이블 모양이라 TYPE TABLE OF가 아니라 TYPE만 써요. 한 줄은 TYPE LINE OF 테이블타입으로 만들어요.

    FORM 파라미터처럼 인터널 테이블을 타입 이름 하나로 적어야 할 때 편해요. 9장 참고.

    팀 프로젝트나 개별 프로젝트에서는 SE11 Table Type을 거의 만들지 않아요.

    APPEND

    인터널 테이블 맨 끝에 한 줄을 추가해요.

    인터널 테이블에 줄을 직접 하나씩 추가할 때 써요. 구조체 변수에 값을 채우고 APPEND하면 그 내용이 맨 끝 줄로 복사돼요.

    값을 넣는 데 쓴 구조체 변수는 쓰고 나면 CLEAR로 비워요.

    INTO TABLE

    SELECT로 여러 건을 한 번에 인터널 테이블에 담아요.

    SELECT SINGLE은 한 건이지만, INTO TABLE은 조건에 맞는 모든 행을 한 번에 인터널 테이블로 가져와요. DB에 한 번만 다녀오니까 빨라요.

    필드 이름으로 짝지어 담도록 CORRESPONDING FIELDS OF를 붙이는 게 좋아요. INTO TABLE은 원래 내용을 지우고 새로 채우지만, 수업에서는 SELECT 전에 CLEAR하는 습관을 권해요.

    SELECT ... ENDSELECT로 한 줄씩 반복해 읽는 방식은 쓰지 않아요.

    sy-dbcnt

    SELECT로 몇 건을 읽었는지 담겨요. 찾았는지는 sy-subrc(0이면 1건 이상, 4면 없음)로 봐요.

    LOOP AT

    인터널 테이블을 첫 줄부터 한 줄씩 구조체 변수에 꺼내 반복해요. ENDLOOP로 닫아요.

    인터널 테이블의 줄을 처음부터 끝까지 하나씩 구조체 변수에 꺼내서 같은 코드를 반복 실행해요. 줄마다 출력하거나 값을 바꿀 때 써요.

    LOOP 앞, 안, 뒤에서 CLEAR를 잘 써 주는 게 좋아요. 이전 줄의 값이 다음 처리에 섞이지 않아요. CLEAR 쓰는 때는 4장 CLEAR에 모아 뒀어요.

    sy-tabix

    LOOP 안에서 지금 처리 중인 줄 번호예요. 1부터 시작해요.

    LOOP가 지금 몇 번째 줄을 처리하고 있는지 알려 줘요. 줄 번호를 같이 출력하거나 특정 줄에서만 무언가를 할 때 써요.

    MODIFY

    구조체 변수에서 바꾼 값을 인터널 테이블의 그 줄에 다시 반영해요.

    LOOP에서 꺼낸 구조체 변수는 복사본이라서, 값을 바꿔도 인터널 테이블 안의 줄은 그대로예요. MODIFY를 해야 바꾼 값이 테이블에 반영돼요.

    줄을 바꿀 목적이면 MODIFY를 CLEAR보다 위에 써요. 순서가 바뀌면 빈 값이 반영돼요(4장 CLEAR).

    LOOP 안에서는 지금 돌고 있는 줄의 INDEX가 자동으로 정해져서 INDEX를 생략할 수 있어요. 그래서 이 모양은 LOOP 밖에서는 못 써요.

    LOOP 밖에서는 바꿀 줄 번호를 INDEX로 직접 적어요.

    DELETE

    조건에 맞는 줄을 인터널 테이블에서 지워요. DB 테이블은 그대로예요.

    한 번에 읽고 안에서 찾기

    DB에 다녀올 때마다 시간이 들어요. 전체나 필요한 부분을 gt_info에 담아 두고 READ TABLE, LOOP로 찾는 게 더 빨라요.

    가격처럼 지금 이 순간의 값을 보여 줘야 하면 LOOP 안에서 SELECT SINGLE로 줄마다 새로 읽어요. 미리 읽어 둔 값은 그사이 바뀌었을 수 있어요.

    반대로 모든 줄이 같은 시점의 값이어야 하면 LOOP 안 SELECT SINGLE을 쓰지 않아요. 읽는 도중에 값이 바뀌면 줄마다 기준이 달라져요.

    READ TABLE

    인터널 테이블에서 한 줄만 꺼내 구조체 변수에 담아요.

    인터널 테이블 전체를 돌지 않고 원하는 줄 하나만 꺼낼 때 써요. 줄 번호(INDEX)로 꺼내거나 필드 값(WITH KEY)으로 찾아요.

    SELECT처럼 성공 여부가 sy-subrc에 담겨요(0이면 찾음, 4면 없음). sy-tabix에는 읽은 줄 번호가 담겨요.

    조건을 여러 개 쓰면 모두 맞는 줄을 찾아요. AND는 쓰지 않고 이어서 적어요. 비교는 =만 돼요.

    찾았는지는 sy-subrc(0 찾음, 4 없음), 몇 번째 줄인지는 sy-tabix로 봐요.

    SORT

    인터널 테이블의 줄을 필드 값 순서로 정렬해요. 기본은 오름차순(ASCENDING)이에요.

    SELECT로 가져온 순서는 보장되지 않아서, 사용자에게 보여 주기 전에 원하는 순서로 정렬해요. 정렬 기준 필드를 여러 개 적으면 앞 필드부터 차례로 기준이 돼요.

    ASCENDING은 작은 값부터(오름차순), DESCENDING은 큰 값부터(내림차순)예요. 필드 바로 뒤에 붙이면 그 필드에만 적용돼요.

    사용자가 중요하게 볼 필드를 기준으로 정렬하는 게 좋아요. 가격처럼 통화가 붙은 금액은 통화로 먼저 정렬하고 그다음 금액으로 정렬해요.

    보통 SELECT로 가져온 뒤 SORT해요. 원하는 자리에 줄을 끼워 넣는 INSERT는 잘 쓰지 않아요.

    MODIFY TABLE

    LOOP 밖에서 인터널 테이블의 줄을 바꿀 때 써요. 구조체 변수와 키 값이 같은 줄을 찾아서 바꿔요.

    LOOP 밖에서는 "지금 줄"이 없으니까, 구조체 변수의 키 값과 같은 줄을 찾아 바꿔요. 키 값은 그대로 두고 나머지 값만 바꿀 때 써요.

    여기서 키는 DB 테이블의 PK/FK가 아니라 인터널 테이블의 키(Primary Key)예요. 인터널 테이블 타입을 프로그램이나 SE11 Table Type으로 만들 때 정해요.

    키를 정하지 않았으면 문자형 필드(숫자형이 아닌 필드)를 모두 비교해서, 전부 같은 줄을 바꿔요. 그래서 생각한 줄을 못 찾는 경우가 많아요.

    같은 키가 여러 줄이면 첫 번째 줄만 바뀌어요. 맞는 줄이 없으면 아무것도 바뀌지 않고 sy-subrc가 4예요.

    MODIFY … WHERE

    조건에 맞는 모든 줄을 한 번에 바꿔요. LOOP 밖에서 써요.

    TRANSPORTING 뒤에 적은 필드만 바뀌어요. 이 모양에서는 꼭 붙여요. 다른 MODIFY에 붙이면 적은 필드만 바뀌고, 안 붙이면 줄 전체를 덮어써요.

    12장View와 JOIN

    View는 테이블을 보는 또 다른 창이에요. 여러 테이블을 묶어서 필요한 필드만 보여 줘요. 프로그램에서 두 테이블을 묶어 읽을 때는 JOIN을 써요.

    View

    View

    테이블 정보 중 화면에 필요한 필드만 골라 보여 주는 창이에요. 데이터를 따로 저장하지 않아요.

    테이블에는 필드가 많지만, 화면이나 업무에 필요한 건 그중 일부일 때가 많아요. View는 필요한 필드만 보이게 정의해 둔 것이라서, 데이터는 원래 테이블에 그대로 있고 View는 보는 방법만 정해요.

    테이블이 창고라면, View는 필요한 칸만 보이게 뚫어 놓은 창문이에요.

    SE11에서 만들어요. 종류는 Database View, Projection View, Maintenance View 등이 있어요.

    이미 데이터가 들어 있는 테이블은 함부로 다시 Activate하지 않아요(6장 활성화).

    Database View

    여러 테이블을 JOIN해서 만든 View예요. 프로그램에서 DB 테이블처럼 FROM에 넣어 읽을 수 있어요.

    항공사(SCARR)와 노선(SPFLI)처럼 나뉜 테이블을 미리 묶어 둔 View예요. FROM에 View 이름을 적으면 테이블 하나 읽듯이 읽을 수도 있어요. 하지만 수업에서는 프로그램에서 읽으려는 목적만으로 View를 따로 만들지는 않는다고 했어요.

    View 모양으로 구조체나 Table Type처럼 변수를 만들어 받을 수도 있어요.

    Database View에는 MANDT 필드를 꼭 넣어요. 빠지면 다른 클라이언트의 데이터까지 읽을 수 있어요.

    정확한 데이터를 가져오려면 두 테이블을 잇는 키(PK)를 빠짐없이 지정해요. 키가 여러 개인 복합 키도 마찬가지예요. MANDT도 항상 같이 이어요.

    Projection View

    테이블 하나에서 일부 필드만 보여 주는 View예요. 잘 만들지 않아요.

    테이블 하나에서 보여 줄 필드만 고른 가장 단순한 View예요.

    Maintenance View

    사용자가 레코드를 입력·수정·삭제하며 관리하게 만드는 View예요.

    관리자가 정해진 화면에서 데이터를 넣고 고치게 하고 싶을 때 만들어요. 이 View를 바탕으로 입력 화면을 자동으로 만들 수 있어요.

    • 메인 테이블 하나를 기준으로 만들어요. 메인 테이블과 외래 키로 연결된 테이블(예: 텍스트 테이블)만 같이 넣을 수 있어요. 수업에서는 메인 테이블 하나로 만들었어요.
    • 메인 테이블의 줄은 연결된 테이블에 짝이 없어도 다 보여야 해서 LEFT OUTER JOIN 방식으로 읽어요.
    • 메인 테이블의 키 필드는 빠짐없이 넣어야 해요. 그래야 입력한 데이터를 테이블의 정확한 줄에 저장할 수 있어요.
    • 텍스트 테이블을 넣어도 언어 필드(SPRAS)는 View 필드에 넣지 않아요. 넣을 수도 없어요. 저장할 때 로그인 언어가 자동으로 들어가서, 사용자는 지금 언어의 텍스트만 보고 고쳐요.
    Access

    Maintenance View로 사용자가 할 수 있는 일을 정해요.

    데이터를 고칠 수 있는 화면은 잘못 쓰면 위험해요. Access로 읽기만 할지, 고치기까지 할지, 지우고 새로 넣기까지 할지를 정해서 사용자가 할 수 있는 일을 제한해요.

    설정쓰임
    read only읽기만 해요. 거의 안 써요.
    read and change읽고 고칠 수 있어요. 사용자에게 권한을 적당히 줄 때 이걸 쓰는 게 맞아요.
    read, change, delete and insert읽기, 고치기, 지우기, 새로 넣기까지 다 돼요. 수업에서 자주 썼어요.
    관리 화면 만들기

    사용자가 직접 데이터를 고칠 수 있는 화면을 SAP가 자동으로 프로그램으로 만들어 줘요. SE11의 Table Maintenance Generator로 만들어요.

    입력·수정 화면을 직접 프로그램으로 짜지 않아도, Table Maintenance Generator가 Maintenance View를 보고 목록 화면과 상세 화면을 자동으로 만들어 줘요.

    화면을 두 개(목록 + 상세, two step)로 만들거나 하나(one step)로 만들 수 있어요.

    JOIN

    INNER JOIN

    두 테이블에서 ON 조건이 양쪽 다 일치하는 줄만 가져와요.

    두 테이블을 공통 필드(예: CARRID)로 이어 붙여서 한 번에 읽어요. 양쪽 테이블 모두에 짝이 있는 줄만 결과에 나와요. 한쪽에만 있는 데이터는 빠져요.

    두 테이블에 같은 이름의 필드가 있으면 테이블~필드로 어느 쪽인지 적어요. AS로 짧은 별명을 붙여 쓸 수도 있어요.

    외래 키 관계가 없는 테이블끼리도 JOIN으로 데이터를 가져올 수 있어요.

    LEFT OUTER JOIN

    FROM에 적은 왼쪽 테이블의 줄은 무조건 다 가져와요. 오른쪽 테이블에 맞는 줄이 없으면 그 필드는 빈 값이에요.

    INNER JOIN은 짝이 없는 줄을 빼 버려요. 노선이 아직 없는 항공사도 목록에 보여 줘야 한다면, 왼쪽(FROM) 테이블은 다 가져오고 오른쪽은 있으면 붙이는 LEFT OUTER JOIN을 써요.

    관계(1:CN)를 믿지 못할 때, 즉 오른쪽 테이블에 맞는 데이터가 꼭 있다고 보장할 수 없을 때 써요. 관계 설정을 보고 INNER와 LEFT OUTER 중 무엇을 쓸지 판단할 수 있어야 해요. 판단하지 못하면 레코드를 하나하나 비교해 봐야 해요.

    텍스트 테이블(10장)은 INNER JOIN하지 않고 LEFT OUTER JOIN으로 읽어요.

    텍스트 테이블은 언어마다 줄이 있어서, 그냥 이으면 언어 수만큼 줄이 늘어나요. ON 조건에 언어를 같이 적어서 로그인 언어 한 줄만 붙여요.

    언어 조건을 WHERE에 쓰면 텍스트가 없는 줄이 빠져서 INNER JOIN처럼 돼요. 그래서 ON에 적어요.

    13장Search Help

    Search Help는 입력 칸에서 값 목록(F4)을 눌렀을 때 뜨는 검색 목록이에요. SE11에서 만들고, 입력 칸에 연결해서 써요.

    Search Help

    값 목록(F4)에서 고를 수 있는 목록을 정해 둔 객체예요. 이름 예: zsh_c0501, zsh_c05_connid

    입력 칸에서 값 목록(F4)을 눌렀을 때 어떤 테이블에서 어떤 필드를 보여 줄지 미리 정해 둔 것이에요. 사용자는 코드를 외우지 않아도 목록에서 골라 넣을 수 있어요.

    테이블의 PK(키 필드)를 다 넣는 게 일반적이에요. 검색할 때 도움이 되는 다른 필드도 넣을 수 있어요.

    결과는 500건까지 보여 주고, 넘으면 조건을 넣는 화면이 먼저 떠요.

    LPOS · SPOS

    LPOS는 결과 목록에 보이는 필드 순서, SPOS는 조건 입력 화면에 보이는 필드 순서예요.

    값 목록에 필드가 여러 개 보일 때 어떤 순서로 보일지 정해요. 사용자가 먼저 봐야 할 필드를 앞에 두면 고르기 쉬워요.

    IMP · EXP

    EXP는 목록에서 고른 줄의 값을 화면 입력 칸에 돌려줘요. IMP는 화면에 이미 입력된 값을 받아서 검색 조건으로 써요.

    Search Help와 화면 사이에서 값이 오가는 방향을 정해요. EXP는 목록에서 화면으로, IMP는 화면에서 목록으로 가요. 둘 다 체크할 수도 있어요.

    찾으려는 목적에 맞는 필드(입력 칸에 돌려줄 필드)는 반드시 EXP로 체크해요.
