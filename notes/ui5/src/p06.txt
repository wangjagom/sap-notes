@ch ch-6 | 6부 | UI5 앱의 뼈대 | UI5 앱은 화면(View), 동작(Controller), 데이터(Model) 세 부분으로 나뉘어요. 이 구조를 MVC라고 해요. 0~5부의 자바스크립트가 그대로 쓰여요.

@kw MVC
d: 화면(View), 데이터(Model), 동작(Controller)을 나눠 만드는 구조예요. UI5는 이 구조를 미리 정해 둔 프레임워크예요.
tb:
부분 | 파일 | 하는 일 | 비유
View | `view/View1.view.xml` | 무엇을 어디에 보여줄지 | 가게 진열대
Controller | `controller/View1.controller.js` | 버튼을 누르면 무엇을 할지 | 점원
Model | `model/data.json` | 보여줄 데이터 | 진열대 뒤 선반
.

@kw 프로젝트 폴더 구조
d: BAS(SAP Business Application Studio)에서 새 프로젝트를 만들면 `webapp` 폴더에 정해진 파일들이 생겨요. ← 표시가 수업에서 직접 고치는 파일이에요.
c:text
webapp/
├─ index.html            앱을 여는 시작 페이지
├─ Component.js          앱 전체 관리자
├─ manifest.json         앱 설정서 (앱 id, 모델, 화면 연결)
├─ view/
│   ├─ App.view.xml       바깥 틀
│   ├─ View1.view.xml     ← 직접 작업하는 화면
│   └─ Popup.fragment.xml ← 화면 조각 (7부)
├─ controller/
│   └─ View1.controller.js ← 직접 작업하는 동작
├─ model/data.json        ← 데이터 파일
├─ i18n/i18n.properties   화면 문구 (다국어용)
└─ css/style.css          스타일
.

@kw 앱 id
d: `manifest.json`의 `"sap.app": { "id": "ncode.zcXXw0205" }`가 앱 이름이에요. 이 이름이 `webapp` 폴더를 가리키고, 그 뒤의 점은 폴더 구분이에요. 확장자는 생략해요.
tb:
코드에 쓰는 이름 | 실제 파일
`ncode.zcXXw0205.controller.View1` | `webapp/controller/View1.controller.js`
`ncode.zcXXw0205.view.Popup` | `webapp/view/Popup.fragment.xml`
`ncode.zcXXw0205.i18n.i18n` | `webapp/i18n/i18n.properties`
.
w: 다른 프로젝트에서 코드를 복사해 오면 이 이름이 예전 프로젝트 것으로 남기 쉬워요. "failed to load, 404" 에러의 대표 원인이에요. 정확한 앱 id는 항상 `manifest.json`에서 확인해요.
s: 수업 프로젝트 이름 `zcXXw0205`에서 `XX`는 내 번호, `0205`는 2주차 5번째 프로젝트예요. 따라 칠 때는 `XX`를 내 번호로 바꿔 써요.

@kw XML View
d: 화면을 `<태그>`로 적은 파일이에요. 어떤 컨트롤을 어디에 둘지 정해요.
c:xml
<mvc:View controllerName="ncode.zcXXw0205.controller.View1"
    xmlns:mvc="sap.ui.core.mvc"
    xmlns="sap.m">
    <Page id="page" title="학생 찾기">
        <content>
            <Input id="inpName" placeholder="이름을 입력하세요" />
            <Button id="btnSearch" text="검색" />
        </content>
    </Page>
</mvc:View>
.
e: 제목이 "학생 찾기"인 한 장짜리 화면 안에 입력칸 하나와 검색 버튼 하나가 있어요. `controllerName`은 이 화면을 움직이는 컨트롤러 이름이고, 태그가 `/>`로 끝나면 안에 다른 태그가 없다는 뜻이에요.
tb:
이렇게 생긴 것 | 부르는 이름 | 뜻 | 예
대문자로 시작하는 태그 | 컨트롤(Control) | 버튼, 테이블 같은 화면 부품 | `Page`, `Input`, `Button`
소문자로 시작하는 태그 | 애그리게이션(Aggregation) | 컨트롤 안에 다른 컨트롤을 넣는 자리 | `content`, `items`, `columns`
태그 안의 `이름="값"` | 프로퍼티(Property) | 컨트롤의 설정값 | `id`, `title`, `text`
.
s: 값에 `{ }`가 들어 있는 모양(`value="{/name}"`)은 8부에서 배울 바인딩이에요.

@kw xmlns
d: 접두어가 붙은 컨트롤을 어느 라이브러리에서 가져올지 정하는 줄이에요. 접두어가 없는 태그는 기본 라이브러리(`xmlns="sap.m"`)에서 가져와요.
tb:
접두어 | 가져오는 라이브러리 | 예
(없음) | `sap.m` | `Page`, `Input`, `Button`
`mvc:` | `sap.ui.core.mvc` | `View`
`core:` | `sap.ui.core` | `core:Item`
.
w: 다른 라이브러리의 컨트롤(`core:Item`, `f:SimpleForm`, `l:Grid`)은 `xmlns:core`, `xmlns:f`, `xmlns:l`을 먼저 적어야 해요. 선언하지 않은 접두어를 쓰면 에러가 나요.

@kw byId
d: XML에 `id`를 붙인 컨트롤을 컨트롤러에서 꺼내요. `this.byId("x")`는 `this.getView().byId("x")`를 짧게 쓴 거예요.
c:js
const oInput = this.byId("inpName");      // XML의 입력칸을 꺼내요
const sName = oInput.getValue();          // 적힌 글자를 읽어요  예: "민수"
oInput.setValue("지아");                   // 입력칸에 글자를 넣어요
.
s: `this.getView()`는 이 컨트롤러가 맡은 화면 전체를 돌려줘요. 화면에 데이터를 연결할 때도 `this.getView().setModel(...)`처럼 화면을 먼저 꺼내요.
w: XML에 id가 없으면 `byId`는 `undefined`를 돌려줘요.
m: 더 알아보기: document.getElementById와 다른 점
UI5는 XML id 앞에 화면 이름 같은 글자를 붙여서 실제 id를 길게 만들어요(예: `__xmlview0--inpName`). 그래서 `document.getElementById("inpName")`은 못 찾고 `null`을 돌려줘요. UI5에서는 항상 `byId`를 써요.
/m

@kw 컨트롤러 파일
d: 화면의 동작을 적는 파일이에요. 필요한 모듈을 불러오고, 함수를 담은 객체로 컨트롤러를 만들어요.
c:js
sap.ui.define([                                  // ① 필요한 모듈 목록 (모듈 경로)
    "sap/ui/core/mvc/Controller"
], function (Controller) {                       // ② 모듈을 받을 이름 (순서대로)
    "use strict";

    return Controller.extend("ncode.zcXXw0205.controller.View1", {   // ③ 컨트롤러 만들기
        onInit: function () { },                 // ④ 메서드들
        onSearch: function () { }
    });
});
.
e: 모듈(Module)은 UI5가 기능별로 나눠 둔 자바스크립트 파일 하나예요. 대괄호 안에 모듈 경로를 적으면, 뒤에 오는 함수가 그 모듈을 매개변수로 받아요. `Controller.extend`의 두 번째 인자는 그냥 함수를 담은 객체예요.
w: 모듈 경로와 함수의 매개변수는 이름이 아니라 순서로 짝지어져요. 모듈을 추가할 때는 두 곳 모두 같은 순서로 한 줄씩 추가해요.
w: 메서드 사이의 쉼표를 빠뜨리면 파일 전체가 실행되지 않아요.
s: `"use strict"`는 실수를 더 엄격하게 잡아 주는 스위치예요. 항상 넣어 두는 줄로 알면 돼요.

@kw onInit
d: 화면이 만들어질 때 UI5가 자동으로 한 번 실행해 주는 메서드예요. 시작할 때 할 일(데이터 준비 등)을 여기에 써요.
s: 다른 메서드(`onSearch` 등)는 저절로 실행되지 않고, 화면의 버튼 같은 것에 연결해 두었을 때만 실행돼요. 이런 처리 함수 이름은 `on`으로 시작하는 게 관례예요.

@kw 컨트롤러 안의 this
d: 컨트롤러 메서드 안의 `this`는 컨트롤러 자신이에요. 다른 메서드를 부르거나 값을 저장해 둘 때 써요.
c:js
onInit: function () {
    this._oDialog = null;          // 컨트롤러에 값 저장 (함수가 끝나도 남아요)
    this.onSearch();               // 같은 컨트롤러의 다른 메서드 호출
    this.getView();                // 컨트롤러가 가진 기능 사용
}
.
w: 메서드 안에서 `function`으로 함수를 또 만들면 그 안의 `this`는 컨트롤러가 아니에요. 화살표 함수를 써요(4부 this).
c:js
onPopup: function () {
    function inner() { this.getView(); }      // ❌ 여기서 this는 컨트롤러가 아님
    const inner2 = () => { this.getView(); }; // ✅ 바깥 this 유지
}
.

@kw press
d: 버튼을 누르면 실행할 컨트롤러 함수를 연결해요. 버튼 누르기처럼 화면에서 일어나는 일을 이벤트라고 해요.
c:xml
<Button id="btnSearch" text="검색" press=".onSearch" />
.
c:js
onSearch: function () {
    const sName = this.byId("inpName").getValue();
    console.log("검색할 이름:", sName);
}
.
s: `press=".onSearch"`는 콜백 함수예요. "누르면 이 함수를 실행해 줘"라고 UI5에 맡기는 거예요. 앞의 점(`.`)은 "이 화면의 컨트롤러에 있는 함수"라는 뜻이에요.
w: `press=".onSearch()"`처럼 `()`를 붙이면 안 돼요. 맡기는 게 아니라 지금 실행하라는 뜻이 돼요.

@kw 이벤트 객체
d: UI5가 이벤트 함수의 첫 번째 인자로 넣어 주는 객체예요. 누가 일으켰는지, 어떤 정보가 있는지가 들어 있어요.
c:js
onSearch: function (oEvent) {
    const oButton = oEvent.getSource();           // 이벤트를 일으킨 컨트롤 (여기서는 버튼)
    const sText = oButton.getText();              // "검색"
},
onType: function (oEvent) {                       // <Input liveChange=".onType" />
    const sValue = oEvent.getParameter("value");  // 지금까지 입력한 글자
}
.
s: `liveChange`는 글자를 칠 때마다 일어나는 이벤트예요.
s: `getParameter`로 꺼낼 이름(`value`, `selectedItem`, `listItem` 등)은 컨트롤마다 달라요. UI5 API 문서에서 그 컨트롤의 Events 항목을 보면 나와요.

@kw 길게 이어진 메서드
d: UI5 코드는 대부분 메서드 체이닝 모양이에요. 오른쪽으로 갈수록 더 구체적인 것을 꺼내요.
c:js
this.getView().byId("inpName").getValue().trim();
//   화면       → 입력칸        → 적힌 글자 → 앞뒤 공백 제거
.
w: 중간에 하나라도 `undefined`면 그 뒤는 모두 에러예요. XML에 id가 없으면 `byId`가 `undefined`라서 `reading 'getValue'` 에러가 나요. 한 단계씩 끊어서 `console.log`로 확인해요.

@kw UI5 변수 이름 규칙
d: 1부의 접두어에 더해, UI5의 컨트롤, 모델, 이벤트는 모두 객체라서 `o`로 시작해요. 맨 앞의 `_`는 "이 컨트롤러 안에서만 쓰는 것"이라는 표시예요.
tb:
접두어 | 뜻 | 예
`o` | 컨트롤, 모델, 이벤트 객체 | `oView`, `oModel`, `oEvent`
`p` | parameter (매개변수, 수업 관례) | `pModelData`
`_` | 이 컨트롤러 안에서만 쓰는 것 | `this._oDialog`, `_setModel()`
.
w: UI5 컨트롤 안에 보이는 `_sDomValue` 같은 `_` 변수는 UI5 내부용이라 쓰면 안 돼요. 버전이 바뀌면 사라질 수 있어요. 같은 값은 `getValue()` 같은 공식 메서드로 가져와요.
