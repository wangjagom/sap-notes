@ch ch-9 | 9부 | 데이터 바인딩 2: 애그리게이션 바인딩 | 배열 하나를 연결하면 한 줄짜리 틀(템플릿)을 배열 길이만큼 복사해서 목록을 만들어요. 콤보박스 항목, 테이블 행, 리스트가 전부 이 방식이에요. 수업 0205~0206

@kw 애그리게이션 바인딩
d: 컨트롤의 애그리게이션(`items` 등)에 배열을 연결해요. 배열 항목 수만큼 템플릿이 복사돼요.
c:js
const oModel = new JSONModel({
    skillList: [
        { sCode: "S1001", sName: "SAPUI5" },
        { sCode: "S2001", sName: "ABAP" }
    ]
});
this.getView().setModel(oModel);
.
c:xml
<ComboBox items="{/skillList}">                    <!-- ① 배열 연결 (절대경로, /로 시작) -->
    <items>
        <core:Item key="{sCode}" text="{sName}" />   <!-- ② 템플릿 (상대경로, / 없음) -->
    </items>
</ComboBox>
.
s: ①의 `items="{/skillList}"`는 "이 배열의 항목 수만큼 만들어"예요.

@kw 템플릿 · 상대경로
d: 템플릿(Template)은 목록의 한 줄을 어떻게 그릴지 적어 둔 틀이에요. 템플릿 안의 경로는 `/` 없이 쓰는 상대경로라서 복사본마다 자기 데이터를 찾아가요.
l: 붕어빵 틀 하나로 붕어빵 여러 개를 찍듯, 틀은 하나만 쓰고 데이터 개수만큼 복사돼요.
tb:
복사본 | 기준 위치(컨텍스트) | `{sName}`이 가리키는 곳 | 화면 글자
1번째 Item | `/skillList/0` | `/skillList/0/sName` | SAPUI5
2번째 Item | `/skillList/1` | `/skillList/1/sName` | ABAP
.
s: `/`로 시작하는 경로는 절대경로(Absolute Path), `/`가 없는 경로는 상대경로(Relative Path)예요.
w: 이름 있는 모델이면 템플릿 안에도 모델 이름을 붙여요: `items="{bookInfo>/bookList}"` → `key="{bookInfo>bCode}"`. 빠뜨리면 기본 모델에서 찾아서 빈칸이 나와요. (수업 0206)

@kw 바인딩 컨텍스트(Binding Context)
d: 복사된 항목 하나하나가 데이터의 어디를 보고 있는지 담은 정보예요. 사용자가 무엇을 골랐는지 알아낼 때 써요.
c:js
onSelect: function (oEvent) {
    const oItem = oEvent.getParameter("selectedItem");   // 고른 Item
    const oContext = oItem.getBindingContext();          // 그 Item의 위치 정보

    oContext.getPath();              // "/skillList/1"          어디인지 (경로 문자열)
    oContext.getObject();            // { sCode: "S2001", ... } 그 자리의 데이터 통째로
    oContext.getProperty("sName");   // "ABAP"                 그 자리의 값 하나
}
.
l: 경로는 편지 내용이 아니라 편지가 든 우편함 번호예요. `getObject()`는 내용을 꺼내고, `getPath()`는 위치만 알려 줘요.
w: 이름 있는 모델이면 `getBindingContext("bookInfo")`처럼 모델 이름을 넣어요. 안 넣으면 `undefined`예요.
s: 경로(`getPath`)가 가장 중요해요. 10부에서 이 경로를 상세 화면에 넘겨요.

@kw 콤보박스 값 꺼내기
d: 선택된 키는 `getSelectedKey()`, 선택된 항목 자체는 `getSelectedItem()`으로 꺼내요.
tb:
알고 싶은 것 | 방법
선택된 항목의 키 (항상 문자열) | `getSelectedKey()`
선택된 항목 자체 (없으면 `null`) | `getSelectedItem()`
입력칸에 보이는 글자 (직접 친 글자 포함) | `getValue()`
코드로 선택 바꾸기 | `setSelectedKey("S2001")`
.
w: `getSelectedKey()`는 항상 문자열이에요. 숫자 데이터와 비교하려면 `Number(sKey)`로 바꿔요.
s: `ComboBox`는 글자를 직접 칠 수 있고 아무것도 안 고를 수도 있어요. `Select`는 목록에서만 고르고 보통 첫 항목이 자동으로 선택돼요.
w: 다른 콤보박스의 Item을 `setSelectedItem`에 넘기면 동작하지 않아요. Item은 자기 콤보박스에만 속해요. 이럴 때는 키로 골라요: `setSelectedKey(oContext.getProperty("bGrade"))`

@kw 복사해서 보여주기
d: 고른 데이터를 다른 모델에 `setData`로 복사하면 동작은 하지만 데이터가 두 곳에 생겨요. 한쪽을 고쳐도 다른 쪽에 반영되지 않아요. (수업 0206)
c:js
const oContext = oCombo.getSelectedItem().getBindingContext("bookInfo");
this.getView().getModel().setData(oContext.getObject());   // 고른 책 데이터를 기본 모델에 복사
.
s: 복사 없이 "그 경로를 보여줘"라고 하는 더 좋은 방법이 10부의 `bindElement`예요.

@ch ch-10 | 10부 | 데이터 바인딩 3: 엘리먼트 바인딩 | 컨트롤 하나에 "너는 이 데이터 한 건을 기준으로 봐"라고 기준 위치를 정해 줘요. 목록에서 고른 한 건을 상세 화면에 보여줄 때 쓰는 핵심 기술이에요. 수업 0210~0211

@kw bindElement
d: 컨트롤 하나의 기준 위치를 데이터 한 건으로 정해요. 그 안의 자식들은 상대경로만 써도 그 데이터를 읽어요.
c:js
// 모델: { empInfo: { lastName: "김", firstName: "서연" }, stdInfo: { lastName: "홍", firstName: "길동" } }
this.byId("panelId").bindElement("/stdInfo");
.
c:xml
<Panel id="panelId">                     <!-- 기준: /stdInfo -->
    <Input value="{lastName}" />         <!-- → /stdInfo/lastName = 홍 -->
    <Input value="{firstName}" />        <!-- → /stdInfo/firstName = 길동 -->
</Panel>
.
s: `bindElement("/empInfo")`와 `bindElement("/stdInfo")`만 바꾸면 패널 안 내용이 통째로 바뀌어요. 안쪽 XML은 손댈 필요가 없어요.
s: XML에서 처음부터 정해 둘 수도 있어요: `<Panel binding="{/empInfo}">`
s: 여기서 Element는 HTML 태그가 아니라 Panel, Form, Dialog 같은 UI5 컨트롤이에요. "컨트롤 하나를 데이터 한 건에 묶는다"라고 읽어요.

@kw 목록 → 상세
d: 목록에서 고른 줄의 경로를 상세 컨트롤의 `bindElement`에 넣어요. 복사하지 않고 같은 데이터를 가리켜서 어느 쪽을 고쳐도 양쪽에 반영돼요.
c:js
onSelect: function (oEvent) {
    const oItem = oEvent.getParameter("listItem");       // ① 테이블에서 고른 줄
    const sPath = oItem.getBindingContext().getPath();   // ② "/esStdList/63"
    this.byId("pnlStdDetail").bindElement(sPath);        // ③ 상세 패널의 기준을 그 경로로
}
.
s: 테이블을 필터나 정렬해도 `getPath()`는 원본 배열 기준의 번호를 돌려줘요. 화면에서 몇 번째 줄이든 정확한 학생을 가리켜요.
s: 팝업(Dialog)도 컨트롤이라서 열기 전에 `this._oDialog.bindElement("/classList/2")`로 기준만 정해 주면 돼요.

@kw 키로 경로 만들기
d: 다른 배열에 있는 데이터는 `findIndex`로 몇 번째인지 찾아서 경로를 만들어요.
c:js
const aClassList = this.getView().getModel().getProperty("/classList");
const iIdx = aClassList.findIndex(c => c.Cid === sCid);
if (iIdx !== -1) {
    this.byId("pnlClsDetail").bindElement("/classList/" + iIdx);   // "/classList/2"
}
.
w: `findIndex`는 못 찾으면 `-1`을 돌려줘요. 꼭 확인하고 써요.
s: 반 코드 끝자리 숫자로 번호를 계산하는 방법(`CL303` → 2)은 데이터 순서가 바뀌거나 반이 10개를 넘으면 틀려요. 연습용으로만 써요.

@kw 중첩 배열(마스터-디테일)
d: 기준 위치 안에 또 배열이 있으면, 그 배열을 상대경로로 애그리게이션 바인딩해요. 위를 고르면 아래가 따라 바뀌는 화면을 마스터-디테일(Master-Detail)이라고 해요. (수업 0211)
c:js
// 데이터: stdList[1] = { stdName: "이도윤", skills: [ {sName:"SAPUI5"}, {sName:"ABAP"} ] }
this.byId("cmbSkillList").bindElement(sPath);   // sPath = "/stdList/1"
.
c:xml
<Select id="cmbSkillList" items="{skills}">   <!-- → /stdList/1/skills -->
    <core:Item key="{sCode}" text="{sName}" />
</Select>
.

@kw 이름 있는 모델과 bindElement
d: 문자열 대신 `{ path, model }` 객체를 넘기면 어느 모델 기준인지 정할 수 있어요. 기준을 지울 때는 `unbindElement()`예요. (수업 0213)
c:js
oTable.bindElement({ path: "/skills", model: "skillInfo" });
oTable.unbindElement("skillInfo");                 // 지울 때도 모델 이름
.
c:xml
<Table id="tableId" items="{skillInfo>}">   <!-- 경로가 비어 있음 = 기준 위치 그 자체 -->
.

@kw 바인딩 세 가지
d: 모두 "데이터 어디를 가리키느냐"의 차이예요. 값 하나는 프로퍼티에, 배열은 목록에, 객체 한 건은 상세 화면에 연결해요.
tb:
바인딩 | 가리키는 것 | 예
프로퍼티 바인딩 (8부) | 값 하나 | `<Input value="{/bookInfo/name}" />`
애그리게이션 바인딩 (9부) | 배열 | `<ComboBox items="{/skillList}">`
엘리먼트 바인딩 (10부) | 객체 한 건 | `bindElement("/stdList/1")`
.

@ch ch-11 | 11부 | 테이블, 필터, 정렬, 포매터 | 테이블은 엑셀처럼 열과 줄로 데이터를 보여 줘요. 9부의 목록을 열이 있는 모양으로 바꾼 버전이에요. 필터와 정렬은 데이터가 아니라 바인딩에 걸어요. 수업 0212~0213

@kw Table
d: 열 제목(`columns`) 한 번과 한 줄짜리 틀(`ColumnListItem`)로 이뤄져요. 틀이 데이터 건수만큼 복사돼요.
c:xml
<Table id="tabEdu" items="{/edus}" mode="SingleSelectMaster" selectionChange=".onSelect">
    <columns>                                   <!-- ① 열 제목 (한 번만) -->
        <Column><header><Text text="교육코드" /></header></Column>
        <Column><header><Text text="교육명" /></header></Column>
    </columns>
    <items>
        <ColumnListItem>                        <!-- ② 한 줄 템플릿 (데이터 건수만큼 복사) -->
            <cells>
                <Text text="{eCode}" />         <!-- columns와 같은 순서로 -->
                <Text text="{eName}" />
            </cells>
        </ColumnListItem>
    </items>
</Table>
.
w: `columns`와 `cells`의 개수와 순서가 맞아야 해요.
s: `mode`는 `SingleSelectMaster`(행을 누르면 선택), `SingleSelect`(라디오 버튼), `MultiSelect`(체크박스)예요. 행을 고르면 `selectionChange` 이벤트의 `listItem`으로 고른 줄이 와요.

@kw Filter
d: 조건에 맞는 줄만 보여 줘요. 테이블의 `items` 바인딩을 꺼내서 거기에 걸어요. 원본 데이터는 그대로이고 보이는 줄만 달라져요.
c:js
onSearch: function () {
    const oBinding = this.byId("tabEdu").getBinding("items");   // ① 테이블의 items 연결
    const aFilter = [
        new Filter("eduGroup", FilterOperator.EQ, "CODE")      // ② 조건 (필드, 비교, 값)
    ];
    oBinding.filter(aFilter);                                   // ③ 걸기
}
.
tb:
FilterOperator | 뜻
`EQ` / `NE` | 같다 / 다르다
`Contains` | 포함한다 (검색창에 자주 씀)
`StartsWith` | ~로 시작한다
`GT` / `LT` / `GE` / `LE` | 크다 / 작다 / 이상 / 이하
`BT` | 사이 (값 두 개)
.
w: 값의 자료형을 데이터와 맞춰요. 데이터가 숫자 `2`면 필터 값도 `Number("2")`여야 해요.
s: 필터 해제는 `oBinding.filter([])`예요.
s: 여러 조건을 배열로 넣으면 다른 필드끼리는 AND(둘 다), 같은 필드끼리는 OR(하나라도)로 묶여요. 선택한 조건만 넣으려면 배열을 만든 뒤 `if`로 `push`해요.
c:js
const aFilter = [new Filter("Cid", FilterOperator.EQ, sClsCode)];
if (sGrpCode) {
    aFilter.push(new Filter("Sgroup", FilterOperator.EQ, Number(sGrpCode)));
}
oBinding.filter(aFilter);
.

@kw Sorter
d: 보이는 줄의 순서를 바꿔요. 필터처럼 모델 데이터는 그대로 두고 바인딩에 걸어요.
c:js
oBinding.sort(new Sorter("Sname"));          // 이름 오름차순
oBinding.sort(new Sorter("Sname", true));    // 두 번째 값 true = 내림차순
oBinding.sort([
    new Sorter("Sgrade"),                    // 1순위: 학년 오름차순
    new Sorter("Sname", true)                // 2순위: 같은 학년끼리 이름 내림차순
]);
oBinding.filter(aFilter).sort(oSorter);      // 필터와 정렬을 이어서
.
s: 기준을 배열로 넘기면 적은 순서대로 적용돼요. 첫 기준 값이 같은 줄끼리만 두 번째 기준으로 다시 세워요.
w: `sort`를 따로 두 번 부르면 마지막 한 번의 정렬만 남아요. 여러 기준은 배열 하나로 넘겨요.
s: `Filter`, `FilterOperator`, `Sorter`는 `sap.ui.define` 목록에 추가해야 써요: `"sap/ui/model/Filter"`, `"sap/ui/model/FilterOperator"`, `"sap/ui/model/Sorter"`

@kw 포매터(Formatter)
d: 데이터의 코드(`H`)를 화면에는 글자(`상`)로 보여주고 싶을 때 컨트롤러 함수를 거치게 해요. 화면 글자만 바뀌고 모델 데이터는 그대로예요. (수업 0213)
c:xml
<Input value="{skillInfo>sGrade}"
       description="{ path: 'skillInfo>sGrade', formatter: '.formatGrade' }" />
.
c:js
formatGrade: function (sGrade) {
    const mGrade = { H: "상", M: "중", L: "하" };   // 객체 키로 바로 찾기
    return mGrade[sGrade] || sGrade;                // 없는 코드면 원래 값 그대로
}
.
s: `mGrade[sGrade] || sGrade`는 "앞의 값이 비어 있으면 뒤의 값을 돌려줘요"라는 뜻이에요(2부 거짓으로 보는 값).
s: 바인딩 값이 바뀔 때마다 UI5가 이 함수를 다시 불러요(3부 콜백 함수).

@kw growing
d: 데이터가 아주 많을 때 한꺼번에 그리지 않고 나눠서 보여줘요. `growingThreshold="10"`은 한 번에 10줄씩이에요.
tb:
방식 | 설정 | 동작
더 보기 버튼 | `growing="true" growingThreshold="10"` | 10줄씩 보여주고 맨 아래 More 버튼
스크롤 로딩 | 위 설정 + `growingScrollToLoad="true"`, `ScrollContainer` 안에 | 스크롤이 끝에 닿으면 다음 10줄
페이지 버튼 | `bindItems({ ..., startIndex, length, templateShareable: true })` | 1, 2, 3 버튼 (growing과 함께 못 씀)
.
w: 스크롤 로딩은 처음 보여주는 줄이 영역 높이를 넘쳐야 시작돼요. 스크롤바가 없으면 더 불러오지 못해요.
s: `sticky="ColumnHeaders"`를 붙이면 스크롤해도 열 제목이 위에 고정돼요.
s: JSONModel은 데이터가 이미 전부 브라우저에 있어서 그리는 것만 나눠요. ODataModel은 같은 설정으로 서버에 나눠서 요청해요.

@ch ch-12 | 12부 | Expression Binding과 데이터 타입 | 포매터 함수 없이 XML 안에서 바로 간단한 계산을 하는 게 Expression Binding이고, 금액과 날짜를 형식에 맞게 보여주는 게 데이터 타입이에요. 수업 0220, Lev05

@kw Expression Binding
d: `{=`로 시작해서 XML 안에서 바로 간단한 식을 계산해요. 모델 값은 `${경로}`로 꺼내요.
tb:
하고 싶은 것 | 표현식
Y면 체크 | `selected="{= ${Smajor} === 'Y' }"`
코드를 글자로 | `description="{= ${Tgender} === '1' ? '남성' : '여성' }"`
여러 코드를 글자로 | `{= ${Sleader} === 'L' ? '조장' : ${Sleader} === 'S' ? '부조장' : '' }`
값이 있을 때만 보이기 | `visible="{= !!${Cteacher} }"`
이름 있는 모델 값 | `enabled="{= ${viewModel>/editMode} }"`
.
s: 안에는 `===`, `!`, `&&`, `||`, 삼항 연산자 같은 식을 쓸 수 있어요. if문은 못 써요.
w: 프로퍼티 값을 쌍따옴표로 감싸서, 안의 문자열은 홑따옴표 `'Y'`를 써요.
s: `${Smajor}`는 자바스크립트 템플릿 문자열과 모양이 비슷하지만 여기서는 "이 경로의 모델 값"이라는 뜻이에요.
s: 조건이 세 개를 넘거나 계산이 복잡하면 11부의 포매터가 읽기 쉬워요.

@kw 데이터 타입
d: 값을 사용자 언어에 맞는 형식으로 바꿔 보여주고, 입력칸이면 잘못된 값도 걸러 줘요. 예: `370000` → `370,000 KRW`
c:xml
<!-- 금액 + 통화: 값 두 개를 parts로 묶어서 넘김 -->
<Text text="{
    parts: [ { path: 'Sprice' }, { path: 'Swaers' } ],
    type: 'sap.ui.model.type.Currency'
}" />

<!-- 날짜: 데이터 모양은 source로 알려줌 -->
<Text text="{
    path: 'Sbegda',
    type: 'sap.ui.model.type.Date',
    formatOptions: { source: { pattern: 'yyyy.MM.dd' }, style: 'medium' }
}" />
.
tb:
타입 | 쓰는 곳
`sap.ui.model.type.Currency` | 금액 + 통화
`sap.ui.model.type.Date` | 날짜
`sap.ui.model.type.Integer` / `Float` | 정수 / 소수 (글자를 치면 에러 표시)
`sap.ui.model.type.String` | 글자 수 제한 같은 조건 검사
.
s: `parts`는 값 여러 개를 하나로 묶는 바인딩이에요. 금액은 통화를 알아야 소수점 자리를 정할 수 있어서(KRW는 소수점 없음, USD는 두 자리) 항상 통화 필드와 같이 넘겨요.
w: 날짜 패턴에서 월은 대문자 `MM`, 분(minute)은 소문자 `mm`이에요.
tb:
설정 | 뜻
`formatOptions.source.pattern` | 데이터에 들어 있는 글자의 모양
`formatOptions.style` | 화면에 보여 줄 모양 (`short`, `medium`, `long`)
.
s: 새 버전 UI5에서는 타입을 `core:require`로 불러오는 방식을 권장해요. 콘솔에 관련 경고가 보이면 그때 바꿔도 돼요.
