# SAPUI5 총정리 — 자바스크립트 기초부터 데이터 바인딩까지

Nov 6, 2026

## 이 문서 사용법

자바스크립트를 짧게 배우고 바로 SAPUI5로 넘어와서, 코드가 왜 그렇게 생겼는지 몰라서 막히는 사람을 위한 교재예요. SAPUI5(SAP User Interface for HTML5)는 SAP가 만든 웹 화면 개발 도구이고, 줄여서 UI5라고 불러요. 앞부분(0\~5부)은 UI5 없이 **자바스크립트만** 다뤄요. UI5는 6부부터 시작하고, 거기서 앞에서 배운 자바스크립트가 어디에 쓰이는지 연결해요.

| 부분 | 내용 | 언제 읽나 |
| --- | --- | --- |
| 0\~5부 | 자바스크립트 기초 (UI5 없이 자바스크립트만) | 자바스크립트가 처음이거나 헷갈릴 때 |
| 6\~13부 | UI5 개념 (수업 프로젝트 0108\~0220, Lev05 순서) | 수업 복습할 때 |
| 14부 | 흔한 에러 | 막혔을 때 |
| 15부 | 개발 도구 꿀팁 (BAS와 VS Code 단축키, Extension) | BAS나 컴퓨터가 낯설 때, 작업이 느리다고 느낄 때 |
| 부록 | 프로퍼티 사전, 용어 사전, 약어 풀이, 더 공부할 곳 | 프로퍼티나 단어가 헷갈릴 때 |

- **DB 기초, SQL, ABAP 데이터는 SAP 백엔드 총정리로 따로 나눴어요.** 목차 맨 아래 **부가 기능**에서 열 수 있어요.
- **BAS나 VS Code가 처음이면 15부를 먼저 훑어보세요.** 화면 읽는 법, 단축키, 추천 Extension을 모아 뒀어요. 다른 부와 달리 순서대로 읽지 않아도 돼요.
- **처음 보는 영어 약어는 처음 나올 때 풀어 써요.** 예: NaN(Not a Number), JSON(JavaScript Object Notation). 한꺼번에 찾아보고 싶으면 부록의 "약어 풀이" 표를 보세요.
- **"문법 틀"은 모양만 보여주는 그림이에요.** `function`, `if` 같은 키워드와 괄호, 중괄호는 그대로 쓰고, 주황색 한글 글씨로 쓴 자리만 내가 채워요. 틀은 실행하는 코드가 아니라서 복사 버튼이 없어요. 바로 뒤의 실제 코드와 비교해서 읽으세요.
- **"다음 단계" 상자는 문제를 맞히면 열려요.** 어려운 개념(배열 메서드, `this`, Promise 등)은 앞 개념을 이해했는지 묻는 문제를 먼저 풀어요. 답을 고르고 "정답 확인"을 누르세요. 모두 맞히면 내용이 열리고, 틀리면 다시 읽을 곳을 알려 줘요. 6부 이후에서 쓰이는 내용이니, 결국은 모두 읽어야 해요.
- 0\~5부의 예제는 브라우저에서 F12 → Console 탭에 붙여넣으면 바로 실행돼요. UI5 프로젝트가 없어도 돼요. 직접 숫자를 바꿔 보는 게 가장 빨리 느는 방법이에요.
- 0\~5부의 개념은 같은 순서로 설명해요. 한 줄 정의 → 비유 → 문법 틀(구조가 있는 문법만) → 예제 → 자주 하는 실수예요. 이미 아는 내용이면 건너뛰고 필요한 부분만 읽어도 돼요.
- 6부부터 나오는 **\[0205\]** 같은 표시는 수업 프로젝트 `zcXXw0205`에서 다룬 내용이라는 뜻이에요. `XX`는 내 번호 자리예요(읽는 법은 6부 앱 id와 이름 규칙에 있어요). 그 프로젝트를 열어 놓고 같이 보면 좋아요. 앞에서 배운 자바스크립트가 필요한 곳에서는 "몇 부를 보세요"라고 알려 줘요.
- 이 문서는 과제 정답이 아니라 개념 정리예요. Lev05 내용도 패턴만 다뤄요.
- 틀린 곳, 이해가 안 되는 문장은 그 부분을 선택해서 댓글을 남겨 주세요. 질문이 모이면 그 부분을 더 쉽게 고칠게요.

## 0부. 시작 전에 — 자바스크립트, 콘솔, 에러 읽기

### 자바스크립트는 어떤 언어인가요?

**자바스크립트**(JavaScript)는 웹 페이지를 움직이게 만드는 프로그래밍 언어예요. 버튼을 누르면 반응하고, 입력한 값을 검사하고, 서버에서 데이터를 가져와 화면에 보여 주는 일이 모두 자바스크립트로 이뤄져요.

웹 페이지는 세 가지 재료로 만들어요. 집에 비유하면 이래요.

| 재료 | 하는 일 | 집으로 말하면 |
| --- | --- | --- |
| HTML(HyperText Markup Language) | 화면에 무엇이 있는지 정해요 (글, 버튼, 테이블) | 뼈대와 방 구조 |
| CSS(Cascading Style Sheets) | 어떻게 보일지 정해요 (색, 크기, 위치) | 인테리어 |
| 자바스크립트 | 어떻게 움직일지 정해요 | 전기 배선과 스위치 (누르면 불이 켜져요) |

자바스크립트에 대해 먼저 알아 둘 점이 세 가지 있어요.

- **브라우저가 읽고 바로 실행해요.** 크롬 같은 브라우저 안에 자바스크립트를 실행하는 기능이 들어 있어요. 그래서 따로 설치하지 않고 바로 해 볼 수 있어요.
- **위에서 아래로 한 줄씩 실행해요.** 앞에 쓴 줄이 먼저, 뒤에 쓴 줄이 나중에 실행돼요.
- **이름이 비슷한 자바(Java)와는 다른 언어예요.** 이름만 닮았을 뿐 문법도 쓰임새도 달라요.

SAPUI5에서는 화면에 무엇을 놓을지는 UI5가 준비한 부품으로 적고, 화면이 하는 일은 자바스크립트로 써요. 이 교재는 그 자바스크립트를 읽고 쓰는 데 필요한 만큼만 다뤄요.

### 콘솔 열기

코드를 이해하는 가장 빠른 방법은 값을 직접 찍어 보는 거예요. "이 값이 뭐지?"를 상상하지 말고, 콘솔에 찍어서 확인하세요.

콘솔은 코드를 바로 실행해 보고, 코드가 남기는 메모와 에러를 보여 주는 창이에요.

1. 크롬에서 아무 탭이나 열고 F12 (또는 마우스 오른쪽 → 검사)
2. Console 탭 선택
3. 아래 코드를 붙여넣고 Enter

```js
console.log("안녕");           // 안녕
console.log(1 + 2);            // 3
console.log(typeof "민수");    // string  ← 값의 종류까지 확인하면 더 좋아요
```

`console.log(값)`은 괄호 안의 값을 콘솔에 보여 줘요. `typeof 값`은 그 값이 어떤 종류인지 알려 줘요. 종류가 무엇인지는 1부에서 배워요. 지금은 "값을 찍어 볼 수 있구나"만 알면 돼요.

- 붙여넣기가 막히면 `allow pasting`이라고 입력하고 Enter를 누른 뒤 다시 붙여넣으세요.
- 콘솔 화면을 비우고 싶으면 `console.clear()`를 입력하세요.

### 라이브러리와 프레임워크: 남이 만든 도구와 틀

개발자는 모든 걸 처음부터 만들지 않아요. 남이 만들어 둔 코드를 가져다 써요. 이렇게 가져다 쓰는 코드 묶음에는 두 종류가 있어요.

- **라이브러리**(Library)는 남이 만들어 둔 기능을 필요할 때 꺼내 쓰는 도구 모음이에요. 앱 전체를 맡기는 게 아니라, 내가 만들기 번거로운 기능만 골라서 가져다 써요. 앱이 어떻게 생겼는지는 여전히 내가 정해요.
- **프레임워크**(Framework)는 앱의 뼈대와 규칙을 미리 정해 둔 틀이에요. 앱이 어떻게 시작하는지, 파일을 어디에 둘지가 이미 정해져 있어요. 그래서 나는 정해진 자리에 내 코드를 채워 넣기만 하면 돼요.

| | 라이브러리 | 프레임워크 |
| --- | --- | --- |
| 비유 | 공구함 | 인테리어가 끝난 방 |
| 내가 하는 일 | 필요한 공구를 골라서 내가 직접 써요 | 정해진 자리에 내 가구(코드)를 놓아요 |
| 부르는 쪽 | 내가 도구를 불러요 | 틀이 내 코드를 불러요 |
| 이 교재에서 | 자바스크립트의 `Math`, UI5의 `sap.m` (버튼, 입력창 같은 부품 모음) | SAPUI5 |

**라이브러리를 쓰는 모습**

```js
console.log(Math.max(3, 9));    // 9
console.log(Math.round(2.6));   // 3
```

`Math`는 자바스크립트가 기본으로 챙겨 준 수학 도구 모음이에요. 가장 큰 수를 고르는 `max`와 반올림하는 `round`를 내가 만들지 않고 꺼내 썼어요. 괄호 안에 값을 넣는 방법은 3부에서 배워요. 지금은 "남이 만든 도구를 가져다 쓰는구나"만 보세요.

**프레임워크를 쓰는 모습**

SAPUI5(UI5)는 프레임워크예요. 앱을 화면(View), 동작(Controller), 데이터(Model)로 나눠 만든다는 규칙이 이미 정해져 있어요. 어느 폴더에 어떤 파일을 둘지도 정해져 있고요. 우리는 정해진 자리에 코드를 써 넣어요. 앱을 시작하고 화면을 띄우는 일은 UI5가 해요. 그래서 내가 직접 실행하지 않았는데 내 코드가 실행되는 일이 생겨요. 이건 6부에서 보게 돼요.

**자주 헷갈리는 점**

- 두 말을 섞어 쓰는 사람이 많아요. 수업에서 "UI5 라이브러리"라고 하면 UI5 안의 부품 모음(`sap.m` 같은 것)을 가리키는 경우가 많아요.
- 프레임워크는 규칙이 있어서, 파일 이름이나 위치를 규칙과 다르게 쓰면 앱이 열리지 않아요. 6부의 폴더 구조에서 그 규칙을 봐요.
- 도구 이름을 전부 외울 필요는 없어요. 어떤 도구가 있는지는 API 문서에서 찾아보면 돼요.

### 자주 보는 에러 세 가지

에러 메시지는 영어로 나와요. 하지만 모양이 거의 정해져 있어서, 아래 세 가지만 알아도 대부분 읽혀요. 한 줄씩 따로 실행해서 에러를 만나 보세요.

```js
console.log(sName);        // ReferenceError: sName is not defined
console.log("안녕);        // SyntaxError: Invalid or unexpected token
"안녕"();                   // TypeError: "안녕" is not a function
```

| 에러 메시지 | 한마디로 | 흔한 원인 |
| --- | --- | --- |
| `sName is not defined` | 그런 이름이 없어요 | 이름 오타, 아직 만들지 않은 이름 |
| `Invalid or unexpected token` | 문법이 깨졌어요 | 따옴표나 괄호를 열고 안 닫음 |
| `"안녕" is not a function` | 함수가 아닌 값을 함수처럼 불렀어요 | 이름 오타, 값의 종류가 예상과 다름 |

에러 메시지 오른쪽에 파일 이름과 줄 번호(`script.js:42`)가 보여요. 누르면 문제가 난 줄로 바로 이동해요.

빨간 에러가 여러 개면 맨 위의 것부터 보세요. 아래 에러는 대부분 첫 에러 때문에 줄줄이 생겨요.

## 1부. 값과 데이터의 모양 — 변수, 자료형, 객체, 배열

프로그램은 값을 저장하고, 비교하고, 꺼내 쓰는 일의 반복이에요. 이 부에서는 값을 다루는 기본기를 배워요.

### 변수: 값에 이름표 붙이기

변수는 값을 담아 두는 상자예요. 상자에 이름표(변수 이름)를 붙여 두면, 나중에 이름으로 값을 꺼낼 수 있어요.

아래 틀에서 주황색 한글이 직접 채우는 자리예요. 나머지는 자바스크립트가 정해 둔 모양이에요.

```syntax
const 변수이름 = 값;        // 다시 넣을 일이 없는 값
let 변수이름 = 값;          // 나중에 다시 넣을 값
변수이름 = 새 값;           // 상자 안의 값 바꾸기
```

실제 코드는 이래요.

```js
const sName = "민수";         // 상자를 만들고 "민수"을 넣어요
let nCount = 0;               // 상자를 만들고 0을 넣어요
nCount = nCount + 1;          // 상자 안의 값을 1로 바꿔요
console.log(sName, nCount);   // 민수 1
```

- `const`: constant(상수, 변하지 않는 값)의 줄임말이에요. 한 번 넣으면 **다시 넣을 수 없는** 상자예요.
- `let`: 나중에 **다시 넣을 수 있는** 상자예요.
- 다시 넣을 일이 없으면 `const`를 쓰세요. 실수로 값을 바꾸는 일을 막아 줘요.

`=`는 수학의 "같다"가 아니라 "오른쪽 값을 왼쪽 상자에 넣어라"라는 뜻이에요.

자주 듣는 말을 정리하면 이래요.

- **이름표가 붙은 상자**는 **변수**(Variable)라고 불러요.
- **상자를 만드는 일**은 **선언**(Declare)이라고 불러요. `const`, `let`이 선언하는 키워드예요.
- **상자에 값을 넣는 일**은 **할당**(Assign)이라고 불러요. `=`가 하는 일이에요.

이름 앞에 붙은 `s`, `n`은 값의 종류를 알려 주는 표시예요. 자료형을 배운 뒤에 이 부 끝에서 정리해요.

**자주 하는 실수 1:** `const`로 만든 변수에 값을 다시 넣으면 `TypeError: Assignment to constant variable.` 에러가 나요. 값을 바꿔야 하는 변수는 처음부터 `let`으로 만드세요.

**자주 하는 실수 2:** 콘솔에서 같은 이름의 변수를 `const`나 `let`으로 또 만들면 `has already been declared`(이미 만든 이름이에요)라는 에러가 나요. 페이지를 새로고침하고 다시 실행하세요.

### 자료형: 값에도 종류가 있어요

값은 종류에 따라 할 수 있는 일이 달라요. 숫자는 더할 수 있고, 문자는 이어 붙일 수 있어요. 이 **값의 종류**를 **자료형**(Data Type)이라고 불러요. 줄여서 그냥 "타입"이라고도 해요.

| 자료형 | 예 | `typeof` 결과 |
| --- | --- | --- |
| 문자열 (string) | `"CL303"`, `"2"` | `"string"` |
| 숫자 (number) | `2`, `370000` | `"number"` |
| 불리언 (boolean, 참/거짓) | `true`, `false` | `"boolean"` |
| 값 없음 | `undefined` (아직 안 넣음), `null` (일부러 비움) | `"undefined"`, `"object"` |
| 객체, 배열 (아래에서 배워요) | `{ name: "민수" }`, `[1, 2, 3]` | 둘 다 `"object"` |

`null`의 결과가 `"object"`인 건 자바스크립트의 오래된 특이점이에요. 외우지 말고 "이상하게 나오는 값도 있다"만 알아 두세요.

`"2"`(문자)와 `2`(숫자)는 화면에서는 똑같아 보여도 다른 값이에요. `typeof`로 확인할 수 있어요.

```js
typeof "2"    // "string"
typeof 2      // "number"
```

이 차이가 계산과 비교에서 문제를 만들어요. 아래에서 하나씩 볼게요.

**자주 하는 실수:** 값이 이상하면 눈으로만 보지 말고 `typeof`로 종류부터 확인하세요. 같아 보이는 값이 사실은 문자일 때가 많아요.

### 문자열: 따옴표와 이어 붙이기

글자를 값으로 쓰려면 따옴표로 감싸요. 따옴표는 세 가지가 있어요.

```js
const sName1 = "민수";     // 쌍따옴표
const sName2 = '민수';     // 홑따옴표
const sName3 = `민수`;     // 백틱
console.log(sName1, sName2, sName3);    // 민수 민수 민수  ← 셋 다 똑같은 문자열이에요
```

| 따옴표 | 모양 | 특징 |
| --- | --- | --- |
| 쌍따옴표 | `"안녕"` | 가장 기본이에요. 이 교재는 이걸 써요 |
| 홑따옴표 | `'안녕'` | 쌍따옴표와 똑같이 동작해요 |
| 백틱 | `` `안녕` `` | 값을 끼워 넣을 수 있어요{? 백틱은 키보드 왼쪽 위, 숫자 1 옆에 있는 글쇠예요 ?} |

쌍따옴표와 홑따옴표는 기능이 같아서 하나를 정해 꾸준히 쓰면 돼요. 글자 안에 따옴표가 들어갈 때만 아래 "더 알아보기"를 보세요.

**문자열 이어 붙이기**

글자와 값을 합쳐서 하나의 문자열로 만드는 방법이 두 가지 있어요.

```js
const sName = "민수";
"안녕, " + sName + "!"        // "안녕, 민수!"   +로 이어 붙여요
`안녕, ${sName}!`             // "안녕, 민수!"   백틱 안에 ${ }로 끼워 넣어요
```

**`${ }`가 뭔가요?**

백틱 안에서 `${ }`로 감싼 부분은 글자가 아니라 **코드**로 읽어서, 계산한 결과를 그 자리에 끼워 넣어요. 변수뿐 아니라 계산식도 쓸 수 있어요.

```js
const nScore = 85;
`점수는 ${nScore}점이에요`           // "점수는 85점이에요"
`합계는 ${nScore + 10}점이에요`      // "합계는 95점이에요"   ← ${ } 안에서 계산도 돼요
```

**자주 하는 실수:** `${ }`는 **백틱 안에서만** 동작해요. 쌍따옴표나 홑따옴표 안에서는 그냥 글자로 나와요.

```js
// nScore는 위 예제의 85 그대로예요
"점수는 ${nScore}점이에요"            // "점수는 ${nScore}점이에요"  ← 끼워 넣어지지 않아요
```

붙일 게 많을수록 백틱이 읽기 쉬워요. 따옴표를 열고 닫고 `+`를 쓰는 일이 없어요.

```js
"이름: " + sName + ", 점수: " + nScore + "점"      // +로 이어 붙이기
`이름: ${sName}, 점수: ${nScore}점`                 // 백틱: 훨씬 읽기 쉬워요
```

**언제 무엇을 쓸까요?**

| 상황 | 쓰는 것 |
| --- | --- |
| 평범한 글자 | 쌍따옴표 `"..."` |
| 글자 안에 쌍따옴표가 들어갈 때 | 홑따옴표 `'...'` 로 감싸기 |
| 글자 안에 값이나 계산 결과를 끼워 넣을 때 | 백틱 `` `...${값}...` `` |

<details class="more">
<summary>더 알아보기 — 글자 안에 따옴표 쓰기, 여러 줄 글자</summary>

처음에는 건너뛰어도 돼요. 글자 안에 따옴표가 들어가거나, 코드에서 `\"`가 보이거나, 여러 줄짜리 글자를 만났을 때 다시 오세요.

**글자 안에 따옴표를 쓰고 싶을 때**

감싸는 따옴표와 다른 종류를 안에 쓰면 돼요.

```js
"그는 '안녕'이라고 했어요"      // 안에 홑따옴표가 있으니 쌍따옴표로 감싸요
'그는 "안녕"이라고 했어요'      // 안에 쌍따옴표가 있으니 홑따옴표로 감싸요
```

**자주 하는 실수:** 감싼 것과 같은 따옴표를 안에 그냥 쓰면, 글자가 중간에 끝난 것으로 읽혀서 `SyntaxError`가 나요.

```js
"그는 "안녕"이라고 했어요"      // ❌ "그는 " 에서 글자가 끝나 버렸어요
```

**같은 따옴표를 꼭 쓰고 싶을 때**

앞에 역슬래시(`\`)를 붙이면 "이 따옴표는 글자 끝이 아니라 그냥 글자예요"라는 뜻이 돼요.

```js
"그는 \"안녕\"이라고 했어요"    // 쌍따옴표로 감싼 채 안에도 쌍따옴표를 쓸 수 있어요
```

**여러 줄 글자**

쌍따옴표와 홑따옴표는 한 줄만 쓸 수 있어요. 백틱은 줄바꿈도 그대로 넣을 수 있어요.

```js
const sText = `첫째 줄
둘째 줄`;
console.log(sText);     // 첫째 줄 / 둘째 줄 (두 줄로 나와요)
```

### 비교는 항상 `===`

```js
"2" == 2    // true   ← == 는 종류를 몰래 맞춰서 비교해요 (헷갈려요)
"2" === 2   // false  ← === 는 종류까지 비교해요 (정확해요)
"2" !== 2   // true   ← !== 는 "다르다"예요
```

`===`를 쓰면 "값도 같고 종류도 같을 때만" 같다고 봐요. `==`는 쓰지 마세요.

### 형 변환: 문자와 숫자 사이

```js
Number("2")     // 2      문자 → 숫자
String(2)       // "2"    숫자 → 문자
"0" + 1         // "01"   문자 + 숫자는 이어 붙이기예요!
1 + 1           // 2
```

입력창에 적은 값은 숫자처럼 보여도 항상 문자열이에요. 계산하거나 숫자와 비교하려면 `Number(값)`으로 바꿔야 해요.

**자주 하는 실수:** `"10" + 5`는 `15`가 아니라 `"105"`예요. 결과가 이상하게 길면 문자열이 섞였는지 `typeof`로 확인하세요.

### 객체: 이름표가 붙은 상자

객체(Object)는 관련된 값을 이름표를 붙여 한 상자에 담은 거예요.

모양부터 볼게요.

```syntax
const 객체이름 = {
    이름표1: 값1,
    이름표2: 값2
};
객체이름.이름표1        // 값 꺼내기
```

실제 코드는 이래요.

```js
const oStudent = {
    name: "민수",
    group: 2,
    score: 85
};
oStudent.name         // "민수"   점으로 꺼내기
oStudent["name"]      // "민수"   대괄호로도 꺼낼 수 있어요 (아래 "더 알아보기" 참고)
oStudent.score = 90;  // 값 바꾸기
oStudent.nick = "수니"; // 없던 이름표 추가
oStudent.age          // undefined   없는 이름표는 undefined
```

- **이름표**는 **키**(Key)라고 불러요. 상자 안에서 값을 찾아가는 이름이에요. 위에서는 `name`, `group`, `score`예요.
- **이름표에 담긴 것**은 **값**(Value)이라고 불러요. 위에서는 `"민수"`, `2`, `85`예요.
- **이름표와 값 한 쌍**은 **프로퍼티**(Property)라고 불러요. "속성"이라고도 해요. 위 객체에는 프로퍼티가 세 개 있어요.

`const`로 만든 객체도 안의 값은 바꿀 수 있어요. 상자 자체를 바꾸는 게 아니라 상자 안의 내용물만 바꾸는 거라서요.

키로 **바로** 찾아가요. 하나씩 뒤지지 않아요.

<details class="more">
<summary>더 알아보기 — 키를 글자로 쓰기, 따옴표가 필요한 키</summary>

처음에는 건너뛰어도 돼요. 키가 특이한 데이터를 만났을 때 다시 오세요.

**키는 사실 문자열이에요.** 키를 쓸 때 따옴표를 생략해도 되는 것뿐이에요. 아래 두 객체는 똑같아요.

```js
const o1 = { name: "민수" };
const o2 = { "name": "민수" };     // 키도 문자열이에요 (JSON은 이 모양만 허용해요. JSON은 이 부 끝에서 배워요)
```

**따옴표가 꼭 필요한 키도 있어요.** 키에 공백이나 `-`가 들어 있으면 따옴표로 감싸야 하고, 꺼낼 때도 점이 아니라 대괄호를 써야 해요.

```js
const oUser = { "first-name": "민수" };
oUser["first-name"]      // "민수"
oUser.first-name         // ❌ "first 빼기 name"으로 읽혀서 엉뚱하게 계산되거나 에러가 나요
```

</details>

**자주 하는 실수:** 없는 키는 `undefined`가 나와요. 그런데 그 `undefined`에서 또 무언가를 꺼내려 하면 에러가 나요.

```js
oStudent.age            // undefined
oStudent.age.year       // TypeError: Cannot read properties of undefined (reading 'year')
```

`undefined`에는 꺼낼 게 없기 때문이에요. 앞으로 가장 자주 만날 에러예요. 키를 잘못 썼거나, 값이 아직 없는 경우예요.

### 배열: 번호가 붙은 줄

배열(Array)은 값을 줄 세워 놓은 거예요. 각 값에는 번호(인덱스)가 붙어요.

모양부터 볼게요.

```syntax
const 배열이름 = [값1, 값2, 값3];
배열이름[번호]          // 번호는 0부터 시작해요
```

실제 코드는 이래요.

```js
const aGroups = [1, 2, 3];
aGroups[0]          // 1      번호는 0부터 시작해요!
aGroups.length      // 3      값이 몇 개인지
aGroups.push(4);    // [1, 2, 3, 4]   맨 뒤에 추가
aGroups[aGroups.length - 1]   // 4    마지막 값은 (개수 - 1)번
```

- **번호**는 **인덱스**(Index)라고 불러요. 위에서 `aGroups[0]`의 `0`이에요.
- **줄 서 있는 값 하나하나**는 **요소**(Element)라고 불러요. "항목"(Item)이라고도 해요. 위에서는 `1`, `2`, `3`이에요.
- **값이 몇 개인지**는 **길이**(Length)라고 불러요. 위에서 `aGroups.length`가 `3`이에요.

`push`처럼 배열 뒤에 점(`.`)으로 붙여 쓰는 기능을 **메서드**라고 해요. 4부에서 자세히 배워요. 지금은 "배열에 붙어 있는 기능이구나"만 알면 돼요.

**자주 하는 실수:** 첫 번째 값은 `[1]`이 아니라 `[0]`이에요. 세 개가 들어 있으면 마지막 번호는 `[2]`예요. 없는 번호(`aGroups[9]`)를 부르면 에러가 아니라 `undefined`가 나와요.

### 배열 안의 객체, 객체 안의 배열

실제로 다루는 데이터는 객체와 배열이 섞여 있어요. 대부분 이 모양이에요.

```js
const oClass = {
    title: "3반",
    studentList: [                                    // 객체 안에 배열
        { id: "S01", name: "민수" },                  // 배열 안에 객체 (0번)
        { id: "S02", name: "지아" }                   // (1번)
    ]
};
oClass.studentList[1].name    // "지아"
```

읽는 법은 왼쪽에서 오른쪽으로 한 단계씩이에요. `oClass` 안의 `studentList`, 그 안의 1번, 그 안의 `name`.

한 번에 읽기 어려우면 한 단계씩 끊어서 찍어 보세요.

```js
// oClass는 위에서 만든 객체예요
console.log(oClass.studentList);          // 배열 전체
console.log(oClass.studentList[1]);       // { id: "S02", name: "지아" }
console.log(oClass.studentList[1].name);  // 지아
```

### 변수 이름 앞의 글자: 종류를 표시하는 습관

이제 값의 종류를 다 배웠으니, 변수 이름 앞의 글자를 정리할게요. 이 교재의 변수 이름은 첫 글자가 값의 종류를 알려 줘요. `sName`은 문자열, `aGroups`는 배열이라는 식이에요. 자바스크립트가 정한 규칙은 아니고, 이름만 보고 종류를 알아보려는 습관이에요(헝가리안 표기).

| 접두어 | 뜻 | 예 |
| --- | --- | --- |
| `s` | string (문자열) | `sName`, `sCode` |
| `n`, `i` | number (숫자), integer (정수) | `nCount`, `iIdx` |
| `b` | boolean (참/거짓) | `bFound` |
| `a` | array (배열) | `aGroups` |
| `o` | object (객체) | `oStudent` |
| `fn` | function (함수, 3부에서 배워요) | `fnCallback` |

### JSON: 객체를 글자로 저장한 형식

JSON(JavaScript Object Notation, 자바스크립트 객체 표기법)은 객체를 글자로 적어 두는 약속된 형식이에요. `data.json` 같은 파일로 저장하거나, 다른 프로그램과 데이터를 주고받을 때 써요. 자바스크립트 객체와 거의 같지만 규칙이 더 엄격해요.

- 키도 반드시 쌍따옴표: `"name": "민수"` (`name:`이나 `'민수'`는 에러). 홑따옴표와 백틱은 쓸 수 없어요
- 마지막 항목 뒤에 쉼표 금지
- 주석(`//`) 금지

JSON에 오타가 하나만 있어도 전체를 읽지 못하고 에러가 나요.

## 2부. 흐름 제어 — 조건과 반복

코드는 기본적으로 위에서 아래로 한 줄씩 실행돼요. 조건문은 "맞을 때만" 실행하게 하고, 반복문은 "여러 번" 실행하게 해요. 이 두 가지로 코드의 흐름을 바꿔요.

### if: 맞을 때만 실행하기

`if`는 조건이 맞을 때만 코드를 실행해요. **조건**(Condition)은 참(`true`) 또는 거짓(`false`)으로 답이 나오는 식이에요. 이런 참/거짓 값을 **불리언**(Boolean)이라고 불러요(1부 자료형).

가장 단순한 모양부터 볼게요.

```syntax
if (조건) {
    조건이 참일 때 실행할 코드;
}
```

여기에 `else if`("아니고 이 조건이면")와 `else`("모두 아니면")를 이어 붙일 수 있어요.

```syntax
if (조건1) {
    실행할 코드1;
} else if (조건2) {
    실행할 코드2;
} else {
    실행할 코드3;
}
```

실제 코드는 이래요.

```js
const nScore = 75;
if (nScore >= 90) {
    console.log("A");
} else if (nScore >= 60) {
    console.log("B");        // 75는 여기서 실행돼요
} else {
    console.log("C");
}
```

`if (조건)` 뒤의 `{ }`는 조건이 참일 때만 실행돼요. 위에서부터 차례로 확인하고, **처음 맞는 곳 하나만** 실행해요. `else if`와 `else`는 생략해도 돼요.

조건에는 비교 연산자를 써요.

| 연산자 | 뜻 | 예 | 결과 |
| --- | --- | --- | --- |
| `===` | 같다 | `3 === 3` | `true` |
| `!==` | 다르다 | `3 !== 4` | `true` |
| `>`, `<` | 크다, 작다 | `5 > 3` | `true` |
| `>=`, `<=` | 크거나 같다, 작거나 같다 | `60 >= 60` | `true` |

조건 두 개를 합칠 때는 이 세 가지를 써요.

- `&&` (그리고): 둘 다 참이어야 참이에요. `nScore >= 60 && nScore <= 100`
- `||` (또는): 하나라도 참이면 참이에요. `sRole === "A" || sRole === "B"`
- `!` (반대로): 참이면 거짓, 거짓이면 참이에요. `!bFound`

### 거짓으로 보는 값: if가 헷갈리는 순간

`if (값)`은 값이 `true`인지만 보는 게 아니에요. 아래 여섯 개는 모두 거짓으로 취급돼요. 이 밖의 값은 대부분 참이에요.

- `""` (빈 문자열), `0`, `undefined`, `null`, `false`, `NaN` (Not a Number, "숫자가 아님"이라는 뜻이에요. 숫자로 바꾸지 못했을 때 나오는 값이고, `Number("abc")`가 이 값이에요)

그래서 이런 모양이 자주 나와요.

```js
const sInput = "";                  // 아무것도 안 적은 상태
if (!sInput) {                      // ""는 거짓 → 앞에 !를 붙이면 참
    console.log("값을 입력하세요.");
}
```

`!`는 "반대로"라는 뜻이에요. `!sInput`은 "sInput이 비어 있으면"이라고 읽으면 돼요.

**자주 하는 실수:** 숫자 `0`도 거짓이에요. 0점이 정상 값인데 `if (!nScore)`로 검사하면 0점을 "입력 안 함"으로 착각해요. 숫자는 `nScore === undefined`처럼 정확히 비교하세요.

### 삼항 연산자: if를 한 줄로

`if`/`else`로 값 하나를 정하는 코드를 한 줄로 줄여 쓰는 문법이에요. 안 써도 `if`로 똑같이 할 수 있어서, 처음에는 건너뛰어도 돼요. 다른 사람 코드에서 `?`와 `:`가 보일 때 다시 오세요.

<details class="more">
<summary>더 알아보기 — 조건 ? 참일 때 값 : 거짓일 때 값</summary>

먼저 `if`/`else`로 쓴 코드를 볼게요.

```js
const nScore = 75;
let sResult;
if (nScore >= 60) {
    sResult = "합격";
} else {
    sResult = "불합격";
}
console.log(sResult);       // "합격"
```

같은 일을 삼항 연산자로 쓰면 한 줄이에요. 모양부터 볼게요.

```syntax
조건 ? 참일 때 값 : 거짓일 때 값
```

실제 코드는 이래요.

```js
// nScore는 위 예제의 75 그대로예요
const sResult2 = nScore >= 60 ? "합격" : "불합격";    // "합격"
```

`?` 앞이 참이면 왼쪽 값, 거짓이면 오른쪽 값이 돼요. 여러 개를 이어 붙일 수도 있어요.

```js
const sGrade = nScore >= 90 ? "A" : nScore >= 60 ? "B" : "C";   // "B"
```

"값 하나를 정할 때" 쓰면 편하고, 길어지면 `if`/`else`가 읽기 쉬워요.

</details>

### 반복문: 같은 일을 여러 번

**반복문**(Loop)은 같은 일을 여러 번 해야 할 때 쓰는 문법이에요. 한 번 도는 것은 이 교재에서 "한 바퀴"라고 부를게요. 학생 100명의 이름을 찍어야 한다면 `console.log`를 100줄 쓰는 대신, 반복문에게 "100번 해 줘"라고 시키면 돼요.

**for — 횟수를 세면서 반복하기**

모양부터 볼게요.

```syntax
for (시작; 계속할 조건; 한 바퀴 끝날 때마다) {
    반복할 코드;
}
```

실제 코드는 이래요.

```js
for (let i = 0; i < 3; i++) {
    console.log(i);      // 0, 1, 2
}
```

괄호 안은 세 부분으로 나뉘어요.

1. 시작: `let i = 0` (번호 `i`를 0으로 시작해요. 처음에 딱 한 번만 실행돼요)
2. 계속할 조건: `i < 3` (`i`가 3보다 작은 동안 반복해요)
3. 한 바퀴 끝날 때마다: `i++` (`i`를 1 늘려요{? `i = i + 1`과 같아요. 이렇게 1 늘리는 줄임 표현이에요 ?})

실제로 어떻게 움직이는지 따라가 볼게요.

| 바퀴 | i | `i < 3` | 하는 일 |
| --- | --- | --- | --- |
| 1 | 0 | 참 | `console.log(0)` |
| 2 | 1 | 참 | `console.log(1)` |
| 3 | 2 | 참 | `console.log(2)` |
| 끝 | 3 | 거짓 | 반복을 끝내요 |

배열과 같이 쓰면 번호로 하나씩 꺼낼 수 있어요.

```js
const aNames = ["민수", "지아", "도윤"];
for (let i = 0; i < aNames.length; i++) {
    console.log(i, aNames[i]);     // 0 민수 / 1 지아 / 2 도윤
}
```

`aNames.length`{? 배열에 든 항목의 수예요. 여기서는 3이에요 ?}가 3이라서 `i`는 0, 1, 2만 돌아요. 배열의 번호가 0부터 시작하기 때문에 조건이 `<=`가 아니라 `<`예요.

**자주 하는 실수:** `i <= aNames.length`로 쓰면 한 바퀴를 더 돌아서 마지막에 `undefined`{? "값이 없다"는 뜻의 값이에요(1부) ?}가 나와요.

**for...of — 배열을 차례로 꺼내기**

번호가 필요 없고 값만 필요하면 `for...of`가 더 쉽고 안전해요.

모양부터 볼게요.

```syntax
for (const 항목 of 배열) {
    반복할 코드;
}
```

실제 코드는 이래요.

```js
// aNames는 위에서 만든 배열이에요
for (const sName of aNames) {
    console.log(sName);            // 민수 / 지아 / 도윤
}
```

"`aNames`에서 하나씩 꺼내서 `sName`이라고 부르면서 반복해"라고 읽어요. 바퀴마다 새로운 `sName`이 만들어지기 때문에 `const`를 써도 돼요.

<details class="more">
<summary>더 알아보기 — 반복문에서 let과 const는 왜 다를까요?</summary>

처음에는 건너뛰어도 돼요. `for (let i ...)`와 `for (const v of ...)`가 왜 다르게 쓰였는지 궁금할 때 오세요.

1부에서 배운 기준 그대로예요. `let`은 값을 다시 넣을 수 있는 상자이고, `const`는 한 번 넣으면 다시 넣을 수 없는 상자예요.

| 반복문 | 변수 | 한 바퀴 돌 때 | 그래서 |
| --- | --- | --- | --- |
| `for (let i = 0; i < a.length; i++)` | `i` | 같은 상자 `i`의 값을 `i++`로 바꿔 넣어요 (0 → 1 → 2) | 다시 넣어야 해서 `let` |
| `for (const v of a)` | `v` | `v` 상자를 새로 만들어서 그 바퀴의 값을 넣어요 | 다시 넣을 일이 없어서 `const` |

일반 `for`에서 `const`를 쓰면 두 번째 바퀴에서 `i++`가 값을 바꾸려는 순간 에러가 나요.

```js
for (const i = 0; i < 3; i++) {      // ❌ TypeError: Assignment to constant variable.
    console.log(i);                  // 0 까지만 찍히고 에러가 나요
}
```

`for...of`에는 `let`을 써도 에러는 나지 않아요. 다만 "이 바퀴 안에서 값을 바꾸지 않는다"는 약속이 되는 `const`가 더 안전해서 많이 써요. 반복문 안에서 그 변수를 다시 바꿔야 할 때만 `let`을 쓰세요.

```js
for (const v of ["민수", "지아"]) { console.log(v); }    // 민수 / 지아
for (let v of ["민수", "지아"]) { console.log(v); }      // 민수 / 지아  ← let도 돼요
```

`for...in`의 `for (const sKey in oStudent)`도 같은 이유로 `const`를 써요.

</details>

**합계 구하기: 반복문의 대표 패턴**

상자를 하나 만들어 두고, 반복하면서 값을 쌓아 가요.

```js
const aScores = [85, 92, 58, 77];
let nSum = 0;                      // 합계를 담을 상자 (0에서 시작)
for (const nScore of aScores) {
    nSum += nScore;                // nSum = nSum + nScore 와 같아요
}
console.log(nSum);                 // 312
console.log(nSum / aScores.length);   // 78  (평균)
```

바퀴마다 값이 바뀌는 상자라서 `let`을 썼어요. `nSum += nScore`{? `+=`는 "오른쪽 값을 더해서 다시 넣어라"는 줄임 표현이에요 ?}는 합계에 점수를 더하는 줄이에요.

**break, continue — 반복 중간에 조절하기**

```js
for (const nScore of aScores) {
    if (nScore < 60) {
        console.log("60점 미만이 있어요!");
        break;                     // 반복을 아예 끝내요
    }
}

for (const nScore of aScores) {
    if (nScore < 60) continue;     // 이번 바퀴만 건너뛰고 다음 바퀴로 가요
    console.log(nScore);           // 85, 92, 77
}
```

<details class="more">
<summary>더 알아보기 — for...in: 객체의 키 돌기</summary>

처음에는 건너뛰어도 돼요. 객체의 키를 하나씩 꺼내 볼 때 쓰는 문법이에요. 배열에는 `for...of`를 쓰세요.

모양부터 볼게요.

```syntax
for (const 키 in 객체) {
    반복할 코드;
}
```

실제 코드는 이래요.

```js
const oStudent = { name: "민수", score: 85 };
for (const sKey in oStudent) {
    console.log(sKey, oStudent[sKey]);     // name 민수 / score 85
}
```

`oStudent[sKey]`처럼 **대괄호 안에 변수**를 넣으면, 그 변수에 든 글자(`"name"`, `"score"`)가 키가 돼요. 점(`.`)으로 꺼내는 것과 다르니 비교해서 보세요.

```js
const sKey = "score";
oStudent[sKey]           // 85   ← sKey에 든 글자 "score"가 키가 돼요
oStudent.sKey            // undefined   ← 점은 "sKey"라는 글자 그대로를 키로 찾아요
```

| 쓰는 모양 | 찾는 키 |
| --- | --- |
| `oStudent.score` | `score` |
| `oStudent["score"]` | `score` |
| `oStudent[sKey]` | `sKey` 안에 든 글자 → `score` |
| `oStudent.sKey` | `sKey` 라는 글자 그대로 |

찾을 키가 그때그때 달라질 때 이 방법을 써요. 반복문으로 키를 하나씩 꺼내 쓰는 경우가 바로 그래요.

**자주 하는 실수:** `for...in`을 배열에 쓰면 번호가 숫자가 아니라 문자열로 나와요.

```js
for (const k in aNames) {
    console.log(k, typeof k);      // 0 string / 1 string / 2 string
    console.log(k + 1);            // "01" / "11" / "21"  ← 1이 아니라 이어 붙여져요 (1부 형 변환)
}
```

</details>

<details class="more">
<summary>더 알아보기 — 객체를 만들 때 변수를 키로 쓰기</summary>

처음에는 건너뛰어도 돼요. 키가 변수에 담겨 있는 상태에서 새 객체를 만들 때 쓰는 모양이에요. 키 자리를 대괄호로 감싸면 변수에 든 글자가 키가 돼요.

```js
const sKey = "group";
const oNew = { [sKey]: 3 };    // { group: 3 }
```

</details>

<details class="more">
<summary>더 알아보기 — while: 몇 번인지 모를 때</summary>

배열이나 객체를 돌 때는 위의 세 가지로 충분해요. `while`은 UI5 화면 코드에서 거의 쓰지 않아서, 만났을 때 다시 오면 돼요.

```js
let nLeft = 10;
while (nLeft > 0) {            // 조건이 참인 동안 계속 반복해요
    nLeft = nLeft - 3;         // 10 → 7 → 4 → 1 → -2 (그때 멈춰요)
}
```

**자주 하는 실수:** 조건이 영원히 참이면 반복이 끝나지 않아서 브라우저가 멈춰요. 위 코드에서 `nLeft = nLeft - 3;` 줄을 지우면 그렇게 돼요. `while`은 안에서 조건이 바뀌는지 꼭 확인하세요.

</details>

**정리**

| 문법 | 무엇을 꺼내나 | 언제 쓰나 |
| --- | --- | --- |
| `for (let i = 0; i < a.length; i++)` | 번호 `i` (숫자) | 번호가 필요할 때 |
| `for (const v of a)` | 값 자체 | 배열을 차례로 볼 때 (가장 쉽고 안전) |
| `for (const k in o)` | 키 이름 (**문자열**) | **객체**의 키를 돌 때만 (위 "더 알아보기") |
| `while (조건)` | 없음 (조건만 확인) | 몇 번 돌지 모를 때 (위 "더 알아보기") |

### 예제: 중복 없는 목록 만들기

학생 6명이 속한 조 번호에서 겹치는 걸 빼고 한 번씩만 모으는 코드예요. 핵심은 "끝까지 다 비교해 본 뒤에야 없다는 걸 안다"예요. 반복문 안에 반복문이 들어 있어요. 바깥은 학생을 한 명씩, 안쪽은 이미 모아 둔 조를 하나씩 살펴봐요.

```js
const aAll = [1, 2, 1, 3, 2, 1];       // 학생 6명이 속한 조 (겹쳐요)
const aUnique = [];                    // 겹치지 않게 모을 상자

for (const nGroup of aAll) {
    let bFound = false;                // 이미 모았는지 표시
    for (const nSaved of aUnique) {    // 모아 둔 것을 하나씩 확인
        if (nSaved === nGroup) {
            bFound = true;
            break;                     // 찾았으면 더 볼 필요 없음
        }
    }
    if (!bFound) {                     // 끝까지 봤는데 없으면
        aUnique.push(nGroup);          // 추가
    }
}
console.log(aUnique);                  // [1, 2, 3]
```

## 3부. 함수 — 코드를 묶어 이름 붙이기

함수는 코드 덩어리에 이름을 붙여 둔 거예요. 같은 일을 여러 번 시킬 수 있고, 값을 받아서 결과를 돌려줄 수도 있어요. 이 부에서는 아래 개념을 순서대로 배워요. 앞 개념을 알아야 다음 개념이 읽혀요.

### 함수 기본: 받고, 처리하고, 돌려주기

함수는 자판기와 비슷해요. 동전을 넣으면(입력) 음료가 나와요(결과). 한꺼번에 보면 복잡하니까, 가장 단순한 모양에서 하나씩 덧붙여 갈게요.

**1단계 — 만들고 부르기**

```syntax
function 함수이름() {
    실행할 코드;
}
함수이름();        // 함수 부르기
```

```js
function sayHi() {
    console.log("안녕하세요!");
}
sayHi();     // 안녕하세요!
sayHi();     // 안녕하세요!  ← 부를 때마다 다시 실행돼요
```

함수는 만들기만 하면 실행되지 않아요. `sayHi()`처럼 이름 뒤에 `()`를 붙여서 **불러야** 실행돼요.

**2단계 — 값을 받기**

매번 똑같은 인사 말고, 이름을 받아서 인사하고 싶다면 `( )` 안에 "받는 칸"을 만들어요.

```syntax
function 함수이름(받는 칸) {
    실행할 코드;
}
함수이름(넣을 값);
```

```js
function sayHiTo(sName) {
    console.log(sName + "님, 안녕하세요!");
}
sayHiTo("민수");    // 민수님, 안녕하세요!
sayHiTo("지아");    // 지아님, 안녕하세요!
```

- **받는 칸**은 **매개변수**(Parameter)라고 불러요. 함수를 만들 때 `( )` 안에 정해 두는 이름이고, 함수가 불릴 때 넘어온 값을 받아서 담아 둬요. 위에서는 `sName`이에요.
- **넣을 값**은 **인자**(Argument)라고 불러요{? 현장에서는 매개변수와 인자를 구분하지 않고 그냥 "파라미터"라고 부르는 경우가 많아요. 문맥으로 "받는 칸"인지 "넣는 값"인지 알아들으면 돼요 ?}. 함수를 부를 때 `( )` 안에 실제로 넣는 값이에요. 위에서는 `"민수"`, `"지아"`예요.

받는 칸이 여러 개면 쉼표로 이어요: `function add(nA, nB)`로 만들고 `add(1, 2)`로 불러요.

**3단계 — 결과 돌려주기**

화면에 찍기만 하는 게 아니라, 계산한 결과를 돌려받고 싶을 때는 `return`을 써요.

```syntax
function 함수이름(받는 칸) {
    return 돌려줄 값;
}
const 결과 = 함수이름(넣을 값);
```

```js
function getGroupName(nGroup) {
    return nGroup + "조";
}
const sGroupName = getGroupName(2);     // 2를 넣고 불렀더니 "2조"가 돌아와요
console.log(sGroupName);                // 2조
```

- **돌려줄 값**은 **반환값**(Return Value)이라고 불러요. 함수가 일을 마치고 부른 쪽에 돌려주는 결과예요. 위에서는 `"2조"`예요.
- **`return`**은 반환값을 돌려주고 함수를 끝내라는 명령이에요. 돌려받은 값은 변수에 담아서 쓸 수 있어요.
- `return`이 없으면 함수는 `undefined`를 돌려줘요. 위의 `sayHi()`처럼 "일만 하고 돌려줄 게 없는" 함수는 `return`이 없어도 돼요.

### 일찍 끝내기(return)

조건이 안 맞으면 함수를 바로 끝내는 모양이 아주 자주 나와요. 안쪽으로 계속 들여 쓰는 것보다 읽기 쉬워요.

```js
function register(sName) {
    if (!sName) {                       // 1. 이름이 비어 있으면
        console.log("이름을 입력하세요.");
        return;                         // 2. 여기서 함수 끝
    }
    // 3. 여기까지 왔다면 이름이 있다는 뜻 → 안심하고 처리
    console.log(sName + " 등록 완료");
}
register("");         // 이름을 입력하세요.
register("민수");     // 민수 등록 완료
```

### 콜백 함수: 나중에 불러 달라고 건네는 함수

함수도 값이에요. 변수에 담을 수 있고, 다른 함수에 넘길 수도 있어요. 먼저 `()`의 차이를 알아야 해요.

```js
function sayHello() { console.log("안녕"); }

sayHello()     // 지금 실행해요
sayHello       // 함수 자체예요 (실행하지 않아요)
```

함수 이름 뒤에 `()`를 붙이면 **지금 실행**, 안 붙이면 **함수 자체를 건네는 것**이에요.

함수 자체를 건네면 무엇이 좋을까요? 받은 쪽에서 원하는 때에, 원하는 횟수만큼 실행할 수 있어요. 아래 `doTwice`는 건네받은 함수를 두 번 실행해 주는 도구예요.

```js
// sayHello는 위에서 만든 함수예요
function doTwice(fnTask) {     // fnTask = 건네받은 함수
    fnTask();                  // 받은 함수를 실행해요
    fnTask();                  // 한 번 더 실행해요
}
doTwice(sayHello);             // 안녕 / 안녕   ← "이 일을 두 번 해 줘"라고 sayHello를 건넸어요
```

`doTwice`에게 "이 함수를 두 번 불러 줘"라고 일을 맡긴 거예요. 이렇게 건네는 함수는 **콜백 함수**(Callback Function)라고 불러요. "나중에 다시 불러 달라(call back)"는 뜻이에요. 줄여서 그냥 "콜백"이라고도 많이 불러요. 이 함수를 언제, 몇 번 부를지는 받은 쪽(`doTwice`)이 정해요.

이름을 따로 짓지 않고 바로 만들어서 넘기기도 해요.

```js
doTwice(function () {
    console.log("바로 만든 함수예요");     // 두 번 찍혀요
});
```

**자주 하는 실수:** 건넬 때 `()`를 붙이면 안 돼요.

```js
doTwice(sayHello());    // ❌ "안녕"이 한 번 찍히고, 이어서 TypeError: fnTask is not a function
```

`sayHello()`가 지금 바로 실행되고, 그 결과(`undefined`)가 `doTwice`로 건너가요. 그러면 `doTwice` 안에서 `undefined()`를 부르는 셈이라 에러가 나요(0부 자주 보는 에러 세 가지에서 본 `is not a function`).

아래에서 배울 배열 메서드(`find`, `filter`, `forEach`)에 넘기는 함수도 모두 콜백 함수예요.

### 화살표 함수: function을 짧게 쓰는 방법

배열 메서드를 쓰기 시작하면 `=>` 모양이 계속 나와요. 새로운 기능이 아니에요. 같은 함수를 짧게 쓴 거예요. 이 모양을 **화살표 함수**(Arrow Function)라고 불러요. 한 단계씩 줄여 볼게요.

```js
// ① 기본
const f1 = function (v) { return v + "조"; };

// ② function 대신 => 를 써요
const f2 = (v) => { return v + "조"; };

// ③ 본문이 return 한 줄이면 { }와 return을 지워요
const f3 = (v) => v + "조";

// ④ 매개변수가 하나면 ( )도 지워요
const f4 = v => v + "조";

f4(2);    // "2조"
```

네 개 모두 같은 일을 해요. `v => v + "조"`는 "v가 들어오면 v + '조'를 돌려줘요"라고 읽으면 돼요.

줄여 쓴 모양을 틀로 정리하면 이래요.

```syntax
(매개변수1, 매개변수2) => 돌려줄 값
매개변수 => 돌려줄 값                 // 매개변수가 하나면 ( )를 생략해요
(매개변수) => {
    실행할 코드;
    return 돌려줄 값;
}
```

### 배열 메서드: for문이 하던 일에 이름을 붙인 도구

배열에서 찾기, 거르기는 아주 자주 하는 일이에요. 그때마다 for문을 짜면 길어져요. 그래서 자바스크립트가 이름이 붙은 도구를 미리 준비해 뒀어요.

안에서는 똑같이 반복해요. 반복문이 눈에 안 보일 뿐이에요. 괄호 안에는 "각 항목에 할 일"을 콜백 함수로 넘겨요.

이 내용은 6부 이후 코드에서 `find`, `filter` 같은 이름으로 계속 쓰여요.

아래 예제는 모두 이 데이터를 써요. 먼저 콘솔에 붙여넣으세요.

```js
const aStudents = [
    { name: "민수", group: 1, score: 85 },
    { name: "지아", group: 2, score: 92 },
    { name: "도윤", group: 1, score: 58 },
    { name: "서연", group: 3, score: 77 }
];
const aGroups = [1, 2, 3];
```

**includes — 있는지 확인하기**

```syntax
배열.includes(찾을 값)
```

돌려주는 값은 `true` 또는 `false`예요. 콜백 함수가 아니라 찾을 값을 바로 넣어요.

```js
// for문으로 직접
let bFound = false;
for (const nGroup of aGroups) {
    if (nGroup === 3) { bFound = true; break; }
}

// includes 한 줄
aGroups.includes(3);    // true
aGroups.includes(9);    // false
```

2부의 "중복 없는 목록" 예제에서 안쪽 for문이 하던 일이 바로 이 한 줄이에요.

```js
if (!aUnique.includes(nGroup)) aUnique.push(nGroup);
```

**자주 하는 실수:** `includes`는 종류까지 비교해요(1부 `===`와 같아요). 숫자 배열에서 문자를 찾으면 못 찾아요.

```js
aGroups.includes("3");  // false  ← 문자 "3"과 숫자 3은 달라요
```

**find — 조건에 맞는 첫 항목 찾기**

```syntax
배열.find(항목 => 조건)
```

틀에서 `항목`은 콜백 함수의 매개변수{? 3부 함수 기본에서 배운 "받는 칸"이에요 ?}예요. 배열의 항목이 하나씩 여기에 들어와요. `조건`은 참 또는 거짓으로 답이 나오는 식이에요.

```js
// for문으로 직접
let oFound;
for (const s of aStudents) {
    if (s.name === "도윤") { oFound = s; break; }
}

// find 한 줄
aStudents.find(s => s.name === "도윤");   // { name: "도윤", group: 1, score: 58 }
```

`s => s.name === "도윤"`은 "학생 한 명(`s`{? `s`는 학생 한 명을 부르는 임시 이름이에요. 마음대로 지어도 돼요 ?})이 들어오면, 그 학생의 name이 '도윤'인지 알려줘"라는 뜻이에요. `find`는 처음 맞는 항목을 돌려줘요. 하나도 없으면 `undefined`예요.

**자주 하는 실수:** `find`의 결과를 바로 쓰기 전에 `undefined`인지 확인하세요. 없는 이름을 찾으면 그다음 줄에서 `Cannot read properties of undefined` 에러가 나요.

**findIndex — 몇 번째인지 찾기**

```syntax
배열.findIndex(항목 => 조건)
```

```js
aStudents.findIndex(s => s.name === "서연");     // 3
aStudents.findIndex(s => s.name === "없는이름");  // -1  (없으면 -1)
```

찾은 항목이 아니라 **번호**가 필요할 때 써요. 번호를 알면 `aStudents[3]`처럼 다시 꺼낼 수 있어요.

**filter — 조건에 맞는 것만 모으기**

```syntax
배열.filter(항목 => 조건)
```

```js
aStudents.filter(s => s.group === 1);   // 1조 학생 둘을 모은 새 배열
```

`find`는 하나만, `filter`는 맞는 것 전부를 새 배열로 돌려줘요. 하나도 없으면 빈 배열 `[]`이에요.

**forEach — 하나씩 꺼내서 실행하기**

```syntax
배열.forEach(항목 => 실행할 코드)
```

```js
aStudents.forEach(s => console.log(s.name));            // 민수, 지아, 도윤, 서연
aStudents.forEach((s, i) => console.log(i, s.name));    // 0 민수, 1 지아, ...
```

돌려주는 값이 없어요. 하나씩 실행만 해요. 콜백 함수는 항목뿐 아니라 번호도 받을 수 있어요. 두 번째 매개변수(`i`)에 번호가 들어와요.

<details class="more">
<summary>더 알아보기 — map: 하나씩 바꿔서 새 배열 만들기</summary>

처음에는 건너뛰어도 돼요. 아래 표의 `map`이 궁금해지거나 코드에서 만났을 때 오세요.

```syntax
배열.map(항목 => 새 값)
```

```js
aStudents.map(s => s.name);                          // ["민수", "지아", "도윤", "서연"]
aGroups.map(n => n + "조");                           // ["1조", "2조", "3조"]
aGroups.map(n => ({ code: n, label: n + "조" }));    // 객체의 배열
```

객체를 바로 돌려줄 때는 `{ }`를 괄호로 한 번 더 감싸요. 괄호가 없으면 `{ }`를 함수 몸통으로 읽어요.

</details>

**어떤 걸 쓸까요?**

| 하고 싶은 일 | 메서드 | 돌려주는 값 |
| --- | --- | --- |
| 값이 들어 있는지 확인 | `includes(값)` | `true` / `false` |
| 조건에 맞는 첫 항목 | `find(콜백 함수)` | 그 항목 (없으면 `undefined`) |
| 조건에 맞는 첫 항목의 번호 | `findIndex(콜백 함수)` | 번호 (없으면 `-1`) |
| 조건에 맞는 것 전부 | `filter(콜백 함수)` | 새 배열 |
| 하나씩 실행만 | `forEach(콜백 함수)` | 없음 |
| 하나씩 바꿔서 새 배열 | `map(콜백 함수)` | 새 배열 |

이 메서드들은 원래 배열을 바꾸지 않아요. 새 배열이나 값을 돌려줄 뿐이에요.

### 배열 vs 객체: 찾는 방식의 차이

배열과 객체 중 무엇에 데이터를 담을지 고를 때 쓰는 기준이에요.

```js
aStudents.find(s => s.name === "도윤");     // 배열: 처음부터 하나씩 비교해요

const oScoreMap = { "민수": 85, "지아": 92, "도윤": 58 };
oScoreMap["도윤"];                           // 객체: 키로 바로 가요 (비교가 없어요)
```

- 배열에서 찾기: 처음부터 하나씩 비교해요 (`find`, `includes`).
- 객체에서 찾기: 키로 바로 가요. 비교가 없어요.

데이터가 수백 개 정도면 둘 다 충분히 빨라요. 읽기 쉬운 쪽을 고르면 돼요.

## 4부. 자바스크립트 더 알아두기 — 메서드, this, 스코프, 체이닝

3부까지 배웠다면 코드를 읽을 수 있어요. 이 부에서는 코드를 읽다가 자주 막히는 네 가지를 풀어 볼게요.

### 메서드: 객체 안에 들어 있는 함수

객체에는 값뿐 아니라 함수도 넣을 수 있어요. 객체 안에 들어 있는 함수는 **메서드**(Method)라고 불러요.

모양부터 볼게요.

```syntax
const 객체이름 = {
    메서드이름: function () {
        실행할 코드;
    }
};
객체이름.메서드이름();        // 메서드 부르기
```

실제 코드는 이래요. `name: "민수"`처럼 키 뒤에 값이 오는데, 메서드는 그 값 자리에 함수가 온 거예요.

```js
const oPerson = {
    name: "민수",                       // 값
    sayHi: function () {                // 메서드 (값 자리에 함수가 온 거예요)
        console.log("안녕!");
    }
};
oPerson.sayHi();     // 안녕!
```

지금까지 써 온 `push`, `console.log`도 모두 메서드예요. `console`이라는 객체 안에 `log`라는 함수가 들어 있는 거예요.

**자주 하는 실수:** 객체 안의 항목 사이에는 쉼표가 필요해요. 쉼표를 빠뜨리면 `SyntaxError`가 나서 코드 전체가 실행되지 않아요.

<details class="more">
<summary>더 알아보기 — 메서드를 더 짧게 쓰는 방법</summary>

`이름: function () { }`에서 `: function`을 빼고 `이름() { }`로 쓸 수도 있어요. 둘은 같은 뜻이에요. 새로 만든 UI5 프로젝트나 공식 예제에서는 짧은 모양을 자주 만나요.

```syntax
const 객체이름 = {
    메서드이름: function () {       // 지금까지 쓴 모양
        실행할 코드;
    },
    짧은메서드이름() {               // 짧게 쓴 모양 (같은 뜻)
        실행할 코드;
    }
};
```

```js
const oPerson = {
    sayHi: function () { console.log("안녕!"); },
    sayBye() { console.log("잘 가!"); }          // 짧게 쓴 모양
};
oPerson.sayHi();     // 안녕!
oPerson.sayBye();    // 잘 가!
```

이 교재의 예제는 `이름: function () { }` 모양으로 써요. 짧은 모양을 만나면 같은 뜻이라고 읽으세요.

</details>

### this: "나 자신"

메서드 안에서 자기 객체의 값을 쓰고 싶을 때가 있어요. 이때 `this`를 써요. `this`는 그 메서드를 부른 **객체 자신**이에요.

6부 컨트롤러 코드에서 `this`가 계속 나와요.

```js
const oCounter = {
    nCount: 0,
    up: function () {
        this.nCount++;                  // 내(oCounter)의 nCount를 1 늘려요
        this.show();                    // 내(oCounter)의 show를 불러요
    },
    show: function () {
        console.log("현재: " + this.nCount);
    }
};
oCounter.up();     // 현재: 1
oCounter.up();     // 현재: 2
```

`oCounter.up()`으로 불렀으니 `up` 안의 `this`는 `oCounter`예요. 그래서 `this.nCount`는 `oCounter.nCount`고, `this.show()`는 `oCounter.show()`예요.

주의할 점이 하나 있어요. 메서드 안에서 `function`으로 함수를 또 만들면, 그 안의 `this`는 그 메서드가 들어 있는 객체(아래 예제에서는 `oFriend`)가 아니에요. 3부에서 배운 화살표 함수는 바깥의 `this`를 그대로 써요.

```js
function doTwice(fnTask) { fnTask(); fnTask(); }     // 3부에서 만든 함수예요

const oFriend = {
    nick: "민수",
    start: function () {
        doTwice(function () {
            console.log(this.nick);     // ❌ undefined  (여기 this는 oFriend가 아니에요)
        });

        doTwice(() => {
            console.log(this.nick);     // ✅ 민수  (화살표 함수는 바깥 this를 그대로 써요)
        });
    }
};
oFriend.start();
```

**왜 이렇게 될까요?**

`this`는 함수를 **만들 때가 아니라 부를 때** 정해져요. 규칙은 간단해요. 부르는 모양에서 **점(`.`) 바로 앞에 있는 객체**가 `this`가 돼요.

| 부르는 모양 | 함수 안의 `this` |
| --- | --- |
| `oFriend.start()` | `oFriend` (점 앞에 `oFriend`가 있어요) |
| `fnTask()` | 없음 (점 앞이 비어 있어요) |

위 예제에서 `start`는 `oFriend.start()`로 불렀으니 `this`가 `oFriend`예요. 그런데 `function () { ... }`을 `doTwice`에 넘기면, `doTwice` 안에서 `fnTask()`처럼 점 없이 불려요. 점 앞에 객체가 없으니 `this`는 `oFriend`가 아니에요. 그래서 위 예제의 ❌ 줄에서 `this.nick`을 읽지 못해요. 환경에 따라 `undefined`가 찍히거나 에러가 나는데, 이유는 아래 "더 알아보기"에 있어요.

화살표 함수는 달라요. 화살표 함수는 **자기만의 `this`가 없고**, 어떻게 불리든 상관없이 **자기를 적은 자리의 `this`**를 그대로 가져다 써요. 위 예제의 화살표 함수는 `start` 안에 적혀 있으니 `start`의 `this`, 즉 `oFriend`를 써요.

직접 확인해 볼게요. 같은 `this === oFriend`("`this`가 `oFriend`인가요?")를 세 군데에서 찍어요.

```js
const oFriend = {
    nick: "민수",
    start: function () {
        console.log(this === oFriend);        // true   ← start 안: 점 앞이 oFriend
        doTwice(function () {
            console.log(this === oFriend);    // false (두 번)  ← 점 없이 불려서 oFriend가 아니에요
        });
        doTwice(() => {
            console.log(this === oFriend);    // true (두 번)   ← 적힌 자리(start)의 this를 그대로 써요
        });
    }
};
oFriend.start();
```

정리하면 이래요. 일반 함수(`function`)는 "어떻게 불렸는지"로 `this`가 정해지고, 화살표 함수는 "어디에 적혀 있는지"로 `this`가 정해져요. 메서드 안에서 콜백 함수를 넘기고 그 안에서 `this`를 써야 한다면, 화살표 함수로 쓰세요.

### 스코프: 변수가 살아 있는 범위

`let`, `const`로 만든 변수는 자기가 든 `{ }` 안에서만 살아 있어요. `{ }` 밖에서는 그 이름을 몰라요. 이 살아 있는 범위를 **스코프**라고 불러요. 변수가 "어디까지 보이는지"를 정하는 울타리예요.

```js
if (true) {
    const sInner = "안쪽";
}
console.log(sInner);    // ReferenceError: sInner is not defined
```

함수 안에서 만든 변수는 함수가 끝나면 사라지고, 다음에 부르면 새로 만들어져요.

```js
function countUp() {
    let nCount = 0;          // 부를 때마다 0에서 새로 시작해요
    nCount++;
    console.log(nCount);
}
countUp();    // 1
countUp();    // 1  ← 또 1이에요! 지난번 값은 사라졌어요
```

값을 계속 기억하게 하려면 함수 밖이나 객체에 두세요.

```js
let nTotal = 0;                  // 함수 밖에 두면 계속 남아요
function addOne() {
    nTotal++;
    console.log(nTotal);
}
addOne();    // 1
addOne();    // 2
```

앞에서 본 `oCounter.nCount`도 같은 방식이에요. 객체 안에 둔 값이라 메서드를 여러 번 불러도 남아 있어요.

기준은 간단해요. "계속 기억해야 하는 값"은 함수 밖이나 객체(`this`)에 두고, "이번 한 번만 쓸 값"은 함수 안에 `const`나 `let`으로 두세요.

### 메서드 체이닝: 점으로 이어 부르기

앞 메서드가 돌려준 값에 바로 점을 찍고 다음 메서드를 불러요. 이렇게 사슬(chain)처럼 이어 부르는 것을 **체이닝**(Method Chaining)이라고 불러요. 오른쪽으로 갈수록 값이 한 번씩 가공돼요.

6부의 길게 이어진 코드를 읽을 때 써요.

```js
const sRaw = "  김민수, 박지아 ,이도윤  ";
const aNames = sRaw.trim().split(",").map(s => s.trim());
// ["김민수", "박지아", "이도윤"]
```

한 단계씩 따라가 볼게요.

| 단계 | 코드 | 결과 |
| --- | --- | --- |
| 1 | `sRaw.trim()` | `"김민수, 박지아 ,이도윤"` (양 끝 공백 제거) |
| 2 | `.split(",")` | `["김민수", " 박지아 ", "이도윤"]` (쉼표 기준으로 자르기) |
| 3 | `.map(s => s.trim())` | `["김민수", "박지아", "이도윤"]` (각각 공백 제거) |

앞에서 배운 배열 메서드도 이어 붙일 수 있어요. 3부에서 만든 `aStudents`를 그대로 써요.

```js
aStudents.filter(s => s.score >= 70).map(s => s.name);
// ["민수", "지아", "서연"]   70점 이상인 학생의 이름만
```

체이닝에서 에러가 나는 가장 흔한 원인은 중간 값이 `undefined`나 `null`인 경우예요. 1부에서 본 `Cannot read properties of undefined` 에러와 같은 원인이에요. 중간 값이 비어 있으면 그 뒤에 이어 붙인 메서드는 전부 에러가 나요.

```js
const oUser = {};
oUser.address.trim();      // TypeError: Cannot read properties of undefined (reading 'trim')
```

길게 이어진 줄에서 에러가 나면 한 단계씩 끊어서 `console.log`로 확인해 보세요.

## 5부. 비동기 — 기다려야 하는 일

파일을 불러오거나 서버에 요청하는 일은 시간이 걸려요. 0부에서 "위에서 아래로 한 줄씩" 실행한다고 했는데, 시간이 걸리는 일만 예외예요. 자바스크립트는 그걸 기다리지 않고 다음 줄로 넘어가요. 그래서 **결과가 도착했을 때 할 일을 따로 맡겨 둬야** 해요. 이렇게 기다리지 않고 먼저 넘어가는 방식을 **비동기**(Asynchronous)라고 불러요. 코드에서는 줄여서 `async`라고 써요.

### 기다리지 않으면 생기는 일

`setTimeout`은 **"정해진 시간이 지난 뒤에 이 함수를 실행해 줘"라고 알람을 맞춰 두는 기능**이에요. 주방 타이머를 맞춰 놓고 다른 일을 하다가, 삐 소리가 나면 그때 할 일을 하는 것과 같아요.

가장 중요한 점은 **알람을 맞춰 두기만 하고 기다리지 않는다**는 거예요. 맞춰 둔 뒤에는 바로 다음 줄로 넘어가요. 이 교재에서는 서버나 파일처럼 "시간이 걸리는 일"을 흉내 내는 데 써요. 3부에서 배운 콜백 함수를 받는 기능이고, 자바스크립트가 기본으로 갖고 있어요. 모양부터 볼게요.

```syntax
setTimeout(콜백 함수, 기다릴 시간);
```

"정해진 시간이 지나면 이 함수를 실행해 줘"라고 맡기는 거예요. `기다릴 시간`은 밀리초 단위라서 `1000`이 1초예요. 실제 코드는 이래요.

```js
let sResult = "아직 없음";
setTimeout(() => {
    sResult = "도착!";           // 1초 뒤에 실행돼요
}, 1000);
console.log(sResult);            // "아직 없음"  ← 1초를 기다려 주지 않고 바로 실행돼요
```

식당에서 주문하자마자 접시를 들었는데, 아직 음식이 안 나온 것과 같아요. 시간이 걸리는 일은 "주문만 넣고" 다음 줄로 넘어가요.

**자주 하는 실수:** 첫 번째 인자 자리에 함수 이름 뒤에 `()`를 붙이면 알람이 아니라 지금 바로 실행돼요(3부 콜백 함수). 함수 자체를 건네야 해요.

```js
// sayHello는 3부에서 만든 "안녕"을 찍는 함수예요
setTimeout(sayHello(), 1000);   // ❌ sayHello가 지금 바로 실행돼요
setTimeout(sayHello, 1000);     // ✔ 1초 뒤에 실행돼요
```

### Promise: "나중에 줄게"라는 약속

시간이 걸리는 함수는 결과 대신 **진동벨**을 바로 돌려줘요. "준비되면 알려줄게"라는 약속이에요. 이 진동벨을 **Promise**(프로미스)라고 불러요. 이름 그대로 "결과를 나중에 꼭 줄게"라는 약속이에요.

8부에서 데이터 파일을 읽을 때 쓰여요.

아래 `getScore`는 "1초 걸려서 90점을 알려 주는 함수"를 흉내 내는 도구예요. 안쪽 문법은 지금 몰라도 되니 그대로 붙여넣으세요.

```js
function getScore() {
    return new Promise(resolve => {
        setTimeout(() => resolve(90), 1000);   // 1초 뒤에 90을 줄게요
    });
}
```

이제 `getScore()`를 불러서 돌아온 것을 찍어 볼게요. 위의 `getScore`를 만들어 둔 상태에서 아래 세 줄을 이어서 실행해요. 한 번은 바로, 한 번은 1.5초 뒤에 찍어요.

```js
const p = getScore();
console.log(p);                            // 바로 찍으면: Promise {<pending>}
setTimeout(() => console.log(p), 1500);   // 1.5초 뒤에 찍으면: Promise {<fulfilled>: 90}
```

먼저 바로 찍은 결과를 볼게요. 90이 찍힐 것 같지만 90은 아직 없어요. 대신 이렇게 찍혀요.

- `Promise`: 결과가 아니라 **진동벨**이라는 뜻이에요.
- `<pending>`{? 영어 pending은 "보류 중"이라는 뜻이에요 ?}: "아직 기다리는 중"이라는 뜻이에요.

**Promise는 이렇게 움직여요**

Promise는 결과를 담을 **상자**예요. 상자는 처음에 비어 있고, 일이 끝나면 내용물이 채워져요. 상태는 세 가지뿐이에요.

| 상태 | 영어 | 식당으로 말하면 | 상자 안에는 |
| --- | --- | --- | --- |
| 기다리는 중 | `pending` | 음식을 만드는 중 | 아직 아무것도 없어요 |
| 성공 | `fulfilled` | 벨이 울리고 음식이 나옴 | 결과가 들어 있어요 (여기서는 90) |
| 실패 | `rejected` | 재료가 떨어져서 주문이 취소됨 | 왜 실패했는지 에러 정보가 들어 있어요 |

움직이는 순서는 이래요.

1. 시간이 걸리는 일을 시작하면 Promise가 바로 만들어져요. 상태는 항상 **기다리는 중**이에요.
2. 일이 끝나면 상태가 딱 한 번 바뀌어요. 잘 끝나면 **성공**, 문제가 생기면 **실패**예요.
3. 한 번 바뀐 상태는 다시 바뀌지 않아요. 성공한 벨이 다시 기다리는 중으로 돌아가지 않아요.

그래서 돌려받는 것은 항상 같은 종류(Promise 상자)예요. 달라지는 건 상자 안의 내용물이에요. 어떤 함수는 숫자 90을, 어떤 함수는 글자나 객체를 담아 줘요.

1.5초 뒤에 다시 찍어 보면 상자가 채워진 걸 볼 수 있어요. 위 코드의 마지막 줄이 바로 그 부분이에요. `Promise {<fulfilled>: 90}`은 성공했고 상자 안에 90이 있다는 뜻이에요.

아래에서 상자의 상태가 바뀌는 순서를 따라가 보세요.

&#91;embedded content: Promise 상태 변화 · pending에서 fulfilled로\]

(실패한 Promise를 만들어 보고 싶다면 아래 "더 알아보기"를 열어 보세요.)

이제 남은 질문은 하나예요. 상자가 채워졌을 때 안의 90을 어떻게 꺼낼까요? 다음에 나오는 `then`이 그 방법이에요.

<details class="more">
<summary>더 알아보기 — 성공과 실패를 정하는 resolve, reject</summary>

처음에는 건너뛰어도 돼요. `getScore` 안쪽 코드가 궁금해질 때 오세요.

위의 `getScore` 안에 있던 `resolve`는 "일이 잘 끝났어요, 결과는 이거예요"라고 알리는 버튼이에요. 이 버튼을 누르면 Promise가 **성공**이 돼요. 반대로 "문제가 생겼어요"라고 알리는 버튼이 `reject`예요. 누르면 **실패**가 돼요.

```js
function getScoreFail() {
    return new Promise((resolve, reject) => {
        setTimeout(() => reject(new Error("서버 오류")), 1000);   // 1초 뒤에 실패 버튼을 눌러요
    });
}

const q = getScoreFail();
setTimeout(() => console.log(q), 1500);   // Promise {<rejected>: Error: 서버 오류}
```

실패를 받아 주는 코드가 없으면 콘솔에 빨간 에러(Uncaught (in promise))가 같이 나와요. 실패를 처리하는 방법은 이 교재에서 다루지 않아요. 지금은 "실패라는 상태도 있다"는 것만 알면 충분해요.

### then: 결과가 도착하면 실행할 일 맡기기

`then`은 Promise 상자에 "채워지면 이 일을 해 줘"라고 할 일을 맡기는 메서드예요. 진동벨을 받고 자리에 앉아 있다가, 벨이 울리면 음식을 가지러 가는 것과 같아요. 계속 기다릴 필요 없이 "벨이 울리면 할 일"만 맡겨 두는 거예요. `then(할 일)`은 "결과가 오면, 그다음에 이걸 해 줘"라고 읽으면 돼요.

오래된 코드와 UI5 공식 예제에서 `.then`을 자주 만나요.

모양부터 볼게요.

```syntax
시간이 걸리는 함수().then(결과 => {
    결과로 할 일;
});
```

`then`에 넘기는 것은 **함수**예요. 3부의 콜백 함수와 같아요. Promise가 성공하면 상자 안의 결과가 이 함수의 매개변수로 들어와요. 앞에서 붙여넣은 `getScore`로 해 볼게요.

```js
getScore().then(nScore => console.log(nScore));    // 1초 뒤에 90
```

읽는 법은 이래요. "`getScore()`의 상자가 채워지면(성공하면), 그 안의 값을 `nScore`라고 부르고 `console.log`로 찍어 줘요."

`then`은 기다리지 않고 다음 줄로 넘어가요. 맡겨만 두고 가는 거예요.

```js
getScore().then(nScore => console.log("점수:", nScore));
console.log("먼저 찍혀요");
// 먼저 찍혀요
// 점수: 90        ← 1초 뒤
```

**자주 하는 실수:** `then` 바깥에서 결과를 쓰려고 하면 아직 비어 있어요. `then`에 넘긴 함수는 벨이 울린 뒤에야 실행되기 때문이에요.

```js
let nResult;
getScore().then(nScore => { nResult = nScore; });
console.log(nResult);     // ❌ undefined  ← 아직 벨이 안 울렸어요
```

결과를 쓰는 코드는 모두 `then`에 넘긴 함수 **안에** 넣어야 해요. 그런데 기다릴 일이 여러 개가 되면 함수 안에 함수가 계속 들어가서 읽기 힘들어져요. 그래서 같은 일을 위에서 아래로 읽히게 쓰는 문법이 따로 생겼어요. 바로 다음에 나오는 `async / await`예요.

`await`는 `then`과 같은 일을 위에서 아래로 읽히게 쓰는 문법이에요. 진동벨이 울릴 때까지 기다렸다가 안의 결과를 꺼내 줘요{? 4부에서 본 짧은 메서드 모양에서는 `async 이름() { }`로 써요. `이름: async function () { }`와 같은 뜻이에요 ?}.

- 바로 실행되고, `nScore`에는 Promise가 들어와요

- `getScore`가 실패해서
> 5부 then의 "자주 하는 실수"를 다시 읽어 보세요.

가장 핵심이 되는 한 줄부터 볼게요.

```syntax
const 결과 = await 시간이 걸리는 함수();
```

이 줄은 함수 안에서만 쓸 수 있고, 그 함수 앞에는 `async`를 붙여야 해요. 함수 전체 모양은 이래요.

```syntax
async function 함수이름() {
    const 결과 = await 시간이 걸리는 함수();
    결과로 할 일;
}
```

실제 코드는 이래요.

```js
async function showScore() {                // ① 함수 앞에 async
    const nScore = await getScore();        // ② 1초 기다렸다가 결과를 꺼내요
    console.log(nScore);                    // ③ 90
}
showScore();
```

방금 배운 `then`과 나란히 놓으면 같은 일을 해요.

```js
// then으로 쓰면
getScore().then(nScore => console.log(nScore));

// await로 쓰면 (async 함수 안에서)
const nScore = await getScore();
console.log(nScore);
```

- `await`는 **`async`가 붙은 함수 안에서만** 쓸 수 있어요. `async` 없이 `await`를 쓰면 문법 에러가 나서 코드 전체가 실행되지 않아요.
- `await`는 그 함수 안에서만 기다려요. 함수 바깥의 코드는 기다리지 않고 계속 실행돼요.

```js
async function showScore() {
    const nScore = await getScore();
    console.log(nScore);                    // 1초 뒤에 90
}

showScore();
console.log("이 줄이 먼저 찍혀요");    // showScore 안의 1초를 기다리지 않아요
```

아래에서 이 코드가 실행되는 순서를 따라가 보세요. 함수 안에서만 멈추고 바깥은 계속 간다는 점을 눈으로 볼 수 있어요.

&#91;embedded content: async await 실행 순서 · await에서 멈추는 곳\]

**자주 하는 실수:** `await`를 빼먹으면 결과 대신 Promise가 나와요.

```js
async function wrong() {
    const nScore = getScore();         // ❌ await를 빼먹었어요
    console.log(nScore);               // Promise {<pending>}  ← 90이 아니라 진동벨이에요
}
```

지금은 이 한 줄만 기억하면 충분해요. "시간이 걸리는 함수 앞에는 `await`, 그 함수를 담은 함수 앞에는 `async`."

UI5 코드에서 `await`는 주로 두 자리에서 만나요. 데이터 파일을 읽는 `await oModel.loadData(...)`(8부 모델 만들고 연결하기)와, 팝업을 불러오는 `await this.loadFragment(...)`(7부 Dialog 팝업)예요.

## 6부. UI5 앱의 뼈대 — 파일, 화면, 컨트롤러, 이벤트

여기부터는 UI5예요. 0\~5부에서 배운 자바스크립트가 그대로 쓰여요. 코드를 읽다가 막히면 밑줄 친 단어를 눌러서 그 설명으로 돌아가 다시 읽어 보세요.

UI5 앱은 세 부분으로 나뉘어요. 화면(View)은 무엇을 보여줄지, 동작(Controller)은 버튼을 누르면 무엇을 할지, 데이터(Model)는 보여줄 데이터를 맡아요. 이 구조를 MVC(Model-View-Controller, 데이터-화면-동작의 앞글자)라고 불러요. UI5는 이 구조를 미리 정해 둔 프레임워크예요(0부 라이브러리와 프레임워크).

| 부분 | 파일 | 하는 일 | 비유 |
| --- | --- | --- | --- |
| View | `view/View1.view.xml` | 무엇을 어디에 보여줄지 | 가게 진열대 |
| Controller | `controller/View1.controller.js` | 버튼을 누르면 무엇을 할지 | 점원 |
| Model | `model/data.json` | 보여줄 데이터 | 진열대 뒤 선반 |

이 부에서는 아래 순서로 하나씩 배워요. 앞 단계를 알아야 다음 단계가 읽혀요.

1. **파일이 어디에 있나:** 폴더 구조와 앱 id
2. **화면 읽기:** XML View
3. **컨트롤 찾기:** id와 `byId`
4. **동작 읽기:** 컨트롤러 파일과 `this`
5. **화면과 동작 잇기:** 이벤트

데이터를 화면에 보여 주는 방법(바인딩)은 8부에서 배워요. 이 부에서는 몰라도 돼요.

### 프로젝트 폴더 구조

BAS(SAP Business Application Studio, 수업에서 쓰는 개발 도구)에서 새 프로젝트를 만들면 `webapp` 폴더에 이렇게 생겨요. ← 표시가 수업에서 직접 고치는 파일이에요.

```
webapp/
├─ index.html            앱을 여는 시작 페이지
├─ Component.js          앱 전체 관리자
├─ manifest.json         앱 설정서 (앱 id, 모델, 화면 연결)
├─ view/
│   ├─ App.view.xml       바깥 틀
│   ├─ View1.view.xml     ← 직접 작업하는 화면
│   └─ Popup.fragment.xml ← 화면 조각 (7부)
├─ controller/
│   └─ View1.controller.js ← 직접 작업하는 동작
├─ model/data.json        ← 데이터 파일
├─ i18n/i18n.properties   화면 문구 (다국어용, i18n = internationalization)
├─ css/style.css          스타일
└─ test/                  테스트 (지금은 안 봐도 돼요)
```

### 앱 id와 이름 규칙: 점(.)은 폴더예요

`manifest.json`의 `"sap.app": { "id": "ncode.zcXXw0205" }`가 앱의 이름이에요. 이 이름이 `webapp` 폴더를 가리켜요. 그 뒤의 점은 폴더 구분이고, 확장자는 생략해요.

| 코드에 쓰는 이름 | 실제 파일 |
| --- | --- |
| `ncode.zcXXw0205.controller.View1` | `webapp/controller/View1.controller.js` |
| `ncode.zcXXw0205.view.Popup` | `webapp/view/Popup.fragment.xml` |
| `ncode.zcXXw0205.i18n.i18n` | `webapp/i18n/i18n.properties` |

다른 프로젝트에서 코드를 복사해 오면 이 이름이 예전 프로젝트 것으로 남기 쉬워요. "파일을 찾을 수 없다(failed to load, 404)"는 에러의 대표 원인이에요. 정확한 앱 id는 항상 `manifest.json`에서 확인하세요.

### XML View 읽는 법

XML은 `<태그>`로 내용을 감싸서 구조를 적는 글 형식이에요{? eXtensible Markup Language의 줄임말이에요. 웹 페이지를 만드는 HTML(HyperText Markup Language)과 모양이 닮았어요 ?}. UI5의 화면(View) 파일이 이 형식이에요. 아주 간단한 화면부터 읽어 볼게요.

```xml
<mvc:View controllerName="ncode.zcXXw0205.controller.View1"
    xmlns:mvc="sap.ui.core.mvc"
    xmlns="sap.m">
    <Page id="page" title="학생 찾기">
        <content>
            <Input id="inpName" placeholder="이름을 입력하세요" />
            <Button id="btnSearch" text="검색" />
        </content>
    </Page>
</mvc:View>
```

제목이 "학생 찾기"인 한 장짜리 화면 안에 입력칸 하나와 검색 버튼 하나가 있는 화면이에요.

**코드를 위에서부터 읽어 볼게요.**

1. `<mvc:View controllerName="...">`: 화면 파일 전체를 감싸는 가장 바깥 태그예요. `controllerName`은 이 화면을 움직이는 컨트롤러 파일의 이름이에요(앞에서 본 이름 규칙).
2. `xmlns...` 줄들: 아래에서 쓸 컨트롤을 어느 라이브러리에서 가져올지 정해 둬요. 바로 아래에서 자세히 볼게요.
3. `<Page id="page" title="학생 찾기">`: 화면 한 장을 뜻하는 컨트롤이에요. `id`와 `title`로 설정해요.
4. `<content>`: Page 안에서 "내용물을 넣는 자리"예요.
5. `<Input ... />`, `<Button ... />`: 입력칸과 버튼이에요. 태그가 `/>`로 끝나면 안에 다른 태그가 없다는 뜻이에요.

**태그를 부르는 이름**

XML의 각 부분에는 이름이 있어요. 코드를 읽을 때 이 이름이 자주 나와요.

| 이렇게 생긴 것 | 부르는 이름 | 뜻 | 예 |
| --- | --- | --- | --- |
| 대문자로 시작하는 태그 | **컨트롤** (control) | 버튼, 테이블, 입력칸 같은 화면 부품 | `Page`, `Input`, `Button` |
| 소문자로 시작하는 태그 | **애그리게이션** (aggregation) | 컨트롤 안에 다른 컨트롤을 넣는 자리 | `content`, `items`, `columns` |
| 태그 안의 `이름="값"` | **프로퍼티** (property) | 컨트롤의 설정값(1부 객체의 이름과 값 한 쌍과 같아요) | `id`, `title`, `text` |

값에 `{ }`가 들어 있는 모양(`value="{/name}"` 같은 것)은 8부에서 배울 바인딩이에요. 지금은 몰라도 돼요.

**xmlns: 컨트롤을 가져올 라이브러리 정하기**

UI5 컨트롤은 종류별로 여러 라이브러리{? 라이브러리가 무엇인지는 0부 라이브러리와 프레임워크에서 봤어요 ?}에 나뉘어 들어 있어요. `xmlns`는 "이 접두어{? `mvc:View`의 `mvc:`처럼 태그 이름 앞에 붙는 짧은 이름이에요 ?}가 붙은 컨트롤은 이 라이브러리에서 가져와라"고 정해 두는 줄이에요.

| 접두어 | 가져오는 라이브러리 | 이 파일에서 쓰는 컨트롤 |
| --- | --- | --- |
| (없음) | `sap.m` | `Page`, `Input`, `Button` |
| `mvc:` | `sap.ui.core.mvc` | `View` |

접두어가 없는 태그는 `xmlns="sap.m"`으로 정한 기본 라이브러리에서 가져와요. 다른 라이브러리의 컨트롤(`core:Item`, `f:SimpleForm`, `l:Grid` 등)도 같은 방식으로 `xmlns:core`, `xmlns:f`, `xmlns:l`을 먼저 적어야 해요. 선언하지 않은 접두어를 쓰면 에러가 나요.

### id와 byId

XML에 `id="inpName"`을 붙이면 컨트롤러에서 `this.byId("inpName")` 또는 `this.getView().byId("inpName")`로 그 컨트롤을 꺼낼 수 있어요. 꺼낸 컨트롤에는 메서드를 부를 수 있어요(4부 메서드).

`this.getView()`는 이 컨트롤러가 맡은 **화면(View) 전체**를 돌려줘요. `this.byId("x")`는 `this.getView().byId("x")`를 짧게 쓴 것이라 결과가 같아요. 나중에 화면에 데이터를 연결할 때도 `this.getView().setModel(...)`처럼 화면을 먼저 꺼내요.

```js
const oInput = this.byId("inpName");      // XML의 입력칸을 꺼내요
const sName = oInput.getValue();          // 입력칸에 적힌 글자를 읽어요  예: "민수"
oInput.setValue("지아");                   // 입력칸에 글자를 넣어요
```

UI5 컨트롤은 반드시 `byId`로 꺼내세요. XML에 id가 없으면 `byId`는 `undefined`를 돌려줘요.

<details class="more">
<summary>더 알아보기 — 웹에서 쓰는 document.getElementById와는 다른가요?</summary>

처음에는 건너뛰어도 돼요. 인터넷에서 찾은 예제에 `document.getElementById`가 나와서 헷갈릴 때 오세요.

`document.getElementById("이름")`은 일반 웹 페이지(HTML)에서 id가 그 이름인 태그를 찾아 주는 자바스크립트 기본 기능이에요. `document`는 브라우저가 지금 보여 주는 웹 페이지를 담고 있는 객체예요. 이 교재의 0\~5부에서는 다루지 않았어요.

UI5에서는 이 방법으로 찾을 수 없어요. UI5가 XML의 id 앞에 화면 이름 같은 글자를 붙여서 실제 id를 길게 만들기 때문이에요. 예를 들어 XML의 `inpName`이 실제로는 `__xmlview0--inpName`이 될 수 있어요. 그래서 `document.getElementById("inpName")`은 못 찾고 `null`을 돌려줘요. `byId("inpName")`은 이 접두어를 알아서 붙여 주니까 UI5에서는 항상 `byId`를 쓰세요.

### 컨트롤러 파일 읽기

컨트롤러 파일은 처음 보면 낯설지만, 앞에서 배운 자바스크립트(함수, 객체, 메서드)로 모두 읽을 수 있어요. 위에서부터 뜯어 볼게요.

```js
sap.ui.define([                                  // ① 필요한 모듈 목록 (모듈 경로)
    "sap/ui/core/mvc/Controller"
], function (Controller) {                       // ② 모듈을 받을 이름 (순서대로!)
    "use strict";

    return Controller.extend("ncode.zcXXw0205.controller.View1", {   // ③ 컨트롤러 만들기
        onInit: function () { ... },             // ④ 메서드들
        onSearch: function () { ... }
    });
});
```

1. **`sap.ui.define`:** 필요한 **모듈**(Module)을 불러오는 명령이에요. 모듈은 UI5가 기능별로 나눠 둔 자바스크립트 파일 하나예요. `Controller`, `MessageToast`처럼 화면에 보이지 않는 기능도 모듈이에요. 대괄호 안에 모듈이 있는 위치(**모듈 경로**, 슬래시로 적어요)를 적으면, 뒤에 오는 함수가 그 모듈을 매개변수{? 3부에서 배운, 함수가 받는 칸이에요 ?}로 받아요. 이름이 아니라 **순서**로 짝이 지어져요.
2. **`Controller.extend(이름, { ... })`:** "기본 컨트롤러에 이 객체 안의 함수들을 더해서, 내 컨트롤러를 만들어 줘"라는 뜻이에요. 두 번째 인자는 그냥 **함수를 담은 객체**예요.
3. **메서드:** 객체 안에 들어 있는 함수예요(4부). 메서드 사이는 쉼표로 구분해요.

맨 위의 `"use strict"`{? "실수를 더 엄격하게 잡아 줘"라는 스위치예요. 선언하지 않은 변수에 값을 넣는 것 같은 실수를 에러로 알려 줘요 ?}는 항상 넣어 두는 줄로만 알아도 돼요.

모듈을 더 쓰고 싶을 때는 두 군데를 고쳐요. 모듈 경로를 대괄호 안에 **한 줄 추가**하고, 함수의 괄호에도 **같은 순서로 이름을 추가**해요. 아래 그림에서 번호가 같은 것끼리 짝이에요.

### 컨트롤러 안의 this

컨트롤러 메서드 안에서 `this`는 컨트롤러 자신이에요(4부 this와 같은 원리). 그래서 다른 메서드를 부르거나, 값을 저장해 둘 수 있어요.

컨트롤러의 `this.byId`, `this.getView` 같은 코드를 읽을 때 필요해요.

```js
onInit: function () {
    this._oDialog = null;          // 컨트롤러에 값 저장 (함수가 끝나도 남아요)
    this.onSearch();               // 같은 컨트롤러의 다른 메서드 호출
    this.getView();                // 컨트롤러가 가진 기능 사용
}
```

메서드 안에서 `function`으로 함수를 또 만들면, 그 안의 `this`는 컨트롤러가 아니에요. 화살표 함수는 바깥의 `this`를 그대로 써요. 왜 그런지는 4부 this에서 설명했어요.

```js
onPopup: function () {
    function inner() { this.getView(); }      // ❌ 여기서 this는 컨트롤러가 아님
    const inner2 = () => { this.getView(); }; // ✅ 화살표 함수는 바깥 this 유지
}
```

### press: 버튼을 누르면 실행할 함수 연결하기

버튼을 누르는 것처럼 화면에서 일어나는 일을 **이벤트**라고 불러요. 사용자가 클릭하거나 입력하는 것처럼, 앱이 알아채고 반응해야 하는 일이에요. XML에 `press=".함수이름"`을 쓰면 "버튼을 누르면 컨트롤러의 그 함수를 실행해 줘"라는 뜻이에요.

```xml
<Button id="btnSearch" text="검색" press=".onSearch" />
```

```js
onSearch: function () {
    const sName = this.byId("inpName").getValue();   // 입력칸에 적힌 글자
    console.log("검색할 이름:", sName);                 // 콘솔에서 확인해요
}
```

`press=".onSearch"`는 콜백 함수예요. "지금 실행해"가 아니라 "버튼을 누르면 이 함수를 실행해 줘"라고 UI5에게 맡기는 거예요. 앞의 점(`.`)은 "이 화면의 컨트롤러에 있는 함수"라는 뜻이에요.

**자주 하는 실수:** `press=".onSearch()"`처럼 `()`를 붙이면 안 돼요. 맡기는 게 아니라 지금 실행하라는 뜻이 돼요.

### 이벤트 객체: "무슨 일이 있었는지" 담은 봉투

UI5는 이벤트 함수를 부르면서 첫 번째 인자로 **이벤트 객체**를 넣어 줘요. 누가 일으켰는지, 어떤 정보가 있는지가 들어 있어요.

`onSelect(oEvent)` 같은 함수가 모두 이 모양이에요.

```js
onSearch: function (oEvent) {                     // 첫 번째 매개변수가 이벤트 객체예요
    const oButton = oEvent.getSource();           // 이벤트를 일으킨 컨트롤 자신 (여기서는 버튼)
    const sText = oButton.getText();              // "검색"
}
```

이벤트가 알려 주는 정보는 `getParameter("이름")`으로 꺼내요. 입력칸의 `liveChange`{? 글자를 칠 때마다 일어나는 이벤트예요 ?}로 해 볼게요.

```xml
<Input id="inpName" liveChange=".onType" />
```

```js
onType: function (oEvent) {
    const sValue = oEvent.getParameter("value");   // 지금까지 입력한 글자
}
```

어떤 이름(`value`, `selectedItem`, `listItem` 등)으로 꺼내야 하는지는 컨트롤마다 달라요. UI5 API{? Application Programming Interface의 줄임말이에요. 컨트롤과 모듈마다 쓸 수 있는 기능을 정리한 설명서예요 ?} 문서에서 그 컨트롤의 Events 항목을 보면 나와요.

### 길게 이어진 메서드 읽기

4부의 메서드 체이닝이 UI5에서는 이런 모양으로 나와요. 오른쪽으로 갈수록 더 구체적인 것을 꺼내요.

실제 UI5 코드는 대부분 이렇게 이어진 모양이에요.

```js
this.getView().byId("inpName").getValue().trim();
//   화면       → 입력칸        → 적힌 글자 → 앞뒤 공백 제거
```

중간에 하나라도 `undefined`면 그 뒤는 모두 에러예요. 예를 들어 XML에 `id`가 없으면 `byId`가 `undefined`를 돌려줘서, 다음 단계 `getValue`에서 `Cannot read properties of undefined (reading 'getValue')` 에러가 나요. 길게 이어진 줄에서 에러가 나면 한 단계씩 끊어서 `console.log`로 확인해 보세요.

## 7부. 화면 만들기 — 레이아웃, Fragment, 팝업 \[0108\~0202\]

화면은 컨트롤 안에 컨트롤을 넣는 방식으로 만들어요. 다른 컨트롤을 담아 배치만 정하는 컨트롤을 **레이아웃 컨트롤**이라고 해요. 자주 쓰는 화면 조각은 Fragment로 떼어 내고, 팝업(Dialog)은 Fragment로 만들어서 필요할 때 불러와요.

### 레이아웃 컨트롤

| 컨트롤 | 하는 일 | 자주 쓰는 설정 |
| --- | --- | --- |
| `HBox` | 안의 것을 **가로**로 나열 | `alignItems="Center"`(세로 가운데 정렬), `justifyContent="SpaceBetween"`(양 끝으로 벌리기), `wrap="Wrap"` |

### 정렬과 간격: HBox·VBox 설정 읽기

HBox와 VBox 안의 것들을 **어느 쪽에 붙일지(정렬)**, **사이를 얼마나 띄울지(간격)** 정하는 설정이에요.

책장에 책을 꽂는다고 생각해 보세요. 한 줄 칸에 책을 왼쪽부터 붙여 꽂을지, 가운데로 모을지, 양 끝으로 벌릴지는 "줄 방향" 정렬이에요. 책 키가 제각각일 때 칸의 위, 가운데, 아래 중 어디에 맞출지는 "높이 방향" 정렬이에요. UI5도 이 둘을 따로 정해요.

| 설정 | 정하는 것 | HBox에서는 | VBox에서는 |
| --- | --- | --- | --- |
| `justifyContent` | 나열 방향으로의 정렬 | 가로 정렬 | 세로 정렬 |
| `alignItems` | 나열 방향과 직각인 쪽의 정렬 | 세로 정렬 | 가로 정렬 |

HBox와 VBox는 나열 방향만 다르고 설정 이름은 같아요. 그래서 같은 값이라도 VBox에서는 가로와 세로가 뒤바뀌어요.

```syntax
<HBox justifyContent="나열 방향 정렬" alignItems="직각 방향 정렬" wrap="줄 바꿈">
    <!-- 안에 넣을 컨트롤들 -->
</HBox>
```

쓸 수 있는 값은 이래요. 둘 다 안 적으면 `justifyContent`는 `Start`, `alignItems`는 `Stretch`예요.

| `justifyContent` 값 | 모양 |
| --- | --- |
| `Start` (기본) | 시작 쪽(HBox는 왼쪽)부터 붙여요 |
| `Center` | 가운데로 모아요 |
| `End` | 끝 쪽(HBox는 오른쪽)에 붙여요 |
| `SpaceBetween` | 첫 번째와 마지막을 양 끝에 놓고, 나머지는 사이를 똑같이 나눠요 |
| `SpaceAround` | 각 항목의 양옆에 같은 여백을 줘요 |

| `alignItems` 값 | 모양 |
| --- | --- |
| `Stretch` (기본) | 칸의 높이에 맞춰 늘려요 |
| `Start` / `Center` / `End` | 위 / 가운데 / 아래(HBox 기준)에 맞춰요 |
| `Baseline` | 글자의 바닥선을 맞춰요. 글자 크기가 서로 다를 때 써요 |

제목은 왼쪽 끝에, 버튼은 오른쪽 끝에 놓고 둘의 높이는 가운데로 맞춰 볼게요.

```xml
<HBox justifyContent="SpaceBetween" alignItems="Center">
    <Title text="학생 목록" />
    <Button text="추가" press=".onAdd" />
</HBox>
```

아래 연습장에서 값을 바꿔 보세요. 화면에 보이는 동안 저절로 값이 바뀌고, 직접 누르면 그 값대로 움직여요.

### Dialog 팝업: 한 번 만들고 계속 쓰기 \[0201, 0202\]

팝업은 두 번째 클릭부터 문제가 생기기 쉬워요. 처음 한 번만 불러와서 **컨트롤러(`this`)에 저장**하고, 다음부터는 저장해 둔 것을 열어요.

```xml
<!-- view/Popup.fragment.xml -->
<core:FragmentDefinition xmlns="sap.m" xmlns:core="sap.ui.core">
    <Dialog id="dlgPopup" title="강사 정보">
        <content>
            <Text text="팝업 내용" />
        </content>
        <buttons>
            <Button text="닫기" press=".onClose" />
        </buttons>
    </Dialog>
</core:FragmentDefinition>
```

```js
onOpenPopup: async function () {
    if (!this._oDialog) {                         // 처음 한 번만
        this._oDialog = await this.loadFragment({
            name: "ncode.zcXXw0201.view.Popup"    // 앱 id + .view. + 파일 이름
        });
    }
    this._oDialog.open();
},
onClose: function () {
    this._oDialog.close();
}
```

- `loadFragment`는 불러온 팝업을 화면에 자동으로 연결해 줘요. 그래서 화면의 모델을 팝업에서도 그대로 쓸 수 있고, `this.byId("dlgPopup")`로도 찾을 수 있어요.
- `loadFragment`는 시간이 걸려서 `await`가 필요하고, 그래서 이 메서드에 `async`가 붙어요(5부 async / await). `async` 없이 `await`만 쓰면 문법 에러가 나서 앱이 통째로 안 떠요 \[0202\].
- 팝업을 Fragment로 옮겼다면 View XML에 같은 id의 `<Dialog>`가 남아 있으면 안 돼요. id 중복 에러가 나요.

`this._oDialog`에 저장하는 이유는 4부의 스코프 때문이에요. 함수 안에서 만든 변수는 함수가 끝나면 사라지고, 버튼을 누를 때마다 새로 만들어져요.

```js
onOpen: async function () {
    let oDialog;                     // ❌ 버튼을 누를 때마다 새로 생겨요 (항상 undefined)
    if (!oDialog) { ... }            //    → 항상 참 → 매번 새로 불러옴 → id 중복 에러

    if (!this._oDialog) { ... }      // ✅ 컨트롤러에 저장 → 다음 클릭에도 남아 있어요
}
```

"한 번 만들어서 계속 쓸 것"은 `this`에 넣고, "이번 한 번만 쓸 것"은 `const`나 `let`에 넣으세요.

<details class="more">
<summary>더 알아보기 — 공식 예제에 나오는 널 병합 할당(??=)과 .then</summary>

처음에는 건너뛰어도 돼요. 공식 문서의 Dialog 예제를 읽을 때 다시 오세요.

UI5 공식 예제는 같은 내용을 `this.pDialog ??= this.loadFragment({...}); this.pDialog.then(oDialog => oDialog.open());`로 써요(5부 then). `??=`는 "비어 있을 때만 넣어라"는 뜻이에요. 이 기능을 **널 병합 할당**(Nullish Coalescing Assignment)이라고 불러요. 앞의 값이 `undefined`나 `null`일 때만 오른쪽 값을 넣어요. 그래서 위 코드의 `if (!this._oDialog)`와 거의 같은 일을 해요.

</details>

팝업에 특정 데이터를 보여주는 방법(`bindElement`)은 10부에서 다뤄요.

## 8부. 데이터 바인딩 1 — 모델과 프로퍼티 바인딩 \[0203\~0204\]

바인딩(binding, "묶어 둔다"는 뜻)은 "이 컨트롤의 이 프로퍼티는 저 데이터를 보여줘"라고 **연결만 해 두는 것**이에요. 연결해 두면 데이터가 바뀌는 즉시 화면도 바뀌어서, `setValue`를 일일이 부를 필요가 없어져요. 그리고 바인딩은 **항상 모델을 거쳐요.** 컨트롤러의 변수를 XML에서 바로 가리킬 수는 없어요.

6부에서 본 세 부분(View, Controller, Model)이 바인딩으로 이어지는 모습이에요.

&#91;embedded content: UI5 앱의 세 부분 · MVC\]

화면과 데이터는 바인딩으로 직접 이어져 있고, 컨트롤러는 이벤트를 받아 모델을 바꾸거나 컨트롤을 찾아 조작해요.

### 바인딩 전(0108)과 후(0203) 비교

```js
// 바인딩 전: 값을 직접 하나씩 넣기
this.byId("inpFName").setValue("김");
this.byId("inpName").setValue("민수");

// 바인딩 후: 데이터를 모델에 넣고, 화면은 연결만
const oModel = new JSONModel({ bookInfo: { code: "UX400", name: "SAPUI5" } });
this.getView().setModel(oModel);
```

```xml
<Input value="{/bookInfo/code}" />   <!-- UX400 -->
<Input value="{/bookInfo/name}" />   <!-- SAPUI5 -->
```

중괄호 `{ }`는 "글자 그대로가 아니라 모델에서 가져와 줘"라는 표시예요. 중괄호 안이 모델 속 위치예요. 이 위치를 **Binding Path**라고 해요. 6부의 모듈 경로(`"sap/ui/model/json/JSONModel"`처럼 파일이 있는 위치)와 모양은 비슷하지만, Binding Path는 **데이터 안의 위치**를 가리켜요. `JSONModel`도 `sap.ui.define` 목록에 그 모듈 경로를 추가해야 쓸 수 있어요(6부 컨트롤러 파일 읽기).

### Binding Path는 자바스크립트 경로와 같아요

Binding Path는 1부에서 배운 객체와 배열의 경로에서 점(`.`)과 대괄호를 슬래시(`/`)로 바꾼 것뿐이에요. 이 표 하나가 바인딩 이해의 절반이에요.

```js
const oData = {
    bookInfo: { code: "UX400", name: "SAPUI5" },
    esStdList: [
        { Sid: "25010001", Sname: "민수" },     // 0번
        { Sid: "25010002", Sname: "지아" }      // 1번
    ]
};
```

| 자바스크립트 | UI5 Binding Path |
| --- | --- |
| `oData.bookInfo.code` | `{/bookInfo/code}` |
| `oData.esStdList` | `{/esStdList}` |
| `oData.esStdList[1].Sname` | `{/esStdList/1/Sname}` |
| `oCatData.CAT01` (이름 있는 모델 catModel) | `{catModel>/CAT01}` |

맨 앞의 `/`는 모델의 맨 위(`oData`)를 뜻해요. 배열 번호도 0부터라서 `/esStdList/1`은 두 번째 학생이에요. 이름 있는 모델은 바로 아래에서 설명해요.

아래에서 칸을 눌러 경로를 확인해 보세요. 화면에 보이면 저절로 하나씩 보여 줘요.

&#91;embedded content: 경로 찾기 연습장 · 데이터의 각 칸\]

### 모델 만들고 연결하기

6부의 비유로 말하면, 모델은 진열대 뒤 선반이고 화면은 진열대예요. 바인딩은 "진열대의 이 자리에는 선반의 저 물건을 놓아 줘"라고 적어 둔 라벨이에요. (서버의 데이터베이스는 이보다 멀리 있는 창고예요. SAP 백엔드 총정리에서 다뤄요.)

1. **만들기:** `new JSONModel(oData)` 또는 `new JSONModel()` 다음 `setData(oData)`
2. **연결하기:** `this.getView().setModel(oModel)`(`getView`는 6부 id와 byId) → 이 화면과 그 안의 모든 컨트롤이 이 모델을 볼 수 있어요. 모델은 부모에서 자식으로 전달돼요.
3. **파일에서 읽기:** `await oModel.loadData("경로/data.json")` (5부 async / await의 `await`를 잊지 마세요)

**`await`를 빼먹으면:** `loadData`는 파일을 읽는 데 시간이 걸려요(5부 기다리지 않으면 생기는 일).

```js
const oModel = new JSONModel();
oModel.loadData("model/data.json");           // 요청만 보내고 바로 다음 줄로
console.log(oModel.getData());                // {}  ← 아직 도착 안 함!

await oModel.loadData("model/data.json");     // ✅ 도착할 때까지 기다렸다가 다음 줄로
console.log(oModel.getData());                // { ... }  이제 데이터가 있음
```

`await`는 `async`가 붙은 메서드(`async onInit() { ... }`) 안에서만 쓸 수 있어요. 데이터 파일(`data.json`)에 문법 오타가 있으면 모델이 비어서 화면이 텅 비어 보여요(1부 JSON).

### 기본 모델과 이름 있는 모델

한 화면에 모델을 여러 개 연결할 수 있어요. 이름 없이 연결한 것 하나가 기본 모델이고, 나머지는 이름을 붙여서 구분해요.

|  | 연결 | XML에서 쓰기 | 컨트롤러에서 꺼내기 |
| --- | --- | --- | --- |
| 기본 모델 | `setModel(oModel)` | `{/bookInfo/code}` | `getModel()` |
| 이름 있는 모델 | `setModel(oModel, "empModel")` | `{empModel>/empName}` | `getModel("empModel")` |

이름 있는 모델은 **모델 이름이 맨 앞, 그다음 `>`, 그다음 경로**예요. \[0203\]의 `{/empModel>/empName}`처럼 슬래시를 이름 앞에 붙이면 동작하지 않아요. 화면 제목의 `{i18n>title}`도 `i18n`이라는 이름 있는 모델이에요.

### 모델의 종류

| 모델 | 쓰는 곳 |
| --- | --- |
| `JSONModel` | 직접 만든 데이터, 화면 상태값 (지금 수업에서 쓰는 것) |
| `ResourceModel` | 다국어 문구 (`i18n.properties`). 화면 제목 같은 문구를 `{i18n>title}`처럼 가져올 때 써요 |
| `ODataModel` | SAP 백엔드 서버의 실제 데이터 (나중에 배울 내용). OData는 Open Data Protocol, 서버와 데이터를 주고받는 약속이에요 |

### 값 읽고 바꾸기: getProperty / setProperty

모델에서 값을 꺼내거나 바꾸는 방법이에요. 선반(모델)에 "이 자리의 물건을 알려 줘"(`getProperty`)와 "이 자리의 물건을 바꿔 줘"(`setProperty`)를 말하는 거예요. 자리는 Binding Path로 적어요.

```js
const oModel = this.getView().getModel();
oModel.getProperty("/bookInfo/name");             // "SAPUI5"
oModel.setProperty("/bookInfo/name", "ABAP");     // → 화면도 자동으로 "ABAP"
```

- `setProperty`로 바꾸면 연결된 화면이 자동으로 바뀌어요.
- `getData()`로 꺼낸 객체를 직접 고치면 모델은 바뀐 걸 모르기 때문에 화면이 그대로예요. 값을 바꿀 때는 `setProperty`를 쓰세요.

### TwoWay Binding: 입력하면 모델도 바뀌어요

JSONModel은 기본이 TwoWay예요. `<Input value="{/bookInfo/name}" />`에 사용자가 글자를 치면 모델의 `/bookInfo/name`도 같이 바뀌어요. 그래서 검색 조건 같은 입력값은 `byId(...).getValue()` 대신 모델에서 `getProperty`로 꺼낼 수도 있어요. \[0205\]의 `selectedKey="{/selectedSCode}"`가 그 예예요.

## 9부. 데이터 바인딩 2 — 애그리게이션 바인딩 \[0205\~0206\]

애그리게이션 바인딩은 **배열 하나를 연결하면, 한 줄짜리 틀(템플릿)을 배열 길이만큼 복사해서 목록을 만드는 것**이에요. 콤보박스 항목, 테이블 행, 리스트가 전부 이 방식이에요.

### 템플릿과 상대경로

템플릿은 **목록의 한 줄을 어떻게 그릴지 적어 둔 틀**이에요. 붕어빵 틀 하나로 붕어빵 여러 개를 찍듯, 틀은 하나만 쓰고 데이터 개수만큼 복사돼요. 상대경로는 "각 줄 안에서의 위치"라서, 줄마다 자기 데이터를 찾아가요. 그래서 `{sName}`처럼 맨 앞에 `/`를 붙이지 않아요.

```js
const oModel = new JSONModel({
    skillList: [
        { sCode: "S1001", sName: "SAPUI5" },
        { sCode: "S2001", sName: "ABAP" }
    ]
});
this.getView().setModel(oModel);
```

```xml
<ComboBox items="{/skillList}">              <!-- ① 배열 연결 (절대경로, /로 시작) -->
    <items>
        <core:Item key="{sCode}" text="{sName}" />   <!-- ② 템플릿 (상대경로, / 없음) -->
    </items>
</ComboBox>
```

- ①의 `items="{/skillList}"`는 "이 배열의 항목 수만큼 만들어"예요.
- ②의 `core:Item`은 화면에 한 번만 쓰여 있지만 실제로는 항목 수만큼 복사돼요. 이걸 **템플릿**(Template)이라고 불러요. 찍어 내는 틀이라는 뜻이에요.
- 템플릿 안의 `{sCode}`는 `/`가 없는 **상대경로**(Relative Path)예요. 반대로 `/`로 시작하는 경로는 **절대경로**(Absolute Path)라고 불러요. 첫 번째 복사본에서는 `/skillList/0/sCode`, 두 번째에서는 `/skillList/1/sCode`로 풀려요.

| 복사본 | 기준 위치(컨텍스트) | `{sName}`이 가리키는 곳 | 화면 글자 |
| --- | --- | --- | --- |
| 1번째 Item | `/skillList/0` | `/skillList/0/sName` | SAPUI5 |
| 2번째 Item | `/skillList/1` | `/skillList/1/sName` | ABAP |

아래 연습장에서 항목을 늘리거나 줄여 보세요. 템플릿은 그대로인데 줄 수만 바뀌어요.

&#91;embedded content: 템플릿 복사 연습장 · 항목 수만큼 복사\]

이름 있는 모델이면 템플릿 안에도 모델 이름을 붙여야 해요: `items="{bookInfo>/bookList}"` → `key="{bookInfo>bCode}"` \[0206\]. 빠뜨리면 기본 모델에서 찾아서 빈칸이 나와요.

### 바인딩 컨텍스트: "나는 몇 번째 데이터입니다"

복사된 항목 하나하나는 자기가 데이터의 어디를 보고 있는지 알고 있어요. 이걸 **바인딩 컨텍스트**(Binding Context)라고 해요. 바인딩이 가리키는 "자리"라는 뜻이에요. 사용자가 무엇을 골랐는지 알아낼 때 써요.

```js
onSelect: function (oEvent) {
    const oItem = oEvent.getParameter("selectedItem");   // 고른 Item
    const oContext = oItem.getBindingContext();          // 그 Item의 위치 정보

    oContext.getPath();              // "/skillList/1"          어디인지 (경로 문자열)
    oContext.getObject();            // { sCode: "S2001", ... } 그 자리의 데이터 통째로
    oContext.getProperty("sName");   // "ABAP"                 그 자리의 값 하나
}
```

- 이름 있는 모델이면 `getBindingContext("bookInfo")`처럼 모델 이름을 넣어야 해요. 안 넣으면 `undefined`예요.
- **경로(`getPath`)가 가장 중요해요.** 다음 10부에서 이 경로를 상세 화면에 넘겨주거든요.

- 경로는 데이터 자체가 아니라 **데이터가 있는 위치(주소)**예요. 편지 내용이 아니라 편지가 든 우편함 번호라고 생각하세요. `getObject()`는 그 위치의 내용을 꺼내고, `getPath()`는 위치만 알려 줘요.

### 콤보박스에서 값 꺼내기

| 알고 싶은 것 | 방법 |
| --- | --- |
| 선택된 항목의 키 (항상 문자열) | `getSelectedKey()` |
| 선택된 항목 자체 (없으면 `null`) | `getSelectedItem()` |
| 입력칸에 보이는 글자 (직접 친 글자 포함) | `getValue()` |
| 코드로 선택 바꾸기 | `setSelectedKey("S2001")` |

`getSelectedKey()`는 항상 문자열이에요. 숫자 데이터와 비교하려면 `Number(sKey)`로 바꿔야 해요(1부 형 변환).

`ComboBox`는 글자를 직접 칠 수 있고 아무것도 안 고를 수도 있어요. `Select`는 목록에서만 고르고 보통 첫 항목이 자동으로 선택돼 있어요.

### 복사해서 보여주기 \[0206\]: 동작은 하지만 데이터가 두 곳에 생겨요

```js
const oContext = oCombo.getSelectedItem().getBindingContext("bookInfo");
this.getView().getModel().setData(oContext.getObject());   // 고른 책 데이터를 기본 모델에 복사
```

동작은 하지만 데이터가 두 곳에 생겨요. 한쪽을 고쳐도 다른 쪽에는 반영되지 않아요. 복사 없이 "그 경로를 보여줘"라고 하는 더 좋은 방법이 다음 10부의 `bindElement`예요.

같은 프로젝트의 `oComboBox2.setSelectedItem(oSltItem)`은 **다른 콤보박스의 Item**을 넘겨서 동작하지 않아요. Item은 자기 콤보박스에만 속해요. 이럴 때는 키로 고르세요: `oComboBox2.setSelectedKey(oContext.getProperty("bGrade"))`.

## 10부. 데이터 바인딩 3 — 엘리먼트 바인딩 \[0210\~0211\]

`bindElement`는 **컨트롤 하나에 "너는 이 데이터 한 건을 기준으로 봐"라고 기준 위치를 정해 주는 것**이에요. 그러면 그 안의 자식들은 상대경로만 써도 그 데이터를 읽어요. 목록에서 고른 한 건을 상세 화면에 보여줄 때 쓰는 핵심 기술이에요.

9부의 애그리게이션 바인딩은 배열 하나로 같은 모양의 줄 여러 개를 만들었어요. 엘리먼트 바인딩은 반대로 **한 건**을 기준으로 정해 두고, 그 안의 컨트롤들이 그 한 건의 값을 보게 해요.

### 이름의 뜻: Element = UI5 컨트롤

여기서 Element는 웹 페이지(HTML)의 `<div>`가 아니라 Panel, Form, Dialog 같은 **UI5 컨트롤**이에요. 모든 UI5 컨트롤은 `sap.ui.core.Element`를 바탕으로 만들어져서 이런 이름이 붙었어요. "컨트롤 하나를 데이터 한 건에 묶는다"라고 읽으면 돼요.

### 기본 모양 \[0210\]

```js
// 모델: { empInfo: { lastName: "김", firstName: "서연" }, stdInfo: { lastName: "홍", firstName: "길동" } }
this.byId("panelId").bindElement("/stdInfo");
```

```xml
<Panel id="panelId">                     <!-- 기준: /stdInfo -->
    <Input value="{lastName}" />         <!-- → /stdInfo/lastName = 홍 -->
    <Input value="{firstName}" />        <!-- → /stdInfo/firstName = 길동 -->
</Panel>
```

- 버튼에 따라 `bindElement("/empInfo")` ↔ `bindElement("/stdInfo")`만 바꾸면 패널 안 내용이 통째로 바뀌어요. 안쪽 XML은 손댈 필요가 없어요.
- XML에서 처음부터 정해 둘 수도 있어요: `<Panel binding="{/empInfo}">`

### 목록 → 상세: 경로를 넘겨주기

9부에서 고른 항목의 경로를 구했어요. 그 경로를 상세 화면의 `bindElement`에 넣으면 끝이에요. 복사하지 않고 같은 데이터를 가리키기 때문에 어느 쪽을 고쳐도 양쪽에 반영돼요.

```js
onSelect: function (oEvent) {
    const oItem = oEvent.getParameter("listItem");   // ① 테이블에서 고른 줄
    const sPath = oItem.getBindingContext().getPath(); // ② "/esStdList/63"
    this.byId("pnlStdDetail").bindElement(sPath);     // ③ 상세 패널의 기준을 그 경로로
}
```

테이블을 필터나 정렬해도 `getPath()`는 원본 배열 기준의 번호를 돌려줘요. 화면에서 몇 번째 줄이든 상관없이 정확한 학생을 가리켜요.

### 팝업에도 똑같이

팝업(Dialog)도 컨트롤이라서 `bindElement`를 그대로 쓸 수 있어요. 팝업을 열기 전에 "이 데이터 한 건을 보여 줘"라고 기준만 정해 주면 돼요.

```js
this._oDialog.bindElement("/classList/2");   // 팝업 안의 {Cteacher}는 → /classList/2/Cteacher
this._oDialog.open();
```

### 키로 경로 만들기

학생 데이터에는 반 코드(`Cid: "CL303"`)만 있고, 반 정보는 다른 배열(`classList`)에 있어요. 이럴 때는 몇 번째인지 찾아서 경로를 만들어요.

```js
const aClassList = this.getView().getModel().getProperty("/classList");
const iIdx = aClassList.findIndex(c => c.Cid === sCid);   // for문으로 찾아도 돼요
if (iIdx !== -1) {
    this.byId("pnlClsDetail").bindElement("/classList/" + iIdx);
}
```

찾은 번호(`iIdx`)로 경로를 만드는 게 포인트예요: `"/classList/" + iIdx` → `"/classList/2"`. `findIndex`는 못 찾으면 `-1`을 돌려주니(3부 배열 메서드) 꼭 확인하고 쓰세요.

<details class="more">
<summary>더 알아보기 — 끝자리 숫자로 번호를 계산하는 방법</summary>

반 코드의 끝자리 숫자로 번호를 계산하는 방법(`CL303` → 2)도 있지만, 데이터 순서가 바뀌거나 반이 10개를 넘으면 틀려요. 데이터 순서에 기대는 코드는 연습용으로만 쓰세요.

</details>

### 엘리먼트 안의 목록: 중첩 배열 \[0211\]

기준 위치 안에 또 배열이 있으면, 그 배열을 상대경로로 애그리게이션 바인딩할 수 있어요.

```js
// 데이터: stdList[1] = { stdName: "이도윤", skills: [ {sName:"SAPUI5"}, {sName:"ABAP"} ] }
this.byId("cmbSkillList").bindElement(sPath);   // sPath = "/stdList/1"
```

```xml
<Select id="cmbSkillList" items="{skills}">   <!-- → /stdList/1/skills -->
    <core:Item key="{sCode}" text="{sName}" />
</Select>
```

학생을 바꾸면 스킬 목록도 그 학생의 것으로 바뀌어요. 이렇게 "위를 고르면 아래가 따라 바뀌는" 화면을 마스터-디테일(Master-Detail)이라고 불러요.

### 이름 있는 모델과 bindElement \[0213\]

```js
oTable.bindElement({ path: "/skills", model: "skillInfo" });
```

```xml
<Table id="tableId" items="{skillInfo>}">   <!-- 경로가 비어 있음 = 기준 위치 그 자체(/skills 배열) -->
```

문자열 대신 `{ path, model }` 객체를 넘기면 어느 모델 기준인지 정할 수 있어요. 기준을 지우고 싶을 때는 `unbindElement()`를 써요.

이름 있는 모델이면 지울 때도 `unbindElement("skillInfo")`처럼 모델 이름을 넣어요.

세 가지 모두 "데이터 어디를 가리키느냐"의 차이예요. 값 하나는 프로퍼티 하나에, 배열은 목록에, 객체 한 건은 상세 화면에 연결해요.

## 11부. 테이블, 필터, 정렬, 포매터 \[0212\~0213\]

**테이블**(Table)은 엑셀처럼 열과 줄로 데이터를 보여 주는 화면 컨트롤이에요. 애그리게이션 바인딩(9부)의 목록을 열이 있는 모양으로 바꾼 버전이에요. 한 줄 템플릿이 데이터 건수만큼 복사되고, 필터와 정렬은 데이터가 아니라 **바인딩에** 걸어요.

### 테이블 구조

테이블은 **열 제목 한 번 + 한 줄짜리 틀**로 이뤄져요. 9부의 목록과 같은 원리라서, 틀 하나가 데이터 건수만큼 복사돼요. 코드의 번호(①②③)가 각각 무슨 일을 하는지 따라가며 읽어 보세요.

```xml
<Table id="tabEdu" items="{/edus}" mode="SingleSelectMaster" selectionChange=".onSelect">
    <columns>                                   <!-- ① 열 제목 (한 번만) -->
        <Column><header><Text text="교육코드" /></header></Column>
        <Column><header><Text text="교육명" /></header></Column>
    </columns>
    <items>
        <ColumnListItem>                        <!-- ② 한 줄 템플릿 (데이터 건수만큼 복사) -->
            <cells>
                <Text text="{eCode}" />         <!-- columns와 같은 순서로 -->
                <Text text="{eName}" />
            </cells>
        </ColumnListItem>
    </items>
</Table>
```

- `columns`의 개수와 `cells`의 개수, 순서가 맞아야 해요.
- `mode`: `SingleSelectMaster`(행을 누르면 선택), `SingleSelect`(라디오 버튼), `MultiSelect`(체크박스).
- 행을 고르면 `selectionChange` 이벤트의 `listItem`으로 고른 줄이 와요. 그 다음은 10부 목록 → 상세 그대로예요.

### 필터: 조건에 맞는 줄만 보여주기

테이블과 모델 사이에는 **바인딩**이라는 연결 객체가 있어요. `items="{/edus}"`라고 적으면 UI5가 그 연결을 하나 만들어요. 필터와 정렬은 모델의 데이터가 아니라 이 연결에 걸어요. 그래서 원본 데이터는 그대로이고, 테이블에 보이는 줄만 달라져요.

&#91;embedded content: 필터가 걸리는 곳 · 모델, 바인딩, 표\]

```js
onSearch: function () {
    const oBinding = this.byId("tabEdu").getBinding("items");   // ① 테이블의 "items 연결"을 꺼내고
    const aFilter = [
        new Filter("eduGroup", FilterOperator.EQ, "CODE")      // ② 조건 만들기 (필드, 비교, 값)
    ];
    oBinding.filter(aFilter);                                   // ③ 걸기
}
```

| FilterOperator | 뜻 |
| --- | --- |
| `EQ` / `NE` | 같다 / 다르다 (Equal / Not Equal) |
| `Contains` | 포함한다 (검색창에 자주 씀) |
| `StartsWith` | \~로 시작한다 |
| `GT` / `LT` / `GE` / `LE` | 크다 / 작다 / 이상 / 이하 (Greater Than / Less Than / Greater or Equal / Less or Equal) |
| `BT` | 사이 (값 두 개, BeTween) |

- **필터 해제:** `oBinding.filter([])`
- **값의 자료형을 데이터와 맞추세요.** 데이터가 숫자 `2`면 필터 값도 `Number("2")`여야 해요(1부 형 변환).
- **여러 조건을 배열로 넣으면:** 서로 다른 필드끼리는 AND(둘 다 만족), 같은 필드끼리는 OR(하나만 만족)로 묶여요. 예를 들어 `[반=CL303, 조=2]`는 "3반이면서 2조"예요.
- 선택한 조건만 넣고 싶으면 배열을 만든 뒤 `if`로 `push`하세요.

```js
const aFilter = [new Filter("Cid", FilterOperator.EQ, sClsCode)];
if (sGrpCode) {
    aFilter.push(new Filter("Sgroup", FilterOperator.EQ, Number(sGrpCode)));
}
oBinding.filter(aFilter);
```

### 정렬

정렬은 **보이는 줄의 순서를 바꾸는 것**이에요. 필터처럼 모델 데이터는 그대로 두고, 테이블의 바인딩에 "이 기준으로 줄 세워 줘"라고 알려 줘요. 도서관에서 책 순서를 바꿔 진열해도 책 자체는 그대로인 것과 같아요.

```js
oBinding.sort(new Sorter("Sname"));          // 이름 오름차순
oBinding.sort(new Sorter("Sname", true));    // 두 번째 값 true = 내림차순
oBinding.filter(aFilter).sort(oSorter);      // 필터와 정렬을 이어서 (메서드 체이닝)
```

**정렬 기준을 여러 개 쓸 수도 있어요.** `sort`에는 `Sorter` 하나 대신 `Sorter`를 담은 **배열**을 넘길 수 있어요. 배열에 적은 순서대로 적용돼요. 첫 번째 기준으로 먼저 줄을 세우고, 첫 번째 기준 값이 같은 줄끼리만 두 번째 기준으로 다시 세워요. 학교에서 "학년 순으로, 같은 학년이면 이름 순으로" 줄 세우는 것과 같아요.

```js
oBinding.sort([
    new Sorter("Sgrade"),          // 1순위: 학년 오름차순
    new Sorter("Sname", true)      // 2순위: 같은 학년끼리 이름 내림차순
]);
```

기준은 두 개 이상 넘길 수 있어요. 순서를 바꾸면 결과가 달라지니, 가장 중요한 기준을 맨 앞에 쓰세요. 배열을 넘기는 것은 "정렬을 한 번에 여러 기준으로 하는 것"이에요. `sort`를 따로 두 번 부르면 마지막 한 번의 정렬만 남아요.

`Filter`, `FilterOperator`, `Sorter`는 `sap.ui.define` 목록에 추가해야 쓸 수 있어요(6부): `"sap/ui/model/Filter"`, `"sap/ui/model/FilterOperator"`, `"sap/ui/model/Sorter"`.

### 포매터: 값을 보기 좋게 바꿔 보여주기 \[0213\]

데이터에는 코드(`H`)가 있고 화면에는 글자(`상`)를 보여주고 싶을 때, 컨트롤러의 함수를 거치게 할 수 있어요.

```xml
<Input value="{skillInfo>sGrade}"
       description="{ path: 'skillInfo>sGrade', formatter: '.formatGrade' }" />
```

```js
formatGrade: function (sGrade) {
    const mGrade = { H: "상", M: "중", L: "하" };   // 객체 키로 바로 찾기 (1부)
    return mGrade[sGrade] || sGrade;                // 없는 코드면 원래 값 그대로
}
```

`mGrade[sGrade] || sGrade`는 "앞의 값이 비어 있으면(2부 거짓으로 보는 값) 뒤의 값을 돌려줘요"라는 뜻이에요. 목록에 없는 코드는 `undefined`가 되니까 원래 코드를 그대로 보여줘요.

바인딩 값이 바뀔 때마다 UI5가 이 함수를 다시 불러요(3부 콜백 함수). 포매터는 **화면에 보이는 글자만** 바꾸고 모델 데이터는 그대로예요.

### 많은 데이터 나눠 보여주기

## 12부. Expression Binding과 데이터 타입 \[0220, Lev05\]

포매터 함수를 만들지 않고 XML 안에서 바로 간단한 계산을 하는 게 **Expression Binding**이고, 금액·날짜를 형식에 맞게 보여주는 게 **데이터 타입**이에요. 이 부는 Lev05에서 쓴 내용으로 정리했어요.

### Expression Binding `{= ... }`

- `{=`로 시작하고, 모델 값은 `${경로}`로 꺼내요.
- 안에는 `===`, `!`, `&&`, `||`, 삼항 연산자(`조건 ? 참일 때 값 : 거짓일 때 값`, 2부 "더 알아보기") 같은 자바스크립트 식을 쓸 수 있어요. if문은 못 써요.
- XML에서 프로퍼티 값을 쌍따옴표로 감싸서 안의 문자열은 홑따옴표 `'Y'`를 써요. 1부 문자열의 "안에 따옴표가 있으면 다른 종류로 감싸기"와 같은 원리예요.

| 하고 싶은 것 | 표현식 |
| --- | --- |
| Y면 체크 | `selected="{= ${Smajor} === 'Y' }"` |
| 코드를 글자로 | `description="{= ${Tgender} === '1' ? '남성' : '여성' }"` |
| 여러 코드를 글자로 | `{= ${Sleader} === 'L' ? '조장' : ${Sleader} === 'S' ? '부조장' : '' }` |
| 값이 있을 때만 보이기 | `visible="{= !!${Cteacher} }"` |
| 이름 있는 모델 값 | `enabled="{= ${viewModel>/editMode} }"` |

`${Smajor}`는 모양이 자바스크립트의 템플릿 문자열(`` `${a}` ``)과 비슷하지만 뜻이 달라요. 여기서는 "이 경로의 모델 값"이라는 뜻이에요.

조건이 세 개를 넘거나 계산이 복잡하면 11부의 포매터가 읽기 쉬워요.

### 데이터 타입: 금액과 날짜

숫자 `370000`을 `370,000 KRW`{? KRW는 한국 원화의 통화 코드예요 ?}처럼 보여주려면 타입을 지정해요. 타입은 사용자 언어에 맞는 형식으로 바꿔 주고, 입력칸이면 잘못된 값도 걸러 줘요.

```xml
<!-- 금액 + 통화: 값 두 개를 parts로 묶어서 넘김 -->
<Text text="{
    parts: [ { path: 'Sprice' }, { path: 'Swaers' } ],
    type: 'sap.ui.model.type.Currency'
}" />
```

- `parts`는 값 여러 개를 하나로 묶는 바인딩이에요. 금액은 통화를 알아야 소수점 자리를 정할 수 있어서{? KRW(원)는 소수점이 없고 USD(미국 달러)는 두 자리예요 ?} 항상 통화 필드와 같이 넘겨요.
- 날짜 문자열은 `sap.ui.model.type.Date`로 형식을 바꿀 수 있어요. 데이터가 어떤 모양인지는 `source`로 알려줘요.

```xml
<Text text="{
    path: 'Sbegda',
    type: 'sap.ui.model.type.Date',
    formatOptions: { source: { pattern: 'yyyy.MM.dd' }, style: 'medium' }
}" />
```

`pattern: 'yyyy.MM.dd'`는 "연(year).월(Month).일(day)" 모양이라는 뜻이에요. 월은 대문자 `MM`, 분(minute)은 소문자 `mm`이라서 대소문자가 달라요.

| 타입 | 쓰는 곳 |
| --- | --- |
| `sap.ui.model.type.Currency` | 금액 + 통화 |
| `sap.ui.model.type.Date` | 날짜 |
| `sap.ui.model.type.Integer` / `Float` | 정수 / 소수 (입력칸에 글자를 치면 에러 표시) |
| `sap.ui.model.type.String` | 글자 수 제한 같은 조건 검사 |

<details class="more">
<summary>더 알아보기 — 날짜 타입의 설정을 한 줄씩 읽기</summary>

처음에는 건너뛰어도 돼요. 위 날짜 코드의 `formatOptions`가 헷갈릴 때 오세요.

| 설정 | 뜻 |
| --- | --- |
| `type` | 어떤 형식 규칙을 쓸지 정해요 |
| `parts` | 값 여러 개를 하나로 묶어 타입에 넘겨요 (금액과 통화) |
| `formatOptions.source.pattern` | "데이터에 들어 있는 글자가 이런 모양이에요"라고 알려 줘요. UI5는 이 모양대로 읽어요 |
| `formatOptions.style` | 화면에 보여 줄 모양이에요 (`short`, `medium`, `long`) |

</details>

## 13부. 종합 — 검색, 목록, 상세, 팝업이 한 화면에서 이어지는 흐름

실무에서 가장 흔한 화면은 **조건을 고르고 → 목록을 걸러 보고 → 한 건을 골라 상세를 보고 → 더 자세한 건 팝업으로** 보는 구조예요. Lev05가 바로 이 패턴이에요. 정답 코드가 아니라 단계별로 어떤 개념이 들어가는지 지도처럼 정리했어요.

&#91;embedded content: 검색-목록-상세-팝업 흐름 · 5단계\]

목록에서 고른 한 줄의 경로(`getPath()`)가 상세 → 반 → 팝업으로 이어져요. 데이터를 복사하지 않고 경로만 넘기는 게 핵심이에요.

| 단계 | 메서드 | 하는 일 | 핵심 코드 한 줄 | 배운 곳 |
| --- | --- | --- | --- | --- |
| 1. 준비 | `onInit` | 데이터 파일 읽기, 콤보용 목록 만들기, 초깃값 정하기 | `await oModel.loadData(...)` | 5부, 8부 |
| 2. 검색 | `onSearch` | 선택값 읽기, 필수값 검사, 필터와 정렬 | `oBinding.filter(aFilter).sort(oSorter)` | 2부, 3부, 11부 |
| 3. 상세 | `onSelect` | 고른 줄의 경로로 상세 패널 연결 | `oPanel.bindElement(oCtx.getPath())` | 9부, 10부 |
| 4. 관련 정보 | `onSelect` | 학생의 반 코드로 반 목록에서 위치 찾기 | `"/classList/" + iIdx` | 3부, 10부 |
| 5. 팝업 | `onOpen...` | 한 번만 불러오기, 같은 경로로 연결, 열기 | `this._oDialog.bindElement(sPath)` | 4부, 7부 |
| 6. 표시 | XML | 코드를 글자로, 금액 형식 | `{= ... }`, `type: 'sap.ui.model.type.Currency'` | 12부 |

### 작은 앱 한 개 완성하기: 처음부터 끝까지

지금까지 조각으로 본 코드를 모아서 돌아가는 앱 하나를 만들어 봐요. "반을 골라 검색하면 그 반 학생만 테이블에 보이고, 한 줄을 누르면 아래에 상세가 나오는" 앱이에요. 파일은 세 개예요.

**1. 데이터 파일: `model/data.json`**

```json
{
    "esStdList": [
        { "Sid": "25010001", "Sname": "민수", "Cid": "CL301" },
        { "Sid": "25010002", "Sname": "지아", "Cid": "CL302" },
        { "Sid": "25010003", "Sname": "도윤", "Cid": "CL301" }
    ]
}
```

**2. 화면: `view/View1.view.xml`**

```xml
<mvc:View controllerName="ncode.zcXXw0205.controller.View1"
    xmlns:mvc="sap.ui.core.mvc" xmlns:core="sap.ui.core" xmlns="sap.m">
    <Page title="학생 찾기">
        <content>
            <HBox alignItems="Center" class="sapUiSmallMargin">
                <ComboBox id="cmbClass" class="sapUiSmallMarginEnd">
                    <items>
                        <core:Item key="CL301" text="301반" />
                        <core:Item key="CL302" text="302반" />
                    </items>
                </ComboBox>
                <Button text="검색" press=".onSearch" />
            </HBox>
            <Table id="tabStd" items="{/esStdList}" mode="SingleSelectMaster" selectionChange=".onSelect">
                <columns>
                    <Column><header><Text text="학생번호" /></header></Column>
                    <Column><header><Text text="이름" /></header></Column>
                </columns>
                <items>
                    <ColumnListItem>
                        <cells>
                            <Text text="{Sid}" />
                            <Text text="{Sname}" />
                        </cells>
                    </ColumnListItem>
                </items>
            </Table>
            <Panel id="pnlDetail" headerText="상세" class="sapUiSmallMargin">
                <Text text="{Sname}" />
                <Text text="{Sid}" />
            </Panel>
        </content>
    </Page>
</mvc:View>
```

**3. 동작: `controller/View1.controller.js`**

```js
sap.ui.define([
    "sap/ui/core/mvc/Controller",
    "sap/ui/model/json/JSONModel",
    "sap/ui/model/Filter",
    "sap/ui/model/FilterOperator"
], function (Controller, JSONModel, Filter, FilterOperator) {
    "use strict";

    return Controller.extend("ncode.zcXXw0205.controller.View1", {
        onInit: async function () {
            const oModel = new JSONModel();
            await oModel.loadData("model/data.json");      // 파일이 도착할 때까지 기다려요
            this.getView().setModel(oModel);               // 화면에 모델 연결
        },

        onSearch: function () {
            const sClass = this.byId("cmbClass").getSelectedKey();
            const oBinding = this.byId("tabStd").getBinding("items");
            const aFilter = sClass ? [new Filter("Cid", FilterOperator.EQ, sClass)] : [];
            oBinding.filter(aFilter);                      // 반을 안 골랐으면 전체 보기
        },

        onSelect: function (oEvent) {
            const oItem = oEvent.getParameter("listItem");           // 고른 줄
            const sPath = oItem.getBindingContext().getPath();       // 그 줄의 위치
            this.byId("pnlDetail").bindElement(sPath);               // 상세 패널의 기준으로 지정
        }
    });
});
```

앱이 움직이는 순서는 이래요. 화면이 만들어지면 `onInit`이 한 번 실행돼서 데이터 파일을 읽고 모델을 연결해요. 사용자가 검색 버튼을 누르면 `onSearch`가, 테이블의 한 줄을 누르면 `onSelect`가 실행돼요. 각 코드를 어디서 배웠는지 표로 찾아보세요.

| 코드 | 하는 일 | 배운 곳 |
| --- | --- | --- |
| `sap.ui.define([...], function (...) {...})` | 필요한 모듈을 불러오기 | 6부 컨트롤러 파일 읽기 |
| `onInit`, `await oModel.loadData(...)` | 시작할 때 한 번, 데이터 파일 읽기 | 6부 컨트롤러 파일 읽기, 5부 async / await |
| `this.getView().setModel(oModel)` | 화면에 모델 연결 | 8부 모델 만들고 연결하기 |
| `items="{/esStdList}"`와 `{Sname}` | 배열만큼 줄 복사 | 9부 템플릿과 상대경로 |
| `getBinding("items")`, `filter(...)` | 테이블에 보이는 줄 걸러내기 | 11부 필터 |
| `getBindingContext().getPath()` | 고른 줄의 위치 구하기 | 9부 바인딩 컨텍스트 |
| `bindElement(sPath)` | 상세 패널을 그 한 건에 연결 | 10부 기본 모양 |

### 단계별로 기억할 점

1. **초깃값을 정한 뒤에는 `this.onSearch()`를 부르세요.** onInit에 필터 코드를 또 쓰면 같은 논리가 두 곳에 생겨요. 둘이 어긋나면 처음 화면과 검색 결과가 달라져요.
2. **상세는 복사하지 말고 경로로 연결하세요.** `setData(getObject())`보다 `bindElement(getPath())`가 짧고 안전해요.
3. **팝업은 "화면에 보이는 것"을 기준으로 연결하세요.** 콤보박스 선택값을 기준으로 하면, 콤보만 바꾸고 검색을 안 누른 상태에서 패널과 팝업의 내용이 달라져요. 반 패널의 `getBindingContext().getPath()`를 쓰면 항상 일치해요.
4. **아무것도 선택되지 않은 경우를 막으세요.** `getSelectedItem()`이나 `getBindingContext()`가 없을 때는 `if (!oCtx) return;`로 일찍 끝내세요.

### 화면 배치 팁

작업 순서대로 왼쪽에서 오른쪽으로 \[검색 조건 | 목록 | 상세\]를 놓으면 시선이 한 방향으로만 움직여요. 상세를 목록 아래에 두면 목록이 길어질 때마다 상세가 아래로 밀려요. SAP Fiori의 목록-상세(Flexible Column Layout) 화면도 같은 생각으로 만들어졌어요.

## 14부. 흔한 에러 모음

수업 프로젝트와 과제에서 실제로 나온 에러들이에요. 증상으로 찾아보세요.

| 증상 | 원인 | 해결 | 예 |
| --- | --- | --- | --- |
| 앱이 아예 안 열림, 콘솔에 SyntaxError | `async` 없는 함수에서 `await` 사용, 메서드 사이 쉼표 누락 | 함수 앞에 `async`, 메서드 끝마다 `,` | 0202 |
| 팝업이 두 번째 클릭부터 에러 (duplicate id) | `let oDialog`가 함수 안에 있어서 매번 새로 만듦 | `this._oDialog`에 저장 | 0201 |
| 팝업 첫 클릭부터 duplicate id | View XML에 같은 id의 Dialog가 남아 있음 | View의 Dialog 삭제 | Lev05 |
| Fragment를 못 불러옴 (failed to load, 404) | Fragment 이름의 앱 id가 틀림 (다른 프로젝트에서 복사) | `manifest.json`의 앱 id + `.view.파일이름` | Lev05 |
| `Cannot read properties of undefined` | `byId("...")`인데 XML에 그 id가 없음 | XML에 `id` 추가 | 0205, 0210 |
| `oPage is not defined` | 선언하지 않은 변수, 오타 | 변수 이름 확인 | 0210 |
| 바인딩한 컨트롤이 비어 있음 | 이름 있는 모델 문법 오류 `{/empModel>/...}` | `{empModel>/...}` | 0203 |
| 목록은 생기는데 글자가 빈칸 | 템플릿 안에서 모델 이름을 빠뜨림 | `{bookInfo>bCode}`처럼 이름 붙이기 | 0206 |
| `getBindingContext()`가 `undefined` | 이름 있는 모델인데 이름을 안 넣음 | `getBindingContext("bookInfo")` | 0206 |
| 데이터 파일을 읽었는데 화면이 빈칸 | JSON 파일 내용이 화면이 기대하는 구조가 아님, JSON 문법 오류 | 콘솔에 `oModel.getData()`를 찍어 구조 확인 | 0210 |
| 필터 결과가 0건 | 자료형 불일치 (`"2"` vs `2`) | `Number(sKey)` | Lev05 |
| 데이터를 바꿨는데 화면이 그대로 | `getData()`로 꺼낸 객체를 직접 수정 | `setProperty` 또는 마지막에 `refresh(true)` | - |
| `setData` 후에도 화면이 그대로 | 화면이 보는 모델과 다른 모델에 넣음, `await` 없는 `loadData`가 나중에 덮어써요 | `getModel("이름")`으로 같은 모델인지 확인, `await` | - |
| 다른 콤보박스 선택이 안 바뀜 | 다른 콤보박스의 Item으로 `setSelectedItem` | `setSelectedKey(키)` | 0206 |
| 배열 번호가 `"01"`이 됨 | 배열에 `for...in` 사용 | `for` 또는 `for...of` | Lev05 |
| 안쪽 함수에서 `this`가 컨트롤러가 아님 | 메서드 안에 `function`으로 함수를 또 만듦 | 화살표 함수 | 0201 |
| 페이지 이동 두 번째부터 에러 | `bindItems`에 `templateShareable: true` 누락 | 옵션 추가 | - |
| 스크롤해도 더 안 불러옴 | 처음 보여주는 줄이 영역보다 짧아 스크롤이 없음 | `growingThreshold`를 늘리거나 높이를 줄이기 | - |

### 막혔을 때 순서

1. 콘솔(F12)의 **맨 위 빨간 에러**부터 읽기. 오른쪽 줄 번호를 눌러 해당 줄로 이동해요.
2. 문제가 나는 줄 바로 앞에서 값을 `console.log`로 찍기. `undefined`가 나오는 첫 단계를 찾아요.
3. 화면이 비어 있으면 모델 데이터 확인: `console.log(this.getView().getModel().getData())`
4. Binding Path를 자바스크립트 경로로 바꿔 보기 (8부 표): `{/esStdList/1/Sname}` → `oData.esStdList[1].Sname`이 실제로 있나요?
5. 그래도 모르겠으면 Chrome Extension **UI5 Inspector**로 컨트롤을 눌러 보세요. 어떤 모델의 어느 경로에 바인딩돼 있는지 보여줘요.

## 15부. 개발 도구 꿀팁 — BAS와 VS Code를 처음 쓰는 사람을 위해

이 부는 코드가 아니라 코드를 쓰는 **도구**에 익숙해지는 부분이에요. 컴퓨터를 잘 모르거나 BAS가 처음이어도 따라올 수 있게 썼어요. 다른 부와 달리 순서대로 읽지 않아도 돼요. 지금 막힌 곳만 골라 읽으세요.

BAS(SAP Business Application Studio)는 수업에서 쓰는 개발 도구예요. 브라우저 안에서 열리는 코드 편집기라서, 컴퓨터에 따로 설치하지 않아도 돼요. 겉모습과 단축키는 마이크로소프트의 **VS Code**(Visual Studio Code)와 거의 같아요. BAS가 VS Code와 같은 뿌리(Code-OSS)로 만들어졌기 때문이에요. 그래서 이 부의 단축키는 VS Code에서도 그대로 써요.

단축키는 윈도우 기준이에요. 맥을 쓴다면 `Ctrl` 대신 `Cmd`(⌘)를 누르세요. `Ctrl + C`처럼 `+`로 이은 것은 앞의 키를 누른 채로 뒤의 키를 누른다는 뜻이에요.

### BAS 처음 열기: Dev Space와 프로젝트 폴더

BAS를 열면 바로 코드 화면이 나오지 않고, **Dev Space** 목록이 먼저 나와요. Dev Space는 내 코드와 도구를 담아 둔 "내 전용 작업실"이에요. 이 작업실은 서버 위에 있어서, 내 컴퓨터를 바꿔도 같은 작업실을 다시 열 수 있어요.

작업실에는 상태가 있어요. 주로 보게 되는 건 세 가지예요.

| 상태 | 뜻 | 해야 할 일 |
| --- | --- | --- |
| RUNNING | 켜져 있어요 | 이름을 눌러 들어가요 |
| STOPPED | 꺼져 있어요 | 시작(Start) 버튼을 누르고 기다려요 |
| STARTING | 켜지는 중이에요 | 잠시 기다려요 |

한동안 쓰지 않으면 작업실이 자동으로 꺼질 수 있어요. 꺼지는 시간은 환경마다 달라서 정확히는 알려 드릴 수 없어요. 그래서 "어제까지 되던 화면이 안 열려요" 싶으면 먼저 상태가 STOPPED인지 보세요.

들어가면 **프로젝트 폴더**를 열어야 해요. 폴더는 파일을 담는 상자예요. 위쪽 메뉴에서 파일(File) → 폴더 열기(Open Folder)를 고르고, 수업 프로젝트(예: `zcXXw0205`)가 들어 있는 폴더를 고르세요. 보통 `projects`라는 폴더 안에 있어요.

**자주 하는 실수**

- 프로젝트 폴더 **바로 위** 폴더를 열면, 파일이 한 단계 더 깊이 들어가 있어서 헷갈려요. 왼쪽 파일 목록의 맨 위에 프로젝트 이름이 보이도록 여세요.
- 작업실이 꺼진 줄 모르고 "BAS가 고장 났다"고 생각해요. 먼저 상태를 보세요.

### 화면 읽기: 어디에 무엇이 있나요?

BAS 화면은 다섯 구역으로 나뉘어요. 처음에는 이 이름만 알아도 설명을 알아듣기 쉬워져요. 집으로 비유하면, 현관 옆 안내판이 맨 왼쪽 줄이고 방이 편집 영역이에요.

| 구역 | 어디 | 하는 일 |
| --- | --- | --- |
| Activity Bar | 맨 왼쪽 세로 아이콘 줄 | 파일, 검색, Extension 같은 **서랍**을 바꿔요 |
| Side Bar | Activity Bar 오른쪽 | 선택한 서랍의 내용 (예: 파일 목록) |
| 편집기(Editor) | 가운데 큰 영역 | 코드를 읽고 써요. 열린 파일은 위쪽에 탭으로 늘어서요 |
| 패널(Panel) | 아래쪽 | 터미널, 문제 목록, 출력이 들어 있어요 |
| Status Bar | 맨 아래 가는 줄 | 현재 줄 번호, 파일 종류, 에러 개수를 보여 줘요 |

Activity Bar에서 가장 자주 쓰는 서랍은 세 개예요. 맨 위의 **Explorer**는 파일 목록이고, 돋보기 모양 **검색**(Search)은 프로젝트 전체에서 글자를 찾고, 네모가 모인 모양의 **확장**(Extensions)은 기능을 추가해요. 아이콘이 낯설면 마우스를 올려 보세요. 이름이 떠요.

**탭의 점(●)을 조심하세요.** 파일 이름 옆에 `X` 대신 동그라미가 보이면 아직 저장하지 않았다는 뜻이에요. 저장하기 전에는 실행 결과가 바뀌지 않아요. 코드를 고쳤는데 화면이 그대로면 제일 먼저 이 점부터 보세요.

### 컴퓨터 기본 단축키: 복사, 붙여넣기, 되돌리기

**단축키**는 마우스 대신 키보드 조합으로 하는 지름길이에요. 외우려 하지 말고, 하루에 하나씩만 써 보세요. 아래 표는 BAS뿐 아니라 거의 모든 프로그램에서 똑같이 통해요.

| 단축키 | 하는 일 | 이럴 때 |
| --- | --- | --- |
| `Ctrl + C` | 복사 | 코드를 다른 곳에 가져가고 싶을 때 |
| `Ctrl + X` | 잘라내기 | 옮기고 싶을 때 (원래 자리에서는 사라져요) |
| `Ctrl + V` | 붙여넣기 | 복사한 걸 놓을 때 |
| `Ctrl + Z` | 되돌리기 | 실수했을 때. 여러 번 누르면 계속 거슬러 올라가요 |
| `Ctrl + Y` | 되돌리기 취소 | 너무 많이 되돌렸을 때 |
| `Ctrl + S` | 저장 | 고친 직후 습관처럼 눌러요 |
| `Ctrl + A` | 전체 선택 | 파일 전체를 복사하거나 지울 때 |
| `Ctrl + F` | 찾기 | 파일 안에서 단어를 찾을 때 |

컴퓨터 자체에도 알아 두면 편한 지름길이 있어요.

| 단축키 | 하는 일 |
| --- | --- |
| `Alt + Tab` | 열려 있는 창 사이를 오가요 (수업 자료와 BAS를 번갈아 볼 때) |
| `Win + Shift + S` | 화면 일부를 캡처해요. 에러 화면을 질문할 때 보내기 좋아요 |
| `Ctrl + 마우스 휠` 또는 `Ctrl + +` / `Ctrl + -` | 브라우저 화면을 키우고 줄여요 |

**자주 하는 실수**

- `Ctrl + Z`를 너무 많이 눌러서 내가 쓴 코드까지 사라져요. 그럴 때는 `Ctrl + Y`로 한 단계씩 돌아오세요.
- 복사한 줄 위에 또 복사하면 앞의 복사본은 사라져요. 복사는 항상 **마지막 한 번**만 기억해요.
- 에러를 질문할 때는 "안 돼요"보다 **화면 캡처**나 에러 메시지 글자를 같이 보내세요. 읽는 사람이 원인을 훨씬 빨리 찾아요.

### Command Palette와 파일 열기: 일단 Ctrl+Shift+P

**Command Palette**는 BAS가 할 수 있는 모든 일을 글자로 검색해서 실행하는 창이에요. 식당의 메뉴판과 비슷해요. 메뉴가 어디 숨어 있는지 몰라도, 하고 싶은 일의 이름만 치면 나와요.

| 단축키 | 하는 일 | 이럴 때 |
| --- | --- | --- |
| `Ctrl + Shift + P` | Command Palette 열기 | 기능이 어디 있는지 모를 때. 안 열리면 `F1`을 눌러 보세요 |
| `Ctrl + P` | 파일 이름으로 바로 열기 | 폴더를 하나씩 열지 않고 `View1.controller.js`처럼 이름 일부만 쳐서 열 때 |
| `Ctrl + Shift + F` | 프로젝트 전체에서 글자 찾기 | 어느 파일에 있는지 모르는 문장을 찾을 때 |
| `Ctrl + G` | 줄 번호로 이동 | 에러 메시지에 `42번째 줄`이 나왔을 때 |

`Ctrl + P`는 처음 써 보면 가장 놀라워요. 파일이 수십 개여도 이름 몇 글자면 열려요. 6부에서 배우는 `View1.view.xml`과 `View1.controller.js`를 오갈 때 특히 편해요. `view1`만 쳐도 후보가 떠요.

Command Palette에 치면 편한 말도 몇 개 있어요.

| 입력 | 하는 일 |
| --- | --- |
| `format document` | 들여쓰기를 자동으로 정리해요 |
| `color theme` | 화면 색(밝게, 어둡게)을 바꿔요 |
| `new terminal` | 터미널을 새로 열어요 |
| `reload window` | BAS 화면을 새로고침해요. 확장을 설치한 뒤나 화면이 이상할 때 써요 |

명령은 영어로 나오는 경우가 많아요. 한글로 검색되지 않아도 이상한 게 아니에요.

### 코드 편집 단축키: 손이 덜 가요

코드를 쓸 때 가장 많이 하는 일은 "줄 단위 작업"이에요. 줄 하나를 복사하고, 옮기고, 지우는 일이요. 이걸 마우스로 드래그하지 않고 키 하나로 끝내면 하루에 수백 번 손이 덜 가요.

| 단축키 | 하는 일 | 이럴 때 |
| --- | --- | --- |
| `Alt + ↑` / `Alt + ↓` | 현재 줄을 위/아래로 옮겨요 | 줄 순서를 바꿀 때 |
| `Shift + Alt + ↓` | 현재 줄을 아래에 복사해요 | 비슷한 줄을 하나 더 만들 때 (위로 복사는 `Shift + Alt + ↑`) |
| `Ctrl + Shift + K` | 현재 줄 지우기 | 선택하지 않아도 줄 전체가 사라져요 |
| `Ctrl + Enter` | 아래에 빈 줄을 만들고 이동 | 줄 끝으로 가지 않고도 새 줄을 쓸 때 |
| `Ctrl + /` | 현재 줄을 주석 처리/해제 | 코드를 지우지 않고 잠깐 꺼 둘 때 |
| `Ctrl + D` | 같은 단어를 하나씩 더 선택 | 같은 변수 이름을 한 번에 바꿀 때 |

`Ctrl + D`는 한 번 써 보면 신세계예요. 단어 위에 커서를 놓고 누르면 그 단어가 선택되고, 한 번 더 누르면 다음에 나오는 같은 단어가 함께 선택돼요. 이 상태로 글자를 치면 선택된 곳이 **모두 동시에** 바뀌어요. 변수 이름을 고칠 때 하나씩 찾아다니지 않아도 돼요. 단, 같은 글자가 다른 이름 안에 들어 있으면 그것도 선택되니, 바꾸기 전에 화면에 선택된 곳을 눈으로 확인하세요.

이동할 때는 마우스 대신 이 키들을 써 보세요.

| 단축키 | 하는 일 |
| --- | --- |
| `Home` / `End` | 줄의 맨 앞 / 맨 뒤로 가요 |
| `Ctrl + ←` / `Ctrl + →` | 한 글자씩이 아니라 **단어 단위**로 움직여요 |
| `Ctrl + Home` / `Ctrl + End` | 파일의 맨 처음 / 맨 끝으로 가요 |
| `Shift`를 함께 누르기 | 위 이동 키에 `Shift`를 더하면 지나간 곳이 선택돼요 |
| `F8` | 다음 에러/경고로 이동해요 |
| `Ctrl + Shift + [` | 코드 블록을 접어요. 펼치려면 `Ctrl + Shift + ]` |

**자주 하는 실수**

- 한글 입력 상태에서 코드를 쓰면 변수 이름이 한글로 들어가거나 `ㅊ` 같은 글자가 찍혀요. 코드는 **영문 상태**에서 쓰세요. 한글을 쓸 곳은 주석과 화면 문구뿐이에요.
- `Ctrl + /`로 주석 처리한 줄을 잊고 "코드가 사라졌다"고 놀라요. 회색이 된 줄은 다시 `Ctrl + /`로 살려요.

처음에는 건너뛰어도 돼요. 단축키가 손에 익은 뒤에 찾아오세요.

`Ctrl + K → Ctrl + S`처럼 차례로 누르면 **단축키 목록**이 열려요. 위쪽 검색창에 "comment"처럼 영어로 치면 관련 단축키가 나오고, 연필 모양을 누르면 키를 내 마음대로 바꿀 수 있어요.

`→`는 "앞의 키를 눌렀다 떼고, 이어서"라는 뜻이에요. `Ctrl + K`로 시작하는 단축키는 이렇게 두 번에 나눠 눌러요. 예를 들어 `Ctrl + K → Z`는 방해되는 것을 모두 숨기는 **젠 모드**예요. 빠져나올 때는 `Esc`를 두 번 눌러요.

| 단축키 | 하는 일 |
| --- | --- |
| `Ctrl + B` | 왼쪽 사이드바를 접고 펴요 (코드 영역이 넓어져요) |
| `Ctrl + J` | 아래 패널(터미널 등)을 접고 펴요 |
| `Ctrl + Shift + X` | Extension 서랍을 열어요 |
| `Ctrl + ,` | 설정 화면을 열어요 |

**터미널**(Terminal)은 마우스 대신 글자로 컴퓨터에 일을 시키는 창이에요. 클릭할 버튼이 없는 대신, 명령을 치고 `Enter`를 누르면 바로 실행돼요. 아래 패널에 있고, `` Ctrl + ` ``(숫자 1 왼쪽 키)로 열어요. 이 키가 안 먹히면 위쪽 메뉴의 터미널(Terminal) → 새 터미널(New Terminal)을 고르세요.

BAS의 터미널은 **bash**라는 종류예요. 처음에는 아래 다섯 개만 알면 돼요.

| 명령 | 하는 일 | 비유 |
| --- | --- | --- |
| `pwd` | 지금 내가 어느 폴더에 있는지 알려줘요 | "여기가 어디지?" |
| `ls` | 지금 폴더 안의 파일과 폴더를 보여줘요 | 상자 안 들여다보기 |
| `cd 폴더이름` | 그 폴더 안으로 들어가요 | 상자 열고 들어가기 |
| `cd ..` | 한 단계 바깥으로 나와요 | 상자에서 나오기 |
| `clear` | 터미널 화면을 깨끗이 비워요 | 칠판 지우기 |

터미널에서 알아 두면 좋은 키 세 가지가 있어요.

- `Tab`: 폴더나 파일 이름을 앞부분만 치고 누르면 나머지를 채워 줘요. 긴 이름을 다 치지 않아도 돼요.
- `↑`: 방금 쓴 명령을 다시 불러와요. 같은 명령을 또 칠 일이 많아요.
- `Ctrl + C`: 실행 중인 일을 멈춰요. 끝나지 않는 명령이 돌고 있을 때 눌러요. 글자를 선택한 상태에서 누르면 멈추지 않고 복사가 돼요.

### 브라우저 안의 BAS: 단축키가 안 먹힐 때

BAS는 브라우저 안에서 돌아가요. 그래서 컴퓨터에 설치한 VS Code와 다른 점이 하나 있어요. **브라우저가 먼저 가져가는 단축키**가 있다는 거예요.

가장 위험한 건 `Ctrl + W`예요. VS Code에서는 열린 파일 탭을 닫지만, 브라우저는 이 키를 "현재 탭 닫기"에 써요. BAS가 열린 브라우저 탭 자체가 닫힐 수 있어요. `Ctrl + N`(새 창), `Ctrl + T`(새 탭)도 같은 문제가 있어요. 브라우저가 가로채면 BAS는 눌린 줄도 몰라요.

| 하고 싶은 일 | 안전한 방법 |
| --- | --- |
| 열린 파일 탭 닫기 | 탭의 `X` 버튼을 눌러요 |
| 새 파일 만들기 | 왼쪽 파일 목록에서 오른쪽 클릭 → 새 파일 |
| 실수로 브라우저 탭을 닫았을 때 | `Ctrl + Shift + T`를 눌러 닫은 탭을 되살려요. 저장하지 않은 내용은 안 돌아올 수 있어요 |

환경(브라우저 종류, 설정)에 따라 어떤 키가 먹히는지가 달라요. 단축키가 안 먹히면 고장이 아니에요. 같은 일을 Command Palette(`F1`)에서 이름으로 찾아 실행하면 대부분 해결돼요.

그리고 하나 더. **저장하지 않은 작업은 브라우저를 닫으면 날아갈 수 있어요.** 그래서 다음에 나오는 자동 저장을 꼭 켜 두세요.

### 추천 Extension: 설치하는 법과 추천 목록

**Extension**은 편집기에 기능을 덧붙이는 작은 프로그램이에요. 스마트폰 앱처럼 필요한 것만 골라 깔아요.

**설치하는 법**

1. 왼쪽 Activity Bar에서 Extensions 아이콘을 누르거나 `Ctrl + Shift + X`를 눌러요.
2. 처음에는 안내문(disclaimer)이 나와요. 읽고 동의해야 목록이 보여요.
3. 검색창에 이름을 치고, 원하는 것의 설치(Install) 버튼을 눌러요.
4. 설치가 끝나면 버튼이 제거(Uninstall)로 바뀌어요. 화면이 반응하지 않으면 Command Palette에서 `reload window`를 실행하세요.

BAS의 확장 목록은 VS Code와 달리 **Open VSX**라는 다른 저장소에서 가져와요. SAP는 마이크로소프트 마켓의 이용 조건 때문에 BAS에서 그 마켓을 쓰지 못하기 때문이에요. 그래서 VS Code에서 쓰던 확장이 BAS 검색에 안 나올 수 있어요. 고장이 아니에요.

**수업에 도움이 되는 추천 목록**

| 확장 | 하는 일 | 이럴 때 좋아요 |
| --- | --- | --- |
| {{ic:toolbox:blue}} SAP Fiori tools - Extension Pack (UI5 Language Assistant 포함) | XML 뷰에서 컨트롤 이름과 프로퍼티를 자동완성하고, 틀린 이름을 알려 줘요 | `*.view.xml`, `*.fragment.xml`을 쓸 때 (6부~) |
| {{ic:magnifier:red}} Error Lens | 에러와 경고를 문제가 난 줄 끝에 바로 보여 줘요 | 아래 패널을 열지 않고도 빨간 글씨를 보고 싶을 때 |
| {{ic:wand:amber}} Prettier - Code formatter | 들여쓰기와 줄 바꿈을 한 번에 정리해요 | 코드 모양이 들쭉날쭉해서 읽기 힘들 때 |
| {{ic:folders:amber}} Material Icon Theme | 파일 종류마다 다른 아이콘을 붙여요 | `.js`, `.xml`, `.json` 파일이 한눈에 구분되길 원할 때 |
| {{ic:book:green}} UI5 Docs KR | UI5 공식 문서의 영어 설명을 한국어로 보여 줘요 | 컨트롤과 프로퍼티가 무슨 뜻인지 영어 문서 없이 바로 알고 싶을 때 |
| {{ic:target:teal}} UI5 Inspector (크롬 확장) | 화면의 컨트롤을 눌러 어떤 모델과 경로에 바인딩됐는지 보여 줘요 | 화면이 비어 있는 이유를 찾을 때 (14부 막혔을 때 순서) |

표의 처음 네 개는 BAS 확장 서랍에서 이름으로 검색해 설치해요. **UI5 Docs KR**은 확장 서랍에서 검색되지 않을 수 있어요. 설치 파일(`.vsix`)을 받았다면 아래 "더 알아보기"의 방법으로 설치해요. **UI5 Inspector**는 BAS가 아니라 크롬 브라우저에 설치해요.

첫 번째 줄은 **이미 설치돼 있을 수 있어요.** 새로 받기 전에 확장 서랍의 "설치됨" 목록부터 확인하세요. UI5 Language Assistant는 처음 쓸 때 UI5 정보를 내려받아서, 자동완성이 뜨기까지 잠시 걸릴 수 있어요. 인터넷이 연결된 상태에서 조금 기다리면 돼요.

**자주 하는 실수**

- 확장을 한꺼번에 많이 깔면 BAS가 느려질 수 있어요. 필요할 때 하나씩 깔고, 안 쓰면 지워요.
- 확장을 깔고 나서 아무 변화가 없다고 생각해요. 파일을 다시 열거나 `reload window`를 해 보세요.
- Prettier를 켜고 나서 코드 모양이 팀원과 달라져요. 팀 프로젝트에서는 함께 쓸지 먼저 정하세요.

<summary>더 알아보기 — 검색에 안 나오는 확장을 파일로 직접 설치하기</summary>

수업에서 꼭 필요하지는 않아요. 필요한 확장이 목록에 없을 때만 보세요.

확장은 `.vsix`라는 파일 하나로 배포되기도 해요. BAS는 이 파일을 직접 설치하는 것도 지원해요. 컴퓨터에 받아 둔 `.vsix` 파일을 BAS 왼쪽 파일 목록으로 끌어다 놓아 올린 뒤, Command Palette에서 `Install from VSIX`를 검색해 실행하는 방식이에요. 메뉴 이름은 BAS 버전에 따라 조금 다를 수 있어요.

주의할 점이 있어요. 확장은 **내 작업실 안에서 코드를 실행**해요. 출처를 모르는 `.vsix`는 설치하지 마세요. 사용 권한과 책임은 설치하는 사람에게 있어요.

</details>

### 설정 꿀팁: 자동 저장, 글자 크기, 줄 바꿈

설정은 `Ctrl + ,`로 열어요. 위쪽 검색창에 찾는 설정의 이름을 쳐서 바꿔요. 아래 세 가지만 바꿔도 체감이 확 달라져요.

| 하고 싶은 일 | 설정 검색어 | 바꿀 값 |
| --- | --- | --- |
| 저장을 잊어도 되게 하기 | `auto save` | `afterDelay` (코드를 고치고 잠깐 멈추면 자동 저장) |
| 코드 글자 크기 키우기 | `editor font size` | 숫자를 키워요 (14~18) |
| 긴 줄을 화면 안에서 줄 바꿈 | `word wrap` | `on` |

자동 저장은 위쪽 메뉴의 파일(File) → 자동 저장(Auto Save)으로도 켤 수 있어요. 켜 두면 "고쳤는데 화면이 안 바뀌어요"의 가장 흔한 원인인 **저장 안 함**이 사라져요.

줄 바꿈은 설정을 열지 않고도 `Alt + Z`로 켜고 끌 수 있어요. 가로로 긴 줄을 읽으려고 스크롤을 옆으로 밀 필요가 없어져요.

화면 색은 `Ctrl + K → Ctrl + T`를 차례로 누르면 바꿀 수 있어요. 눈이 편한 색을 골라 보세요.

<details class="more">
<summary>더 알아보기 — 설정 파일을 직접 고치기 (settings.json)</summary>

처음에는 건너뛰어도 돼요. 설정 화면의 모든 값은 사실 `settings.json`이라는 파일에 글자로 저장돼요. 설정 화면에서 클릭으로 바꾸는 것과 이 파일을 고치는 것은 같은 일이에요.

```json
{
  "files.autoSave": "afterDelay",
  "editor.fontSize": 16,
  "editor.wordWrap": "on"
}
```

Command Palette에서 `Open User Settings (JSON)`을 실행하면 이 파일이 열려요. 위 세 줄은 앞의 표와 같은 설정이에요. JSON 모양은 1부에서 배운 객체 그대로예요. 키와 값을 쉼표로 이어 쓰고, 마지막 줄 뒤에는 쉼표를 붙이지 않아요.

</details>

### 컨트롤 프로퍼티 사전: 자주 보이는 프로퍼티 한 줄 설명

XML에서 컨트롤 태그 안에 적는 `이름="값"`은 대부분 컨트롤의 **프로퍼티**(6부)예요. 이름은 "무엇을 정할지", 값은 "어떻게 할지"예요. `press` 같은 이벤트와 `xmlns` 같은 파일 설정도 같은 모양으로 적어서 여기에 함께 모았어요. 컨트롤마다 쓸 수 있는 프로퍼티가 달라요. 여기에는 이 교재에 나온 것만 모았어요. 없는 것은 UI5 API Reference에서 컨트롤 이름을 검색하면 전체 목록이 나와요.

**모든 컨트롤에 쓰는 프로퍼티**

| 이름 | 하는 일 | 자세히 |
| --- | --- | --- |
| `id` | 컨트롤마다 붙이는 고유한 이름이에요. 컨트롤러에서 `byId`로 찾으려면 꼭 필요해요 | 6부 id와 byId |
| `class` | CSS 클래스 이름이에요. 여백 같은 모양을 정해요. 여러 개는 공백으로 띄워요 | 7부 여백 클래스 |
| `visible` | `false`면 화면에서 숨겨요. 자리도 차지하지 않아요 | 12부 Expression Binding |
| `enabled` | `false`면 회색이 돼서 누르거나 입력할 수 없어요 | 12부 Expression Binding |
| `width`, `height` | 폭과 높이예요. `100%`, `20rem`, `auto`처럼 단위와 함께 적어요<span class="tip" tabindex="0" role="button" aria-label="rem이 뭐예요?">?<span class="tip-body"><b>rem</b>은 화면의 기본 글자 크기(보통 16px)를 1로 잡은 길이 단위예요. 1rem은 16px, 0.5rem은 8px, 2rem은 32px이에요. <b>em</b>은 비슷하지만 그 컨트롤 자신의 글자 크기를 1로 잡아요.</span></span> | 7부 정렬과 간격 |

**글자와 입력**

| 이름 | 하는 일 | 자세히 |
| --- | --- | --- |
| `text` | 화면에 보이는 글자예요 (`Button`, `Label`, `Text`, `Title`) | 6부 XML View 읽는 법 |
| `title` | `Page` 같은 큰 컨트롤의 제목이에요 | 6부 XML View 읽는 법 |
| `value` | `Input` 입력칸의 내용이에요. `{Sname}`처럼 모델과 연결하면 입력과 데이터가 같이 바뀌어요 | 8부 TwoWay Binding |
| `placeholder` | 비어 있을 때 흐리게 보이는 안내 글이에요 | 6부 XML View 읽는 법 |
| `editable` | `Input`에서 `false`면 읽기만 되고 수정은 못 해요. `SimpleForm`에서는 `true`면 입력용 배치가 돼요 | 7부 레이아웃 컨트롤 |
| `description` | `Input` 값 뒤에 붙는 덧붙임 글이에요. 포매터와 함께 코드를 글자로 바꿔 보여줄 때 써요 | 11부 포매터 |
| `selected` | `CheckBox`의 체크 여부(`true`/`false`)예요 | 12부 Expression Binding |

**이벤트: "…하면 이 함수를 실행해 줘"** 값은 `.함수이름` 모양이에요.

| 이름 | 실행되는 때 | 자세히 |
| --- | --- | --- |
| `press` | 버튼을 눌렀을 때 | 6부 press |
| `liveChange` | `Input`에 글자를 칠 때마다 (한 글자마다) | 6부 press |
| `change` | `Input`에 입력을 마치고 Enter를 누르거나 다른 곳을 눌렀을 때 | 6부 press |
| `selectionChange` | 테이블, 목록, 콤보박스에서 고른 항목이 바뀔 때 | 11부 테이블 구조 |

**목록, 콤보박스, 테이블**

| 이름 | 하는 일 | 자세히 |
| --- | --- | --- |
| `items` | 목록을 만들 데이터의 경로예요. 데이터 건수만큼 항목이 복사돼요 | 9부 템플릿과 상대경로 |
| `key` | `core:Item`의 코드값이에요. 사용자에게는 `text`가 보이고, 코드는 `key`가 가져가요 | 9부 콤보박스에서 값 꺼내기 |
| `selectedKey` | 콤보박스에서 고른 항목의 `key`예요. 값을 넣으면 그 항목이 선택돼요 | 9부 콤보박스에서 값 꺼내기 |
| `mode` | 테이블에서 줄을 고르는 방식이에요 (`SingleSelectMaster`, `MultiSelect` 등) | 11부 테이블 구조 |
| `growing` | `true`면 데이터를 한꺼번에 그리지 않고 나눠서 보여줘요 | 11부 많은 데이터 나눠 보여주기 |
| `growingThreshold` | 한 번에 보여줄 줄 수예요 | 11부 많은 데이터 나눠 보여주기 |
| `growingScrollToLoad` | `true`면 "더 보기" 버튼 대신 스크롤을 끝까지 내릴 때 다음 줄을 불러와요 | 11부 많은 데이터 나눠 보여주기 |
| `sticky` | `ColumnHeaders`를 적으면 스크롤해도 열 제목이 위에 붙어 있어요 | 11부 많은 데이터 나눠 보여주기 |

| `growFactor` | `FlexItemData`에서 남는 칸을 얼마나 가져갈지 정해요 | 7부 정렬과 간격 |
| `headerText` | `Panel`의 제목 글자예요 | 7부 레이아웃 컨트롤 |
| `expandable`, `expanded` | `Panel`을 접고 펼 수 있게 할지, 처음에 펼쳐 둘지 정해요 | 7부 레이아웃 컨트롤 |
| `labelSpanM` | `SimpleForm`에서 라벨이 12칸 중 몇 칸을 차지할지 정해요 (중간 크기 화면) | 7부 레이아웃 컨트롤 |
| `columnsL` | `SimpleForm`을 큰 화면에서 몇 열로 나눌지 정해요 | 7부 레이아웃 컨트롤 |
| `span` | `l:GridData`에서 12칸 중 몇 칸을 차지할지 정해요 | 7부 레이아웃 컨트롤 |
| `vertical` | `ScrollContainer`가 세로로 스크롤되게 할지 정해요 | 11부 많은 데이터 나눠 보여주기 |

**파일과 연결을 정하는 설정**

| 이름 | 하는 일 | 자세히 |
| --- | --- | --- |
| `xmlns`, `xmlns:mvc`, `xmlns:core` | 이 파일에서 쓸 라이브러리를 접두어와 짝지어요. `xmlns`는 기본 라이브러리(`Button`, `Page`), `mvc:`나 `core:`는 다른 라이브러리예요 | 6부 XML View 읽는 법 |
| `controllerName` | 이 View를 맡는 컨트롤러 파일이에요 | 6부 컨트롤러 파일 |
| `fragmentName`, `type` | 불러올 Fragment 파일 이름과 파일 형식이에요 | 7부 Fragment |
| `binding` | 컨트롤 하나를 통째로 한 데이터 위치에 연결해요 | 10부 기본 모양 |

### 용어 사전

| 용어 | 한 줄 뜻 | 나오는 곳 |
| --- | --- | --- |
| 라이브러리 (Library) | 필요할 때 꺼내 쓰는, 남이 만든 도구 모음 | 0부, 6부 |
| 프레임워크 (Framework) | 앱의 뼈대와 규칙을 정해 둔 틀 (UI5가 프레임워크예요) | 0부, 6부 |
| MVC | 화면(View), 동작(Controller), 데이터(Model)를 나눠 만드는 구조 | 6부 |
| 컨트롤 (Control, Element) | 버튼, 테이블, 패널처럼 화면에 놓는 UI5 부품 | 6부, 10부 |
| 프로퍼티 (Property) | 컨트롤의 설정값 (`text`, `value`, `visible`) | 6부 |
| 애그리게이션 (Aggregation) | 컨트롤 안에 다른 컨트롤을 넣는 자리 (`items`, `content`) | 6부, 9부 |
| 네임스페이스 (xmlns) | XML 태그가 어느 라이브러리의 컨트롤인지 알려주는 접두어 | 6부 |
| manifest.json | 앱 id, 모델, 설정을 적은 앱 설정서 | 6부 |
| i18n | 화면 문구를 모아 둔 파일 (다국어용 이름 있는 모델) | 6부, 8부 |
| Fragment | 컨트롤러 없는 화면 조각 | 7부 |
| Dialog | 팝업 창 컨트롤 | 7부 |
| 모델 (Model) | 화면이 쓰는 데이터를 들고 있는 객체 (JSONModel, ODataModel) | 8부 |
| 바인딩 (Binding) | 컨트롤의 프로퍼티와 모델 데이터를 연결해 두는 것 | 8부 |
| 절대경로 / 상대경로 | `/`로 시작 = 모델 맨 위부터, `/` 없음 = 기준 위치부터 | 9부, 10부 |
| 템플릿 (Template) | 목록의 한 줄 틀, 데이터 건수만큼 복사됨 | 9부 |
| 바인딩 컨텍스트 (Binding Context) | 항목 하나가 가리키는 데이터 위치 (`getPath()`) | 9부 |
| 엘리먼트 바인딩 | 컨트롤의 기준 위치를 데이터 한 건으로 정하기 (`bindElement`) | 10부 |
| 마스터-디테일 | 목록에서 고르면 상세가 따라 바뀌는 화면 | 10부, 13부 |
| 포매터 (Formatter) | 값을 화면용 글자로 바꿔 주는 컨트롤러 함수 | 11부 |
| Expression Binding | XML 안에서 `{= ... }`로 하는 간단한 계산 | 12부 |
| 콜백 함수 (Callback function) | 나중에 불러 달라고 넘겨주는 함수. 줄여서 "콜백" | 3부 |
| Promise / then / async / await | 시간이 걸리는 일의 결과를 받아 처리하는 문법 | 5부 |
| OData | SAP 백엔드와 데이터를 주고받는 표준 방식 (다음 단계) | 8부 |
| BAS | SAP Business Application Studio, 수업에서 쓰는 개발 도구 | 15부 |
| Dev Space | BAS 안에 있는 내 전용 작업실. 꺼져 있으면 먼저 시작해야 해요 | 15부 |
| Command Palette | 하고 싶은 일의 이름을 쳐서 실행하는 창 (`Ctrl + Shift + P`) | 15부 |
| 터미널 (Terminal) | 글자로 명령을 입력해 컴퓨터에 일을 시키는 창 | 15부 |
| Extension | 편집기에 기능을 덧붙이는 작은 프로그램 | 15부 |

### 더 공부할 곳

- [SAPUI5 SDK](https://ui5.sap.com/) — SDK는 Software Development Kit(개발 도구 모음)이고, 여기서는 공식 문서 사이트예요. Documentation의 Walkthrough는 이 문서 순서와 비슷하게 한 단계씩 앱을 만들어요. API Reference에서 컨트롤 이름을 검색하면 Properties, Aggregations, Events, Methods가 다 나와요.
- UI5 코드를 열어 둔 채로 모르는 메서드를 API Reference에서 찾는 습관이 가장 효과가 커요. 예: `sap.m.ComboBox` → Events → `selectionChange`의 파라미터.
- [ABAP Keyword Documentation](https://help.sap.com/doc/abapdocu_latest_index_htm/latest/en-US/abennews.htm) — ABAP 공식 문법 문서. 수업 시스템에서는 키워드에 커서를 두고 F1을 누르면 같은 문서가 나와요.
- [ABAP Cheat Sheets (SAP 공식 GitHub)](https://github.com/SAP-samples/abap-cheat-sheets) — 주제별 ABAP 문법 요약과 실행 예제.
- AI에게 물어본 내용은 항상 직접 실행하거나 공식 문서로 확인하세요. 기본 문법은 대체로 정확하지만, 버전별 차이나 덜 알려진 메서드 이름은 틀릴 수 있어요.
