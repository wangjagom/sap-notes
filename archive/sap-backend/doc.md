# SAP 백엔드 총정리 — DB 기초부터 SQL, ABAP 데이터까지

Nov 12, 2026

## 이 문서 사용법

ABAP을 배우기 전에 데이터베이스(DB)와 SQL을 처음 만나는 사람을 위한 교재예요. 같은 수업의 화면 쪽(SAPUI5, 자바스크립트)은 **SAPUI5 총정리**에 따로 정리돼 있어요. 이 교재는 화면 뒤에서 데이터가 어떻게 보관되고 꺼내지는지를 다뤄요.

| 부분 | 내용 | 언제 읽나 |
| --- | --- | --- |
| 1부 | DB 기초 (테이블, 키, 관계, 정규화, ERD) | ABAP을 배우기 전에 |
| 2부 | ABAP Dictionary ① (Domain, Data Element, Package, 테이블 만들기, 참조 필드, Structure) | SE11 수업을 들을 때. SQL은 안 나와요 |
| 3부 | ABAP Dictionary ② (Check Table, 외래키, Text Table, F4, SM30, 관계 분석) | 테이블을 잇고 값을 검사할 때. SQL은 안 나와요 |
| 4부 | SQL 기초 (꺼내기, 조인, 바꾸기, 모아서 계산하기, Internal Table) | ABAP 코드의 SELECT가 낯설 때 |
| 5부 | ABAP 기초 (개발 화면, 문법, 타입, Internal Table, SELECT SINGLE) | ABAP 수업을 들을 때 |
| 6부 | UI5와 백엔드 데이터 잇기 (대응표, 데이터 규칙, 확인할 것) | UI5에서 받은 데이터가 이상할 때 |
| 부록 | 용어 사전, 약어 풀이, 더 공부할 곳 | 단어가 헷갈릴 때 |
| 부록 | 책 추천 (임시) | 수업과 같이 볼 책을 고를 때 |

**이 교재가 다루는 버전**

화면 설명과 코드는 수업 서버를 기준으로 썼어요.

| 항목 | 기준 |
| --- | --- |
| SAP 시스템 | SAP S/4HANA 2023 온프레미스 (FPS01) |
| ABAP | 7.58 (SAP_BASIS 758) |
| 데이터베이스 | SAP HANA 2.0 |
| SAP GUI | 8.00 (패치 19) |
| 화면 언어 | 영어(EN) 로그인 기준. 메뉴와 버튼 이름을 영어로 적었어요 |

- **다른 버전에서 볼 때:** 2·3부의 SE11, SE16, SM30 화면은 SAP ECC 6.0과 S/4HANA가 거의 같아요. 버튼 이름이나 위치만 조금 다를 수 있어요.
- **ABAP 문법:** 회사마다 옛 문법과 요즘 문법(ABAP 7.40 이후) 중 하나를 써요. 그래서 이 교재의 ABAP 코드는 **두 문법으로 모두** 볼 수 있어요. 코드 상자 위의 탭으로 고르면 교재 전체가 그 문법으로 바뀌어요. 처음에는 수업 서버 기준인 요즘 문법으로 보여요.

- **테이블**(Table)은 데이터를 담는 표예요. 엑셀 시트 한 장을 떠올리면 돼요. 이 책은 처음부터 끝까지 "테이블"이라고 불러요.
- **1부는 SQL 코드 없이** 테이블의 구조만 다뤄요. SAP에서 직접 만드는 법은 2·3부(SQL 없이 화면으로), 꺼내고 바꾸는 문장은 4부에서 배워요.
- 예제는 계속 같은 학생 테이블(ZSTUDENT)과 반 테이블(ZCLASS)을 써요. 1부 첫머리에서 테이블 내용을 볼 수 있어요.
- "SAPUI5 총정리 3부"처럼 적힌 곳은 화면 쪽 교재의 내용이에요. 자바스크립트를 몰라도 이 교재는 따라올 수 있어요.
- **"다음 단계" 상자는 문제를 맞히면 열려요.** 답을 고르고 "정답 확인"을 누르세요.
- 테이블을 직접 그려 보고 싶으면 목차 맨 아래 **부가 기능 → ERD 설계 도구**를 열어 보세요.

## 1부. DB 기초 — ABAP을 배우기 전에

UI5 화면에 보이는 데이터는 어딘가에 저장돼 있어요. 그 "어딘가"가 **데이터베이스**예요. 그리고 5부에서 배울 ABAP은 하는 일의 대부분이 이 데이터베이스에서 데이터를 꺼내거나 넣는 일이에요. 그래서 ABAP을 읽으려면 "데이터가 어떤 모양으로 저장되는가"를 먼저 알아야 해요.

이 부는 외워야 할 문법이 아니라 **테이블을 읽는 눈**을 만드는 부분이에요. 엑셀을 써 본 적이 있다면 절반은 이미 아는 내용이에요. 자바스크립트와 연결되는 곳은 "자바스크립트로는" 표로 같이 보여 드려요.

이 부는 테이블의 **구조**만 다뤄요. 테이블에서 데이터를 꺼내고 바꾸는 언어(SQL)는 4부에서 따로 배워요. 그 전에 2·3부에서 SAP 화면으로 테이블을 직접 만들어요. SAPUI5 총정리 6\~13부(UI5)와 이어서 읽지 않아도 돼요. SAPUI5 총정리 1\~3부(객체, 배열, 배열 메서드)만 알면 따라올 수 있어요.

이 부에서는 아래 학생 테이블 두 장을 계속 예제로 써요.

**ZSTUDENT** (학생)

| MANDT | SID | SNAME | CID | SCORE |
| --- | --- | --- | --- | --- |
| 100 | 0001 | 민수 | CL301 | 85 |
| 100 | 0002 | 지아 | CL303 | 92 |
| 100 | 0003 | 도윤 | CL301 | 78 |
| 100 | 0004 | 서연 | CL303 | 88 |
| 100 | 0005 | 하준 | CL301 | 80 |

**ZCLASS** (반)

| MANDT | CID | CNAME |
| --- | --- | --- |
| 100 | CL301 | ABAP반 |
| 100 | CL303 | UI5반 |

맨 앞의 `MANDT`는 SAP가 거의 모든 테이블 맨 앞에 붙이는 **Client 번호** 필드예요. 지금은 "SAP 테이블에는 늘 붙어 있는 필드"로만 보고 넘어가세요. 뜻은 2부 "SAP 테이블 읽는 법"에서 설명해요.

### 프론트엔드와 백엔드: 화면 쪽과 서버 쪽

웹 앱은 일하는 곳이 두 군데로 나뉘어요.

- **프론트엔드**(Frontend): 사용자의 **브라우저 안에서** 도는 부분이에요. 화면을 그리고, 클릭과 입력을 받아요. SAPUI5 총정리 0\~13부에서 배운 자바스크립트와 UI5가 여기에 있어요.
- **백엔드**(Backend): **서버**(항상 켜져 있는 회사 쪽 컴퓨터)에서 도는 부분이에요. 데이터를 저장하고, 규칙을 지키고, 요청이 오면 데이터를 꺼내 보내 줘요. 이 교재 1\~5부의 DB와 ABAP이 여기에 있어요.

식당에 비유하면 프론트엔드는 **홀**이에요. 손님(사용자)을 맞이하고 메뉴를 보여 주고 주문을 받아요. 백엔드는 **주방과 창고**예요. 손님은 안 보이지만 재료(데이터)를 보관하고 음식을 만들어요. 둘 사이에서 주문서와 음식을 나르는 것이 **통신**이에요.

&#91;embedded content: 프론트엔드와 백엔드 구조 · 브라우저와 서버\]

| | 프론트엔드 | 통신 | 백엔드 |
| --- | --- | --- | --- |
| 어디서 | 사용자의 브라우저 | 인터넷 (HTTP{? 브라우저와 서버가 요청과 응답을 주고받는 규칙이에요 ?}) | SAP 서버 |
| 하는 일 | 화면 그리기, 클릭 받기, 받은 데이터 보여 주기 | 요청 보내기, 데이터 받아 오기 | 데이터 저장, 규칙 검사, 데이터 꺼내 주기 |
| 쓰는 것 | UI5 (View XML, Controller 자바스크립트, 모델) | OData(SAPUI5 총정리 8부), JSON | ABAP, 데이터베이스 |
| 교재 | SAPUI5 총정리 0\~13부 | SAPUI5 총정리 5부(비동기), 8부 | 이 교재 1\~6부 |

한 번의 동작이 두 쪽을 어떻게 오가는지 따라가 볼게요. 사용자가 반 이름을 검색하는 경우예요.

&#91;embedded content: 데이터 왕복 애니메이션 · 스크롤로 따라가기\]

이 구조에서 기억할 것이 세 가지 있어요.

1. **프론트엔드는 DB에 직접 닿지 않아요.** 브라우저에서 DB를 바로 열면 누구나 데이터를 볼 수 있으니까요. 항상 백엔드를 거쳐서 받아 와요.
2. **규칙 검사는 백엔드가 최종 책임져요.** 프론트에서 "점수는 0\~100만 입력"이라고 막아도, 요청을 직접 만들어 보내는 사람이 있을 수 있어요. 프론트 검사는 사용자를 돕는 용도이고, 진짜 검사는 서버에서 해요.
3. **둘이 만나는 곳이 데이터의 모양이에요.** 백엔드가 어떤 필드를 어떤 형식으로 보내느냐가 프론트의 모델과 Binding Path를 정해요. 그래서 "화면에 데이터가 이상하게 보인다"면 프론트 문제인지 백엔드 문제인지 먼저 나눠서 봐야 해요.

문제가 생겼을 때 어느 쪽인지 나누는 방법이에요.

| 확인할 것 | 어디서 | 이상하면 |
| --- | --- | --- |
| 서버가 보낸 데이터 자체가 이상한가 | 브라우저 개발자 도구(F12)의 Network 탭에서 응답 보기 | 백엔드 문제예요 (필드 값, 형식) |
| 데이터는 맞는데 화면이 이상한가 | 콘솔에서 `getModel().getData()` 찍어 보기 (SAPUI5 총정리 14부) | 프론트 문제예요 (Binding Path, 포매터) |

처음에는 건너뛰어도 돼요.

- **풀스택**(Full-stack): 프론트와 백엔드를 모두 다루는 개발자예요. SAP 현장에서는 UI5(프론트)와 ABAP(백엔드)을 같이 하는 사람을 가리키기도 해요.

- **API**: 프론트가 백엔드에 "이 데이터 주세요"라고 요청하는 약속된 창구예요. 여기서는 OData 서비스가 API 역할을 해요.

### 데이터베이스와 테이블: 엑셀 시트 한 장

**데이터베이스**(Database, DB)는 데이터를 정리해서 보관하는 창고예요. 그 안에서 데이터는 **테이블**(Table)이라는 표에 나뉘어 담겨요. 테이블은 엑셀 시트 한 장과 비슷해요. 이 책에서는 앞으로 이 표를 계속 **테이블**이라고 불러요.

비유하면 엑셀 파일 하나가 데이터베이스이고, 그 안의 시트 한 장이 테이블이에요. 위의 ZSTUDENT가 시트 한 장이에요.

&#91;embedded content: 데이터베이스와 테이블 · DB와 테이블\]

| 엑셀 | DB 용어 | 자바스크립트로는 |
| --- | --- | --- |
| 시트 한 장 | 테이블(Table) | 객체가 든 배열 `[{ }, { }]` (SAPUI5 총정리 1부) |
| 맨 윗줄의 열 이름 | 필드(Field){? 열이라고도 불러요. SAP 문서에서는 필드라고 많이 써요 ?} | 객체의 프로퍼티 이름 (`SID`, `SNAME` 같은 것) |
| 데이터 한 줄 | 레코드(Record){? 행이라고도 불러요. SAP에서는 "엔트리(Entry)"라고도 해요 ?} | 배열 안의 객체 하나 |

&#91;embedded content: 테이블의 구조 · 필드, 레코드, 키, 값\]

이 책에서는 데이터 한 줄을 앞으로 **레코드**라고 불러요. 몇 개인지 셀 때는 SAP 현장에서 하듯 "3건", "300건"처럼 **건**으로 세요.

같은 데이터를 자바스크립트로 쓰면 이렇게 돼요. SAPUI5 총정리 1부에서 배운 모양 그대로예요.

```js
const aZstudent = [
    { MANDT: "100", SID: "0001", SNAME: "민수", CID: "CL301", SCORE: 85 },
    { MANDT: "100", SID: "0002", SNAME: "지아", CID: "CL303", SCORE: 92 }
    // ... 나머지 레코드
];
```

엑셀과 다른 점이 세 가지 있어요.

- **필드마다 담을 수 있는 종류가 정해져 있어요.** 숫자 필드에 글자를 넣을 수 없어요(아래 "데이터 타입").
- **레코드마다 겹치지 않는 번호(키)가 있어요.** 같은 레코드가 두 번 들어갈 수 없어요(아래 "키").
- **여러 사람이 동시에 읽고 써요.** 그래서 수정할 때 규칙이 엄격해요.

### 키(Key): 레코드 하나를 콕 집는 번호

**키**(Key)는 테이블에서 **레코드 하나를 정확히 찾아내는 필드**예요. 학교의 학번과 같아요. 이름은 동명이인이 있을 수 있지만 학번은 사람마다 달라서, 학번을 알면 딱 한 사람이 정해져요.

**헷갈리지 마세요:** 자바스크립트 객체의 "키"(프로퍼티 이름)와 이름만 같고 뜻이 달라요. DB에서 키는 **레코드를 구분하는 필드**를 말해요.

키에는 규칙이 두 가지 있어요.

- 비어 있으면 안 돼요.
- 다른 레코드와 같은 값이면 안 돼요. 같은 키로 한 번 더 넣으려 하면 DB가 거부해요.

ZSTUDENT에서는 `SID`(학생번호)가 레코드를 구분해요. `SNAME`(이름)은 같은 이름이 두 명 있을 수 있어서 키로 쓸 수 없어요.

**복합 키**(Composite Key)는 필드 **여러 개를 합쳐서** 키로 쓰는 거예요. 필드 하나로는 겹치지만 둘을 합치면 겹치지 않을 때 써요. 예를 들어 "2026년 1학기 수강 기록"처럼 학생번호만으로는 레코드가 여러 건일 때, 학생번호 + 학기를 같이 키로 잡아요.

SAP 테이블은 거의 항상 맨 앞 키가 `MANDT`예요(2부 "SAP 테이블 읽는 법"에서 설명해요). 그래서 ZSTUDENT의 진짜 키는 `MANDT` + `SID` 둘의 묶음이에요.

자바스크립트로는 키로 레코드를 찾는 일이 이런 코드와 같아요.

```js
aZstudent.find(s => s.SID === "0003");   // 도윤 레코드 하나가 나와요 (SAPUI5 총정리 3부 find)
```

</details>

### 데이터 타입: 필드마다 담는 종류가 정해져 있어요

자바스크립트의 변수는 숫자를 넣었다가 글자를 넣어도 돼요. 하지만 DB의 필드는 **처음에 정한 종류(타입)와 길이만** 담을 수 있어요. 그래야 정렬, 계산, 검색이 빠르고 정확해요.

SAP 데이터베이스에서 자주 만나는 타입은 이래요.

| 타입 | 뜻 | 예 |
| --- | --- | --- |
| CHAR | 글자. 길이를 정해요 (CHAR 10 = 최대 10글자) | `ABAP반` |
| NUMC | 숫자로만 된 글자. 앞자리 0을 지키는 번호용이에요 | `0001` |
| DATS | 날짜. 연월일 8자리 글자예요 | `20260902` |
| TIMS | 시간. 시분초 6자리 글자예요 | `143000` |
| INT4 | 정수 | `85` |
| DEC | 소수점이 있는 수 | `81.50` |
| CURR | 금액. 통화 필드를 꼭 연결해요 | `370000.00` |
| QUAN | 수량. 반드시 단위 필드와 연결해요 | `12.000` |
| CLNT | Client 번호. `MANDT` 필드의 타입이에요 | `100` |

헷갈리기 쉬운 두 가지를 짚어 둘게요.

- **`NUMC`는 숫자가 아니라 글자예요.** `0001`처럼 앞의 0이 지워지면 안 되는 학번, 문서 번호에 써요. 더하기 같은 계산용이 아니에요.
- **날짜는 `YYYYMMDD` 글자 8개예요.** 화면용 형식(`2026.09.02`)은 화면에서 만들어요(SAPUI5 총정리 12부 데이터 타입, 6부 "자주 만나는 백엔드 데이터 규칙").

그리고 SAP 필드는 비어 있을 때 `null` 같은 "없음" 값이 아니라 **초기값**(Initial Value)을 가져요. 글자는 빈칸, 숫자는 0, 날짜는 `00000000`이에요. 점수가 `0`인지 아직 입력을 안 한 건지 구분하려면 이 규칙을 알고 있어야 해요.

### 테이블을 나누는 이유: 같은 내용을 두 번 쓰지 않으려고

학생 테이블에 반 이름을 바로 넣으면 편해 보여요.

| SID | SNAME | CNAME |
| --- | --- | --- |
| 0001 | 민수 | ABAP반 |
| 0003 | 도윤 | ABAP반 |
| 0005 | 하준 | ABAP반 |

그런데 "ABAP반"의 이름이 "SAP ABAP반"으로 바뀐다면 어떨까요? ABAP반 학생이 300명이면 300건을 모두 고쳐야 해요. 한 건이라도 빠뜨리면 같은 반인데 이름이 두 가지가 돼요.

그래서 **반 정보는 반 테이블(ZCLASS)에 한 번만** 적고, 학생 테이블에는 반 **코드**(`CL301`)만 넣어요. 이름이 바뀌어도 ZCLASS의 레코드 1건만 고치면 돼요.

&#91;embedded content: 테이블을 나누는 그림 · 나누기 전과 후\]

| 테이블 | 담는 것 |
| --- | --- |
| ZSTUDENT | 학생마다 달라지는 정보 (이름, 점수) + 어느 반인지 가리키는 코드 |
| ZCLASS | 반마다 한 번만 적는 정보 (반 이름) |

"같은 내용을 여러 곳에 쓰지 말고, 한 곳에 쓰고 코드로 가리킨다"가 DB 설계의 가장 큰 원칙이에요. 6부에서 나오는 "코드만 저장하고 글자는 보여 줄 때 만든다"가 바로 이 원칙이에요.

### 외래키와 조인: 나뉜 테이블을 다시 이어 붙이기

학생 테이블의 `CID`는 반 테이블의 키(`CID`)를 가리켜요. 이렇게 **다른 테이블의 키를 가리키는 필드**를 **외래키**(Foreign Key)라고 해요. "다른 테이블을 가리키는 안내 번호"라고 생각하면 돼요.

외래키로 이어진 두 테이블은 **부모**와 **자식**이라고 불러요. **키를 가진 쪽(ZCLASS)이 부모**, **그 키를 외래키로 가져다 쓰는 쪽(ZSTUDENT)이 자식**이에요. 자식이 부모를 가리키는 모양이에요. 영어로는 키를 **PK**(Primary Key), 외래키를 **FK**(Foreign Key)라고 줄여 쓰기도 해요.

화면에 "민수 - ABAP반"을 보여 주려면 두 테이블을 이어서 봐야 해요. 학생 테이블의 `CL301`을 반 테이블에서 찾아 반 이름을 가져오는 거예요. 이렇게 **같은 값을 기준으로 두 테이블을 옆으로 이어 붙이는 것**을 **조인**(Join)이라고 해요. 엑셀의 `VLOOKUP`이 하는 일과 같아요.

&#91;embedded content: 외래키로 이어진 테이블 · CID로 연결\]

이어 붙인 결과는 이런 한 장의 테이블처럼 보여요.

| SID | SNAME | CNAME |
| --- | --- | --- |
| 0001 | 민수 | ABAP반 |
| 0002 | 지아 | UI5반 |
| 0003 | 도윤 | ABAP반 |
| 0004 | 서연 | UI5반 |
| 0005 | 하준 | ABAP반 |

자바스크립트로는 이렇게 쓸 수 있어요(SAPUI5 총정리 3부 `map`, `find`).

```js
const aJoined = aZstudent.map(s => ({
    SID: s.SID,
    SNAME: s.SNAME,
    CNAME: aZclass.find(c => c.CID === s.CID).CNAME   // CID가 같은 반 레코드를 찾아 이름만 가져와요
}));
```

<summary>더 알아보기 — SAP의 Check Table</summary>

처음에는 건너뛰어도 돼요.

**Check Table**은 SAP에서 외래키에 넣을 수 있는 값을 "이 테이블에 있는 코드만"으로 제한하는 설정이에요. 학생 테이블의 `CID`에 ZCLASS에 없는 코드를 넣으면 막아 줘요. 직접 거는 방법은 3부 "SE11에서 외래키 걸기"에서 따라 해 봐요.

### 테이블 사이의 관계: 일대일, 일대다, 다대다

두 테이블이 **서로 몇 개씩 짝을 이루는가**를 **관계**(Relationship)라고 불러요. 테이블을 나누고 외래키로 이을 때 가장 먼저 정해야 하는 것이 이 관계예요. 관계는 크게 세 가지예요(1:1, 1:N, N:M).

| 관계 | 읽는 법 | 뜻 | 예 |
| --- | --- | --- | --- |
| 1:1 | 일대일 | 이쪽 레코드 1건에 저쪽도 1건 | 학생 1명 ↔ 학생증 1장 |
| 1:N | 일대다 | 이쪽 레코드 1건에 저쪽은 여러 건 | 반 1개 ↔ 학생 여러 명 |
| N:1 | 다대일 | 이쪽 레코드 여러 건에 저쪽은 1건 | 학생 여러 명 ↔ 반 1개 |
| N:M | 다대다 | 양쪽 모두 여러 건 | 학생 여러 명 ↔ 과목 여러 개 |

&#91;embedded content: 테이블 사이의 관계 세 가지 · 1:1, 1:N, N:M\]

**1:N(일대다)이 가장 많아요.** 위의 반과 학생이 그래요. 반 하나에 학생이 여러 명이지만, 학생 한 명은 반이 하나뿐이에요. 이때 **"여러 쪽"(N쪽) 테이블이 외래키를 가져요.** 학생 테이블에 `CID`(반 코드)가 있고, 반 테이블에는 학생 정보가 없어요. 반대로 반 테이블에 학생 번호를 여러 개 적으면 필드 하나에 값이 여러 개 들어가서 테이블 모양이 깨져요.

```
ZCLASS (1)  ──────<  ZSTUDENT (N)
 CID 가 키            CID 가 외래키 (반 코드를 가리켜요)
```

SAP에도 같은 구조가 많아요. 판매 문서 헤더(`VBAK`) 레코드 1건에 품목(`VBAP`) 레코드 여러 건이 달려요. 주문서 한 장에 상품이 여러 개 있는 것과 같아요. 품목 테이블의 키는 문서 번호 + 품목 번호(`VBELN` + `POSNR`)라서, 복합 키가 1:N에서 자주 쓰여요.

**N:1(다대일)은 1:N을 반대쪽에서 읽은 말이에요.** 같은 관계인데 어느 테이블을 기준으로 읽느냐만 달라요. 반을 기준으로 읽으면 "반 1개에 학생 여러 명"이라 1:N이고, 학생을 기준으로 읽으면 "학생 여러 명이 반 1개를 가리킴"이라 N:1이에요. 그래서 학생 테이블의 `CID`를 "N:1로 반을 가리키는 외래키"라고 말하기도 해요. 외래키는 항상 N쪽에 있다고 기억하면 돼요.

**1:1(일대일)은 드물어요.** 거의 안 쓰는 정보를 다른 테이블로 빼 둘 때 정도예요. 두 테이블이 같은 키를 쓰면 레코드가 1건씩 짝이 돼요.

**N:M(다대다)은 테이블 두 개로 못 이어요.** 학생은 여러 과목을 듣고, 과목 하나는 여러 학생이 들어요. 어느 쪽 테이블에도 외래키를 둘 수 없어요. 그래서 **가운데에 "연결 테이블"을 하나 더 만들어요.** 연결 테이블에는 "누가 어떤 과목을 듣는지"가 레코드 1건씩 들어가고, N:M이 1:N 두 개로 풀려요.

**ZENROLL** (수강)

| MANDT | SID | SUBJ |
| --- | --- | --- |
| 100 | 0001 | JS101 |
| 100 | 0001 | UI5101 |
| 100 | 0002 | UI5101 |
| 100 | 0002 | ABAP101 |
| 100 | 0003 | JS101 |

이 테이블의 키는 `SID` + `SUBJ`를 합친 복합 키예요(앞의 키 설명). 한 학생이 같은 과목을 두 번 등록할 수 없다는 규칙이 키로 그대로 지켜져요. `SID`는 학생 테이블을, `SUBJ`는 과목 테이블을 가리키는 외래키예요.

&#91;embedded content: 연결 테이블로 푸는 다대다 · 연결 테이블\]

```
ZSTUDENT (1) ──<  ZENROLL (N)  >── (1) ZSUBJECT
```

위 그림처럼 테이블을 상자로, 관계를 선으로 그린 그림을 **ERD**(Entity Relationship Diagram, 개체 관계 그림)라고 해요. 읽는 법과 그리는 법은 이 부 뒤쪽 "ERD 그리기"에서 자세히 봐요.

**몇 개까지, 없어도 되는지: 카디널리티**

1:N이라고만 하면 빠지는 정보가 있어요. "학생이 0명인 반도 있어도 되나?", "반이 정해지지 않은 학생도 있어도 되나?" 같은 거예요. 이렇게 **한쪽에 몇 개까지 이어질 수 있고, 아예 없어도 되는지**를 함께 적은 것을 **카디널리티**(Cardinality, 관계의 개수)라고 해요.

SAP에서는 네 가지 기호로 적어요. 일반 DB 책이나 ERD 도구는 같은 뜻을 다른 기호로 적을 뿐이에요.

| SAP 기호 | 뜻 | 개수 | ERD 선 끝 모양 (자세히 그릴 때) | 숫자로 적으면 |
| --- | --- | --- | --- | --- |
| 1 | 반드시 하나 | 딱 1개 | 막대 두 개 | 1..1 |
| C | 없거나 하나 | 0개 또는 1개 | 동그라미 + 막대 | 0..1 |
| N | 하나 이상 | 1개 이상 | 막대 + 까마귀 발 | 1..* |
| CN | 없거나 여러 개 | 0개 이상 | 동그라미 + 까마귀 발 | 0..* |

`C`는 Conditional(조건부), 즉 "있을 수도 없을 수도"의 첫 글자예요. 동그라미(0)가 붙으면 "없어도 된다"는 뜻이라고 기억하면 돼요.

```syntax
[부모 쪽] : [자식 쪽]
  1 또는 C   1, C, N, CN 중 하나
```

**부모 쪽(왼쪽)에는 1이나 C만 올 수 있어요.** 자식 레코드 1건의 외래키 필드에는 값이 하나 들어가거나 비어 있거나 둘 중 하나뿐이라서예요. 그래서 가능한 조합은 여덟 가지예요.

- **1 : N** — 반 하나에 학생이 1명 이상, 학생은 반이 꼭 있어요.
- **1 : CN** — 반 하나에 학생이 0명이어도 돼요. 아직 학생이 없는 새 반도 괜찮아요.
- **C : N** — 반이 정해지지 않은 학생도 있을 수 있어요. 학생 테이블의 `CID` 필드를 비워 둘 수 있어요.
- **1 : 1**, **1 : C**, **C : 1**, **C : C**, **C : CN**도 같은 방식으로 읽어요.

양쪽이 모두 "여러 개"인 관계(N:M)는 기호 하나로 못 적어요. 앞에서 본 것처럼 연결 테이블을 넣어 1:N 두 개로 나눠요.

**부모 쪽 C가 안 되는 경우도 있어요.** 외래키가 자식 테이블 **키의 일부**일 때예요. ZENROLL의 `SID`처럼 키에 들어간 필드는 절대 비워 둘 수 없으니까, 부모(학생)가 반드시 있어야 해요. 그래서 이런 관계는 항상 1이에요. 이렇게 **외래키가 자식 테이블 키의 일부인 관계**를 **식별 관계**(Identifying Relationship)라고 하고, ERD에서는 실선으로 그려요. 외래키가 키 밖에 있는 보통 관계는 **비식별 관계**라고 하고 점선으로 그려요. ERD 설계 도구에서 식별 관계(실선)를 고르면 "선택"을 못 고르는 이유가 이거예요.

<details class="more">
<summary>더 알아보기 — DB가 이 규칙을 실제로 지켜 줄까</summary>

ERD에 적었다고 DB가 전부 막아 주지는 않아요. 테이블을 만들 때 붙이는 설정으로 지켜지는 건 일부예요.

| 규칙 | DB가 지켜 주나요 | 방법 |
| --- | --- | --- |
| 부모 쪽 1과 C | 지켜 줘요 | 외래키 필드를 비우지 못하게 하면(NOT NULL) 1, 비워도 되게 두면 C |
| 자식 쪽 "최대 하나"(1, C) | 지켜 줘요 | 외래키 필드에 같은 값을 두 번 못 넣게 하면(UNIQUE) 자식이 하나로 제한돼요 |
| 자식 쪽 "최소 하나"(N과 CN의 차이) | 못 지켜요 | 프로그램에서 따로 확인해야 해요 |

그래서 실무에서는 1:N과 1:CN을 설계 문서에서만 구분하고, 테이블은 똑같이 만드는 경우가 많아요.

SAP도 비슷해요. SE11에서 외래키를 정할 때 카디널리티를 적는 칸이 있지만, 이 값은 **설명용**이에요. 시스템이 실제로 검사하는 건 "입력한 값이 부모 테이블(Check Table)에 있는지"뿐이에요.

</details>

관계를 정했으면 다음은 중복을 찾는 정규화, 그다음은 ERD를 직접 그려 보는 순서예요.

```quiz
- 학생 테이블에 과목 코드를 여러 개 적어요
- 과목 테이블에 학생 번호를 여러 개 적어요
- 가운데에 `SID`와 `SUBJ`를 담은 연결 테이블을 하나 더 만들어요 ✓
- 두 테이블을 하나로 합쳐요
> N:M은 연결 테이블로 1:N 두 개로 풀어요. 앞의 ZENROLL 테이블을 보세요.

Q: 반에는 학생이 0명이어도 되고, 학생은 반이 반드시 있어야 해요.
Q: SAP 카디널리티로 적으면?
- 1 : N
- 1 : CN ✓
- C : N
- CN : 1
> 부모 쪽(반)은 "반드시 있음"이라 1, 자식 쪽(학생)은 "0명 이상"이라 CN이에요. 부모 쪽에는 1이나 C만 올 수 있어요.
```

</details>

### 정규화: 1·2·3정규형으로 중복 찾기

앞에서 "같은 내용은 한 곳에만 쓴다"를 봤어요. 이 원칙을 단계별 기준으로 정리한 것이 **정규화**(Normalization)예요. 테이블을 분석하거나 개선점을 찾을 때 이 세 가지 기준으로 하나씩 확인하면 돼요.

| 단계 | 규칙 | 한 줄로 |
| --- | --- | --- |
| **1정규형** (1NF) | 필드 하나에는 값 하나만 넣어요 | 한 칸에 여러 값 금지 |
| **2정규형** (2NF) | 키가 여러 필드일 때, 키 **전체**에 종속되지 않고 **일부**에만 종속된 필드가 없어야 해요 | 키 일부에만 딸린 필드 금지 |
| **3정규형** (3NF) | 키가 아닌 필드가 **다른 키가 아닌 필드**에 종속되면 안 돼요 | 일반 필드에 딸린 필드 금지 |

**종속**은 "A를 알면 B가 정해진다"는 뜻이에요. 학번을 알면 이름이 정해지니까, 이름은 학번에 종속돼요.

**1정규형 위반: 한 칸에 값이 여러 개**

| SID | SNAME | SUBJ |
| --- | --- | --- |
| 0001 | 민수 | JS101, UI5101 |

`SUBJ` 한 칸에 과목이 두 개 들어 있어요. "UI5101을 듣는 학생"을 찾기도 어렵고, Check Table로 검사할 수도 없어요. **개선**: 과목마다 레코드 1건씩, 수강 테이블 ZENROLL로 나눠요(앞의 다대다 관계).

**2정규형 위반: 키 일부에만 딸린 필드**

| SID (키) | SUBJ (키) | SNAME |
| --- | --- | --- |
| 0001 | JS101 | 민수 |
| 0001 | UI5101 | 민수 |

ZENROLL의 키는 `SID` + `SUBJ`인데, `SNAME`(학생 이름)은 `SID`만 알면 정해져요. 그래서 과목 수만큼 이름이 반복돼요. **개선**: `SNAME`은 키가 `SID`인 학생 테이블로 옮겨요.

**3정규형 위반: 일반 필드에 딸린 필드**

| SID (키) | SNAME | CID | CNAME |
| --- | --- | --- | --- |
| 0001 | 민수 | CL301 | ABAP반 |
| 0003 | 도윤 | CL301 | ABAP반 |

`CNAME`(반 이름)은 키(`SID`)가 아니라 일반 필드 `CID`에 종속돼요. 학번 → 반 코드 → 반 이름처럼 두 단계를 거쳐 정해지는 걸 **이행 종속**이라고 해요. **개선**: 반 이름은 반 테이블(ZCLASS)로 옮기고, 학생 테이블에는 `CID`만 남겨요. 앞의 "테이블을 나누는 이유"가 바로 3정규형이에요.

**확인 순서.** ① 한 칸에 값이 여러 개인가(1NF) → ② 복합 키라면 키 일부만으로 정해지는 필드가 있나(2NF) → ③ 키가 아닌 필드로 정해지는 필드가 있나(3NF).

**일부러 중복을 두기도 해요.** 실무에서는 빠르게 읽으려고, 또는 그 시점의 값을 기록으로 남기려고 일부러 중복을 두기도 해요. 예를 들어 주문 품목에 그날의 판매 가격을 복사해 두면, 나중에 상품 가격이 바뀌어도 주문할 때의 가격이 그대로 남아요. 강사 성과금 지급 기록에 지급 당시의 숙련도와 배정일수를 복사해 두는 것도 같은 이유예요. 나중에 배정 정보가 바뀌어도, 그때 어떤 기준으로 계산했는지가 남아요. 중복이 보이면 무조건 틀렸다고 하기보다 "의도한 것인지"를 같이 적는 게 좋아요.

### ERD 그리기: 테이블과 선으로 그리는 설계도

**ERD**는 DB에 어떤 테이블이 있고 테이블끼리 어떻게 이어지는지를 **한 장에 그린 설계도**예요. 집을 짓기 전에 도면부터 그리는 것처럼, 테이블을 만들기 전에 ERD부터 그려요. 말로 설명하면 길어지는 구조를 그림 한 장으로 팀원과 맞출 수 있어요.

ERD는 아래 세 가지만 알면 읽을 수 있어요.

- **상자**는 테이블이에요. 상자 안에 필드를 적고, 키와 외래키를 표시해요.
- **선**은 두 테이블의 관계예요.
- **선 끝 모양**이 1인지 N인지 알려 줘요. 막대(`|`)는 1, 세 갈래로 갈라진 까마귀 발은 N이에요.

이 교재의 ERD는 **간단 표기**를 써요. 막대 하나는 "1", 까마귀 발은 "여러 개"만 나타내요. 0개도 되는지까지 적고 싶을 때는 앞의 카디널리티 표처럼 막대 두 개(꼭 1개), 동그라미 + 막대(0개 또는 1개)로 더 자세히 그려요.

&#91;embedded content: ERD 읽는 법 · 선 끝 모양\]

위 그림은 "반 한 개에 학생 여러 명"이라고 읽어요. 선은 **키(PK)에서 외래키(FK)로** 이어져요. 외래키는 N쪽 테이블에 있다는 것도 그림에서 확인돼요.

처음 그릴 때는 아래 순서를 따라가세요.

1. **담을 대상을 테이블로 정해요.** 학생, 반, 과목처럼 "따로 관리할 것"을 하나씩 상자로 놓아요.
2. **테이블마다 필드를 적고, 레코드를 구분하는 키를 정해요.**
3. **두 테이블 사이마다 물어봐요.** "한 ○○에 △△가 몇 개 있지?" 그리고 반대로 "한 △△는 ○○가 몇 개지?" 두 질문의 답이 관계(1:1, 1:N, N:M)를 정해요.
4. **N:M이 나오면 연결 테이블을 가운데 둬요.** 선이 모두 1:N이 되도록요.
5. **선을 긋고 1과 N을 표시해요.** N쪽 테이블에 외래키를 적어요.

아래 연습장에서 직접 그려 보세요. 테이블을 눌러 놓고, 테이블 두 개를 차례로 눌러 선을 그어요. 막히면 "정답 확인"을 눌러 어디가 틀렸는지 보세요.

### 더 알아둘 개념: 이름만 먼저 알아 두기

ABAP을 처음 배울 때는 몰라도 돼요. 선배나 문서에서 이 말을 들었을 때 "아, 그런 게 있구나" 하고 넘어갈 수 있게 한 줄씩만 적어요.

| 개념 | 한 줄 설명 |
| --- | --- |
| 인덱스(Index) | 책 뒤의 "찾아보기"처럼, 특정 필드로 빨리 찾게 미리 만들어 둔 색인이에요 |
| 트랜잭션(Transaction) | 여러 변경을 한 묶음으로 처리해서, 전부 성공하거나 전부 취소되게 하는 단위예요. 계좌 이체(출금과 입금)가 대표적인 예예요 |
| 락(Lock) | 한 사람이 수정하는 동안 다른 사람이 같은 레코드를 못 고치게 잠그는 장치예요 |
| 뷰(View) | 조인 결과를 저장해 둔 "가상의 테이블"이에요. 내용은 원래 테이블들에 있고, 이름만 따로 붙어요 |


## 2부. ABAP Dictionary ① — SE11에서 테이블 만들기

1부에서 테이블을 **설계**했다면, 2부와 3부에서는 그 테이블을 SAP 안에 **직접 만들어요.** 코드는 한 줄도 쓰지 않아요. SAP GUI의 **SE11** 화면에서 칸을 채우고 버튼을 눌러 만들어요. 수업에서도 SQL을 배우기 전에 이 순서로 진행해요.

2부는 **테이블 하나를 만드는 것**까지예요.

1. SAP GUI 첫 화면: 로그인, 명령 입력칸, T-code
2. SAP 테이블 읽는 법: Client, 이름, 도구
3. ABAP Dictionary: Domain과 Data Element로 필드 만들기
4. 저장할 곳 정하기: Package와 Transport Request
5. SE11에서 만드는 순서: Domain → Data Element → 테이블
6. Currency/Quantity Fields: 금액과 수량에는 단위 필드를 꼭 연결해요
7. 만든 뒤에 고칠 때: 공유 Data Element, 버전 되돌리기, SE14 변환
8. Structure, Table Type, Include, Append: 테이블이 아닌 DDIC 객체

테이블끼리 잇고 값을 검사하는 것은 3부에서 이어서 해요.

**SAP 연습용 항공 테이블.** SAP 시스템에는 연습용 항공 데이터가 처음부터 들어 있어요. 2·3부 예제에 자주 나오니까 이름만 먼저 알아 두세요. 테이블 이름에 마우스를 올리면(모바일은 탭) 샘플 데이터와 관계 그림이 떠요.

| 테이블 | 담는 것 | 키 (MANDT 빼고) |
| --- | --- | --- |
| SCARR | 항공사 (LH 루프트한자, AA 아메리칸 항공) | CARRID |
| SPFLI | 운항 노선 (항공사마다 노선 번호를 따로 매겨요) | CARRID, CONNID |
| SFLIGHT | 날짜별 운항편 (같은 노선이 날짜마다 1건) | CARRID, CONNID, FLDATE |
| SAPLANE | 기종 (747-400, A380-800) | PLANETYPE |

네 테이블이 어떻게 이어지는지는 3부 마지막 "여러 테이블의 관계와 제약 조건 분석하기"에서 자세히 분석해요.

### SAP GUI 첫 화면: 로그인, 명령 입력칸, T-code

2·3부의 모든 작업은 PC에 설치한 **SAP GUI**에서 해요. SAP 서버에 접속하는 전용 프로그램이에요. 웹 브라우저로 여는 UI5 앱과 달리, 개발 화면은 대부분 이 프로그램 안에 있어요.

&#91;embedded content: SAP GUI 첫 화면 · 로그인부터 T-code까지\]

**① 로그인.** SAP Logon에서 서버를 고르면 로그인 화면이 떠요.

| 칸 | 적는 것 | 수업 예 |
| --- | --- | --- |
| Client | 데이터 칸막이 번호(다음 섹션) | `100` |
| User / Password | 내 계정 | 수업에서 받은 계정 |
| Language | 화면 언어 | `EN` |

**② 첫 화면과 명령 입력칸.** 로그인하면 **SAP Easy Access** 화면이 떠요. 왼쪽 위의 흰 칸이 **명령 입력칸**(Command Field)이에요. 여기에 `SE11` 같은 짧은 코드를 치고 Enter를 누르면 그 화면이 열려요. 이 코드를 **Transaction Code**, 줄여서 **T-code**라고 불러요. SAP의 화면마다 T-code가 하나씩 붙어 있어요.

이 교재에서 쓰는 T-code예요. 지금 다 외울 필요는 없고, 나올 때마다 다시 설명해요.

| T-code | 하는 일 | 나오는 곳 |
| --- | --- | --- |
| `SE11` | 테이블, Data Element, Domain 만들고 보기 (ABAP Dictionary) | 2·3부 |
| `SE16` / `SE16N` | 테이블에 든 데이터 보기, 넣기 | 2·3부 |
| `SE21` / `SE80` | Package 만들기 / 개발 객체를 폴더처럼 모아 보기 | 2부 |
| `SE09` / `SE10` | 내 Transport Request 목록 | 2부 |
| `SE14` | DB 테이블 조정(변환) | 2부 |
| `SM30` | Z 테이블 입력 화면 | 3부 |
| `SE38` | ABAP 프로그램 만들기 | 5부 |
| `SE93` | 내 프로그램에 T-code 붙이기 | 5부 |

**③ 앞에 붙이는 기호.** 그냥 `SE11`은 첫 화면에서만 통해요. 다른 화면을 쓰는 중이면 앞에 기호를 붙여요.

| 입력 | 뜻 |
| --- | --- |
| `/nSE11` | 지금 화면을 끝내고 SE11로 가요 (저장 안 한 내용은 사라져요) |
| `/oSE16` | **새 창**(세션)에 SE16을 열어요. 지금 창은 그대로예요 |
| `/n` | 지금 화면을 끝내고 첫 화면으로 가요 |
| `/nend` | 로그오프해요 (확인 창이 떠요) |

**④ 자주 쓰는 키.**

| 키 | 하는 일 |
| --- | --- |
| Enter | 입력 확인, 다음 단계 |
| F3 | 뒤로(Back), 한 화면 전으로 |
| F8 | 실행(Execute) |
| F4 | 이 칸에 넣을 수 있는 값 목록 |
| F1 | 이 칸의 도움말. 아래 **Technical Information** 버튼을 누르면 이 칸의 테이블 이름과 필드 이름이 나와요 |
| Ctrl+S | 저장 |
| Ctrl+F1 | 보기(Display)와 고치기(Change) 모드 바꾸기 |

**⑤ 보기 모드와 고치기 모드.** SE11 같은 화면은 **Display**로 열면 보기만 하고, **Change**로 열어야 고칠 수 있어요. 남이 만든 객체나 SAP 표준 객체는 Display로 여는 습관을 들이세요(뒤의 "저장할 곳 정하기"에서 이유를 설명해요).

**⑥ 지금 어떤 화면인지 확인하기.** 메뉴 **System → Status**를 누르면 로그인한 Client와 User, 지금 화면의 **T-code와 프로그램 이름**이 나와요. "이 화면이 뭐지?" 싶을 때 써요.

### SAP 테이블 읽는 법: Client, 이름, 도구

SAP 테이블은 처음 보면 암호처럼 보여요. 규칙을 알면 읽을 수 있어요.

**Client와 `MANDT`.** SAP 시스템 하나 안에는 서로 다른 데이터 칸막이가 여러 개 있어요. 이 칸막이를 **Client**라고 불러요. 같은 시스템이어도 100번, 200번 Client는 데이터가 따로예요. 예를 들어 "연습용 100번"과 "시험용 200번"처럼 나눠 쓸 수 있어요.

그래서 SAP 테이블의 맨 앞 필드는 거의 항상 `MANDT`(독일어 Mandant, Client)예요. 다행히 SAP는 **로그인한 Client의 데이터만 자동으로** 보여 줘요. 그래서 평소에는 `MANDT`를 신경 쓰지 않아도 돼요.

&#91;embedded content: Client 칸막이 · MANDT로 나뉘는 데이터\]

**MANDT는 누가 채울까요?** 개발자가 할 일은 테이블의 **맨 앞 키에 `MANDT` 필드를 넣는 것**뿐이에요. 값은 SAP가 **로그인한 Client 번호**로 알아서 채워요. 다른 필드처럼 기본값을 따로 정할 필요가 없어요.

- **데이터를 넣을 때:** 입력 화면은 MANDT 칸을 묻지 않고, 저장하는 순간 로그인한 Client 번호를 넣어요.
- **데이터를 볼 때:** 로그인한 Client의 레코드만 보여요. 조건에 MANDT를 적지 않아도 돼요.
- 뒤에서 배울 입력 화면(SE16, SM30, 3부)과 SQL·ABAP 프로그램(4·5부)도 모두 이 규칙을 따라요.


**테이블 이름 규칙.**

- 내가 만든 테이블은 `Z`나 `Y`로 시작해요. 이 교재의 `ZSTUDENT`, `ZCLASS`가 그래요. SAP가 준 표준 테이블과 이름이 겹치지 않게 하려는 규칙이에요.
- SAP 표준 테이블은 독일어에서 온 4\~5글자 이름이 많아요. 자주 보는 것만 소개할게요.

| 테이블 | 담는 것 |
| --- | --- |
| MARA | 자재 마스터(자재 기본 정보) |
| MAKT | 자재 설명 (언어별 텍스트) |
| KNA1 | 고객 마스터 (S/4HANA에서는 Business Partner로 만들고, 데이터는 여기에도 저장돼요) |
| LFA1 | 공급업체 마스터 (KNA1과 같아요) |
| VBAK / VBAP | 판매 문서의 헤더(머리) / 아이템(품목) |
| EKKO / EKPO | 구매 문서의 헤더 / 아이템 |
| T001 | 회사 코드 목록 |

**필드 이름도 같은 식이에요.** `MATNR`(자재 번호), `WERKS`(플랜트, 공장), `KUNNR`(고객 번호), `MENGE`(수량), `WAERS`(통화), `SPRAS`(언어) 등이 있어요. 모르는 필드는 아래 도구로 찾아보세요.

**Text Table.** 코드의 이름(설명)은 따로 모은 테이블에 있어요. 예를 들어 자재 `MARA`에는 자재 번호만 있고, 자재 이름은 `MAKT`에 **언어별로** 저장돼요(`MATNR` + `SPRAS` + 이름). 로그인 언어에 맞는 레코드를 골라 보여 주는 거예요. 앞의 "테이블을 나누는 이유"가 SAP에서 쓰이는 방식이에요.

**테이블을 보는 도구 두 가지.**

- **SE11**(ABAP Dictionary): 테이블의 **구조**(필드 이름, 타입, 키)를 보는 화면이에요.
- **SE16**(또는 SE16N, 데이터 브라우저): 테이블에 **들어 있는 데이터**를 엑셀처럼 보는 화면이에요.

둘 다 앞에서 본 T-code예요. 명령 입력칸에 치고 Enter를 누르면 열려요. 구조는 SE11, 내용은 SE16이라고 기억하세요.

### ABAP Dictionary: Domain과 Data Element로 필드 만들기

SAP에서는 필드를 만들 때 바로 타입을 정하지 않고 **세 단계**를 거쳐요. 이 모든 정의를 모아 둔 곳이 **ABAP Dictionary**(DDIC)이고, 여는 화면이 SE11이에요.

| 단계 | 정하는 것 | 비유 |
| --- | --- | --- |
| Domain | 기술적 모양: 타입, 길이, 가능한 Fixed Value | 그릇의 크기와 모양 |
| Data Element | 의미: 이름, 화면에 보일 제목(필드 라벨) | 그릇에 붙이는 라벨 |
| 테이블 필드 | 위 둘을 가져다 테이블의 한 열로 쓴 것 | 실제로 놓인 그릇 |

&#91;embedded content: 필드가 만들어지는 세 단계 · Domain, Data Element, 필드\]

왜 나눌까요? **같은 의미의 필드는 어디서나 같은 모양이어야 하기 때문이에요.** "성별" Domain을 한 번 만들어 두면, 학생 테이블, 강사 테이블, 직원 테이블이 모두 같은 타입과 같은 Fixed Value(`1` 남성, `2` 여성)를 가져다 써요. 나중에 Domain만 고치면 모두 같이 바뀌어요.

Data Element에는 화면에 보일 제목(필드 라벨)이 들어 있어서, UI5 화면의 열 제목이 언어에 맞게 나오는 것도 여기서 와요. 6부에서 "모르는 필드명은 SE11에서 Data Element를 찾아본다"고 하는 이유예요.

**필드 → Data Element → Domain.** 방향부터 정리해요. 테이블 필드는 Data Element를 쓰고, Data Element는 Domain을 써요. 그래서 필드의 모양(타입, 길이)은 결국 Domain에서 오고, 필드의 의미(화면 라벨)는 Data Element에서 와요.

| | Domain | Data Element |
| --- | --- | --- |
| 정하는 것 | **기술적 모양**: 타입, 길이, 소수 자릿수, 넣을 수 있는 값의 범위 | **의미**: 화면에 보일 라벨, F1 도움말 |
| SE11에서 적는 곳 | Definition 탭(타입, 길이), Value Range 탭(값 범위) | Data Type 탭(쓸 Domain), Field Label 탭(라벨) |
| 예 (반 코드) | `ZCID`: CHAR, 길이 5, Value Table ZCLASS | `ZCID`: Domain `ZCID` 사용, 라벨 "반 코드" |
| 여러 곳에서 쓰기 | Domain 하나를 여러 Data Element가 같이 써요 | Data Element 하나를 여러 테이블 필드가 같이 써요 |

Domain 하나를 여러 Data Element가 같이 쓰는 예를 들어 볼게요. "현재 반"과 "이전 반"은 모양이 똑같은 반 코드지만 화면 라벨이 달라야 해요. 그래서 Domain은 `ZCID` 하나로 두고, Data Element를 `ZCID`(라벨 "반 코드")와 `ZCID_OLD`(라벨 "이전 반")로 두 개 만들어요.

**Data Element의 라벨.** Field Label 탭에는 짧게, 중간, 길게, 열 제목 네 가지 길이로 라벨을 적어요. 화면 공간에 맞춰 SAP가 알맞은 길이를 골라 써요. UI5 화면의 열 제목이 여기서 오는 경우가 많아요.

**Domain의 값 범위: Fixed Value와 Value Table.** Domain의 Value Range 탭에서 "이 Domain에 들어갈 수 있는 값"을 두 가지 방법으로 정해요.

- **Fixed Value**: 값이 몇 개 안 되고 거의 안 바뀔 때 Domain 안에 직접 적어요. 예: 성별 `1` 남성, `2` 여성. 입력 화면에서 자동으로 검사하고, **F4**(입력칸에서 누르면 넣을 수 있는 값 목록을 보여 주는 키)를 누르면 이 목록이 떠요.
- **Value Table**: 값이 많거나 자주 늘어날 때, "이 Domain의 값 목록은 이 테이블에 있어요"라고 테이블 이름을 적어 둬요. 예: 반 코드는 반이 생길 때마다 늘어나니까 Domain `ZCID`에 Value Table `ZCLASS`를 적어요.

### 저장할 곳 정하기: Package와 Transport Request

SE11이나 SE38에서 처음 저장하면 **어디에 저장할지** 묻는 창이 떠요. 이 창에서 고르는 것이 Package와 Transport Request예요.

| 용어 | 뜻 | 비유 |
| --- | --- | --- |
| **Package** | 관련된 개발 객체(테이블, Data Element, 프로그램)를 묶는 폴더 | 프로젝트 폴더 |
| **Local Object** (`$TMP`) | 다른 시스템으로 옮기지 않는 연습용 폴더 | 내 컴퓨터의 임시 폴더 |
| **Transport Request** | 바뀐 객체를 다른 시스템(테스트, 운영)으로 옮기기 위한 묶음 번호 | 택배 송장 |

SAP는 보통 시스템이 세 개예요. **개발**(DEV)에서 만들고, **테스트**(QAS)에서 확인하고, **운영**(PRD)에서 실제로 써요. 개발 시스템에서 만든 객체를 운영으로 옮기는 수단이 Transport Request예요.

&#91;embedded content: Transport 이동 · 개발에서 운영까지\]

- **`$TMP`로 저장하면** 요청 번호를 묻지 않아요. 대신 다른 시스템으로 절대 옮길 수 없어요. 혼자 연습할 때 써요.
- **수업이나 회사에서 정한 Package로 저장하면** Transport Request 번호를 물어요. 기존 요청을 고르거나 새로 만들어요. 내가 바꾼 객체가 그 요청에 기록돼요.
- 내 요청 목록은 **SE09**나 **SE10**에서 볼 수 있어요.

**Package 직접 만들기.** 수업이나 회사에서 정해 준 Package가 없으면 직접 만들어요.

1. 명령 입력칸에 `SE21`을 쳐요. (`SE80`에서 왼쪽 목록을 Package로 바꾸고 이름을 적어 만들어도 돼요.)
2. Package 이름을 적고 **Create**를 눌러요. 이름은 테이블처럼 `Z`나 `Y`로 시작해요. 예: `ZC05`
3. 창이 뜨면 칸을 채워요.

   | 칸 | 적는 것 |
   | --- | --- |
   | Short Description | Package 설명. 예: C05 교육 관리 |
   | Software Component | 고객이 직접 개발하는 객체는 보통 `HOME` |
   | Package Type | 객체를 직접 담는 Package면 **Development Package**(기본값) |
   | Transport Layer | 시스템이 제안하는 값을 그대로 둬요 |

4. 확인을 누르면 Transport Request 번호를 물어요. 기존 요청을 고르거나 새로 만들어요.

이제 테이블이나 프로그램을 저장할 때 이 Package 이름을 적으면 돼요. 만든 객체 목록은 `SE80`에서 Package 이름으로 열면 폴더처럼 한눈에 보여요. 칸 이름과 기본값은 시스템 설정마다 조금씩 달라요. 수업에서 정해 준 값이 있으면 그 값을 따르세요.

**주의.** 남의 객체를 Change 모드로 열 때도 요청 번호 창이 뜰 수 있어요. 여기서 확인을 누르면 그 객체가 **내 요청에 들어가요.** 보기만 할 거면 Display 모드로 열고, 요청 창이 뜨면 취소하세요.

### SE11에서 만드는 순서: Domain → Data Element → 테이블

앞에서 본 세 단계를 SE11에서 실제로 만들어 봐요. **만드는 순서가 중요해요.** 테이블 필드는 Data Element를 가리키고, Data Element는 Domain을 가리켜요. 가리킬 대상이 먼저 있어야 하니까 **Domain → Data Element → 테이블** 순서로 만들고, 하나 만들 때마다 **활성화**(Activate)해요.

활성화는 "저장한 내용을 SAP가 실제로 쓰는 최신 버전으로 확정"하는 거예요. 저장(Ctrl+S)만 하면 아직 초안이라서, 다른 Data Element나 테이블이 가져다 쓸 수 없어요. 활성화 단축키는 **Ctrl+F3**이에요.

&#91;embedded content: 저장과 활성화 · 두 가지 버전\]

SE11 첫 화면에는 무엇을 만들지 고르는 동그란 선택지가 있어요. 지금 쓰는 것은 세 가지예요.

| SE11 첫 화면의 선택지 | 만드는 것 |
| --- | --- |
| Database table | 테이블 |
| Data type | Data Element (그 밖에 Structure, Table Type도 여기서 만들어요) |
| Domain | Domain |

**① Domain 만들기 (예: `ZCID`)**

1. SE11에서 **Domain**을 고르고 이름 `ZCID`를 적은 뒤 **Create**를 눌러요.
2. **Short Description**에 설명을 적어요. 예: 반 코드
3. **Definition** 탭에서 **Data Type**은 `CHAR`, **No. Characters**(길이)는 `5`로 적어요.
4. 저장해요. 패키지를 물으면 수업에서 정한 패키지를 적어요. 연습용이면 **Local Object**(`$TMP`)로 저장해도 돼요.
5. 활성화(Ctrl+F3)해요.

**② Data Element 만들기 (예: `ZCID`)**

1. SE11에서 **Data type**을 고르고 이름 `ZCID`를 적은 뒤 **Create**를 눌러요. 무엇을 만들지 묻는 창에서 **Data Element**를 골라요.
2. **Short Description**을 적어요.
3. **Data Type** 탭에서 **Domain**을 고르고 `ZCID`를 적어요. Enter를 누르면 Domain의 타입과 길이가 자동으로 채워져요.
4. **Field Label** 탭에서 짧게(Short), 중간(Medium), 길게(Long), 열 제목(Heading) 네 칸에 "반 코드" 같은 라벨을 적어요.
5. 저장하고 활성화해요.

Domain과 Data Element의 이름은 같아도 돼요. 종류가 달라서 서로 겹치지 않아요. 수업에서도 같은 이름으로 만드는 경우가 많아요.

**③ 테이블 만들기 (예: `ZCLASS`)**

1. SE11에서 **Database table**을 고르고 이름 `ZCLASS`를 적은 뒤 **Create**를 눌러요.
2. **Short Description**을 적어요.
3. **Delivery and Maintenance** 탭에서 두 가지를 골라요.
   - **Delivery Class**: `A`(Application table, 업무 데이터를 담는 일반 테이블)
   - **Data Browser/Table View Editing**: **Display/Maintenance Allowed**. 이걸 골라야 나중에 SE16에서 데이터를 직접 넣을 수 있어요.
4. **Fields** 탭에서 필드를 한 줄씩 적어요.

| Field | Key | Initial Values | Data element | 뜻 |
| --- | --- | --- | --- | --- |
| `MANDT` | ✓ | ✓ | `MANDT` | Client (SAP 표준 Data Element) |
| `CID` | ✓ | ✓ | `ZCID` | 반 코드 (②에서 만든 것) |
| `CNAME` | | | `ZCNAME` | 반 이름 (같은 방법으로 미리 만들어 둬요) |

   - **Key**: 체크한 필드가 테이블의 키예요. 키 필드는 맨 위에 연달아 적어야 해요.
   - **Initial Values**: 키 필드는 보통 같이 체크해요. "빈 값 대신 초기값(빈칸, 0)을 넣어 둔다"는 설정이에요.
5. 위쪽의 **Technical Settings** 버튼을 눌러 **Data Class**(예: `APPL0` 마스터 데이터)와 **Size Category**(예: `0` 작은 테이블)를 고르고 저장한 뒤 돌아와요. 테이블을 DB에 실제로 만들 때 필요한 설정이라서, 빠뜨리면 활성화가 안 돼요.
6. 메뉴 **Extras → Enhancement Category**에서 범주를 골라요. 연습용이면 **Can Be Enhanced (Deep)** 같은 기본 선택을 그대로 써도 돼요. 안 고르면 활성화할 때 경고가 떠요.
7. 저장하고 활성화해요.

ZSTUDENT도 같은 순서로 만들어요. ZSTUDENT의 `CID`에도 Data Element `ZCID`를 쓰는 게 중요해요. 그래야 뒤에서 ZCLASS와 이을 수 있어요(3부 "SE11에서 외래키 걸기").

**활성화 순서 정리.** Domain → Data Element → **부모 테이블(ZCLASS)** → 자식 테이블(ZSTUDENT) 순서예요. 가리킬 대상이 먼저 활성화돼 있어야 해요.

### Currency/Quantity Fields: 금액과 수량에는 단위 필드를 꼭 연결해요

금액이나 수량은 숫자만으로는 뜻이 정해지지 않아요. `1000`이 1,000원인지 1,000달러인지, `6162`가 킬로미터인지 마일인지 알 수 없어요. 그래서 SAP는 금액·수량 타입 필드에 **단위를 담은 필드(참조 필드)를 반드시 연결해** 두게 해요.

| 값 필드의 타입 | 연결할 참조 필드의 타입 | 예 (SAP 항공 모델) |
| --- | --- | --- |
| `CURR` (금액) | `CUKY` (통화 키: KRW, USD, EUR) | SFLIGHT의 `PRICE` ↔ `CURRENCY` |
| `QUAN` (수량) | `UNIT` (단위: KM, MI, EA) | SPFLI의 `DISTANCE` ↔ `DISTID` |

**SE11에서 정하는 곳.** 테이블의 **Currency/Quantity Fields** 탭에서, 금액·수량 필드 옆의 **Reference table**과 **Ref. field** 칸에 연결할 테이블과 필드를 적어요. 보통은 같은 테이블의 단위 필드를 적어요. 예: `PRICE` → Reference table `SFLIGHT`, Ref. field `CURRENCY`.

&#91;embedded content: 참조 필드 연결 · 값과 단위\]

- **빠뜨리면 활성화가 안 돼요.** `CURR`나 `QUAN` 필드에 참조 필드가 없으면 활성화할 때 오류가 나요. 테이블을 처음 만들 때 가장 많이 막히는 곳이에요.
- **왜 이렇게까지 할까요?** 통화마다 소수점 자릿수가 달라요. 원화와 엔화는 소수점이 없고, 달러는 둘째 자리까지 있어요. SAP는 참조 필드를 보고 금액을 화면에 맞게 보여 줘요. 수량도 단위를 알아야 KM ↔ MI 같은 변환과 합계를 제대로 할 수 있어요.
- **통화 키의 기본값은 SE11에서 정할 수 없어요.** "통화는 늘 KRW"처럼 미리 채우고 싶으면 입력 화면 쪽에서 해요. SM30에서 채우는 방법은 3부 "Table Maintenance Generator와 SM30"에서 따라 해 봐요.
- **단위가 섞이면 조심해요.** SPFLI에는 같은 구간인데도 노선마다 `KM`과 `MI`가 섞여 있어요. 단위를 보지 않고 `DISTANCE`만 더하거나 정렬하면 틀린 결과가 나와요.

### 만든 뒤에 고칠 때: 공유 Data Element, 버전 되돌리기, SE14 변환

테이블을 한 번 활성화한 뒤에 고칠 때는 조심할 것이 세 가지 있어요.

**① Domain과 Data Element는 여러 테이블이 같이 써요.** 앞의 "ABAP Dictionary"에서 본 것처럼, Domain이나 Data Element를 고치면 **그걸 쓰는 모든 필드가 같이 바뀌어요.** 편리하지만, 한 테이블만 바꾸려다 다른 테이블까지 망가뜨리기 쉬워요.

예를 들어 성과금 Data Element `ZEC05BONUS`(Domain `ZDC05BONUS`, CURR 15,2)를 지급 테이블과 배정 테이블이 같이 쓴다고 해요. 배정 테이블에 3자리 순번이 필요하다고 `ZEC05BONUS`의 Domain을 `ZDC05PAYNO`(NUMC 3)로 바꾸면 어떻게 될까요? 활성화하는 순간 **지급 테이블의 금액 필드도 NUMC 3이 돼요.** 금액을 담을 수 없고, CURR가 아니라서 통화 참조도 깨져요.

- **고치기 전에 누가 쓰는지 확인해요.** Data Element나 Domain 화면에서 **Where-Used List**(메뉴 Utilities, 또는 Ctrl+Shift+F3)를 누르면 그걸 쓰는 테이블과 프로그램이 나와요.
- **모양이 다른 필드가 필요하면 새 Data Element를 만들어요.** 순번이 필요하면 `ZEC05PAYNO` 같은 순번용 Data Element를 따로 써요. 남이 쓰는 것을 고치지 않아요.

**② 잘못 고쳤으면 활성 버전으로 되돌려요.** 저장만 하고 활성화하지 않은 변경은 **비활성 버전**(Inactive)으로 남아요. 화면 위에 이름 옆으로 `Inactive`나 `Revised`가 보이면, 지금 보는 게 아직 확정되지 않은 버전이라는 뜻이에요. 다른 테이블은 여전히 **활성 버전**을 쓰고 있어요.

- 가장 쉬운 방법은 원래 값으로 다시 고치고 저장, 활성화하는 거예요.
- 무엇을 바꿨는지 기억나지 않으면 메뉴 **Utilities → Versions → Version Management**를 열어요. 활성 버전과 비활성 버전이 나란히 나와요. 두 버전을 비교(Compare)해 보고, 활성 버전을 골라 **Retrieve**를 누르면 그 내용으로 돌아가요.

**③ 필드 모양을 바꾸면 DB 테이블도 바뀌어야 해요: SE14.** 테이블을 처음 활성화하면 DB 안에 실제 테이블이 만들어져요. 그 뒤에 **필드의 타입이나 길이를 바꾸거나, 키를 바꾸거나, 필드를 지우면** SE11만 고쳐서는 끝나지 않아요. DB의 실제 테이블도 새 모양으로 다시 만들어야 해요. 이걸 **변환**(Conversion)이라고 해요.

활성화 결과(Activation Log, 메뉴 Utilities)에 이런 메시지가 보이면 변환이 필요하다는 뜻이에요.

```
Structure change at field level (convert table YTC0511)
```

먼저 **의도한 변경인지** 확인해요. ①처럼 공유 Data Element를 잘못 고쳐서 생긴 거라면, 변환하지 말고 Data Element부터 되돌려요. 의도한 변경이 맞으면 SE14로 변환해요.

1. 명령 입력칸에 `SE14`(Database Utility)를 쳐요.
2. Object Name에 테이블 이름을 적고 **Edit**를 눌러요.
3. Processing Type은 **Direct**로 둬요.
4. 데이터를 어떻게 할지 골라요.
   - **Save data**: 들어 있는 데이터를 살리면서 바꿔요. 실제 데이터가 있으면 이걸 골라요.
   - **Delete data**: 데이터를 지우고 새로 만들어요. 연습 데이터뿐이면 빠르고 깔끔해요.
5. **Activate and adjust database**를 누르고, SE11에서 테이블이 Active인지 확인해요.

Save data를 골라도 CURR → NUMC처럼 타입이 크게 바뀌면 값이 깨지거나 사라질 수 있어요. 데이터가 많은 운영 테이블은 변환에 시간도 오래 걸려요. 그래서 실무에서는 **이미 쓰고 있는 테이블의 필드 모양을 함부로 바꾸지 않아요.**

### Structure, Table Type, Include, Append: 테이블이 아닌 DDIC 객체

SE11의 **Data type**에서는 Data Element 말고도 두 가지를 더 만들 수 있어요. 또 테이블 화면에는 다른 필드 묶음을 가져다 붙이는 기능이 있어요.

| 객체 | 뜻 | 데이터가 저장되나 | 어디에 쓰나 |
| --- | --- | --- | --- |
| **Structure** | 필드 여러 개를 묶은 **모양(타입)**. 테이블처럼 필드를 적지만 DB 테이블은 아니에요 | 아니요 | ABAP에서 레코드 1건 모양의 변수 타입(5부), 화면 입력 묶음 |
| **Table Type** | "이 Structure가 여러 건 들어가는 목록"이라는 타입 | 아니요 | ABAP 프로그램 안의 임시 목록(Internal Table, 4부)의 타입 |
| **Include** | 여러 테이블에 똑같이 들어가는 필드 묶음(Structure)을 한 번에 끼워 넣기 | 넣은 테이블에 저장 | 예: 만든 사람, 만든 날짜 같은 공통 필드 |
| **Append Structure** | SAP 표준 테이블을 직접 고치지 않고 뒤에 내 필드를 덧붙이기 | 원래 테이블에 저장 | 표준 테이블에 회사 전용 필드(`ZZ`로 시작) 추가 |

&#91;embedded content: 테이블이 아닌 DDIC 객체 · 네 가지 비교\]

- **Structure와 테이블의 차이.** 둘 다 필드 목록이 있지만, **테이블은 DB에 데이터를 저장하고 Structure는 모양만 정의해요.** 그래서 Structure에는 키, Technical Settings, Delivery Class가 없어요.
- **Include 넣는 법.** 테이블의 Fields 탭에서 Field 칸에 `.INCLUDE`라고 적고, Data element 칸에 Structure 이름을 적어요. 그 Structure의 필드들이 한꺼번에 들어와요.
- **Append Structure는 표준 테이블용이에요.** 표준 테이블 화면의 **Append Structure...** 버튼으로 만들어요. 표준 테이블은 SAP가 업그레이드할 때 덮어쓰니까 직접 고치면 안 돼요. Append로 붙인 필드는 업그레이드해도 남아요. 이때 표준 테이블의 Enhancement Category가 확장을 허용해야 해요(앞의 "SE11에서 만드는 순서" 6번).

## 3부. ABAP Dictionary ② — 테이블 잇기와 값 검사

2부에서 만든 테이블들을 **외래키로 잇고**, 필드에 **넣을 수 있는 값을 검사**하는 방법이에요. 마지막에는 여러 테이블의 관계와 제약 조건을 분석해 봐요. 여기도 코드와 SQL은 나오지 않아요.

1. Value Table → Check Table → Check Field
2. SE11에서 외래키 걸기
3. 외래키 설정 자세히: Foreign key field type, 카디널리티, KEY·REF
4. SE16에서 데이터 넣어 보고 Check Table 확인하기
5. Table Maintenance Generator와 SM30
6. 외래키를 쓸 때 주의할 점
7. Text Table 만들기
8. Input Help/Check 탭과 Search Help
9. 여러 테이블의 관계와 제약 조건 분석하기 (SCARR, SPFLI, SFLIGHT)

### Value Table → Check Table → Check Field

세 이름이 비슷해서 가장 많이 헷갈리는 부분이에요. 한 줄로 먼저 정리하면 이래요.

- **Value Table**: Domain에 적어 두는 **제안**이에요. 혼자서는 아무것도 검사하지 않아요.
- **Check Table**: 필드에 외래키를 걸 때 정하는 **실제 검사 기준** 테이블이에요.
- **Check Field**: 외래키를 건 필드, 즉 **검사를 받는 쪽** 필드예요.

&#91;embedded content: Value Table과 Check Table · 제안에서 검사까지\]

순서대로 보면 이렇게 이어져요.

1. **Domain에 Value Table을 적어요.** Domain `ZCID`의 Value Table은 `ZCLASS`예요. 아직 검사는 하나도 일어나지 않아요.
2. **외래키를 만들 때 Check Table로 제안돼요.** ZSTUDENT의 `CID` 필드는 Data Element `ZCID`를 거쳐 Domain `ZCID`를 써요. 그래서 이 필드에 외래키를 만들려고 하면 SE11이 "Check Table은 ZCLASS 아닌가요?" 하고 미리 채워 줘요. 확정하면 ZCLASS가 이 외래키의 **Check Table**이 되고, 외래키를 가진 ZSTUDENT는 **Foreign Key Table**이라고 불러요.
3. **Check Field 값을 Check Table에서 찾아봐요.** 외래키를 건 `ZSTUDENT-CID`가 **Check Field**예요. 입력 화면에서 여기에 값을 넣으면, SAP가 그 값이 ZCLASS의 키 필드 `CID`에 있는지 확인해요. 없으면 오류를 내고, F4를 누르면 ZCLASS의 반 목록을 보여 줘요.

| 구분 | 어디에 정하나 | 검사하나 | 예 |
| --- | --- | --- | --- |
| Fixed Value | Domain (Value Range 탭) | 해요 (입력 화면) | 성별 `1`, `2` |
| Value Table | Domain (Value Range 탭) | **안 해요.** Check Table 후보로 제안만 해요 | Domain `ZCID` → `ZCLASS` |
| Check Table | 테이블 필드의 외래키 (직접 고를 수 있어요) | 해요 (입력 화면) + F4 목록 | `ZSTUDENT-CID`의 외래키 → `ZCLASS` |
| Check Field | 외래키를 건 필드 그 자체 | 검사를 **받는** 쪽 | `ZSTUDENT-CID` |

**SAP 표준 예.** 나라 코드 Domain `LAND1`의 Value Table은 나라 목록 테이블 `T005`예요. 고객 마스터 `KNA1`의 나라 필드 `LAND1`에는 Check Table `T005`로 외래키가 걸려 있어요. 나라 코드를 쓰는 테이블이 아주 많은데, 모두 같은 Domain을 쓰니까 외래키를 만들 때마다 `T005`가 제안돼요. Value Table은 이렇게 "매번 같은 Check Table을 적는 수고"를 덜어 주는 장치예요.

**Value Table과 Check Table이 다를 수도 있어요.** Check Table은 외래키를 만들 때 **직접 고르는 것**이에요. Value Table은 그 칸을 미리 채워 주는 추천일 뿐이라서, 지우고 다른 테이블을 적으면 둘이 달라져요. Value Table이 없는 Domain이면 칸이 비어 있어서 처음부터 직접 적어요.

예를 들어 강사 국적(`NATIO`, Domain `LAND1`)을 전 세계 나라가 아니라 **학원이 운영하는 나라만** 받고 싶다고 해 볼게요.

1. 운영 국가만 담은 테이블 `ZCOUNTRY`를 만들어요. 키는 `MANDT` + `LAND1`이고, `LAND1`은 Domain `LAND1`을 쓰는 Data Element로 만들어요. 데이터는 `KR`, `US`, `JP`만 넣어요.
2. 강사 테이블의 `NATIO`에 외래키를 만들 때, SE11이 제안한 `T005`를 지우고 `ZCOUNTRY`를 적어요.
3. `ZCOUNTRY-LAND1`에도 Check Table `T005`로 외래키를 걸어 두면, ZCOUNTRY에는 실제로 있는 나라 코드만 들어가요.

&#91;embedded content: Check Table 직접 고르기 · ZCOUNTRY 예\]

이제 강사 국적에서 F4를 누르면 세 나라만 뜨고, `DE`처럼 T005에는 있지만 ZCOUNTRY에 없는 코드는 오류가 나요. 다른 테이블의 나라 필드는 여전히 `T005`가 제안돼요.

**직접 고를 때 조건은 하나예요.** 검사받는 필드와 Check Table의 키 필드가 **같은 Domain**을 써야 해요. 그래야 SE11이 필드 짝을 지어 줘요. 그래서 1번에서 `ZCOUNTRY-LAND1`이 Domain `LAND1`을 쓰게 만든 거예요.

<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz
Q: Domain LAND1의 Value Table은 T005예요. 강사 테이블 NATIO(Domain LAND1)에 외래키를 만들면서 Check table 칸을 ZCOUNTRY로 바꿨어요.
Q: 입력 화면에서 NATIO 값은 무엇으로 검사할까요?
- T005로 검사해요. Value Table이 우선이에요
- ZCOUNTRY로 검사해요 ✓
- T005와 ZCOUNTRY 둘 다에 있어야 해요
- 검사하지 않아요
> 실제 검사는 외래키에서 정한 Check Table로 해요. Value Table은 처음에 칸을 채워 주는 추천일 뿐이에요.
```

</details>

**헷갈리기 쉬운 이름 하나 더.** SE11 외래키 창의 `ChkTablFld`(Check Table Field)는 Check Field가 아니라 **비교 대상**인 Check Table 쪽 키 필드(`ZCLASS-CID`)예요. Check Field는 외래키를 건 `ZSTUDENT-CID`예요.

**자주 하는 오해.** "Domain에 Value Table을 적었는데 아무 값이나 들어가요." Value Table은 제안일 뿐이라서, 필드에 **외래키를 만들어야** 검사가 시작돼요. 외래키를 거는 방법은 바로 다음 "SE11에서 외래키 걸기"에서 따라 해 봐요.

<details class="more practice">
<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz

Q: 입력 화면에서 CID에 ZCLASS에 없는 반 코드를 넣으면?
- 오류가 나서 저장되지 않아요
- 검사 없이 그대로 들어가요 ✓
- Value Table에 그 반이 자동으로 추가돼요
- Domain이 비활성화돼요
> Value Table은 Check Table 후보를 제안만 해요. 검사는 외래키를 만들어 Check Table이 정해진 뒤부터 일어나요.
```

```quiz

Q: 이 외래키의 Check Field는?
- `ZCLASS-CID`
- `ZSTUDENT-CID` ✓
- Domain `ZCID`
- `ZCLASS-CNAME`
> Check Field는 외래키를 건 필드, 즉 검사를 받는 쪽이에요. ZCLASS-CID는 비교 대상인 Check Table의 키 필드예요.
```

### SE11에서 외래키 걸기: Check Table 연결

1부 "외래키와 조인"에서 본 **Check Table**을 실제 SAP 화면에서 거는 방법이에요. 목표는 하나예요. 학생 테이블(ZSTUDENT)의 `CID`에 반 테이블(ZCLASS)에 없는 반 코드가 들어가지 못하게 막는 거예요.

**시작 전에 두 가지를 확인해요.**

1. **부모 테이블이 먼저 활성화돼 있어야 해요.** 가리킬 대상인 ZCLASS가 활성화(Activate)되지 않았으면 외래키를 걸 수 없어요.
2. **두 필드가 같은 Domain을 써야 해요.** SAP는 Domain이 같아야 "같은 종류의 값"으로 보고 짝을 지어 줘요. 가장 쉬운 방법은 두 테이블의 `CID`에 같은 Data Element를 쓰는 거예요.

| 필드 | Data Element | Domain |
| --- | --- | --- |
| `ZCLASS-CID` (부모, 키) | `ZCID` | `ZCID` |
| `ZSTUDENT-CID` (자식, 외래키) | `ZCID` | `ZCID` |

Domain `ZCID`에 Value Table `ZCLASS`를 적어 두었다면(앞 섹션), 4단계의 Check table 칸은 처음부터 `ZCLASS`로 채워져 있어요. 이 외래키에서 `ZSTUDENT-CID`가 Check Field예요.

&#91;embedded content: SE11 외래키 따라 하기 · 일곱 단계\]

화면의 버튼 이름은 SAP 버전이나 로그인 언어에 따라 조금 다를 수 있어요. 열쇠 모양 아이콘과 "Foreign Keys", "Check table", "Generate proposal" 같은 단어를 찾으면 돼요.

**결과 확인하기.** 데이터를 입력하는 SAP 화면(뒤의 "SE16에서 데이터 넣어 보고 Check Table 확인하기")에서 `CID` 칸에 커서를 두고 F4를 누르면 ZCLASS의 반 목록이 떠요. 목록에 없는 반 코드를 적으면 오류 메시지가 나오고 저장되지 않아요. Check Table이 제대로 걸렸다는 뜻이에요.

**꼭 알아 둘 점: 검사는 SAP 입력 화면에서 일어나요.** SE16 같은 입력 화면이 Check Table을 보고 값을 검사해요. 데이터베이스 자체에 막는 장치가 생기는 건 아니에요. 그래서 ABAP 프로그램으로 데이터를 넣을 때(`INSERT`)는 이 검사가 저절로 일어나지 않아요. 프로그램에서는 넣기 전에 부모 테이블에 그 값이 있는지 직접 확인해야 해요(5부 "키로 데이터 읽기").

**자주 막히는 곳**

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 외래키 버튼이 회색이라 안 눌려요 | 표시(Display) 모드로 열었어요 | Change를 눌러 변경 모드로 바꿔요 |
| 제안 생성을 눌러도 필드 짝이 안 채워져요 | 두 `CID`의 Domain이 달라요 | 같은 Data Element(또는 같은 Domain)로 맞춰요 |
| Check Table을 적으면 오류가 나요 | ZCLASS가 아직 활성화되지 않았어요 | ZCLASS를 먼저 활성화해요 |
| 엉뚱한 필드에 외래키가 걸렸어요 | 버튼을 누를 때 커서가 다른 필드에 있었어요 | 외래키를 지우고, `CID`에 커서를 둔 뒤 다시 만들어요 |

ERD 설계 도구에서 ZCLASS와 ZSTUDENT를 잇는 선 하나가, 여기서 거는 외래키 설정 하나예요. ERD로 먼저 그려 두면 어느 필드에 외래키를 걸지 바로 보여요.

<details class="more practice">
<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz
Q: ZSTUDENT의 CID에 Check Table ZCLASS를 걸었어요. SE16에서 새 학생을 넣으면서 CID에 ZCLASS에 없는 CL999를 적었어요.
Q: 저장하면 어떻게 될까요?
- 그대로 저장돼요
- 오류가 나고 저장되지 않아요 ✓
- ZCLASS에 CL999가 자동으로 만들어져요
- CID가 빈칸으로 저장돼요
> CID는 Check Field라서, 입력 화면이 그 값이 Check Table ZCLASS의 키에 있는지 검사해요.
```

```quiz
Q: Generate proposal을 눌렀는데 필드 짝이 채워지지 않아요.
Q: 가장 먼저 확인할 것은?
- 카디널리티를 골랐는지
- 두 테이블의 CID가 같은 Domain을 쓰는지 ✓
- 테이블 이름이 Z로 시작하는지
- SE16에 데이터가 들어 있는지
> SAP는 Domain이 같은 필드끼리만 외래키 짝을 지어 줘요.
```

</details>

### 외래키 설정 자세히: Foreign key field type, 카디널리티, KEY·REF

외래키 창(Create Foreign Key)의 아래쪽에는 **의미를 적는 칸**이 두 가지 있어요. 이 칸은 검사 방식을 바꾸지 않아요. "이 관계가 어떤 관계인지"를 기록해 두는 거예요. 대신 SE11 그래픽, 뷰, 도구들이 이 정보를 읽어서 써요.

**① Foreign key field type: 외래키 필드가 자식 테이블에서 어떤 자리인가**

| 선택지 | 뜻 | 예 | SE11 그래픽 표시 |
| --- | --- | --- | --- |
| Key fields/candidates | 외래키 필드가 자식 테이블의 **키(의 일부)**예요. 식별 관계 | SPFLI-CARRID → SCARR | **KEY** |
| Non-key-fields/candidates | 외래키 필드가 **일반 필드**예요. 비식별 관계 | 강사-NATIO → T005, SFLIGHT-PLANETYPE → SAPLANE | **REF** |
| Key fields of a text table | 자식 테이블이 부모의 **Text Table**이에요(뒤의 "Text Table 만들기") | T005T-LAND1 → T005 | KEY |
| Not specified | 정하지 않음 | | |

**② 카디널리티: `왼쪽 : 오른쪽`**

- **왼쪽**은 Check Table(부모) 쪽이에요. 자식 레코드 하나가 부모 몇 건과 이어지나요?
  - `1`: 반드시 1건이에요. 외래키 필드를 비울 수 없어요.
  - `C`: 0건 또는 1건이에요. 외래키 필드를 비워 둘 수 있어요(Conditional).
- **오른쪽**은 자식(Foreign Key Table) 쪽이에요. 부모 레코드 하나에 자식이 몇 건 달리나요?

| 오른쪽 | 뜻 |
| --- | --- |
| `1` | 정확히 1건 |
| `C` | 0건 또는 1건 |
| `N` | 1건 이상 |
| `CN` | 0건 이상 |

| 예 | 카디널리티 | 읽는 법 |
| --- | --- | --- |
| SCARR → SPFLI | `1 : CN` | 노선은 반드시 항공사 1개에 속하고, 항공사는 노선을 0개 이상 가져요 |
| T005 → 강사-NATIO (비워도 됨) | `C : CN` | 강사는 국적이 없을 수도 있고, 나라 하나에 강사가 0명 이상이에요 |
| 식별 관계 | `1 : …` | 외래키가 키의 일부라 비울 수 없어서, 왼쪽이 `C`일 수 없어요 |

**③ Screen check.** 외래키 창의 **Check required** 체크는 "입력 화면에서 실제로 검사할지"예요. 기본은 켜져 있어요. 끄면 외래키 관계는 남지만 입력 검사는 하지 않아요.

**SE11 그래픽 읽기.** 테이블 화면의 그래픽 버튼(Graphic)을 누르면 외래키 관계를 그림으로 보여 줘요. 선 위의 `1:CN`이 카디널리티이고, 그 아래 `KEY`나 `REF`가 ①의 종류예요. 이 그래픽은 **걸려 있는 외래키를 모두** 그려서, 개념 ERD보다 선이 많아요. 예를 들어 Client 목록 T000으로 가는 선이 테이블마다 그려져요. 또 SFLIGHT-CARRID가 SPFLI를 거치지 않고 SCARR를 바로 가리키는 외래키도 따로 걸려 있어서, SCARR → SFLIGHT 선이 하나 더 보여요.

### SE16에서 데이터 넣어 보고 Check Table 확인하기

테이블을 만들었으면 데이터를 넣어 봐요. 여기서도 코드는 쓰지 않아요.

1. 명령 입력칸에 `SE16`을 치고, 테이블 이름 `ZCLASS`를 적어요.
2. 메뉴 **Table Entry → Create**(또는 F5)를 눌러 입력 화면을 열어요. 이 메뉴가 회색이면 테이블의 **Data Browser/Table View Editing**이 **Display/Maintenance Allowed**인지 확인해요.
3. `CL301`, `ABAP반`처럼 값을 적고 저장해요. `MANDT`는 로그인한 Client 번호가 자동으로 들어가요.
4. 이번엔 `ZSTUDENT`를 열고 새 학생을 넣어요. `CID` 칸에 커서를 두고 **F4**를 누르면 ZCLASS의 반 목록이 떠요. Check Table이 걸려 있다는 뜻이에요.
5. `CID`에 ZCLASS에 없는 코드(예: `CL999`)를 적고 저장해 보세요. 오류 메시지가 나오고 저장되지 않아요. 이게 Check Field 검사예요.

넣은 데이터는 SE16 첫 화면에서 실행(F8)하면 엑셀처럼 볼 수 있어요. **구조는 SE11, 데이터는 SE16**이에요.

### Table Maintenance Generator와 SM30: Z 테이블 입력 화면 만들기

SE16의 입력 화면은 개발자용이에요. 업무 담당자가 Z 테이블에 데이터를 넣고 고치게 하려면 보통 **Table Maintenance Generator**(TMG)로 전용 입력 화면을 만들고, **SM30**에서 열게 해요.

**만드는 순서**

1. SE11에서 테이블을 Change 모드로 열고, **Delivery and Maintenance** 탭의 Data Browser/Table View Editing이 **Display/Maintenance Allowed**인지 확인해요.
2. 메뉴 **Utilities → Table Maintenance Generator**를 열어요.
3. 칸을 채워요.

   | 칸 | 적는 것 | 예 |
   | --- | --- | --- |
   | Authorization Group | 이 화면을 쓸 권한 묶음. 연습용은 권한 제한 없음 | `&NC&` |
   | Function Group | 화면 프로그램을 담을 그룹. 없으면 새 이름을 적어요 | `ZFG_TC0510` |
   | Maintenance type | 화면 구성. 목록 화면 하나로 넣고 고치면 **one step** | one step |
   | Maint. Screen No. | 화면 번호. **Find Scr. Number(s)**를 누르면 제안해 줘요 | |

4. **Create**(새로 만들기 아이콘)를 누르고, Package와 Transport Request를 정해 저장해요.
5. 명령 입력칸에 `SM30`을 치고 테이블 이름을 적은 뒤 **Maintain**을 눌러요. 엑셀처럼 줄을 추가하고 고칠 수 있는 화면이 열려요.

**SE16과 비교**

| | SE16 Create Entries | SM30 (TMG) |
| --- | --- | --- |
| 쓰는 사람 | 개발자, 테스트 | 업무 담당자 |
| 화면 | 한 건씩 입력 | 목록에서 여러 건을 한꺼번에 추가, 수정, 삭제 |
| 권한 | 개발 권한 필요 | Authorization Group으로 따로 관리 |
| Check Table 검사 | 해요 | 해요 |

**주의.** 테이블에 필드를 추가하거나 바꾸면 TMG 화면은 자동으로 바뀌지 않아요. TMG 화면에서 **Change**로 다시 만들어야 새 필드가 보여요.

**새 줄에 기본값 넣기: 이벤트 05.** SE11에는 필드의 기본값(예: 통화는 늘 KRW)을 적는 칸이 없어요. Fields 탭의 Initial Values는 빈칸이나 0 같은 초기값을 넣는 설정일 뿐이에요. SM30으로 넣을 때 기본값을 채우려면 TMG의 **이벤트**(Event)를 써요. 이벤트는 "새 줄을 만들 때", "저장하기 전"처럼 정해진 순간에 내가 적은 코드를 실행해 주는 장치예요. 새 줄을 만드는 순간은 **05번**이에요.

아래 예는 ZCLASS에 수강료 `FEE`(CURR)와 통화 `WAERS`(CUKY)를 추가했다고 보고, 새 반을 넣을 때 통화가 KRW로 미리 채워지게 해요.

&#91;embedded content: 통화 키 기본값 넣기 · TMG 이벤트 05\]

- 코드 창에 적는 한 줄은 ABAP이에요. 지금은 `테이블이름-필드 = '값'.` 모양만 따라 적으면 돼요. 문법은 5부에서 배워요.
- 이 기본값은 **SM30 화면에서만** 채워져요. SE16으로 넣거나 프로그램에서 `INSERT`할 때는 그쪽에서 값을 직접 넣어야 해요.

### 외래키를 쓸 때 주의할 점

외래키를 걸고 SE16, SM30으로 데이터를 넣어 봤다면, 실제 과제에서 자주 헷갈리는 점 네 가지를 정리해 둘게요.

**① 검사는 입력 화면에서만 해요.** SAP의 외래키는 DB가 직접 막아 주는 규칙이 아니에요. SE11 안에만 있는 정보예요. 그래서 검사는 **SE16, SM30 같은 입력 화면**에서 값을 넣을 때만 일어나요.

- 5부에서 배울 ABAP 프로그램으로 `INSERT`하면 외래키를 검사하지 않아요. Check Table에 없는 값도 그대로 들어가요.
- 그래서 프로그램으로 넣을 때는 **넣기 전에 직접 확인**해요(5부 "키로 데이터 읽기"의 "넣기 전에 부모 테이블에 값이 있는지 확인하기").

**② 외래키는 Check Table의 키를 가리켜요.** Check Table 쪽 짝은 항상 **그 테이블의 키 필드**예요. 키가 아닌 필드는 가리킬 수 없어요.

- 예를 들어 배정 테이블(키: 과정 + 날짜)에 숙련도가 있고, 지급 테이블에도 숙련도를 복사해 둔다고 해요. 지급 테이블의 숙련도를 배정 테이블의 숙련도로 외래키를 걸 수는 없어요. 배정 테이블의 키가 아니니까요.
- 어느 배정에서 나온 지급인지는 **키(과정 + 날짜) 외래키 하나**로 이미 연결돼 있어요. 복사해 둔 값은 프로그램이 넣어요. 왜 복사해 두는지는 1부 "정규화"의 "일부러 중복을 두기도 해요"를 보세요.
- 짝이 되는 두 필드는 **Domain이 같아야** 하지만, 필드 이름과 Data Element는 달라도 돼요. 예를 들어 교육과정 테이블의 `MAINT`(메인 강사, Data Element `ZEC05MAINT`)가 강사 테이블의 `TEHNO`(강사 번호, `ZEC05TEHNO`)를 가리킬 수 있어요. 둘 다 Domain `ZDC05TEHNO`를 쓰면 돼요. Data Element를 따로 두면 화면 라벨이 "메인 강사"로 나와서 의미가 더 분명해져요.

**③ 두 테이블이 서로를 가리키면 안 돼요.** 외래키는 **자식 → 부모** 한 방향이에요. 반대 방향 외래키까지 걸면 순환이 돼요.

```
배정 ZTC0511 ──(BONUS)──▶ 지급 YTC0511
     ▲                           │
     └──────────(키)─────────────┘
```

- 배정을 넣으려면 지급이 먼저 있어야 하고, 지급을 넣으려면 배정이 먼저 있어야 해요. 데이터를 넣을 수 있는 순서가 없어요.
- 부모에 자식의 값을 담는 필드(위의 BONUS)가 있다면 그 필드부터 지워요. 부모에서 자식 값이 필요하면 JOIN으로 읽어요(4부).

**④ MANDT → T000은 걸어도 거의 차이가 없어요.** `MANDT`는 로그인한 Client로 자동으로 채워지고, 입력 화면에도 칸이 없어요. 사용자가 값을 넣을 일이 없으니 검사할 기회도 없어요.

- 걸어 두면 SE11 그래픽의 관계도에 T000 선이 그려지는 정도예요. SAP 표준 테이블도 많이 걸어 두니까, 관례대로 걸어 두면 돼요.
- 테이블이 Client마다 나뉘는지는 외래키가 아니라 **첫 번째 키 필드가 CLNT 타입인지**로 정해져요.
- 다른 필드에 외래키를 걸 때 MANDT 짝이 자동으로 들어가는 것은 이것과 별개예요.

| 외래키 | 실제 효과 |
| --- | --- |
| MANDT → T000 | 거의 없음. 관계도와 문서용 |
| CID → ZCLASS, WAERS → TCURC 같은 것 | 입력 화면에서 잘못된 값을 막고 F4 목록을 띄워요 |

### Text Table 만들기: 코드와 언어별 이름 나누기

코드 테이블에 이름을 한 언어로만 넣으면, 다른 언어로 로그인한 사람은 그 이름을 읽을 수 없어요. 그래서 SAP는 **코드 테이블**과 **언어별 이름 테이블(Text Table)**을 나눠요. 나라 목록 `T005`와 나라 이름 `T005T`가 대표적인 예예요.

| 테이블 | 키 | 일반 필드 | 예 |
| --- | --- | --- | --- |
| `T005` (코드) | MANDT, LAND1 | 나라별 설정 | KR |
| `T005T` (Text Table) | MANDT, **SPRAS**, LAND1 | `LANDX`(나라 이름), `NATIO`(국적 이름) | 3 / KR / 대한민국, E / KR / South Korea |

`SPRAS`는 **언어 키**예요. `3`은 한국어, `E`는 영어처럼 언어마다 레코드가 1건씩 있어요. (`3`은 SAP 안에 저장되는 한 글자 언어 키이고, 화면에는 `KO`로 보여요.)

&#91;embedded content: 로그인 언어와 Text Table · 언어별 이름\]

**만드는 순서 (예: 운영 국가 ZCOUNTRY의 이름 테이블 ZCOUNTRYT)**

1. 키를 **MANDT + SPRAS + 코드 테이블의 키 필드** 순서로 적어요. `SPRAS`의 Data Element는 표준 `SPRAS`를 써요.

   | Field | Key | Data element |
   | --- | --- | --- |
   | `MANDT` | ✓ | `MANDT` |
   | `SPRAS` | ✓ | `SPRAS` |
   | `LAND1` | ✓ | `LAND1` |
   | `LANDX` | | 이름을 담을 Data Element |

2. `LAND1`에 외래키를 걸어요. Check Table은 코드 테이블 `ZCOUNTRY`예요.
3. **Foreign key field type**을 **Key fields of a text table**로 고르고, 카디널리티는 `1 : CN`으로 적어요.
4. 활성화하면 SAP가 ZCOUNTRYT를 **ZCOUNTRY의 Text Table**로 인식해요.
5. 언어별 이름은 앞에서 배운 SE16이나 SM30으로 넣어요. 같은 코드(KR)를 언어마다 한 줄씩(3 대한민국, E South Korea) 넣으면 돼요.

**인식되면 좋은 점.** 코드 필드에서 F4를 누르면, 코드 옆에 **로그인 언어의 이름**이 같이 떠요. 그래서 KR만 보이는 대신 "KR 대한민국"이 보여요. 한 코드 테이블에 Text Table은 하나만 지정할 수 있어요.

### Input Help/Check 탭과 Search Help: F4 목록은 어디서 올까

테이블의 **Input Help/Check** 탭에는 필드마다 외래키, Check Table, 그리고 **Origin of Input Help**(F4 목록의 출처)가 보여요. F4를 눌렀을 때 무엇이 뜨는지가 여기서 정해져요.

| Origin of Input Help에 보이는 말 | 뜻 | 예 |
| --- | --- | --- |
| Input help implemented with check table | Check Table의 목록이 떠요 | 강사-NATIO → T005 나라 목록 |
| Input help with fixed values | Domain의 Fixed Value 목록이 떠요 | 성별 1, 2 |
| Input help based on data type | 타입에 맞는 기본 도움이 떠요 | 날짜(DATS)는 달력, 시간(TIMS)은 시계 |
| Explicit search help attachment to field | 필드에 직접 붙인 Search Help가 떠요 | |
| Input help with search help of data element | Data Element에 붙인 Search Help가 떠요 | |

**Search Help란?** F4 창을 **직접 설계한 검색 화면**이에요. Check Table 목록은 키만 쭉 보여 주지만, Search Help는 "어떤 필드로 검색할지", "목록에 어떤 열을 보여 줄지", "고른 값을 어느 칸에 넣을지"를 정할 수 있어요. 예를 들어 학생 번호 F4에서 이름으로 검색하고 반 이름까지 같이 보여 주고 싶을 때 써요. SE11 첫 화면의 **Search help**에서 만들어요.

표의 문구는 SAP 버전에 따라 조금 다를 수 있어요.

**여러 개가 있으면 무엇이 뜰까요?** 대략 **필드에 직접 붙인 Search Help → Check Table(과 그 Search Help) → Data Element의 Search Help → Fixed Value → 데이터 타입** 순서로 앞에 있는 것이 먼저 쓰여요. 수업 단계에서는 "Check Table을 걸면 F4가 생긴다"까지만 알면 충분해요.

### 여러 테이블의 관계와 제약 조건 분석하기: SCARR, SPFLI, SFLIGHT

수업 과제에 "테이블들의 관계를 분석하고 제약 조건(Business Rule)을 적으세요"라는 문제가 자주 나와요. SAP 연습용 항공 테이블 세 개로 분석 순서를 따라가 봐요. **Key Field만 보고** 분석해요. 다른 필드는 보지 않아도 돼요.

**제약 조건이란?** 데이터가 **반드시 지켜야 하는 규칙**이에요. 규칙을 어기는 데이터는 들어오면 안 돼요. **Business Rule**은 그 규칙을 "~해야 한다, ~할 수 없다, ~개 이상 가질 수 있다" 같은 업무 문장으로 풀어 쓴 거예요. 키에서 나오는 제약 조건은 세 종류예요.

| 종류 | 무엇을 막나 | 어디서 보이나 |
| --- | --- | --- |
| **키 제약** (유일성, 필수) | 같은 키가 두 번 들어오거나 키가 비는 것 | 각 테이블의 Key 필드 |
| **참조 제약** (외래키) | 부모에 없는 값을 자식이 가리키는 것 | 자식 키 안에 들어 있는 부모 키 |
| **관계 제약** (카디널리티) | 몇 대 몇으로 이어지는지, 꼭 있어야 하는지 | 1 : N, 식별 관계 여부 |

**① 테이블마다 Key 필드만 적어요.** SE11 Fields 탭에서 Key에 체크된 필드만 옮겨 적어요.

| 테이블 | 뜻 | Key Field |
| --- | --- | --- |
| SCARR | 항공사 | MANDT, **CARRID** |
| SPFLI | 운항 노선 | MANDT, CARRID, **CONNID** |
| SFLIGHT | 날짜별 운항편 | MANDT, CARRID, CONNID, **FLDATE** |

**② 키가 겹치는 부분을 찾아요.** 한 테이블의 키 전체가 다른 테이블 키의 **앞부분**에 그대로 들어 있으면 부모와 자식이에요. MANDT는 모든 테이블에 붙는 Client라서 빼고 봐요.

&#91;embedded content: 키 물려받기 · SCARR, SPFLI, SFLIGHT\]

- SPFLI의 키에 SCARR의 키(CARRID)가 들어 있어요. 그래서 SCARR가 부모, SPFLI가 자식이에요.
- SFLIGHT의 키에 SPFLI의 키(CARRID + CONNID)가 들어 있어요. 그래서 SPFLI가 부모, SFLIGHT가 자식이에요.
- 자식 키 안에 들어간 부모 키가 곧 **외래키**예요.

**③ 예시 데이터로 관계를 확인해요.** 머릿속으로 레코드를 몇 건 만들어 보면 몇 대 몇인지 보여요.

**SCARR**

| CARRID |
| --- |
| LH |
| AA |

**SPFLI**

| CARRID | CONNID |
| --- | --- |
| LH | 0400 |
| LH | 0402 |
| AA | 0017 |

**SFLIGHT**

| CARRID | CONNID | FLDATE |
| --- | --- | --- |
| LH | 0400 | 2026-11-20 |
| LH | 0400 | 2026-11-21 |
| AA | 0017 | 2026-11-20 |

- 항공사 LH 하나에 노선이 여러 개(0400, 0402) → SCARR : SPFLI = **1 : N**
- 노선 LH 0400 하나에 날짜별 운항편이 여러 개 → SPFLI : SFLIGHT = **1 : N**
- 외래키가 자식 키의 일부라서 비울 수 없어요 → 둘 다 **식별 관계**예요. 부모 쪽은 항상 1이에요(1부 관계).

| 관계 | 카디널리티 | 외래키 (Check Field → Check Table) |
| --- | --- | --- |
| SCARR : SPFLI | 1 : N (SE11에서는 1 : CN) | SPFLI-CARRID → SCARR |
| SPFLI : SFLIGHT | 1 : N (SE11에서는 1 : CN) | SFLIGHT-CARRID, CONNID → SPFLI |

**왜 1 : N과 1 : CN을 같이 적을까요?** 일반 ERD에서 N은 "여러 개"라는 뜻이라 0개도 넓게 포함해요. 그런데 SAP 기호에서는 **N이 "1개 이상", CN이 "0개 이상"**이에요(1부 카디널리티). 노선이 아직 하나도 없는 항공사도 있을 수 있으니까 SE11에는 `1 : CN`으로 적어요. 아래 문장에서는 정확하게 SAP 기호로 적을게요.

**④ 제약 조건을 문장으로 적어요.** 키 구조, 외래키, 카디널리티를 하나씩 문장으로 바꾸고, 끝에 종류를 붙여요.

1. 항공사는 CARRID로 하나씩 구분된다. 같은 CARRID는 두 번 등록할 수 없다. (키 제약)
2. 노선 번호 CONNID는 **항공사 안에서만** 유일하다. 다른 항공사는 같은 CONNID를 쓸 수 있으므로, 노선은 CARRID + CONNID로 구분한다. (키 제약)
3. 같은 노선은 같은 날짜에 한 번만 운항한다. CARRID + CONNID + FLDATE는 겹칠 수 없다. (키 제약)
4. SCARR에 없는 항공사로는 노선을 만들 수 없다. (참조 제약)
5. SPFLI에 없는 노선(CARRID + CONNID)으로는 운항편을 만들 수 없다. (참조 제약)
6. 항공사 하나는 0개 이상의 노선을 가질 수 있고, 노선은 반드시 항공사 하나에 속한다. (관계 제약, SAP 기호 1 : CN)
7. 노선 하나는 0개 이상의 운항편을 가질 수 있고, 운항편은 반드시 노선 하나에 속한다. (관계 제약, SAP 기호 1 : CN)
8. 부모 키가 자식 키에 포함된 식별 관계라서, 자식의 부모 키 필드는 비울 수 없다. (관계 제약)
9. 모든 테이블의 첫 키는 MANDT이고, 데이터는 Client별로 나뉜다. (키 제약)

**다른 테이블에도 쓰는 분석 순서**

1. 테이블마다 Key 필드만 적어요.
2. 한 테이블의 키 전체가 다른 테이블 키의 앞부분에 들어 있는지 찾아요. 들어 있으면 부모와 자식이에요.
3. 예시 레코드를 몇 건 만들어 몇 대 몇인지 확인해요. 외래키가 키 안에 있으면 식별 관계예요.
4. 키 제약, 참조 제약, 관계 제약 순서로 문장을 적어요.

키 안이 아니라 일반 필드에 외래키가 있는 경우(예: 강사 테이블의 국적 NATIO → T005)는 비식별 관계예요. 이때는 그 필드를 비워 둘 수 있는지에 따라 카디널리티가 `1 : CN` 또는 `C : CN`으로 달라져요.

<details class="more practice">
<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz

- CONNID는 같은 항공사 안에서만 유일하다 ✓

- CARRID는 비워 둘 수 있다
> 키가 CARRID + CONNID 묶음이라서, CONNID만 같고 CARRID가 다르면 다른 노선이에요. 그래서 CONNID는 항공사 안에서만 유일해요.

```

## 4부. SQL 기초 — 데이터베이스에 말 걸기

1\~3부에서는 테이블이 어떤 모양으로 저장되고, SAP에서 어떻게 만드는지 배웠어요. 이 부에서는 그 테이블에서 **데이터를 꺼내고, 넣고, 고치고, 지우는 언어**인 SQL을 배워요. ABAP 코드의 상당수가 이 SQL 문장이라서, 읽을 수 있으면 ABAP이 훨씬 쉬워져요.

1부와 같은 학생 테이블(ZSTUDENT)과 반 테이블(ZCLASS)을 계속 써요. 테이블 내용은 1부 첫머리에서 다시 확인할 수 있어요.

### SQL: 데이터베이스에게 말로 시키는 언어

**SQL**(Structured Query Language)은 DB에게 "이 조건의 레코드를 보여 줘"라고 시키는 언어예요. 가장 많이 쓰는 문장이 데이터를 꺼내는 `SELECT`예요.

아래 틀에서 주황색 한글이 직접 채우는 자리예요.

```syntax
SELECT 필드1, 필드2
  FROM 테이블이름
  WHERE 조건
  ORDER BY 필드1 DESC;
```

실제 문장은 이래요. "CL301반 학생의 번호, 이름, 점수를 점수 높은 순으로 보여 줘"예요.

```sql
SELECT sid, sname, score
  FROM zstudent
  WHERE cid = 'CL301'
  ORDER BY score DESC;
```

결과는 이래요.

| SID | SNAME | SCORE |
| --- | --- | --- |
| 0001 | 민수 | 85 |
| 0005 | 하준 | 80 |
| 0003 | 도윤 | 78 |

읽는 순서는 쓰인 순서와 달라요. **FROM(어느 테이블에서) → WHERE(어떤 레코드만) → SELECT(어떤 필드를) → ORDER BY(어떻게 줄 세워서)** 순서로 읽으면 쉬워요.

- `FROM`: 어느 테이블을 볼지 정해요.
- `WHERE`: 조건에 맞는 레코드만 남겨요. 생략하면 모든 레코드예요.
- `SELECT`: 보고 싶은 필드를 골라요. 전부 보고 싶으면 `*`예요.
- `ORDER BY`: 정렬해요. `ASC`는 오름차순(기본), `DESC`는 내림차순이에요.

자바스크립트와 비교하면 같은 일을 하는 말이 이렇게 짝지어져요.

| SQL | 자바스크립트로는 |
| --- | --- |
| `FROM zstudent` | `aZstudent` (배열) |
| `WHERE cid = 'CL301'` | `.filter(s => s.CID === "CL301")` |
| `SELECT sid, sname` | `.map(s => ({ SID: s.SID, SNAME: s.SNAME }))` |
| `ORDER BY score DESC` | `.sort((a, b) => b.SCORE - a.SCORE)` |

자주 쓰는 조건 연산자예요. 자바스크립트와 달리 **같다는 `=` 하나**예요. `===`가 아니에요.

| 쓰는 법 | 뜻 |
| --- | --- |
| `score = 80` | 같다 |
| `score <> 80` | 같지 않다 |
| `score >= 80` | 80 이상 |
| `score BETWEEN 70 AND 85` | 70 이상 85 이하 |
| `sname LIKE '민%'` | 민으로 시작 (`%`는 아무 글자나 여러 개) |
| `cid = 'CL301' AND score >= 80` | 둘 다 만족 |
| `cid = 'CL301' OR cid = 'CL303'` | 하나라도 만족 |

글자 값은 **홑따옴표**(`'CL301'`)로 감싸요. 숫자는 감싸지 않아요. ABAP에서는 `=` 대신 `EQ`, `<>` 대신 `NE`처럼 글자로도 비교할 수 있어요(5부 "조건문: IF와 비교 연산자").

<details class="more practice">
<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz
Q: 학생 테이블(ZSTUDENT)에서 점수가 90점 이상인 학생의 이름만 보고 싶어요.
Q: 알맞은 SQL 문장은?
- `SELECT sname FROM zstudent WHERE score >= 90;` ✓
- `SELECT score FROM zstudent WHERE sname >= 90;`
- `FROM zstudent SELECT sname WHERE score >= 90;`
- `SELECT sname FROM zstudent ORDER BY score >= 90;`
> `SELECT`에는 보고 싶은 필드, `FROM`에는 테이블, `WHERE`에는 레코드를 거르는 조건이 들어가요. 정렬은 `ORDER BY`가 맡아요.
```

</details>

### JOIN: 두 테이블을 이어서 읽기

두 테이블을 이을 때는 `JOIN`을 써요.

```sql
SELECT s.sid, s.sname, c.cname
  FROM zstudent AS s
  INNER JOIN zclass AS c ON s.cid = c.cid;
```

- `AS s`, `AS c`: 테이블에 짧은 별명을 붙여요.
- `s.sid`: "s 테이블의 sid 필드"라는 뜻이에요. 두 테이블에 같은 이름의 필드(`cid`)가 있을 때 어느 쪽인지 구분하려고 `별명.필드`로 써요.
- `ON s.cid = c.cid`: "이 두 필드가 같은 레코드끼리 이어 줘"예요.
- ABAP 프로그램 안에서는 점 대신 물결(`~`)을 써요. 이 부 마지막 "SQL 결과를 ABAP에서 받기"에서 봐요.

**조인의 종류.** 짝이 없는 레코드를 어떻게 할지에 따라 두 가지를 많이 써요.

- **INNER JOIN**: 양쪽 테이블에 짝이 있는 레코드만 남겨요. 반 코드가 비어 있거나 ZCLASS에 없는 학생은 결과에서 빠져요.
- **LEFT OUTER JOIN**: 왼쪽 테이블(`FROM` 쪽)의 레코드는 모두 남기고, 짝이 없으면 오른쪽 테이블의 필드를 비워 둬요. "반이 아직 없는 학생도 보여 줘"일 때 써요.

아래 그림에는 반이 아직 정해지지 않은 학생 가온(0007)을 한 명 더 넣었어요. 스크롤하면서 두 조인의 결과가 어떻게 다른지 보세요.

### 데이터 바꾸기: 넣기, 고치기, 지우기

데이터를 다루는 일은 네 가지로 정리돼요. 앞 글자를 모아 **CRUD**(크러드)라고 불러요. 화면 기능과 연결해서 외우면 쉬워요.

| CRUD | SQL | 화면에서는 |
| --- | --- | --- |
| Create(만들기) | `INSERT` | 등록 버튼 |
| Read(읽기) | `SELECT` | 목록, 상세 보기 |
| Update(고치기) | `UPDATE` | 수정 버튼 |
| Delete(지우기) | `DELETE` | 삭제 버튼 |

모양부터 볼게요.

```syntax
INSERT INTO 테이블이름 (필드1, 필드2) VALUES (값1, 값2);
UPDATE 테이블이름 SET 필드1 = 새 값 WHERE 조건;
DELETE FROM 테이블이름 WHERE 조건;
```

실제 문장은 이래요.

```sql
INSERT INTO zstudent (mandt, sid, sname, cid, score)
  VALUES ('100', '0006', '유나', 'CL303', 95);   -- 새 레코드 추가

UPDATE zstudent SET score = 90 WHERE sid = '0003';   -- 도윤의 점수를 90으로

DELETE FROM zstudent WHERE sid = '0004';             -- 서연의 레코드 삭제
```

`--` 뒤는 설명이에요(SQL의 주석).

**`UPDATE`와 `DELETE`에서 `WHERE`를 빠뜨리면 테이블의 모든 레코드가 바뀌거나 지워져요.** 위에서 `WHERE sid = '0003'`이 없었다면 모든 학생의 점수가 90이 돼요. 실행 전에 `WHERE`를 한 번 더 확인하는 습관을 들이세요.

그리고 `INSERT`할 때 이미 있는 키(`MANDT`+`SID`)를 또 넣으면 DB가 거부해요. 키는 겹칠 수 없기 때문이에요.

<details class="more">
<summary>더 알아보기 — ABAP에서 쓰는 INSERT 모양, SAP 표준 테이블 수정 금지</summary>

처음에는 건너뛰어도 돼요.

- ABAP SQL은 값을 하나씩 나열하는 대신 **Structure**(레코드 1건 모양의 묶음, 2부)를 통째로 넘기는 모양을 자주 써요. 예: `INSERT zstudent FROM @ls_std.` Structure를 만드는 법은 5부에서 배워요.
- SAP가 기본으로 주는 표준 테이블(`MARA`, `KNA1` 등)은 **SQL로 직접 고치면 안 돼요.** 테이블들끼리 맞물려 있어서, 한 곳만 고치면 데이터가 어긋나요. 표준 테이블은 읽기만 하고, 바꿀 때는 SAP가 만든 전용 기능을 통해서 해요. 직접 `UPDATE`, `DELETE`해도 되는 건 `Z`로 시작하는 내가 만든 테이블이에요.

</details>

<details class="more practice">
<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz
Q: 아래 문장을 실행하려고 해요.
| UPDATE zstudent SET score = 0;
Q: 이 문장의 결과로 맞는 것은?
- 점수가 비어 있는 학생만 0이 돼요
- 아무 레코드도 바뀌지 않아요
- `WHERE`가 없어서 모든 학생의 점수가 0이 돼요 ✓
- 에러가 나서 실행되지 않아요
> `UPDATE`와 `DELETE`는 `WHERE`로 레코드를 거르지 않으면 테이블 전체에 적용돼요.
```

</details>

### 모아서 계산하기: 개수, 합계, 평균, 그룹

레코드를 하나씩 보는 대신 **레코드들을 모아서 하나의 값**으로 만들 때 쓰는 함수가 있어요.

| 함수 | 뜻 |
| --- | --- |
| `COUNT(*)` | 레코드 건수 |
| `SUM(필드)` | 합계 |
| `AVG(필드)` | 평균 |
| `MAX(필드)` / `MIN(필드)` | 가장 큰 값 / 가장 작은 값 |

"반별로 인원과 평균 점수"처럼 **묶어서** 계산하려면 `GROUP BY`를 같이 써요. `GROUP BY cid`는 "`cid`가 같은 레코드끼리 한 묶음으로 보라"는 뜻이에요.

```sql
SELECT cid, COUNT(*) AS cnt, AVG(score) AS avg_score
  FROM zstudent
  GROUP BY cid;
```

| CID | CNT | AVG_SCORE |
| --- | --- | --- |
| CL301 | 3 | 81 |
| CL303 | 2 | 90 |

`AS cnt`는 결과 필드에 이름을 붙여요. 평균의 소수점 표시는 환경마다 조금 달라요.

자바스크립트로 같은 계산을 하려면 반별로 배열을 나눠 `reduce` 같은 것을 써야 해서 코드가 길어져요. SQL은 이런 계산을 DB가 한 번에 해 주니까 빠르고 짧아요. 데이터가 수만 건이어도 결과 몇 건만 화면으로 보내면 되고요.

### Internal Table: 프로그램 안의 임시 테이블

지금까지 본 테이블은 DB에 **영구히** 저장돼 있어요. 프로그램을 꺼도 남아 있어요. 반면 **Internal Table**은 ABAP 프로그램이 돌아가는 동안만 **메모리에** 잠깐 가지고 있는 테이블이에요.

| | DB 테이블 | Internal Table |
| --- | --- | --- |
| 있는 곳 | 데이터베이스 | 프로그램 메모리 |
| 언제까지 | 지울 때까지 | 프로그램이 끝날 때까지 |
| 자바스크립트로는 | (서버에 있는 원본) | 변수에 담긴 객체 배열 |

Internal Table의 한 줄(레코드 1건)은 **Structure** 모양이에요. Structure는 "필드 여러 개를 묶은 모양"(2부)이고, 자바스크립트의 객체 하나(`{ }`)와 같아요. Internal Table은 Structure 여러 개를 담은 배열이에요.

ABAP은 DB에서 꺼낸 데이터를 Internal Table에 담아서 다뤄요. SQL로 꺼낸 결과를 바로 다음 섹션에서 Internal Table에 담아 봐요. 직접 만드는 법은 5부에서 배워요.

전체 흐름을 한눈에 보면 이래요. UI5 쪽 이름은 SAPUI5 총정리에서 배운 것들이에요.

&#91;embedded content: DB에서 화면까지 · 데이터의 길\]

그래서 UI5에서 보는 `esStdList` 같은 **배열 모양 데이터는 결국 DB 테이블의 레코드들**이에요. 필드 이름, 코드, 날짜 형식이 이상하다면 원인은 대부분 DB 테이블과 그 필드의 타입에 있어요. 이 흐름을 알면 "이 값은 어디서 왔을까?"를 거슬러 올라갈 수 있어요.

### SQL 결과를 ABAP에서 받기: Internal Table에 담기

SQL로 꺼낸 레코드들은 ABAP 프로그램 안의 **Internal Table**(바로 앞 섹션)에 담겨요. 이 교재에서 ABAP을 만나는 첫 코드예요.

```abap
SELECT sid, sname, score
  FROM zstudent
  WHERE cid = 'CL301'
  INTO TABLE @DATA(lt_std).        " 결과를 lt_std에 담아요

IF sy-subrc = 0.                   " 0이면 레코드를 1건 이상 찾았다는 뜻이에요
  " lt_std를 1건씩 처리해요
ENDIF.
```
```abap-old
DATA lt_std TYPE TABLE OF zstudent.   " 받을 변수를 먼저 만들어요

SELECT sid sname score                " 필드 사이에 쉼표가 없어요
  FROM zstudent
  INTO CORRESPONDING FIELDS OF TABLE lt_std   " 고른 필드를 이름이 같은 칸에 담아요
  WHERE cid = 'CL301'.

IF sy-subrc = 0.                      " 0이면 레코드를 1건 이상 찾았다는 뜻이에요
  " lt_std를 1건씩 처리해요
ENDIF.
```

<div class="syn-only syn-new">

- 앞에서 본 `SELECT`와 거의 같고, 결과를 담을 곳을 `INTO TABLE`로 알려 줘요. `@DATA(lt_std)`는 `lt_std`라는 Internal Table을 그 자리에서 만들어요. 필드 사이에는 쉼표를 넣고, 변수 앞에는 `@`를 붙여요.

</div>
<div class="syn-only syn-old">

- 받을 Internal Table `lt_std`를 먼저 `DATA`로 만들고, `INTO CORRESPONDING FIELDS OF TABLE`로 담아요. 고른 필드(sid, sname, score)가 `lt_std`에서 이름이 같은 칸에 들어가요.
- 필드 사이에 쉼표가 없고, 변수 앞에 `@`도 없어요. `INTO`는 `WHERE` 앞에 와요.

</div>

- `sy-subrc`는 직전 명령이 잘 됐는지 알려 주는 시스템 변수예요. `0`은 성공이고, 데이터를 하나도 못 찾으면 `4`가 돼요. `IF ... ENDIF.`는 "조건이 맞을 때만 안쪽을 실행"하라는 뜻이고, 5부 "조건문: IF와 비교 연산자"에서 자세히 배워요.
- ABAP 문장은 **마침표(`.`)로 끝나요.** 자바스크립트의 `;`에 해당해요. 큰따옴표(`"`) 뒤는 주석이에요.

**ABAP SQL로 JOIN 쓰기.** 앞의 JOIN을 ABAP 프로그램 안에서 쓰면 이렇게 돼요. 이렇게 ABAP 안에 쓰는 SQL을 **ABAP SQL**이라고 불러요.

```abap
SELECT s~sid, s~sname, c~cname
  FROM zstudent AS s
  INNER JOIN zclass AS c ON s~cid = c~cid
  INTO TABLE @DATA(lt_join).
```
```abap-old
DATA lt_join TYPE TABLE OF zstudent.   " 받을 변수를 먼저 만들어요 (반 이름 칸은 5부 TYPES로 따로 만들어요)

SELECT s~sid s~sname c~cname
  FROM zstudent AS s
  INNER JOIN zclass AS c ON s~cid = c~cid
  INTO CORRESPONDING FIELDS OF TABLE lt_join.
```

| 일반 SQL | ABAP SQL |
| --- | --- |
| `s.sid` (별명 뒤 점) | `s~sid` (별명 뒤 물결) |
| 끝에 `;` | 끝에 `.` |
| 결과는 화면에 나와요 | 결과를 담을 곳을 `INTO`로 꼭 적어요 |
| 변수를 쓰지 않아요 | 요즘 문법은 변수 앞에 `@`를 붙이고, 옛 문법은 그냥 써요 |

## 5부. ABAP 기초 — SAP 서버에서 데이터 다루기

ABAP(Advanced Business Application Programming)은 SAP 서버 쪽에서 쓰는 프로그래밍 언어예요. 1부에서 테이블을 설계하고, 2·3부에서 SE11로 만들어 잇고, 4부에서 SQL로 데이터를 꺼냈다면, 이 부에서는 그 SQL을 감싸고 데이터를 처리하는 **ABAP 프로그램**을 직접 만들어요.

이 부는 수업 진도에 맞춰 계속 채워 나가요. 지금은 이런 순서예요.

1. 개발 화면: 프로그램을 만들고 실행하는 곳
2. ABAP 문장의 모양과 변수 이름 규칙
3. 변수와 타입
4. 입력 받기: PARAMETERS와 START-OF-SELECTION
5. 내 프로그램에 T-code 붙이기: SE93
6. 조건문: IF와 비교 연산자
7. Structure와 Internal Table 만들기 (넣기, 세기, 반복, 찾기)
8. TYPES와 테이블 종류 (STANDARD, SORTED, HASHED)
9. Internal Table 바꾸기, 정렬과 중복 지우기
10. LOOP 자세히 (WHERE, sy-tabix, ASSIGNING)
11. 줄 꺼내기와 값 만들기 (Table Expression, VALUE, CORRESPONDING)
12. 키로 데이터 읽기 (입력값으로 읽기, 복합 키, 넣기 전에 값 확인하기)
13. DB 테이블 바꾸기 (ABAP SQL, COMMIT WORK)
14. 옛 문법과 요즘 문법 한눈에 보기

**옛 문법과 요즘 문법.** ABAP에는 같은 일을 하는 옛 문법과 요즘 문법이 함께 쓰여요. 회사 시스템의 버전과 코딩 규칙에 따라 둘 중 하나를 쓰기 때문에, 이 교재의 ABAP 코드는 **두 문법으로 모두** 볼 수 있어요. 코드 상자 위의 탭이나 아래 버튼으로 고르면 교재 전체의 코드와 관련 설명이 그 문법으로 바뀌고, 다음에 들어와도 그대로 유지돼요. 두 문법을 나란히 비교한 표는 이 부 마지막 섹션에 있어요.

### 개발 화면: SE38에서 프로그램 만들기

ABAP 프로그램은 SAP GUI 안에서 만들어요. 테이블 구조는 SE11(2부)에서 만들었죠. 프로그램은 **SE38**(ABAP 편집기, ABAP Editor)에서 만들어요.

1. 명령 입력칸에 `SE38`을 치고 Enter를 눌러요.
2. 프로그램 이름을 적어요. 내가 만드는 것은 테이블처럼 `Z`나 `Y`로 시작해요. 예: `ZSTUDENT_LIST_05`
3. **Create**를 누르고, Title을 적고, Type은 **Executable Program**(실행 가능 프로그램)을 골라요.
4. 저장할 패키지를 물으면 수업에서 정한 패키지를 적어요. 연습용이면 **Local Object**(`$TMP`)로 저장해도 돼요.

코드를 쓴 다음에는 아래 순서로 진행해요. 단축키를 손에 익혀 두면 편해요.

| 단계 | 하는 일 | 단축키 |
| --- | --- | --- |
| 저장 | 코드를 저장해요. 아직 실행용은 아니에요 | Ctrl+S |
| 문법 검사 | 오타와 문법 오류를 찾아요 | Ctrl+F2 |
| **활성화**(Activate) | 저장한 코드를 "실행해도 되는 최신 버전"으로 확정해요 | Ctrl+F3 |
| 실행 | 프로그램을 돌려요 | F8 |
| 코드 정리 | 들여쓰기와 대소문자를 보기 좋게 맞춰요(Pretty Printer) | Shift+F1 |

**저장과 활성화는 달라요.** 저장만 하고 활성화하지 않으면, 실행했을 때 고치기 전의 코드가 돌아가요. SE11의 테이블도 같아요. "고쳤는데 그대로예요"라면 활성화를 빠뜨린 경우가 가장 많아요.

<details class="more">
<summary>더 알아보기 — 자동완성이 저절로 뜨게 하기</summary>

편집기에서 Ctrl+Space를 누르면 자동완성 목록이 떠요. 타이핑만 해도 뜨게 하려면 편집기 오른쪽 아래의 Options 아이콘을 눌러 **Code Completion** 화면을 열어요.

- **Enable AutoComplete**에 체크해요.
- **Open completion automatically after … msec** 값을 `1500`에서 `300`\~`500` 정도로 줄여요. 기본값 1.5초는 길어서 안 뜨는 것처럼 느껴져요.
- **Use simple autocompletion (without dictionary)** 는 꺼 두세요. 켜면 테이블 이름이나 필드 이름 제안이 빠져요.

저장(Save)한 뒤 편집기를 다시 열면 적용돼요.

</details>

### ABAP 문장의 모양: 마침표, 콜론, 주석

4부 마지막에서 ABAP 코드를 잠깐 봤어요. 기본 규칙 네 가지만 알면 대부분의 코드를 읽을 수 있어요.

```abap
* 별표로 시작하는 줄은 줄 전체가 주석이에요
DATA lv_name TYPE string.          " 큰따옴표 뒤는 그 줄 끝까지 주석이에요
lv_name = 'ABAP'.
WRITE lv_name.                     " 화면에 출력해요

DATA: lv_a TYPE i,                 " 콜론과 쉼표로 같은 명령을 이어 써요
      lv_b TYPE i.
```

1. **문장은 마침표(`.`)로 끝나요.** 자바스크립트의 `;`와 같아요. 빠뜨리면 문법 오류예요.
2. **주석은 두 가지예요.** 줄 맨 앞의 `*`는 줄 전체, `"`는 그 뒤부터 줄 끝까지예요.
3. **콜론(`:`)으로 같은 명령을 묶어요.** `DATA: lv_a TYPE i, lv_b TYPE i.`는 `DATA lv_a TYPE i.`와 `DATA lv_b TYPE i.` 두 문장을 줄인 거예요. 각 항목은 쉼표로 나누고 마지막만 마침표예요.
4. **명령어는 대소문자를 가리지 않아요.** `data`와 `DATA`는 같아요. 보통 명령어는 대문자, 변수는 소문자로 써요. Pretty Printer(Shift+F1)가 맞춰 줘요. 문자 값은 작은따옴표(`'ABAP'`)로 감싸요.

### 변수 이름 규칙

ABAP 변수 이름 앞 두 글자는 "어디서 쓰는지 + 어떤 모양인지"예요. UI5의 `oView`, `aList`와 같은 발상이에요.

| 접두어 | 뜻 |
| --- | --- |
| `lv_` / `ls_` / `lt_` | Local Variable / Structure / Table (메서드 같은 작은 단위 안에서만 쓰는 지역 변수) |
| `lc_` | Local Constant (상수) |
| `gv_` / `gs_` / `gt_` | Global Variable / Structure / Table (프로그램 전체에서 쓰는 변수) |
| `is_` / `it_` | Importing (받는 값) |
| `es_` / `et_` | Exporting (돌려주는 값) |

이 교재의 짧은 예제 프로그램은 수업에서처럼 `lv_`, `ls_`, `lt_`로 적어요.

Lev05 데이터의 `esStdList`는 "백엔드가 내보낸 학생 목록"을 흉내 낸 이름으로 보여요. 엄밀히는 여러 건이니까 Table을 뜻하는 `et`가 맞아요.

### 변수와 타입: DATA와 TYPE

ABAP은 변수를 만들 때 **타입**을 꼭 정해요. 자바스크립트의 `let`과 달리, 한 번 정한 타입은 바뀌지 않아요(1부 데이터 타입).

```abap
DATA lv_count TYPE i.                    " 정수
DATA lv_score TYPE p DECIMALS 2.         " 소수점 둘째 자리까지
DATA lv_cid   TYPE c LENGTH 5.           " 5글자 고정 문자 (옛 코드: DATA lv_cid(5) TYPE c.)
DATA lv_date  TYPE d.                    " 날짜 (YYYYMMDD)
CONSTANTS lc_max TYPE i VALUE 30.        " 바꿀 수 없는 값(상수)
```

**기본 타입.** ABAP에 원래 들어 있는 타입이에요.

| 타입 | 뜻 | 예 |
| --- | --- | --- |
| `i` | 정수 | `85` |
| `p` | 소수 (소수 자릿수는 `DECIMALS`로 정해요) | `92.50` |
| `c` | 고정 길이 문자 (`LENGTH`로 길이를 정해요) | `'CL301'` |
| `n` | 숫자로만 된 문자, NUMC (앞자리 0 유지) | `'0003'` |
| `d` / `t` | 날짜 / 시간 | `'20261112'` / `'093000'` |
| `string` | 길이가 정해지지 않은 문자 | `'민수'` |

**ABAP Dictionary 타입.** 실무에서는 기본 타입보다 **ABAP Dictionary(2부)에 있는 타입**을 더 많이 써요. 테이블 필드와 똑같은 모양을 쓰면 길이나 형식이 어긋날 일이 없어요.

```abap
DATA lv_sid1 TYPE zstudent-sid.          " ① ZSTUDENT 테이블 SID 필드와 같은 타입 (옛 코드: LIKE zstudent-sid)
DATA lv_cid  TYPE zcid.                  " ② Data Element ZCID 타입 (2부에서 만든 것)
DATA lv_matnr TYPE matnr.                " ② SAP 표준 Data Element MATNR (자재 번호)
```

- **①** `테이블-필드`로 적으면 "그 필드가 쓰는 타입을 그대로 써 줘"라는 뜻이에요.
- **②** 이름만 적으면 그 이름의 **Data Element**를 가리켜요.

`TYPE matnr`가 되는 건 테이블 이름을 생략해서가 아니에요. `MATNR`라는 Data Element가 ABAP Dictionary에 있어서예요. 필드 이름과 Data Element 이름이 다를 때도 많아요.

| 테이블-필드 | 그 필드의 Data Element | `TYPE 필드이름`만 쓰면 |
| --- | --- | --- |
| `MARA-MATNR` | `MATNR` | 돼요 (이름이 같아요) |
| `VBAK-VBELN` | `VBELN_VA` | `TYPE vbeln`도 있지만 다른 Data Element예요 |
| `SCARR-CARRID` | `S_CARR_ID` | `TYPE carrid`는 없어서 오류가 나요 |

Data Element 이름은 SE11에서 테이블을 열고 Fields 탭의 Data element 칸을 보면 알 수 있어요. 헷갈리면 ①처럼 `테이블-필드`로 쓰면 틀릴 일이 없어요.

**인라인 선언.** 4부의 `@DATA(lt_std)`처럼, 값을 넣는 자리에서 바로 변수를 만들 수도 있어요. 타입은 넣는 값을 보고 정해져요. ABAP 7.40부터 쓸 수 있어요.

</div>



### 입력 받기: PARAMETERS와 START-OF-SELECTION

지금까지는 값을 코드에 직접 적었어요. 실제 프로그램은 실행할 때 사용자에게 값을 **입력받아요.** 예를 들어 "학번을 넣으면 그 학생을 보여 주는" 프로그램이에요. 이때 `PARAMETERS`를 써요.

```abap
REPORT zc05_param.

PARAMETERS pa_sid TYPE zstudent-sid OBLIGATORY.   " 입력칸 1개 (꼭 입력해야 해요)
PARAMETERS pa_cnt TYPE i DEFAULT 3.                " 기본값 3이 미리 들어가 있어요

START-OF-SELECTION.
  WRITE: / '입력한 학번:', pa_sid.
  WRITE: / '입력한 숫자:', pa_cnt.
```

**실행하면 무슨 일이 일어날까요?**

1. F8로 실행하면 코드보다 먼저 **입력 화면**이 떠요. `PARAMETERS` 한 줄마다 입력칸이 하나씩 생겨요. 이 화면을 **Selection Screen**이라고 하고, 기본 번호는 **1000**이에요.
2. 칸을 채우고 화면의 실행 버튼(F8)을 누르면, 입력한 값이 `pa_sid`, `pa_cnt` 변수에 들어가요.
3. 그다음 `START-OF-SELECTION.` 아래 코드가 실행돼요. 그래서 이 구간에서는 `pa_sid`를 보통 변수처럼 쓸 수 있어요.

**PARAMETERS 규칙.**

- `PARAMETERS`는 변수 선언(`DATA`)과 같아요. 다만 입력칸까지 만들어 줘요. 타입은 `DATA`처럼 `TYPE 테이블-필드`로 빌려 오는 게 좋아요. 그러면 F4 목록과 Check Table 검사도 따라와요.
- **이름은 8글자까지**예요. 그래서 `pa_`나 `p_`로 시작하는 짧은 이름을 써요.
- 자주 쓰는 옵션이에요.

| 옵션 | 뜻 |
| --- | --- |
| `OBLIGATORY` | 꼭 입력해야 실행돼요 |
| `DEFAULT 값` | 입력칸에 기본값을 미리 넣어 둬요 |
| `LOWER CASE` | 소문자를 대문자로 바꾸지 않아요 (기본은 대문자로 바뀌어요) |
| `AS CHECKBOX` | 체크박스로 만들어요 (값은 `'X'` 또는 빈칸) |

- `WRITE: /`의 `/`는 줄을 바꾸고 출력하라는 뜻이에요.

**START-OF-SELECTION은 "실행 버튼을 누른 다음"이라는 표시예요.** ABAP REPORT는 정해진 순간마다 실행할 구간을 나눠 적을 수 있어요. 이런 순간을 **이벤트**라고 해요. 지금은 `START-OF-SELECTION` 하나만 알면 돼요.

- 입력 화면이 없는 프로그램은 `START-OF-SELECTION.`을 안 적어도 돌아가요. 이벤트를 안 적은 코드는 자동으로 이 구간으로 들어가요.
- 그래도 `PARAMETERS`가 있는 프로그램에서는 **입력 부분과 실행 부분을 나누려고** 적어 두는 게 좋아요.
- 입력 화면이 뜨기 전에 값을 채우는 `INITIALIZATION`, 입력값을 검사하는 `AT SELECTION-SCREEN` 같은 이벤트도 있어요. 이름만 알아 두세요.

**입력칸 이름 바꾸기.** 입력 화면에는 기본으로 `PA_SID` 같은 변수 이름이 보여요. 메뉴 **Goto → Text Elements → Selection Texts**에서 칸마다 "학번" 같은 이름을 적을 수 있어요. **Dictionary Ref.**에 체크하면 Data Element의 Field Label을 그대로 가져와요. 저장하고 활성화해야 반영돼요.

입력받은 값으로 DB 테이블을 읽는 방법은 뒤의 "키로 데이터 읽기"에서 이어서 봐요.

### 내 프로그램에 T-code 붙이기: SE93

지금은 프로그램을 실행하려면 SE38에서 이름을 치고 F8을 눌러요. 실제 사용자는 그렇게 하지 않아요. **SE93**에서 프로그램에 `ZC05_EDU` 같은 **나만의 T-code**를 붙여 두면, 명령 입력칸에 그 코드만 쳐서 바로 실행해요.

- 사용자는 T-code만 알면 돼요. 프로그램 이름을 몰라도 돼요.
- T-code마다 권한을 줄 수 있어요. "이 사람은 이 화면만 쓸 수 있다"를 정할 수 있어요.
- 기존 T-code가 **어떤 프로그램을 실행하는지** 볼 때도 SE93을 써요. T-code를 넣고 **Display**를 누르면 돼요.

&#91;embedded content: SE93으로 T-code 만들기 · 내 REPORT 프로그램에\]

**T-code 종류.** Create를 누르면 무엇을 실행할지 골라요.

| 종류 | 언제 쓰나 |
| --- | --- |
| **Program and selection screen (report transaction)** | SE38로 만든 REPORT 프로그램. 지금 단계에서 가장 많이 써요 |
| Program and screen (dialog transaction) | 화면(Dynpro)을 직접 그린 프로그램 |
| **Transaction with parameters** | 기존 T-code에 값을 미리 채워서 실행할 때. 예: SM30 + 내 테이블 이름 |
| Method of a class (OO transaction) | 클래스의 메서드를 실행할 때 |
| Transaction with variant | 기존 T-code에 화면 변형을 입힐 때 |

**내 REPORT 프로그램에 붙이기.**

1. `SE93`에서 Transaction Code에 `ZC05_EDU`를 적고 **Create**를 눌러요. 이름은 Z나 Y로 시작해요.
2. Short text를 적고 **Program and selection screen (report transaction)**을 골라요.
3. Program에 프로그램 이름을, Selection screen에 **1000**을 적어요. 앞에서 본 `PARAMETERS` 입력 화면 번호예요.
4. **GUI support**에서 **SAP GUI for Windows**에 체크해요.
5. 저장해요. Package와 Transport Request를 물으면 수업에서 정한 값을 적어요.
6. 명령 입력칸에 `/nZC05_EDU`를 치면 입력 화면이 바로 열려요.

**내 테이블의 SM30 입력 화면에 붙이기.** 3부에서 Table Maintenance Generator를 만들었다면, 매번 SM30에서 테이블 이름을 적지 않고 바로 입력 화면으로 가게 할 수 있어요.

1. `SE93`에서 `ZC05_0511`을 적고 Create → **Transaction with parameters**를 골라요.
2. Transaction에 `SM30`을 적고 **Skip initial screen**에 체크해요.
3. 아래 Default values 표에 두 줄을 넣어요.

| Name of screen field | Value |
| --- | --- |
| `VIEWNAME` | `ZTC0511` (내 테이블 이름) |
| `UPDATE` | `X` (고치기 모드로 열기) |

4. 저장하면 `ZC05_0511`만 쳐도 ZTC0511 입력 화면이 바로 열려요.

지금 쓰는 화면의 T-code와 프로그램 이름이 궁금하면 2부에서 본 **System → Status**를 보면 돼요.

### 조건문: IF와 비교 연산자

조건에 따라 다른 일을 할 때는 `IF`를 써요. 자바스크립트의 `if`와 같은데, 괄호와 중괄호 대신 **마침표와 `ENDIF`**로 구간을 나눠요.

```abap
DATA lv_score TYPE i.
DATA lv_grade TYPE c LENGTH 1.
lv_score = 85.

IF lv_score >= 90.          " 조건 뒤에 마침표
  lv_grade = 'A'.
ELSEIF lv_score >= 80.      " 앞 조건이 아닐 때 다음 조건 (한 단어예요)
  lv_grade = 'B'.
ELSE.                       " 어느 조건도 아닐 때
  lv_grade = 'C'.
ENDIF.                      " 여기까지가 IF 구간

WRITE lv_grade.             " B
```

- `IF`, `ELSEIF`, `ELSE`, `ENDIF` 뒤에는 모두 마침표를 찍어요.
- 조건을 이을 때는 4부 SQL처럼 `AND`, `OR`, `NOT`을 써요. 예: `IF lv_score >= 80 AND lv_grade = 'B'.`
- **비었는지 확인**은 `IS INITIAL`이에요. 1부에서 본 초기값(빈칸, 0)인지 보는 거예요. 예: `IF lv_grade IS INITIAL.`, 반대는 `IS NOT INITIAL`.
- **참/거짓 값이 따로 없어요.** ABAP에는 불리언 타입이 없어서, 참은 `'X'`, 거짓은 빈칸 `' '`로 써요. 이름을 붙인 상수 `abap_true`, `abap_false`를 쓰면 읽기 쉬워요. 예: `IF lv_flag = abap_true.`
- 4부에서 본 `IF sy-subrc = 0.`도 같은 IF예요. "직전 명령이 성공했으면"이라는 뜻이에요.

**비교 연산자는 기호와 글자 두 가지로 써요.** `IF`나 `WHERE` 안에서 둘 다 되고 뜻은 같아요. 요즘 코드는 기호를 더 많이 쓰고, 옛 코드와 책에는 글자가 자주 나와요.

| 기호 | 글자 | 뜻 |
| --- | --- | --- |
| `=` | `EQ` (EQual) | 같다 |
| `<>` | `NE` (Not Equal) | 같지 않다 |
| `<` | `LT` (Less Than) | 작다 |
| `>` | `GT` (Greater Than) | 크다 |
| `<=` | `LE` (Less or Equal) | 작거나 같다 |
| `>=` | `GE` (Greater or Equal) | 크거나 같다 |

**`=`는 두 가지 뜻이에요.** `lv_grade = 'A'.`처럼 문장 맨 앞에 오면 값을 **넣는** 거고, `IF`나 `WHERE` 안에 있으면 **비교**예요. 자바스크립트처럼 `==`나 `===`는 없어요.

| ABAP | 자바스크립트로는 |
| --- | --- |
| `IF ... ELSEIF ... ELSE ... ENDIF.` | `if (...) { } else if (...) { } else { }` |
| `=` / `EQ` (비교) | `===` |
| `<>` / `NE` | `!==` |
| `AND`, `OR`, `NOT` | `&&`, `\|\|`, `!` |
| `IS INITIAL` | 빈 값인지 확인 (`!value`와 비슷해요) |
| `abap_true` / `abap_false` | `true` / `false` |

### Structure와 Internal Table 만들기

4부에서 **Structure**는 레코드 1건 모양의 묶음이고, **Internal Table**은 Structure 여러 개를 담은 프로그램 안의 임시 테이블이라고 했어요. 하나씩 만들어 볼게요.

**① Structure 만들기: 레코드 1건 담기**

```abap
DATA ls_std TYPE zstudent.     " ZSTUDENT 레코드 1건과 같은 모양
ls_std-sid   = '0006'.         " 필드는 하이픈(-)으로 꺼내요
ls_std-sname = '유나'.
WRITE ls_std-sname.            " 유나
```

`TYPE zstudent`처럼 DB 테이블 이름을 적으면 그 테이블의 필드를 그대로 가진 Structure가 돼요. 필드는 `변수-필드`로 꺼내요. 자바스크립트의 `.` 대신 하이픈(`-`)을 쓰는 게 가장 헷갈리는 부분이에요. ABAP에서 `.`은 문장 끝이니까요.

**Structure를 만드는 세 가지 방법.** 위처럼 DB 테이블 모양을 빌리는 것 말고도 방법이 두 가지 더 있어요.

```abap
" 방법 1. DB 테이블 모양 그대로: 테이블의 모든 필드를 가져요
DATA gs_std1 TYPE zstudent.

" 방법 2. SE11에 미리 만든 Structure 타입으로 (2부 "Structure, Table Type, Include, Append")
DATA gs_std2 TYPE zs_student.

" 방법 3. 프로그램 안에서 필요한 필드만 골라 직접 만들기
DATA: BEGIN OF gs_std3,               " 여기서부터 gs_std3 시작
        sid   TYPE zstudent-sid,      " 필드 1
        sname TYPE zstudent-sname,    " 필드 2
        score TYPE zstudent-score,    " 필드 3
      END OF gs_std3.                 " 여기서 끝
```

| 방법 | 언제 쓰나 |
| --- | --- |
| 1. `TYPE DB테이블` | 테이블의 모든 필드가 필요할 때 |
| 2. `TYPE SE11의 Structure` | 여러 프로그램이 같은 모양을 같이 쓸 때 |
| 3. `DATA: BEGIN OF ... END OF` | 필드 몇 개만 골라 이 프로그램에서만 쓸 때 |

방법 3을 쓸 때 기억할 점이에요.

- `BEGIN OF 이름`과 `END OF 이름`의 **이름이 같아야** 해요.
- 콜론(`:`)으로 이어 쓰는 문장이라, 필드마다 쉼표를 찍고 맨 끝 `END OF ...` 뒤에만 마침표를 찍어요.
- 필드 타입은 `TYPE 테이블-필드`로 DB 테이블의 필드 타입을 빌려 오면 길이나 형식이 어긋나지 않아요.
- 만든 뒤에는 똑같이 `gs_std3-sname`처럼 하이픈으로 꺼내요. 그래서 **변수 이름에는 하이픈을 넣을 수 없고**, 단어를 이을 때는 밑줄(`_`)을 써요. `gs-std`라고 쓰면 "gs 안의 std 필드"로 읽혀요.
- 자바스크립트로 치면 `{ sid: "", sname: "", score: 0 }`처럼 필요한 키만 가진 빈 객체를 하나 만드는 것과 같아요.
- 이 문법은 옛 코드와 요즘 코드 모두에서 그대로 써요. 같은 모양을 여러 변수에 쓸 때는 설계도만 만드는 `TYPES: BEGIN OF`가 더 편해요(뒤의 "TYPES와 테이블 종류").

**② Internal Table 만들기: 여러 건 담을 목록**

```abap
DATA lt_std TYPE TABLE OF zstudent.   " ZSTUDENT 레코드가 여러 건 들어가는 목록. 처음에는 비어 있어요
```

**③ APPEND: 맨 뒤에 1건 넣기**

```abap
APPEND ls_std TO lt_std.       " ls_std의 내용을 복사해서 맨 뒤에 붙여요 → 1건

ls_std-sid   = '0007'.
ls_std-sname = '가온'.
APPEND ls_std TO lt_std.       " → 2건
```

`APPEND`는 Structure의 **내용을 복사해서** 넣어요. 그래서 넣은 뒤에 `ls_std`를 다른 값으로 바꿔도 이미 들어간 첫 줄(유나)은 그대로예요.

**④ 몇 건인지 세기**

```abap
DATA(lv_cnt) = lines( lt_std ).   " 2
```
```abap-old
DATA lv_cnt TYPE i.
DESCRIBE TABLE lt_std LINES lv_cnt.   " 2
```

<div class="syn-only syn-new">

`lines( )`는 Internal Table의 줄 수를 돌려줘요. `DATA(...)`는 앞의 "변수와 타입"에서 본 인라인 선언이에요.

</div>
<div class="syn-only syn-old">

`DESCRIBE TABLE ... LINES`는 Internal Table의 줄 수를 변수에 넣어 줘요. 받을 변수를 먼저 만들어 둬요.

</div>

**⑤ LOOP AT: 한 줄씩 꺼내 반복하기**

```abap
LOOP AT lt_std INTO ls_std.    " 첫 줄부터 마지막 줄까지 한 줄씩 ls_std에 담아요
  WRITE / ls_std-sname.        " 줄마다 한 번씩 실행돼요
ENDLOOP.                       " 여기까지가 반복 구간
```

- `LOOP AT`과 `ENDLOOP` 사이가 **줄 수만큼 반복**돼요. 지금은 2건이라 두 번 돌아요.
- `INTO ls_std`는 "꺼낸 줄을 담을 곳"이에요. 돌 때마다 다음 줄이 담겨요.
- `WRITE /`의 `/`는 **줄을 바꾼 다음 출력**하라는 뜻이에요. 빼면 같은 줄에 옆으로 이어서 찍혀요. 결과는 "유나", "가온"이 두 줄로 나와요.

조건을 붙이거나 줄을 바로 고치는 방법은 뒤의 "LOOP 자세히"에서 봐요.

**⑥ READ TABLE: 조건에 맞는 1건 찾기**

```abap
READ TABLE lt_std INTO ls_std WITH KEY sid = '0006'.
IF sy-subrc = 0.               " 찾았으면 0, 없으면 4
  WRITE ls_std-sname.          " 유나
ENDIF.
```

`WITH KEY` 뒤의 조건에 맞는 첫 줄을 `ls_std`에 담아요. 찾았는지는 앞의 IF에서 본 `sy-subrc`로 확인해요.

<div class="syn-only syn-old">

**헤더 라인.** 옛 코드에는 Structure와 Internal Table을 **같은 이름 하나로** 합쳐 만드는 방식이 자주 나와요. 이 합쳐진 Structure 쪽을 **헤더 라인**(Header Line)이라고 불러요.

```abap
DATA gt_std TYPE TABLE OF zstudent WITH HEADER LINE.   " 테이블 + 같은 이름의 Structure
" 더 옛날 모양: DATA: BEGIN OF gt_std OCCURS 0, ... END OF gt_std.

gt_std-sid   = '0006'.         " 헤더 라인(Structure 쪽)에 값을 넣고
gt_std-sname = '유나'.
APPEND gt_std.                 " 헤더 라인을 테이블에 추가해요 (TO가 없어요)

LOOP AT gt_std.                " INTO가 없으면 헤더 라인에 한 줄씩 담겨요
  WRITE / gt_std-sname.
ENDLOOP.

READ TABLE gt_std WITH KEY sid = '0006'.   " 찾은 줄이 헤더 라인에 담겨요
DESCRIBE TABLE gt_std LINES lv_cnt.        " lines( ) 대신 건수 세기
CLEAR gt_std[].                            " [ ]를 붙여야 테이블 본체를 비워요
```

| 이름 | 가리키는 것 |
| --- | --- |
| `gt_std` | 헤더 라인 (Structure 쪽, 1건) |
| `gt_std[]` | 테이블 본체 (여러 건) |

- 이름 하나가 두 가지를 가리켜서 헷갈리기 쉬워요. 그래서 요즘에는 쓰지 말라고 하고, **클래스 안에서는 아예 쓸 수 없어요.**
- 일반 프로그램(SE38)에서는 지금도 돌아가요. 회사 코드에서 `APPEND gt_std.`처럼 `TO`가 없는 문장이 보이면 헤더 라인이에요.

</div>

**정리하면**

| ABAP | 하는 일 | 자바스크립트로는 |
| --- | --- | --- |
| `TYPE zstudent` | Structure 만들기 | 객체 `{ }` |
| `TYPE TABLE OF zstudent` | Internal Table 만들기 | 객체 배열 `[ ]` |
| `ls_std-sname` | 필드 꺼내기 | `oStd.SNAME` |
| `APPEND ... TO` | 맨 뒤에 추가 | `push` |
| `LOOP AT ... ENDLOOP` | 1건씩 반복 | `for ... of` |
| `READ TABLE ... WITH KEY` | 조건에 맞는 1건 찾기 | `find` |
| `lines( )` / `DESCRIBE TABLE ... LINES` | 건수 | `length` |


### TYPES와 테이블 종류: STANDARD, SORTED, HASHED

앞에서는 `TYPE zstudent`처럼 DB 테이블의 모양을 그대로 빌려 썼어요. 프로그램 안에서만 쓰는 모양을 직접 정하고 싶을 때는 **`TYPES`**를 써요.

```abap
TYPES: BEGIN OF ty_std,                 " 레코드 1건의 모양(Structure 타입)
         sid   TYPE zstudent-sid,
         sname TYPE zstudent-sname,
         cid   TYPE zstudent-cid,
         score TYPE zstudent-score,
       END OF ty_std.
TYPES tt_std TYPE STANDARD TABLE OF ty_std WITH EMPTY KEY.   " 그 모양이 여러 건인 목록 타입

DATA ls_std TYPE ty_std.                " 실제 변수는 DATA로 만들어요
DATA lt_std TYPE tt_std.
```

- **`TYPES`는 설계도, `DATA`는 실제 변수**예요. `TYPES`로 만든 것에는 값을 넣을 수 없고, `DATA ... TYPE 설계도`로 변수를 만들어야 써요.
- 이름 앞의 `ty_`는 Structure 타입, `tt_`는 Table 타입이라는 관례예요.
- `WITH EMPTY KEY`는 "키를 따로 정하지 않은 STANDARD 테이블"이라는 뜻이에요(ABAP 7.40부터). 옛 코드는 `WITH DEFAULT KEY`(글자 필드 전체를 키로 봐요)를 많이 쓰는데, 평소 쓰임은 거의 같아요.
- `TYPES` 없이 `DATA: BEGIN OF ls_one, ... END OF ls_one.`처럼 Structure 변수를 바로 만들기도 해요.
- 2부의 DDIC **Structure**와 **Table Type**을 프로그램 안에서 만드는 거라고 보면 돼요. 여러 프로그램이 같이 쓰면 DDIC에, 이 프로그램에서만 쓰면 `TYPES`로 만들어요.

**Internal Table은 세 종류예요.** 앞에서 쓴 `TYPE TABLE OF zstudent`는 `TYPE STANDARD TABLE OF`를 줄여 쓴 거예요.

| 종류 | 줄 순서 | 키 | 키로 찾는 속도 | 언제 쓰나 |
| --- | --- | --- | --- | --- |
| STANDARD | 넣은 순서 그대로 | 겹쳐도 돼요 | 처음부터 하나씩 찾아서 느려요 | 기본. 대부분 이걸 써요 |
| SORTED | 키 순서로 항상 정렬돼 있어요 | 겹침 허용(`NON-UNIQUE`) 또는 금지(`UNIQUE`) | 빨라요 | 늘 정렬된 목록이 필요할 때 |
| HASHED | 순서 없음 | 반드시 겹침 금지(`UNIQUE`) | 가장 빨라요 | 키로 1건씩 자주 찾을 때 |

```abap
DATA lt_sorted TYPE SORTED TABLE OF ty_std WITH UNIQUE KEY sid.
DATA lt_hashed TYPE HASHED TABLE OF ty_std WITH UNIQUE KEY sid.
```

- **SORTED와 HASHED에는 `APPEND`를 쓰지 마세요.** `APPEND`는 맨 뒤에 붙이는 명령이라, 순서가 정해진 SORTED에서는 순서가 어긋나면 실행 중 오류가 나고, HASHED에서는 아예 문법 오류예요. 대신 다음 섹션의 `INSERT ... INTO TABLE`을 써요.
- **HASHED는 "몇 번째 줄"로 꺼낼 수 없어요.** 줄 순서가 없어서 `INDEX`를 쓰는 명령은 안 돼요.

| ABAP | 자바스크립트로는 |
| --- | --- |
| STANDARD TABLE | 배열 `[ ]` |
| SORTED TABLE | 늘 정렬된 상태로 유지되는 배열 |
| HASHED TABLE | 키로 바로 찾는 `Map` 또는 객체 `{ "0001": { … } }` |

<summary>문제 풀기 — 배운 내용 확인</summary>

### Internal Table 바꾸기: INSERT, MODIFY, DELETE, CLEAR

이제 Internal Table 안의 줄을 넣고, 고치고, 지워 볼게요. 모두 **프로그램 메모리 안의 목록**만 바뀌고, DB 테이블은 그대로예요. DB를 바꾸는 법은 이 부 마지막 "DB 테이블 바꾸기"에서 봐요.

```abap
" 넣기
ls_std-sid = '0006'. ls_std-sname = '유나'. ls_std-cid = 'CL303'. ls_std-score = 95.
APPEND ls_std TO lt_std.                 " 맨 뒤에 붙여요 (STANDARD 전용)
INSERT ls_std INTO TABLE lt_std.         " 테이블 종류에 맞는 자리에 넣어요 (세 종류 모두)
INSERT ls_std INTO lt_std INDEX 1.       " 1번째 자리에 끼워 넣어요

" 고치기
ls_std-score = 90.
MODIFY lt_std FROM ls_std INDEX 2.       " 2번째 줄을 ls_std 내용으로 바꿔요
MODIFY lt_std FROM ls_std TRANSPORTING score WHERE sid = '0003'.   " 조건에 맞는 줄의 score만 바꿔요

" 지우기
DELETE lt_std INDEX 1.                   " 1번째 줄을 지워요
DELETE lt_std WHERE score < 60.          " 조건에 맞는 줄을 모두 지워요

" 비우기
CLEAR lt_std.                            " 모든 줄을 지워요
CLEAR ls_std.                            " Structure는 모든 필드가 초기값(빈칸, 0)이 돼요
FREE lt_std.                             " 모든 줄을 지우고 메모리도 돌려줘요
```

- **줄 번호(`INDEX`)는 1부터 세요.** 자바스크립트 배열은 0부터라서 가장 많이 헷갈리는 곳이에요. `INDEX 1`이 첫 줄이에요.
- **`TRANSPORTING`**은 "이 필드만 옮겨 줘"라는 뜻이에요. 빼면 ls_std의 모든 필드로 줄 전체를 덮어써요.
- 옛 코드에서는 테이블을 비울 때 `REFRESH lt_std.`를 많이 써요. `CLEAR lt_std.`와 같아요.
<div class="syn-only syn-old">

- 헤더 라인 테이블은 `MODIFY gt_std INDEX 2.`, `APPEND gt_std.`처럼 `FROM`이나 `TO` 없이 헤더 라인의 내용으로 바꿔요.

</div>
- 명령이 잘 됐는지는 `sy-subrc`로 확인해요. 바꿀 줄을 못 찾으면 `4`예요.

| ABAP | 자바스크립트로는 |
| --- | --- |
| `APPEND ls TO lt` | `a.push(o)` |
| `INSERT ls INTO lt INDEX 1` | `a.unshift(o)` |
| `MODIFY lt FROM ls INDEX 2` | `a[1] = o` (자바스크립트는 0부터) |
| `DELETE lt WHERE score < 60` | `a = a.filter(s => !(s.SCORE < 60))` |
| `CLEAR lt` | `a.length = 0` |

### 정렬과 중복 지우기: SORT, DELETE ADJACENT DUPLICATES

```abap
SORT lt_std BY score DESCENDING.                     " 점수 높은 순
SORT lt_std BY cid ASCENDING score DESCENDING.       " 반 순서대로, 같은 반 안에서는 점수 높은 순
```

`ASCENDING`(오름차순)이 기본이라 생략할 수 있어요. 필드를 여러 개 적으면 앞 필드가 같을 때 뒤 필드로 다시 정렬해요.

**중복 지우기는 꼭 정렬한 다음에 해요.** `DELETE ADJACENT DUPLICATES`는 이름처럼 **바로 옆에 붙어 있는(Adjacent)** 같은 값만 지워요. 같은 값이 떨어져 있으면 못 지워요.

```abap
SORT lt_std BY cid.                                        " ① 같은 반끼리 모아요
DELETE ADJACENT DUPLICATES FROM lt_std COMPARING cid.      " ② 붙어 있는 같은 반은 1건만 남겨요
```

| 정렬 전 CID | ① 정렬 후 | ② 중복 지운 후 |
| --- | --- | --- |
| CL301 | CL301 | CL301 |
| CL303 | CL301 | CL303 |
| CL301 | CL301 | |
| CL303 | CL303 | |
| CL301 | CL303 | |

`COMPARING cid`는 "cid가 같으면 같은 줄로 본다"는 뜻이에요. 빼면 모든 필드가 같은 줄만 지워요. 이 두 줄로 "반 목록만 뽑기"를 자주 해요.

**SORTED 테이블에는 `SORT`를 쓸 수 없어요.** 이미 키 순서로 정렬돼 있기 때문이에요.

| ABAP | 자바스크립트로는 |
| --- | --- |
| `SORT lt BY score DESCENDING` | `a.sort((x, y) => y.SCORE - x.SCORE)` |
| `SORT` + `DELETE ADJACENT DUPLICATES COMPARING cid` | `[...new Set(a.map(s => s.CID))]` |

### LOOP 자세히: WHERE, sy-tabix, ASSIGNING

**조건에 맞는 줄만 돌기.** `LOOP AT`에도 `WHERE`를 붙일 수 있어요.

```abap
LOOP AT lt_std INTO ls_std WHERE score >= 80.
  WRITE: / sy-tabix, ls_std-sname.      " sy-tabix: 지금 도는 줄이 몇 번째인지
ENDLOOP.
```

- **`sy-tabix`**는 지금 줄의 번호예요(1부터). `READ TABLE`로 찾았을 때도 찾은 줄 번호가 들어가요.
- LOOP 안에서 `CONTINUE.`는 이번 줄을 건너뛰고, `EXIT.`는 LOOP를 끝내요. 자바스크립트의 `continue`, `break`와 같아요.

**`INTO`는 복사, `ASSIGNING`은 직접 가리키기.** LOOP에서 가장 중요한 차이예요.

- **`INTO ls_std`**: 줄을 `ls_std`에 **복사**해요. `ls_std`를 바꿔도 테이블은 그대로라서, 바꾸려면 `MODIFY`로 다시 넣어야 해요.
- **`ASSIGNING <ls_std>`**: 줄을 복사하지 않고 **그 줄 자체를 가리키는 이름**을 붙여요. `<ls_std>`를 바꾸면 테이블의 줄이 바로 바뀌어요. 꺾쇠(`< >`)로 감싼 이 이름을 **Field Symbol**이라고 불러요.

```abap
" INTO: 복사본을 고치고, MODIFY로 다시 넣어요
LOOP AT lt_std INTO ls_std.
  ls_std-score = ls_std-score + 5.
  MODIFY lt_std FROM ls_std.            " LOOP 안에서는 지금 줄을 바꿔요
ENDLOOP.

" ASSIGNING: 줄을 바로 고쳐요
LOOP AT lt_std ASSIGNING FIELD-SYMBOL(<ls_std>).
  <ls_std>-score = <ls_std>-score + 5.
ENDLOOP.
```

&#91;embedded content: INTO와 ASSIGNING · 복사와 직접 가리키기\]

- `FIELD-SYMBOL(<ls_std>)`는 인라인 선언이에요(ABAP 7.40부터). 옛 코드는 `FIELD-SYMBOLS <ls_std> TYPE ty_std.`로 먼저 선언하고 `ASSIGNING <ls_std>`로 써요.
<div class="syn-only syn-old">

- 헤더 라인 테이블은 `LOOP AT gt_std.` 안에서 `gt_std-score`를 고친 뒤 `MODIFY gt_std.`로 지금 줄을 바꿔요.

</div>
- 줄을 많이 고칠 때는 `ASSIGNING`이 복사가 없어서 빠르고 코드도 짧아요. 읽기만 할 때는 `INTO`로도 충분해요.
- 자바스크립트의 `for (const o of aStd) { o.SCORE += 5; }`는 원래 배열의 객체가 바뀌어요. 객체는 복사되지 않고 가리켜지기 때문이에요. ABAP의 `ASSIGNING`이 이쪽이고, `INTO`는 매번 `{ ...o }`로 복사한 것과 같아요.

<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz
- 마지막 줄만 100이 돼요
- 문법 오류가 나요
```

### 줄 꺼내기와 값 만들기: Table Expression, VALUE, CORRESPONDING

<div class="syn-only syn-new">

ABAP 7.40부터는 앞의 명령을 더 짧게 쓰는 문법을 쓸 수 있어요. 요즘 코드에 자주 나와요.

</div>
<div class="syn-only syn-old">

옛 문법에는 이 섹션의 짧은 문법(대괄호, `VALUE`, `CORRESPONDING #`)이 없어요. 같은 일을 `READ TABLE`, 하나씩 넣기, `MOVE-CORRESPONDING`으로 해요. 요즘 문법 탭을 누르면 짧은 모양을 볼 수 있어요.

</div>

**1건 꺼내기: Table Expression**

```abap
DATA(ls_one) = lt_std[ sid = '0003' ].         " READ TABLE ... WITH KEY sid = '0003'과 같아요
DATA(ls_first) = lt_std[ 1 ].                  " 첫 번째 줄 (INDEX 1)
```
```abap-old
READ TABLE lt_std INTO ls_one WITH KEY sid = '0003'.   " 조건으로 1건
READ TABLE lt_std INTO ls_first INDEX 1.             " 첫 번째 줄
```

<div class="syn-only syn-new">

**없는 줄을 꺼내면 실행 중 오류가 나요.** `READ TABLE`은 `sy-subrc = 4`로 알려 주고 넘어가지만, 대괄호는 프로그램이 멈춰요. 그래서 먼저 있는지 확인해요.

</div>
<div class="syn-only syn-old">

**있는지만 확인할 때**는 `TRANSPORTING NO FIELDS`를 붙여서, 아무것도 담지 않고 `sy-subrc`만 봐요.

</div>

```abap
IF line_exists( lt_std[ sid = '0003' ] ).      " 있으면 abap_true
  DATA(ls_hit) = lt_std[ sid = '0003' ].
ENDIF.

DATA(ls_safe) = VALUE #( lt_std[ sid = '9999' ] OPTIONAL ).   " 없으면 빈 Structure를 돌려줘요
```
```abap-old
READ TABLE lt_std TRANSPORTING NO FIELDS WITH KEY sid = '0003'.
IF sy-subrc = 0.                               " 있으면 0
  READ TABLE lt_std INTO ls_hit WITH KEY sid = '0003'.
ENDIF.

CLEAR ls_safe.                                 " 못 찾으면 빈 Structure로 남게 먼저 비워요
READ TABLE lt_std INTO ls_safe WITH KEY sid = '9999'.
```

**값 만들기: VALUE**

```abap
ls_std = VALUE #( sid = '0007' sname = '가온' cid = 'CL301' score = 70 ).   " Structure 1건
APPEND VALUE #( sid = '0008' sname = '서아' ) TO lt_std.                    " 만들면서 바로 추가

DATA(lt_demo) = VALUE tt_std( ( sid = '0001' sname = '민수' score = 85 )    " 목록. 괄호 하나가 1줄
                              ( sid = '0002' sname = '지아' score = 92 ) ).
```
```abap-old
CLEAR ls_std.                    " 필드를 하나씩 넣어서 만들어요
ls_std-sid   = '0007'.
ls_std-sname = '가온'.
ls_std-cid   = 'CL301'.
ls_std-score = 70.

CLEAR ls_std.                    " 만들어서 추가하기
ls_std-sid   = '0008'.
ls_std-sname = '서아'.
APPEND ls_std TO lt_std.
```

<div class="syn-only syn-new">

`#`은 "타입은 받는 쪽을 보고 알아서 정해 줘"라는 뜻이에요. 받는 쪽 타입을 알 수 없는 `DATA(...)` 선언에는 `VALUE tt_std(...)`처럼 타입을 적어요.

</div>
<div class="syn-only syn-old">

새 값을 만들기 전에 `CLEAR`로 비우는 게 중요해요. 비우지 않으면 앞에서 넣은 값(예: score 70)이 다음 줄에 그대로 남아요.

</div>

**이름이 같은 필드끼리 옮기기: CORRESPONDING**

```abap
DATA lt_full TYPE TABLE OF zstudent.
lt_full = CORRESPONDING #( lt_std ).           " SID, SNAME, CID, SCORE가 같은 이름의 필드로 옮겨져요
```
```abap-old
DATA lt_full TYPE TABLE OF zstudent.
DATA ls_full TYPE zstudent.

LOOP AT lt_std INTO ls_std.
  CLEAR ls_full.
  MOVE-CORRESPONDING ls_std TO ls_full.        " 이름이 같은 필드끼리 옮겨요
  APPEND ls_full TO lt_full.
ENDLOOP.
```

모양이 다른 두 테이블 사이에서, 이름이 같은 필드만 골라 옮겨요. 없는 필드(예: `MANDT`)는 초기값으로 남아요.

| 요즘 문법 (옛 문법) | 자바스크립트로는 |
| --- | --- |
| `lt_std[ sid = '0003' ]` (`READ TABLE ... WITH KEY`) | `a.find(s => s.SID === "0003")` (없으면 대괄호는 오류) |
| `line_exists( lt_std[ … ] )` (`READ TABLE ... TRANSPORTING NO FIELDS`) | `a.some(s => s.SID === "0003")` |
| `VALUE #( sid = '0007' … )` (필드 하나씩 넣기) | `{ SID: "0007", … }` |
| `VALUE tt_std( ( … ) ( … ) )` | `[{ … }, { … }]` |
| `CORRESPONDING #( lt_std )` (`MOVE-CORRESPONDING`) | `a.map(({ SID, SNAME, CID, SCORE }) => ({ SID, SNAME, CID, SCORE }))` |

<details class="more practice">
<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz
Q: `DATA(ls_x) = lt_std[ sid = '9999' ].`를 실행했는데 SID 9999인 줄이 없어요.
Q: 어떻게 될까요?
- ls_x가 빈 Structure가 돼요
- sy-subrc가 4가 되고 넘어가요
- 실행 중 오류가 나서 프로그램이 멈춰요 ✓
- 맨 뒤에 9999 줄이 생겨요
> Table Expression은 줄이 없으면 오류가 나요. line_exists( )로 먼저 확인하거나 VALUE #( … OPTIONAL )을 써요.
```

### 키로 데이터 읽기: SELECT SINGLE과 복합 키

4부에서는 여러 건을 `INTO TABLE`로 받았어요. **딱 1건**만 읽을 때는 `SELECT SINGLE`을 써요.

```abap
SELECT SINGLE sname, score
  FROM zstudent
  WHERE sid = '0003'
  INTO @DATA(ls_std).              " Structure 1건으로 받아요

IF sy-subrc = 0.
  WRITE ls_std-sname.              " 도윤
ENDIF.
```
```abap-old
DATA ls_std TYPE zstudent.

SELECT SINGLE sname score
  FROM zstudent
  INTO CORRESPONDING FIELDS OF ls_std   " Structure 1건으로 받아요
  WHERE sid = '0003'.

IF sy-subrc = 0.
  WRITE ls_std-sname.              " 도윤
ENDIF.
```

키가 `SID` 하나라서, 키를 적으면 레코드가 정확히 1건 정해져요.

**필드 여러 개를 받는 세 가지 방법.** 가져온 필드를 담을 곳은 변수 여러 개, Structure 하나, 이름 맞추기 중에서 골라요. 앞의 "Structure와 Internal Table 만들기"에서 만든 `gs_std3`(sid, sname, score)로 받아 볼게요.

```abap
" ① 변수 여러 개: 괄호 안 순서대로 들어가요
SELECT SINGLE sname, score FROM zstudent
  WHERE sid = '0003'
  INTO ( @lv_sname, @lv_score ).

" ② Structure 하나: SELECT 필드 순서 = Structure 필드 순서일 때
SELECT SINGLE sid, sname, score FROM zstudent
  WHERE sid = '0003'
  INTO @gs_std3.

" ③ 이름이 같은 필드끼리: 순서가 달라도 돼요
SELECT SINGLE score, sid FROM zstudent
  WHERE sid = '0003'
  INTO CORRESPONDING FIELDS OF @gs_std3.
```
```abap-old
" ① 변수 여러 개: 괄호 안 순서대로 들어가요
SELECT SINGLE sname score FROM zstudent
  INTO ( lv_sname, lv_score )
  WHERE sid = '0003'.

" ② Structure 하나: SELECT 필드 순서 = Structure 필드 순서일 때
SELECT SINGLE sid sname score FROM zstudent
  INTO gs_std3
  WHERE sid = '0003'.

" ③ 이름이 같은 필드끼리: 순서가 달라도 돼요
SELECT SINGLE score sid FROM zstudent
  INTO CORRESPONDING FIELDS OF gs_std3
  WHERE sid = '0003'.
```

- ②는 **순서**로 짝을 지어요. Structure 필드 순서와 다르면 값이 엉뚱한 칸에 들어가요.
- ③은 **이름**으로 짝을 지어요. SELECT에 없는 필드(여기서는 sname)는 그대로 남아요.

**입력받은 값으로 읽기.** 앞의 "입력 받기"에서 만든 `PARAMETERS`와 합치면, 사용자가 넣은 학번의 학생을 읽는 프로그램이 돼요. 수업에서 많이 만드는 모양이에요.

```abap
REPORT zc05_select.

PARAMETERS pa_sid TYPE zstudent-sid OBLIGATORY.

START-OF-SELECTION.
  SELECT SINGLE sname, score
    FROM zstudent
    WHERE sid = @pa_sid             " 입력받은 값을 조건에 써요
    INTO @DATA(ls_one).

  IF sy-subrc = 0.
    WRITE: / ls_one-sname, ls_one-score.
  ELSE.
    WRITE: / '없는 학번이에요:', pa_sid.
  ENDIF.
```
```abap-old
REPORT zc05_select.

PARAMETERS pa_sid TYPE zstudent-sid OBLIGATORY.

DATA: BEGIN OF gs_one,
        sname TYPE zstudent-sname,
        score TYPE zstudent-score,
      END OF gs_one.

START-OF-SELECTION.
  SELECT SINGLE sname score
    FROM zstudent
    INTO gs_one
    WHERE sid = pa_sid.             " 입력받은 값을 조건에 써요

  IF sy-subrc = 0.
    WRITE: / gs_one-sname, gs_one-score.
  ELSE.
    WRITE: / '없는 학번이에요:', pa_sid.
  ENDIF.
```

- 입력 화면에서 `0003`을 넣으면 `도윤 78`, 없는 학번을 넣으면 "없는 학번이에요"가 나와요.
- 요즘 문법에서는 조건의 `pa_sid` 앞에도 `@`를 붙여요. 프로그램 안의 변수라는 표시예요.
- 이 프로그램에 SE93으로 T-code를 붙이면 사용자는 T-code만 쳐서 쓸 수 있어요.

**복합 키는 키 필드를 전부 적어야 1건이 정해져요.** 1부의 수강 테이블 ZENROLL은 `SID` + `SUBJ`가 키예요.

```abap
" ① 키를 전부 적으면 → 1건 (0001 학생이 UI5101을 듣는지 확인)
SELECT SINGLE subj
  FROM zenroll
  WHERE sid  = '0001'
    AND subj = 'UI5101'
  INTO @DATA(lv_subj).
IF sy-subrc = 0.
  WRITE '수강 중이에요'.
ENDIF.

" ② 키의 앞부분만 적으면 → 여러 건 (0001 학생이 듣는 과목 전부)
SELECT subj
  FROM zenroll
  WHERE sid = '0001'
  INTO TABLE @DATA(lt_subj).       " JS101, UI5101 → 2건
```
```abap-old
DATA lv_subj TYPE zenroll-subj.
DATA lt_subj TYPE TABLE OF zenroll-subj.

" ① 키를 전부 적으면 → 1건 (0001 학생이 UI5101을 듣는지 확인)
SELECT SINGLE subj
  FROM zenroll
  INTO lv_subj
  WHERE sid  = '0001'
    AND subj = 'UI5101'.
IF sy-subrc = 0.
  WRITE '수강 중이에요'.
ENDIF.

" ② 키의 앞부분만 적으면 → 여러 건 (0001 학생이 듣는 과목 전부)
SELECT subj
  FROM zenroll
  INTO TABLE lt_subj
  WHERE sid = '0001'.              " JS101, UI5101 → 2건
```

- **①** 키를 다 적었으니 결과는 많아야 1건이에요. `SELECT SINGLE`이 맞아요.
- **②** `SID`만 적으면 그 학생의 수강 기록이 여러 건 나와요. 결과를 Internal Table(`INTO TABLE`)로 받아요. 실무에서는 "이 문서의 품목 전부"처럼 이렇게 묶음으로 읽는 일이 아주 많아요.
- **②에 `SELECT SINGLE`을 쓰면** 여러 건 중 아무거나 1건만 나와서 어떤 게 나올지 보장되지 않아요. 문법 검사에서 경고가 뜰 수 있어요.

<div class="syn-only syn-old">

**한 건씩 꺼내며 돌기: SELECT ... ENDSELECT.** 옛 코드에서 자주 보는 모양이에요. DB에서 한 건씩 꺼내면서 안쪽을 반복해요.

```abap
SELECT * FROM zenroll
  INTO ls_enroll
  WHERE sid = '0001'.
  WRITE / ls_enroll-subj.          " 꺼낸 건마다 실행돼요
ENDSELECT.
```

DB를 여러 번 오가서 느릴 수 있어요. 그래서 `INTO TABLE`로 한꺼번에 받은 뒤 `LOOP AT`으로 도는 쪽을 더 권해요. 남의 코드를 읽을 때 알아보면 돼요.

</div>

**넣기 전에 부모 테이블에 값이 있는지 확인하기.** 3부에서 본 Check Table 검사는 SE16, SM30 같은 **입력 화면**에서만 일어나요. 프로그램에서 `INSERT`하면 SAP가 검사해 주지 않아서, ZCLASS에 없는 반 코드도 그대로 들어가요. 그래서 넣기 전에 `SELECT SINGLE`로 부모 테이블을 먼저 읽어 봐요.

```abap
SELECT SINGLE cid
  FROM zclass
  WHERE cid = @ls_std-cid          " 변수를 SQL 안에 쓸 때는 앞에 @를 붙여요
  INTO @DATA(lv_found).

IF sy-subrc = 0.
  INSERT zstudent FROM @ls_std.    " 반이 있을 때만 학생을 DB에 넣어요 (다음 섹션에서 자세히)
ELSE.
  WRITE '없는 반 코드예요'.
ENDIF.
```
```abap-old
DATA lv_found TYPE zclass-cid.

SELECT SINGLE cid
  FROM zclass
  INTO lv_found
  WHERE cid = ls_std-cid.          " 옛 문법은 변수 앞에 @가 없어요

IF sy-subrc = 0.
  INSERT zstudent FROM ls_std.     " 반이 있을 때만 학생을 DB에 넣어요 (다음 섹션에서 자세히)
ELSE.
  WRITE '없는 반 코드예요'.
ENDIF.
```

`ls_std`는 앞의 "Structure와 Internal Table 만들기"에서 만든 학생 1건이에요. `sy-subrc`가 0이 아니면 ZCLASS에 그 반이 없다는 뜻이라서 넣지 않아요.

JOIN(4부)도 같아요. 복합 키 테이블을 이을 때는 `ON`에 키 필드를 **전부** 적어야 해요. 하나라도 빼면 짝이 여러 개씩 생겨서 결과가 부풀어요. `MANDT`는 ABAP이 알아서 채우니까 적지 않아요(2부 SAP 테이블 읽는 법).

### DB 테이블 바꾸기: ABAP SQL INSERT, UPDATE, MODIFY, DELETE

4부에서 본 `INSERT`, `UPDATE`, `DELETE`를 ABAP 프로그램 안에서 쓰는 모양이에요. 이번에는 Internal Table이 아니라 **DB 테이블**이 바뀌어요.

```abap
INSERT zstudent FROM @ls_std.                        " 1건 넣기. 키가 이미 있으면 sy-subrc = 4
INSERT zstudent FROM TABLE @lt_full.                 " Internal Table의 여러 건을 한 번에 넣기

UPDATE zstudent SET score = 90 WHERE sid = '0003'.   " 조건에 맞는 레코드의 필드만 고치기
UPDATE zstudent FROM @ls_full.                       " 키가 같은 레코드를 ls_full 내용으로 통째로 바꾸기

MODIFY zstudent FROM @ls_full.                       " 키가 있으면 고치고, 없으면 넣기

DELETE FROM zstudent WHERE sid = '0004'.             " 조건에 맞는 레코드 지우기
DELETE zstudent FROM @ls_full.                       " 키가 같은 레코드 1건 지우기

COMMIT WORK.                                         " 바꾼 내용을 DB에 확정해요
```
```abap-old
INSERT zstudent FROM ls_std.                         " 1건 넣기. 키가 이미 있으면 sy-subrc = 4
INSERT zstudent FROM TABLE lt_full.                  " Internal Table의 여러 건을 한 번에 넣기

UPDATE zstudent SET score = 90 WHERE sid = '0003'.   " 조건에 맞는 레코드의 필드만 고치기
UPDATE zstudent FROM ls_full.                        " 키가 같은 레코드를 ls_full 내용으로 통째로 바꾸기

MODIFY zstudent FROM ls_full.                        " 키가 있으면 고치고, 없으면 넣기

DELETE FROM zstudent WHERE sid = '0004'.             " 조건에 맞는 레코드 지우기
DELETE zstudent FROM ls_full.                        " 키가 같은 레코드 1건 지우기

COMMIT WORK.                                         " 바꾼 내용을 DB에 확정해요
```

`ls_full`은 `TYPE zstudent`로 만든 Structure, `lt_full`은 `TYPE TABLE OF zstudent`로 만든 Internal Table이에요. DB 테이블과 모양이 같아야 해요.

<div class="syn-only syn-old">

**아주 옛 모양: TABLES.** 화면 프로그램과 엮인 옛 코드에는 `TABLES zstudent.`처럼 테이블 이름과 같은 작업 영역을 만들고, `zstudent-sid = '0009'.` 뒤에 `INSERT zstudent.`로 넣는 모양도 나와요. 새로 쓸 때는 Structure 변수를 쓰는 게 좋아요.

</div>

**결과는 시스템 변수 두 개로 확인해요.**

| 변수 | 뜻 |
| --- | --- |
| `sy-subrc` | `0`이면 성공, `4`면 바꿀 레코드가 없거나 같은 키가 이미 있어요 |
| `sy-dbcnt` | 실제로 바뀐 레코드 건수예요 |

**`COMMIT WORK`와 `ROLLBACK WORK`.** 1부 "더 알아둘 개념"의 트랜잭션이에요. 여러 테이블을 한 묶음으로 바꿀 때, 다 성공하면 `COMMIT WORK`로 확정하고 중간에 문제가 생기면 `ROLLBACK WORK`로 이번 묶음의 변경을 모두 취소해요. 간단한 연습 프로그램은 끝날 때 SAP가 확정해 주지만, 확정 시점을 직접 정하는 습관을 들이면 좋아요.

**이름이 같은 명령을 헷갈리지 마세요.** `INSERT`, `MODIFY`, `DELETE`는 Internal Table에도 DB 테이블에도 쓰는 이름이에요. 대상을 보고 구분해요.

| | Internal Table | DB 테이블 |
| --- | --- | --- |
| 넣기 | `INSERT ls_std INTO TABLE lt_std.` | `INSERT zstudent FROM @ls_full.` (옛 문법은 `@` 없음) |
| 고치기 | `MODIFY lt_std FROM ls_std INDEX 2.` | `UPDATE zstudent FROM @ls_full.` |
| 넣거나 고치기 | (없음) | `MODIFY zstudent FROM @ls_full.` |
| 지우기 | `DELETE lt_std WHERE score < 60.` | `DELETE FROM zstudent WHERE score < 60.` |
| 바뀌는 곳 | 프로그램 메모리 | 데이터베이스 |

- DB 쪽은 대상이 `zstudent` 같은 DB 테이블 이름이에요. 요즘 문법은 변수 앞에 `@`가 붙어요.
- 3부의 Check Table 검사는 여기서 일어나지 않아요. 넣기 전에 부모 테이블을 확인하는 법은 앞의 "키로 데이터 읽기"에서 봤어요.
- SAP 표준 테이블(`MARA`, `KNA1` 등)은 이 명령으로 직접 바꾸면 안 돼요(4부). 직접 바꾸는 건 `Z` 테이블만이에요.

### 옛 문법과 요즘 문법 한눈에 보기

ABAP은 오래된 언어라서, 같은 일을 하는 **옛 문법**과 **요즘 문법**이 함께 쓰여요. 어느 쪽을 쓰는지는 회사마다 달라요.

- **시스템이 오래된 회사:** ABAP 7.40보다 낮은 시스템(예: SAP ECC 6.0 EHP6 이하)은 요즘 문법이 아예 없어서 옛 문법만 써요.
- **시스템은 새것이어도 규칙이 옛 문법인 회사:** 오래 쓰던 코드와 모양을 맞추려고 옛 문법을 계속 쓰기도 해요.
- **요즘 문법을 쓰는 회사:** S/4HANA 신규 개발, 클래스 중심 개발, ABAP Cloud(RAP)는 요즘 문법이 기본이에요.

그래서 **둘 다 읽을 줄 알고, 회사 규칙에 맞춰 쓰는 것**이 가장 중요해요. 이 교재의 ABAP 코드는 위쪽 탭으로 두 문법을 오가며 볼 수 있고, 이 표는 두 문법을 나란히 비교할 때 써요.

<div class="syn-switch" role="group" aria-label="ABAP 문법 고르기"><span>ABAP 코드를 어떤 문법으로 볼까요?</span><button type="button" data-set-syn="new">요즘 문법 (7.40+)</button><button type="button" data-set-syn="old">옛 문법</button></div>


**꼭 지킬 규칙 세 가지**

1. **SQL 문장 하나 안에서는 섞지 않아요.** 쉼표나 `@`를 하나라도 쓰면 그 문장 전체가 요즘 모양이어야 해요. 문장마다는 달라도 돼요.
2. **헤더 라인은 클래스 안에서 쓸 수 없어요.** 일반 프로그램(SE38)에서만 돌아가요.
3. **회사 코드가 옛 문법이면 그 프로그램 안에서는 옛 문법으로 맞춰요.** 한 프로그램 안에 두 모양이 섞이면 읽기 어려워요.

| 하는 일 | 옛 문법 | 요즘 문법 | 자세히 |
| --- | --- | --- | --- |
| 변수 선언 | `DATA lv_x TYPE i.` 맨 위에 먼저 | `DATA(lv_x) = 10.` 쓰는 자리에서 | 변수와 타입 |
| 값 넣기 | `MOVE a TO b.` | `b = a.` | 변수와 타입 |
| 비교 | `EQ`, `NE`, `GT` … | `=`, `<>`, `>` … (둘 다 돼요) | 조건문 |
| Internal Table 선언 | `... WITH HEADER LINE`, `OCCURS 0` | `TYPE TABLE OF` + Structure 따로 | Structure와 Internal Table |
| 한 줄 넣기 | `APPEND gt_std.` (헤더 라인) | `APPEND ls_std TO lt_std.` | Structure와 Internal Table |
| 건수 | `DESCRIBE TABLE lt LINES lv_n.` | `lines( lt )` | Structure와 Internal Table |
| 테이블 비우기 | `REFRESH lt.` / `CLEAR gt_std[].` | `CLEAR lt.` | Internal Table 바꾸기 |
| 키 없는 STANDARD | `WITH DEFAULT KEY` | `WITH EMPTY KEY` | TYPES와 테이블 종류 |
| Field Symbol | `FIELD-SYMBOLS <fs> TYPE ...` 먼저 선언 | `ASSIGNING FIELD-SYMBOL(<fs>)` | LOOP 자세히 |
| 1건 꺼내기 | `READ TABLE lt INTO ls WITH KEY ...` | `lt[ ... ]` | 줄 꺼내기와 값 만들기 |
| 있는지 확인 | `READ TABLE ... TRANSPORTING NO FIELDS` + `sy-subrc` | `line_exists( lt[ ... ] )` | 줄 꺼내기와 값 만들기 |
| 값 만들기 | 필드 하나씩 넣고 `APPEND` | `VALUE #( ... )` | 줄 꺼내기와 값 만들기 |
| 같은 이름 필드 옮기기 | `MOVE-CORRESPONDING a TO b.` | `CORRESPONDING #( a )` | 줄 꺼내기와 값 만들기 |
| SELECT 필드 목록 | `SELECT a b` (쉼표 없음) | `SELECT a, b` | 키로 데이터 읽기 |
| SQL 안의 변수 | `WHERE f = lv_x` | `WHERE f = @lv_x` | 키로 데이터 읽기 |
| 결과 받기 | `INTO CORRESPONDING FIELDS OF TABLE lt` (먼저 선언) | `INTO TABLE @DATA(lt)` | SQL 결과를 ABAP에서 받기 (4부) |
| 한 건씩 읽기 | `SELECT ... ENDSELECT` | `INTO TABLE` 후 `LOOP AT` | 키로 데이터 읽기 |
| DB에 넣기 | `INSERT ztab FROM ls.` / `TABLES` | `INSERT ztab FROM @ls.` | DB 테이블 바꾸기 |

<details class="more practice">
<summary>문제 풀기 — 배운 내용 확인</summary>

```quiz
Q: 회사 프로그램에 `APPEND gt_list.`처럼 TO가 없는 문장이 있어요.
Q: gt_list는 무엇일까요?
- 오타라서 문법 오류가 나요
```

## 6부. UI5와 백엔드 데이터 잇기

SAPUI5 총정리에서 배운 화면이 이 교재의 백엔드 데이터를 받을 때 알아 둘 것들이에요. ABAP과 자바스크립트를 나란히 비교하고, 백엔드 데이터에 묻어 오는 규칙과 확인할 점을 정리해요.

### ABAP과 자바스크립트 대응표

| ABAP | 자바스크립트 / UI5 |
| --- | --- |
| Structure | 객체 `{ }` |
| Internal Table | 객체의 배열 `[{ }, { }]` = 모델의 목록 |
| `LOOP AT lt_std INTO DATA(ls_std). ... ENDLOOP.` | `for (const oStd of aStd) { ... }` |
| `IF ... ENDIF.` | `if (...) { ... }` |
| 참/거짓 `'X'` / `' '` (`abap_true` / `abap_false`) | `true` / `false` |
| 날짜 타입 `d` (내부 값 `"20260902"`) | 날짜 문자열 또는 `Date` |

### 자주 만나는 백엔드 데이터 규칙

실무에서 UI5가 받는 데이터는 ABAP 개발자가 SAP 테이블에서 꺼내 보내 줘요. 그래서 **ABAP의 관습이 데이터에 그대로 묻어 와요.** 이걸 알면 "이상한 데이터"가 오류인지 규칙인지 구분할 수 있어요. 수업 예제(Lev05)의 학생 데이터도 이런 백엔드 데이터를 흉내 낸 모양이에요.

1. **참/거짓은 `"X"`와 `""`예요.** ABAP에는 불리언 타입이 없어서 `"X"`가 참이에요. 그래서 Lev05의 `Smajor: "X"`는 오타가 아니라 "전공자 맞음"일 수도 있어요. 진짜 문제는 같은 필드에 `Y/N` 방식과 `X` 방식이 **섞여 있다는 것**이에요. OData로 받으면 보통 `true`/`false`로 바뀌어 와요.
2. **코드만 저장하고, 글자는 보여 줄 때 만들어요.** 예를 들어 인사 정보의 성별 필드 `GESCH`(독일어 Geschlecht, 성별)는 `1`(남성), `2`(여성) 코드로 저장해요. 코드의 뜻은 Domain Fixed Value에 있어서 로그인 언어에 따라 "남성" 또는 "Male"로 보여요. Lev05처럼 코드(`Sgender`)와 글자(`Sgendert`)를 따로 받는 경우는 백엔드가 텍스트를 같이 보내 준 거예요. 텍스트를 손으로 넣으면 `"남"`처럼 어긋난 값이 생겨요.
3. **같은 의미는 같은 코드 체계여야 해요.** 학생은 `M`/`F`, 강사는 `1`/`2`처럼 섞여 있으면 화면마다 변환 코드가 따로 필요해져요.
4. **날짜는 화면용 형식으로 받지 마세요.** ABAP 내부 날짜는 `"20260902"`이고, OData V2(버전 2)는 `/Date(...)/`, V4(버전 4)는 `"2026-09-02"` 모양으로 와요. `"2026.09.02"` 같은 화면용 문자열을 받으면 사용자마다 다른 형식으로 보여 주기 어려워요. 형식은 UI5의 Date 타입(SAPUI5 총정리 12부 데이터 타입)이 맡게 하세요.
5. **금액은 통화와 항상 함께예요.** SAP는 금액을 내부적으로 소수 둘째 자리까지 저장해요. 소수점이 없는 KRW는 변환을 빠뜨리면 `370000`이 `3700.00`처럼 100분의 1로 보여요. 금액이 이상하게 작으면 이걸 먼저 의심하세요.
6. **앞자리 0이 있는 번호는 문자열이에요.** ABAP의 숫자 문자형(NUMC, Numeric Character)은 `"000123"`처럼 오고, 비교할 때도 문자열로 해야 해요. 학생번호 `Sid`가 문자열인 것도 계산할 숫자가 아니라 식별용 코드이기 때문이에요.
7. **필드 이름에 SAP 표준 이름이 숨어 있어요.** `Sbegda`의 BEGDA는 시작일(Begin Date), `Swaers`의 WAERS는 통화 키(독일어 Währungsschlüssel)예요. 모르는 필드명은 SE11(ABAP Dictionary를 여는 SAP 화면 번호)에서 Data Element를 찾아보면 뜻이 나와요.

### 백엔드 데이터를 받으면 확인할 것

- [ ] 참/거짓 필드가 한 가지 방식인가 (`X`/`""`, `Y`/`N`, `true`/`false` 중 하나)
- [ ] 같은 의미의 코드가 같은 체계인가 (성별, 상태 등)
- [ ] 날짜가 원본 형식인가
- [ ] 금액에 통화 필드가 같이 있고, 크기가 맞는가
- [ ] 코드와 텍스트가 서로 맞는가
- [ ] 숫자 필드와 문자 필드의 타입이 일관되어 있는가 (필터에 영향)

## 부록. 책 추천

수업과 같이 보면 좋은 책을 모아 두는 곳이에요. 지금은 임시로 한 권만 정리해 뒀어요. 책을 더 찾으면 여기에 이어서 넣을게요.

### Easy ABAP 2.0: ABAP 기본기를 한국어로 넓게 다룬 책

| 항목 | 내용 |
| --- | --- |
| 지은이 | 김성준 |
| 출판사 | 프리렉 |
| 나온 해 | 2012년 초판 (2017년 3쇄) |
| 분량 | 약 1,200쪽, 22장 |
| 기준 버전 | SAP ECC 6.0 |
| 한 줄 평 | ABAP 개념서이자 사전으로 좋아요. 코드 문법은 수업 기준으로 바꿔 읽어야 해요. |

**어떤 책인가요?** 현장에서 ABAP을 10년 넘게 다룬 개발자가 신입 교육용으로 정리한 책이에요. 장마다 문법을 먼저 설명하고, 바로 실습 예제로 확인하는 순서예요. 앞쪽 11장은 이론(데이터 타입, SQL, Internal Table, Dictionary 등), 뒤쪽 11장은 실무 화면 프로그램(리포트, 모듈 풀, ALV, 객체지향 등)이에요.

**좋은 점**

- **ABAP 기본기를 거의 다 다뤄요.** 데이터 타입부터 Open SQL, Internal Table, 서브루틴과 함수, 디버깅, ABAP Dictionary, ALV, 객체지향, 권한 체크까지 한 권에 있어요.
- **이 교재와 바로 이어져요.** 7장 ABAP Dictionary는 2·3부에서 본 테이블, 외래키, Domain, Data Element를 SE11 화면 기준으로 더 깊게 설명해요. 3장 Open SQL은 4부를, 5장 Internal Table은 4·5부를 이어 줘요.
- **예제가 많아요.** 설명 뒤에 바로 실행해 볼 수 있는 프로그램과 결과 화면이 붙어 있어요.

**조심할 점**

- **문법이 옛날 방식이에요.** 2012년 ECC 6.0 기준이라 옛 문법(`OCCURS`, `WITH HEADER LINE`, `TABLES` 파라미터)이 자주 나와요. 옛 문법을 그대로 쓰는 회사도 있어서 읽어 두면 도움이 돼요. 5부의 "옛 문법과 요즘 문법 한눈에 보기"와 같이 보세요. 반대로 요즘 수업에서 쓰는 인라인 선언{? 변수를 미리 선언하지 않고 쓰는 자리에서 바로 만드는 문법이에요. `DATA(lt_std)`처럼 적어요 ?}, `VALUE #( )`, SQL 안의 `@` 변수는 거의 없어요.
- **최신 주제는 없어요.** HANA, CDS View, OData와 Gateway, Fiori, Eclipse ADT, S/4HANA는 다루지 않아요. 특히 UI5와 백엔드를 잇는 **OData는 따로 공부해야 해요.**
- **처음 읽기엔 버거워요.** "~한다"체이고, 영어 용어가 우리말 풀이 없이 그대로 나오는 곳이 많아요. 이 교재로 개념을 먼저 잡고, 더 자세히 알고 싶을 때 찾아보는 용도가 좋아요.

**책 코드를 요즘 문법으로 바꿔 읽기**

| 책에 나오는 방식 | 수업에서 쓰는 방식 |
| --- | --- |
| `DATA itab TYPE ... OCCURS 0 WITH HEADER LINE.` | 테이블 타입으로 Internal Table을 만들고, 한 건을 담을 Structure(워크 에어리어)를 따로 둬요 |
| `SELECT ... INTO TABLE itab WHERE f = p_val.` | `SELECT ... WHERE f = @p_val INTO TABLE @itab.` |
| `DATA lv_x TYPE i.` 를 맨 위에 먼저 선언 | 쓰는 자리에서 `DATA(lv_x) = ...` |
| `PERFORM` / `FORM` 서브루틴 | 클래스의 메서드 |
